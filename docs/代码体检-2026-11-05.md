## 三个真问题

### 1. `build_state` — 206 / 447 行

签名本身就在报警：**15 个入参**（`frame, profile, prev_names, prev_blinds, avatar_reads, equity_reads, name_tracker, prev_all_in, lenient_chips, card_icons, shown_seats, prev_fold, ante_fallback, hand_roster, left_seats`）。
一个函数同时干 15 件事：质量闸、座位重建、名字粘性、庄位、盲注继承、弃牌、All-in、名单锁。

- 保护：`tests/test_frame_state.py` 46 个用例，`test_state_stream.py` 34 个，调用点集中在 `state_stream.py`。
- 拆法：按 SYSTEM.md 的口径切成「质量闸 / 座位重建 / 名字与名单 / 弃牌与 All-in」四段，每段出一个 `_xxx(state)`，主函数只做顺序编排。
- 注意：拆的时候**不要动 `errors` 的判定顺序**——`errors` 非空即丢帧，顺序变了会改变哪些帧被丢。

### 2. `observations_from_hand` — 182 / 389 行

把一条 hand 记录翻成每个对手的 `HandObservation`：hero 排除、临时键、街内行动排序、位置修正全在一个函数里。
有 `tests/test_opponent_profile.py`（32 个用例，其中多例直接打这个函数），所以是**安全可拆**的。

### 3. `live.main` — 130 / 527 行

CLI 装配 + `.env` 加载 + profile 校验 + 主循环 + 退出清理。抽出 `_run_live(args)` 只保留参数解析，能立刻降到 C 级。

## 提示词那一批：数字大，但先别动

`render_hand_facts 109`、`render_hand_strength_zh 91`、`_facing_raise_zh 89`、`value_directive 77`、`audit_advice_tags 67`，合计 433 点。
它们本质是「选项多 → 分支多 → 中文模板拼接」，可读性风险远低于数字暗示的。真要降，方向是**表驱动**（`if/elif` 换成模板字典），收益主要在可测试性，不在人读。
而且改提示词要走 AGENTS.md 的三步（bump 两个 version + 更新 golden 哈希），**为了一个静态指标去动它不划算**。

## `radon mi` 的坑（别当 KPI）

可维护性指数分布：A 133 / B 11 / C 14，其中 8 个文件直接 0.00。
但看行数就明白：`opponent_profile.py` 2864 行、`live.py` 2869 行、`replay/service.py` 2783 行、`hand_track.py` 1694 行、`repository.py` 1596 行……
MI 对文件体量和 Halstead 体积极度敏感，**体量大就归零**，它在这里只说明"文件太长"，不说明"写得乱"。
