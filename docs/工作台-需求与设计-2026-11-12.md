## 1. 目标与非目标

### 1.1 目标

1. **一处选择**：profile、视频源、窗口、按钮/滑杆、运行参数，在一个工作区里选齐。
2. **启动前体检**：源/窗口/配置/权限/端口/凭据，失败能解释、能修。
3. **运行中看得见**：帧、ROI、几何、本帧错误，不用再开几个终端。
4. **标定闭环**：拖框 → 试读 OCR → 保存 → 重启 → 浮层核对。
5. **屏幕浮层**：把 ROI/按钮框直接盖在游戏窗口上，核对真实落点。
6. **可追溯**：每次运行有配置哈希、实际窗口 rect、退出码和统计。

### 1.2 非目标（v1 明确不做）

- 不改识别算法、阈值口径、提示词。
- 不替代 CLI；命令行和脚本仍可用。
- 不启动/停止 OBS、MediaMTX、浏览器；工作台只检测和消费流。
- 不做多路并发、热重载、远程访问、多用户/登录。
- 不做“可交互浮层”（浮层只显示、点击穿透；拖框在工作台页面里）。

## 2. 角色与典型场景

| 场景 | 现在 | 工作台之后 |
|---|---|---|
| 日常开局 | 抄 `docs/mac-启动命令.md`，手跑 osascript | 选工作区 → 体检 → 启动 |
| 换桌/换源 | 改命令行、改 profile | 复制工作区 → 改源/窗口 → 体检 → 启动 |
| ROI 漂移 | 停 live、跑 Tk 编辑器、存 JSON、重启 | 暂停点击 → 标定 → 拖框/试读 → 保存 → 自动重启 |
| 按钮点偏 | 跑 `click_marks` 另开一个进程 | 浮层常驻，直接看框和真实按钮的偏差 |
| 识别丢帧 | 翻 `frame.errors`，猜是哪块 ROI | 点错误对应的框，看裁剪/OCR/解析 |
| 事后排查 | 翻日志、对不上当时用的配置 | 运行记录里看配置哈希、窗口 rect、退出码 |

## 4. 状态与核心流程

### 4.1 状态机

```
idle
  │ 体检通过 / 启动
  ▼
starting ──失败──▶ failed
  │ 首帧 + health
  ▼
running ⇄ paused_click
  │            │
  │ 进入标定    │ 退出标定
  ▼            ▼
calibrating ──保存──▶ applying ──重启──▶ running
  │
  │ 停止
  ▼
stopping ──▶ idle
```

### 4.2 启动流程

1. 读工作区，解析 profile/源/窗口/滑杆。
2. 跑体检；有 `fail` 不允许启动，有 `warn` 需确认。
3. 建运行目录 `runs/<时间>-<工作区>/`。
4. 选 live 端口（`:8020` 空闲则用，否则 `:8021+`）。
5. 释放工作台自己的预览源（摄像头必须释放）。
6. `spawn` live 子进程，传入 profile、源、窗口、点击、运行参数、预览/控制 token。
7. 等 `/api/health` + 首帧预览（超时 20s），失败显示日志尾部。
8. 状态 `running`；启动预览代理和浮层（如果开启）。

### 4.3 停止流程

1. 若在标定，先退出标定。
2. 发 SIGINT，等 10s；不退则 SIGKILL。
3. 写 `manifest.json`；关浮层；状态 `idle`。

### 4.4 应用配置（保存并重启）

1. 校验草稿；生成 diff。
2. 备份原文件；原子写。
3. 停 live。
4. 用新配置启动。
5. 启动失败：提示回滚（默认回滚备份并重启旧配置），草稿保留。
6. 成功：清草稿，刷新预览/浮层。

### 4.5 工作台退出

- 停 live、停浮层、写 manifest。
- 使用进程组（`start_new_session=True` + `killpg`），避免工作台被 Ctrl-C 后留下孤儿自动点击。
- 硬杀（SIGKILL 工作台）仍可能留下 live；v1 在文档里注明，v2 可加 `--parent-pid` 看门狗。

## 5. 工作区模型

### 5.1 文件位置

- `workspaces/*.json`（建议提交到仓库；不含密钥）。
- 一个工作区对应**一路源**。多路 = 多个工作区，v1 一次只跑一个。

### 5.2 Schema（v1）

```json
{
  "schema": 1,
  "id": "wpk-mac-live",
  "name": "WePoker Mac 实盘",
  "profile": "config/table_wpk_mac.json",
  "source": {
    "kind": "window",
    "spec": "title:WePoker-H5",
    "label": "Edge · WePoker-H5"
  },
  "window": {
    "expected_size": [736, 838],
    "pin": "manual"
  },
  "click": {
    "enabled": true,
    "mode": "profile_slots",
    "dry_run": true,
    "confirm": true,
    "bet_slider": true,
    "bet_slider_only": false
  },
  "recognizer": "roi",
  "runtime": {
    "initial_blinds": "1/2",
    "every": 0.5,
    "settle": 0.25,
    "ai_advice": true,
    "test": false
  },
  "debug": {
    "preview_fps": 3,
    "screen_overlay": true,
    "overlay_groups": ["buttons", "cards"]
  },
  "created_at": "2026-11-12T11:00:00+08:00",
  "updated_at": "2026-11-12T11:00:00+08:00"
}
```

字段说明：

| 字段 | 说明 |
|---|---|
| `profile` | 相对仓库根的路径；工作台只引用，不复制 |
| `source.kind` | `window` / `camera` / `rtsp` / `file` |
| `source.spec` | live 的 `--url` 写法：`title:...` / `index:N` / `x,y,w,h` / `cam:auto` / `rtsp://...` / 文件路径 |
| `window.expected_size` | 逻辑点；用于体检对比，不强制 |
| `window.spec` | 实现补充：游戏窗口（滑杆点击/浮层用）；窗口源留空=跟随源，摄像头/RTSP/文件源必须显式填 |
| `window.pin` | v1 固定 `manual`；不做自动固定 |
| `click.mode` | v1 固定 `profile_slots`；`legacy_clicker` 只读兼容 |
| `recognizer` | `roi` / `full`；`full` 需要额外 `full_config`，v1 只保证启动 |
| `runtime` | 精选参数；高级参数放“高级”折叠区，仍写入这里 |

### 5.3 与现有配置的关系

| 现有文件 | 在工作台里的角色 |
|---|---|
| `config/table_*.json` | 识别几何 + 按钮/滑杆槽位；工作区引用它，标定直接改它 |
| `config/bet_slider_mac.json` | 滑杆手势参数；工作区引用，窗口可在工作区覆盖 |
| `config/clicker_local.json` | 旧式绝对坐标点击；v1 只读兼容，不编辑 |
| `config/full_browser.json` | 全图识别参数；v1 只在下拉里选，不做可视化编辑 |
| `.env` | AI 凭据；工作台只检查存在性，不读取/不回显密钥 |

### 5.4 工作区发现与兼容性

- 扫描 `config/table_*.json`；能 `Profile.load` 的列为 profile。
- 兼容性标签：
  - `参考比例`（如 0.878 / 0.450）
  - `可点击`（是否有 `hero_*_button` / 滑杆槽位）
  - `可滑杆`（是否有 `hero_bet_slider` 等）
  - `全图`（`runtime` profile 或缺少 seats 时标记）
- 选源时实时比较源比例与 profile 比例：
  - 差 ≤ 2%：绿
  - 2–10%：黄（AspectFit，可能偏）
  - > 10%：红（阻断启动，提示换 profile/源）

## 6. 运行架构

```
浏览器（工作台页面）
   │ HTTP / SSE
poker_ocr.workbench  :8030
   ├─ WorkspaceStore
   ├─ Preflight
   ├─ LiveSupervisor（子进程）
   ├─ PreviewProxy（/api/live/frame.jpg → live）
   ├─ OverlayController（overlay.py）
   └─ CalibrationEngine（OcrEngine，懒加载）
        │ spawn
        ▼
poker_ocr.live  :8020（现有看板 + 新增预览/控制接口）
```

### 6.1 live 需要新增的最小接口

> 只增只读/控制端点，不改识别口径；看板 UI 仍保持只读。

| 接口 | 作用 |
|---|---|
| `GET /api/meta` | 返回本次运行的 profile 哈希、源规格、帧尺寸、content rect、窗口 rect、recognizer、点击开关状态 |
| `GET /api/preview.jpg?w=960` | 最新已处理帧的 JPEG；`?full=1` 取全分辨率；带 `X-Frame-Seq` |
| `POST /api/control/click` | `{"enabled": false}` 暂停/恢复自动点击；暂停时作废待执行点击 |
| `GET /api/control/state` | 当前点击开关、dry-run、暂停原因 |

- 控制接口只绑 `127.0.0.1`，用 `X-Workbench-Token` 校验；看板页面不暴露控制入口。
- 预览只取最新帧，编码在 HTTP 线程；不阻塞 OCR 主循环。
- live 新增 `--preview` / `--control-token` / `--run-id` 启动参数。

### 6.2 点击暂停语义

- 暂停时：清空 `_pending_decision_key` / `_deferred_click`，不执行已排队点击。
- 恢复时：不补点旧决策；只对恢复后的新决策点生效。
- 事件流里发一条 `control` 事件，方便看板/日志对齐。
- 若 live 以 `--no-auto-click` 启动，暂停接口是 no-op，UI 显示“未启用点击”。

### 6.3 预览与摄像头交接

- live 停止时：工作台自己开源（`SourcePreview`），用于标定/体检；摄像头由工作台持有。
- 启动 live 前：**先释放**工作台的采集，再 spawn；否则摄像头被占，live 打不开源。
- live 运行中：工作台不再自己开 `cam:`，一律走 `/api/preview.jpg`。
- 窗口源可以双开，但为了“看到的就是 live 看到的”，运行中也走 live 预览。
- live 启动失败若提示“源打不开”，提供“释放预览并重试”。

### 6.4 帧与几何元数据

- `meta.source.frame_size`：源帧像素尺寸。
- `meta.source.content_rect`：裁黑边/AspectFit 后的内容矩形（像素）。
- `meta.window.rect`：窗口逻辑点矩形；`meta.window.scale`：Retina 缩放。
- 工作台画 ROI 时，使用与 live 相同的 `Profile.slot_to_px` / `WindowMapper` 口径；**不另写一套换算**。
- 预览 JPEG 可缩放，但 ROI 坐标始终用归一化值 + meta，避免“按预览图像素画”导致的误差。

## 7. 配置编辑

### 7.1 原则

- **引用，不复制**：工作区指向 `config/table_*.json`；标定直接改该文件。
- **只改目标键**：加载原始 JSON dict，只更新对应 slot；保留 `_note`、未知键、键顺序。
- **结构化校验**：`Profile.validate()` 现在 `sys.exit`；工作台需要一个返回问题列表的校验函数（字段路径 + 原因 + 级别），CLI 仍可保持原行为。
- **原子写 + 备份**：临时文件 + `os.replace`；备份 `<file>.bak-YYYYmmdd-HHMMSS`，保留最近 20 份。
- **diff 可见**：保存前展示每个槽位的旧/新归一化值，以及参考尺寸下的像素位移。
- **共享提示**：明确告诉用户“这会改共享 profile，其他命令/历史也受影响”。

### 7.2 保存流程

```
草稿 → 校验 → diff → 备份 → 原子写 → 重启 live
                 │
                 └→ 校验失败：不写、不重启、标出字段
```

- 重启失败：回滚备份，默认重启旧配置；草稿保留，便于继续修。
- 保存成功但源/窗口变化导致启动失败：同样走回滚/重试提示。

### 7.3 可编辑范围

| 阶段 | 可编辑 | 只读/高级 |
|---|---|---|
| M1 | 14 个按钮/滑杆槽位（`global_slots`，含全下） | 座位、底池、牌面、阈值 |
| M3 | 全部座位槽位 + 全局槽位 | `hero_seat_id` / `ring_order` / `action_direction` / `canvas` / `thresholds` 先只读，另开“座位身份”工具 |

- 座位编辑按“一个座位一组”呈现（名字/筹码/主筹码备用/下注/动作/头像），不要平铺 45 个框。
- 移动座位名字会触发环序校验；M3 提供“按几何重排环序”的显式动作，不静默改。

### 7.4 按钮坐标的统一

- 工作台只编辑 profile 的 `global_slots`；`--bet-slider` 时 live 本来就由 `clicker_config_from_profile()` 生成点击按钮。
- `config/clicker_local.json` 的绝对坐标仅在不开滑杆时使用；工作台标为“兼容/只读”，避免两套坐标继续打架。

## 8. 调试与标定

### 8.1 三个面，各回答一个问题

| 面 | 回答 | 数据来源 | 刷新 |
|---|---|---|---|
| 页面实时视图 | 现在长什么样 | live 预览 + profile 槽位 | 2–3 fps |
| 游戏窗口浮层 | 框在真实窗口上盖在哪 | `WindowMapper` + `overlay.py` | 1–2 fps 或按需 |
| 冻结帧标定 | 这个框里的字读成了什么 | 工作台 OCR + 现有 parse | 拖框后/手动 |

### 8.2 页面实时视图

- 帧 + 全部 ROI 框；按组开关：座位 / 动作 / 牌 / 底池与盲注 / 按钮 / 滑杆。
- 颜色：
  - 蓝：点击目标
  - 绿：本帧该字段正常
  - 黄：低置信度/警告
  - 红：本帧 `frame.errors` 命中
  - 灰：未参与本帧
- 点框 → 检查器：槽位名、归一化坐标、参考尺寸下像素矩形、本帧错误。
- 几何条：帧尺寸、content rect、缩放、窗口 rect、预计偏移。
- 错误映射：`frame.errors` 是 `pot:遮挡` / `stack:a` 这类字符串；按前缀映射到槽位，映射不到的列在“其他错误”。

### 8.3 游戏窗口浮层

- 复用 `overlay.py`：透明、置顶、点击穿透、心跳退出。
- 工作台用 Pillow 渲染 PNG（窗口逻辑点尺寸，Retina 可 2x），交给浮层进程显示。
- 画：ROI 框、按钮可点区（圆钮画圆）、当前选中框、草稿框（虚线）。
- 组开关 + “只显示选中组”，避免 50 个框糊住画面。
- 浮层只显示，不接收鼠标；拖框在页面里。要直接在游戏窗口上拖，是 v2 的“可交互浮层”。
- 每 1s 读一次窗口 rect；窗口移动/缩放后重渲染，避免浮层错位。
- 浮层失败一律 fail-open：不影响 live，也不阻塞页面。

### 8.4 冻结帧标定 + OCR

- 暂停在最近一帧；拖框/缩放/微调/撤销/重做。
- 选中槽位后：
  1. 按草稿坐标裁图；
  2. 工作台 `OcrEngine` 跑 rec；
  3. 用现有 `parse` / `fields` 解析（筹码过 BB 闸、名字过词库、动作映射）；
  4. 显示裁剪图、原文、置信度、解析值、通过/失败原因。
- 标注“试读”：不走去重/缓存/稳定闸，和 live 实际读数可能略有差异；用于判断“位置对不对、字读不读得出”，不冒充最终结果。
- 拖框时防抖 150ms；也可手动“重新试读”。
- 按钮/滑杆槽位不是 OCR 字段：显示几何 + OCR 是否在框内找到按钮中心（复用 `click_marks` 的逻辑）。

### 8.5 几何诊断

显示三套网格的对齐情况：

```
视频帧     1472×1676
内容区     1472×1676（无 letterbox）
profile    1472×1676  缩放 1.0000 / 1.0000
窗口       736×838 逻辑点 @2x
预计偏移   动作行(ny≈0.85) 偏低 0.0pt
```

- 逐项判定：比例、缩放、偏移、letterbox、窗口高度漂移。
- 出现偏差时，给“固定窗口 / 换源 / 换 profile”的明确建议。

## 10. 安全与权限

1. **只绑 `127.0.0.1`**；不做远程访问。
2. **控制接口加 token + Origin 校验**：本地网页也可能被恶意页面 POST；不能只靠“localhost”。
3. **工作台退出停 live**：进程组 + SIGINT，避免孤儿自动点击。
4. **暂停点击即作废待执行点击**：恢复后不补旧决策。
5. **原子写 + 备份 + 回滚**：坏配置不能静默生效。
6. **参数白名单**：UI 不拼任意 shell 参数；所有参数来自工作区字段。
7. **日志脱敏**：不回显 `.env`/API key；manifest 只存哈希。
8. **权限前置**：屏幕录制、辅助功能、Automation、摄像头，首次运行给出系统设置路径。
9. **外部进程**：只检测 OBS/MediaMTX/浏览器，不启动/不杀。

## 11. 里程碑

### M1 — 日常可用闭环

**交付**

- 工作台骨架（FastAPI + 静态页）：工作区列表/详情/配置/体检。
- 工作区：从 profile 新建、复制、删除；`workspaces/*.json`。
- 体检：profile/源/窗口/权限/端口/凭据（不含源枚举 UI）。
- LiveSupervisor：启动/停止/重启；运行目录 + manifest；日志尾部。
- live 最小接口：`/api/meta`、`/api/preview.jpg`、`/api/control/click`。
- 运行页：预览 + ROI 叠加 + 点框看槽位/错误 + 暂停/恢复点击。
- 屏幕浮层（基础）：ROI/按钮框、组开关、1–2 fps。
- 标定：按钮/滑杆槽位拖拽/缩放/微调/撤销；试读 OCR；保存 + 自动重启。
- 窗口：读取 + 校验 + 手动“固定窗口”。

**验收场景**

1. 从 `table_wpk_mac.json` 新建工作区，选 `window:title:WePoker-H5`，体检通过，启动。
2. 运行页看到帧 + ROI；点 `hero_raise_button` 能看到坐标和本帧错误。
3. 暂停点击；进入标定；拖动主钮 10px；试读显示“加注 / 0.93”；保存；自动重启；备份文件存在；diff 显示位移。
4. 浮层盖在 Edge 窗口上，框与真实按钮对齐；组开关生效。
5. 停止 live，无残留进程；`runs/<...>/manifest.json` 有 profile 哈希、窗口 rect、退出码。

### M2 — 几何与源

- 源管理：窗口枚举/摄像头枚举/RTSP/文件 + 单帧检测。
- 窗口固定：手动按钮 + AppleScript 预览；不自动固定。
- 几何诊断：三套网格、缩放、偏移、letterbox。
- 运行参数面板（基础/高级）。
- 运行历史列表 + manifest 摘要。
- 浮层颜色状态、更多组、选中框联动。

### M3 — 全 ROI 与深度调试

- 全 ROI 编辑：座位（名字/筹码/主筹码备用/下注/动作/头像）+ 全局（底池/本街底池/盲注/公共牌/手牌/手牌标签）。
- 座位身份工具：hero、环序、行动方向（显式操作，不静默改）。
- 逐 ROI OCR + 放大镜 + 单帧重跑 + 与 live 实际读数对比（需要 live 暴露逐 ROI 诊断）。
- 配置 diff/回滚 UI。
- （可选）热重载。

## 12. 风险与待定

| 风险/待定 | 说明 | 建议 |
|---|---|---|
