### A1（P0）河牌攻击块仍写「强听」——与河牌场景段直接冲突

**现状**：`poker_ocr/prompt/user/attack.py`

- `render_attack_zh()` 的六个结论分支（[attack.py:390-411](poker_ocr/prompt/user/attack.py#L390-L411)）全部包含「强听可按牌型段…小注诈唬」；
- `_attack_evidence()` 的湿面提示（[attack.py:283-286](poker_ocr/prompt/user/attack.py#L283-L286)）写「优先用有摊牌价值或能改进的牌」；
- 攻击块**没有按街分支**（陷阱分支 [attack.py:366-376](poker_ocr/prompt/user/attack.py#L366-L376) 已在 11-03.10 按街处理，开放分支漏了）；
- 而 `system/scenario.py` 的河牌段（[scenario.py:68-69](poker_ocr/prompt/system/scenario.py#L68-L69)）明确写「河牌听牌等同空气，不要拿『反超 outs』当跟注权益」。

**后果**：溜入池河牌、Hero 收尾、弃牌率达标时，同一份 prompt 同时说「强听可以小注诈唬」和「听牌已死」。
`test_advice.py` 里没有针对河牌攻击块开放分支的断言，所以一直没被发现。

**改法**：把四处「听牌/空气」措辞抽成按街的槽位，**非河牌文案逐字不变**
（否则会打破既有断言 `test_attack_block_uses_same_draw_rule_and_neutral_wording`，
它要求攻击块出现字面量「强听/空气」）。

1）在 `attack.py` 的 `_board_wet()` 之后新增：

### A2（P0）恒定段硬编码「本池历史 14% / 8%」——换桌即伪事实

**现状**：`poker_ocr/prompt/system/aggression.py`

- [aggression.py:32](poker_ocr/prompt/system/aggression.py#L32)：「目标下注率 ≥40%，**本池历史只有 14%**，这是最大的一处漏。」
- [aggression.py:39](poker_ocr/prompt/system/aggression.py#L39)：「目标 PFR 14–16%（**本池历史 8%**）。」
- [aggression.py:33](poker_ocr/prompt/system/aggression.py#L33)：「对手是跟注站（跟 c-bet ≥55%、河牌跟得多）用满池」

这些数字来自 2026-11-04 的 665 手复盘（某个池子的历史），却写在**任何桌都注入的恒定段**里；
与之对账的「桌况统计」段已在 11-04.1 整体删除，模型无从验证。
换一个池子/换一群对手，这句话就变成了优先级第 3 层以上的「伪事实」——
而事实优先级（`priority.py`）规定硬事实 > 计算 > 画像 > 观察，模型没有依据判定它该不该信。

**改法**：不删（它是有用的行为目标），但**降级为「历史池的统计口径」并显式让位**。

在 `## 频率目标（这张池子的剥削线，不是鼓励乱开火）` 标题下、第一条之前插入一行：

```text
- 本段三个数字（下注率 / PFR / 跟注站阈值）来自 2026-11-04 的 665 手复盘，是**历史池的统计**，不是当前桌实测；与「数据质量」「实时牌力」「对手画像」的实测冲突时以实测为准，没有实测时按这里的频率目标。
```

再把两处「本池历史」改成「历史池」：

```text
- ...目标下注率 ≥40%（依据：2026-11-04 的 665 手复盘，历史池 14%），这是最大的一处漏。
- - 决定入池就加注，不溜入、不补齐：目标 PFR 14–16%（依据同一份复盘，历史池 8%）。范围内默认开池/隔离加注；...
```

同时在 `version.py` 顶部写清依据（见 §5）。

**后续（P2，不在本批）**：把 40 / 14 / 8 / 55 抽到 `poker_ocr/tables/pool_targets.json`
（带 `source` / `verified` / `needs`），由 `strategy_tables.py` 按桌型注入，恒定段只留「怎么用」。
这与项目既定的「数字只住 tables/」一致，但会引入新的注入链路，建议单独立项。

### A3（P1）打牌面 + 强听仍写「一对（未成牌）」

**现状**：`poker_ocr/prompt/user/strength.py:83-84`

```python
        if is_draw:
            made += "（未成牌）"
```

`coach.read_hand()` 在 `cat >= ONE_PAIR and _plays_board(...)` 且 `outs >= 8` 时返回 `STRONG_DRAW`
（[coach.py:617-620](poker_ocr/coach.py#L617-L620)），`situation.hand_class` 因此归 `draw`（[situation.py:164](poker_ocr/situation.py#L164)），
于是同屏出现：

```text
## 牌型：听牌
牌力：强听牌（9 outs）
当前牌型：一对（未成牌）
```

**实测确认**（9♥9♠5♥ + A♥K♥）：

```text
hand_label : 打牌面+强听(9 outs)
tier       : 强听
plays_board: False          ← 注意：这个字段不能当判据
gt.category: 1（一对）
```

**关键坑**：`sit.plays_board` 来自 `read.plays_board`，而 `read_hand.mk()` 里写的是
`plays_board=(tier == BOARD_PLAY)`（[coach.py:612](poker_ocr/coach.py#L612)）——
只有 tier 恰好是「打牌面」时才为 True。这里 tier 已经是 `STRONG_DRAW`，所以它 **False**。
用它当判据改不动这个 bug。

**改法（最小）**：用 `ground_truth.made.category` 判「有没有自己的成牌」。

```python
        if is_draw:
            # 「未成牌」只对真的高牌成立。打牌面 + 强听时已成一对（公面给的），
            # 写「未成牌」会和同屏「当前牌型：一对」自相矛盾；也不能用
            # sit.plays_board 判断（那个字段只在 tier==打牌面 时为真）。
            if made_gt is not None and made_gt.made.category >= ONE_PAIR:
                made += "（打牌面，未成自己的牌）"
            else:
                made += "（未成牌）"
```

（`made_gt` 就是同函数里已有的 `sit.ground_truth`，见 [strength.py:58](poker_ocr/prompt/user/strength.py#L58)；
`ONE_PAIR` 已 import。）

**测试**：

### A4（P1）仲裁 #5 与「池子先验」的逻辑张力

**现状**：

- [arbitration.py:19](poker_ocr/prompt/system/arbitration.py#L19)：「…未知/不匹配对手按保守先验处理，**不能把多家画像平均成一条泛化结论**。」
- [pool.py:181-183](poker_ocr/prompt/user/pool.py#L181-L183)：「某个座位没有该街实测时按这条估计，不要因为「没有这个人的数据」就默认过牌。」

池子先验**就是**把多家画像合并成一条，然后被要求用于逐座位判断。
目前靠组装门控压着（`attack` 或 `fold_eq` 在场就不渲染，见 [user/__init__.py:66-95](poker_ocr/prompt/user/__init__.py#L66-L95)），
但 prompt 文本本身没给豁免——模型严格按仲裁表办事时应当无视池子先验。

## 2. B 组：AI 建议链路

### B1（P0）兜底升级：模型不可用时用规则引擎，而不是「一律过牌/弃」

**现状**：`poker_ocr/advice.py:468-477`

```python
def fallback_option(sit: Situation) -> str:
    if sit.snap.to_call > 0:
        return "fold"
    return "call"           # to_call == 0 时 call 这个 id 就是「过牌」
```

模型超时/报错/未配置时，**Hero 拿着坚果被下注也一律弃**。而 `coach.py` 里已有一套完整规则引擎
`advise(hero_cards, board, street, ...) -> Decision(ok, action, sizing_bb, ...)`（[coach.py:1405](poker_ocr/coach.py#L1405)），
只覆盖 flop/turn/river（无翻前），越界时 `ok=False` 不猜——正好符合 fail-open 口径。

**改法**：新增规则兜底，保留旧函数作为最后一道。

```python
def _rule_fallback(sit: Situation) -> tuple[str, str] | None:
    """翻后兜底：用 coach 规则引擎产出一个可执行的 option id。

    只在「模型不可用」时调用。翻前没有规则引擎（coach 只覆盖 flop/turn/river），
    底池/后手缺失、牌不合法时 coach 返回 ok=False，这里一律放弃、交给最保守口径。
    """
    snap = sit.snap
    if snap.street == PREFLOP:
        return None
    if not snap.hero_cards or len(snap.board) < 3:
        return None
    if snap.pot is None or snap.pot <= 0:
        return None
    from .coach import advise as rule_advise

    try:
        d = rule_advise(
            list(snap.hero_cards), list(snap.board[:5]),
            street=snap.street,
            pot=float(snap.pot),
            hero_position=snap.hero_position,
            opponents=snap.opponents_in_hand,
            stack_bb=snap.hero_stack,
            hero_invested_bb=snap.hero_invested,
        )
    except (ValueError, KeyError):
        return None
    if not d.ok or not d.action:
        return None

    ids = {o.id for o in sit.options}
    if d.action == "fold":
        return ("fold", "规则引擎：牌力与赔率不支持继续") if "fold" in ids else None
    if d.action == "check":
        return ("call", "规则引擎：过牌看下一张") if "call" in ids else None
    if d.action == "call":
        return ("call", "规则引擎：赔率支持跟注") if "call" in ids else None
    # bet / raise：挑最接近 sizing 的档位；没有 sizing 就用 1/3 池
    sized = [o for o in sit.options
             if o.kind in ("bet", "raise") and o.amount is not None]
    if not sized:
        return None
    target = float(d.sizing_bb or 0.0) or float(snap.pot) / 3.0
    best = min(sized, key=lambda o: abs(float(o.amount) - target))
    return (best.id, "规则引擎：按牌力与底池尺度下注")
```

再把 `advise()` 里的 `fallback()` 改成：

```python
    def fallback() -> tuple[Option, str]:
        """模型不可用时的确定性兜底：翻后先用规则引擎，其余按最保守。"""
        hit = _rule_fallback(sit)
        if hit is not None:
            oid, reason = hit
            option = by_id.get(oid) or next((o for o in sit.options if o.id == oid), None)
            if option is not None:
                return option, reason
        oid = fallback_option(sit)
        if oid in by_id:
            return by_id[oid], "未配置模型/模型不可用，按最保守的默认动作"
        return (next((o for o in sit.options if o.id == oid), sit.options[0]),
                "未配置模型/模型不可用，按最保守的默认动作")
```

三处 `make(fallback(), ...)` 改成 `option, why = fallback()` 并传入 `why`；
`source` 用 `"fallback_rules"` 区分（便于统计「模型失效但规则仍给出了动作」）。

**安全性**：`clicker` 的 `allow_fallback` 默认 `False`（[clicker.py:208](poker_ocr/clicker.py#L208)、
[live.py:2203](poker_ocr/live.py#L2203)），所以规则兜底**不会被自动点击**，只在日志/看板/落库里可见。
这与「宁可保守也不要错」的口径一致，同时让复盘能看到「如果模型挂了会怎样」。

### B2（P0）模型 × 规则交叉校验：严重冲突时阻断自动点击

**现状**：模型建议落库后**直接进点击器**，唯一的软闸是 `min_advice_confidence`，默认 `0.0`
（[live.py:1095](poker_ocr/live.py#L1095)）＝不生效；且 prompt 只说 confidence「可选」。
模型可以把「三条全下」这种严重偏离给出来，链路没有任何第二意见。

**改法**：新增 `poker_ocr/cross_check.py`（纯函数，无 I/O、无模型调用）。

```python
"""模型建议 × 规则引擎的交叉校验。

只做一件事：把模型选的 option 归到 fold / passive / aggressive 三类，
和规则引擎的结论比一次。**不投票、不改动作**——它是安全闸与观测信号，
不是第二套策略（两套策略会立刻漂成两份规则，这正是 offline/ 的教训）。
"""

from __future__ import annotations

from dataclasses import dataclass

from .hand_track import PREFLOP

# 严重程度：ok < mild < severe
_OK, _MILD, _SEVERE = "ok", "mild", "severe"


@dataclass(frozen=True)
class CrossCheck:
    conflict: str          # ok | mild | severe
    rule_action: str | None
    detail: str = ""


def _bucket(kind: str) -> str:
    if kind == "fold":
        return "fold"
    if kind in ("check", "call"):
        return "passive"
    return "aggressive"      # bet | raise | allin


def check(sit, option) -> CrossCheck:
    """对比模型动作与规则引擎动作；覆盖范围外一律返回 ok（不误伤）。"""
    snap = sit.snap
    if snap.street == PREFLOP or not snap.hero_cards or len(snap.board) < 3:
        return CrossCheck(_OK, None, "翻前/无牌面：不做交叉校验")
    if snap.pot is None or snap.pot <= 0:
        return CrossCheck(_OK, None, "底池未知：不做交叉校验")
    from .coach import advise as rule_advise

    try:
        d = rule_advise(
            list(snap.hero_cards), list(snap.board[:5]),
            street=snap.street, pot=float(snap.pot),
            hero_position=snap.hero_position,
            opponents=snap.opponents_in_hand,
            stack_bb=snap.hero_stack,
            hero_invested_bb=snap.hero_invested,
        )
    except (ValueError, KeyError):
        return CrossCheck(_OK, None, "规则引擎无法评估")
    if not d.ok or not d.action:
        return CrossCheck(_OK, None, d.reason or "规则引擎超出覆盖范围")

    mine, theirs = _bucket(option.kind), _bucket(d.action)
    if mine == theirs:
        return CrossCheck(_OK, d.action)
    if mine == "aggressive" and theirs == "fold":
        return CrossCheck(_SEVERE, d.action,
                          f"模型 {option.kind} vs 规则 {d.action}")
    return CrossCheck(_MILD, d.action,
                      f"模型 {option.kind} vs 规则 {d.action}")
```

接入点（三处）：

1. `Advice` 数据类加一个可选字段（默认 `None`，**不动已有字段顺序**）：
   `cross_check: str | None = None`，并写进 `to_dict()`。
2. `advise()` 在模型成功返回后调用：
   ```python
   cc = check(sit, by_id[choice])
   return make(by_id[choice], reason, "model", plan=plan,
               confidence=_confidence(data.get("confidence")),
               alias_from=alias_from, meta=..., cross_check=cc.conflict)
   ```
3. `_click_skip_reason()`（[live.py:2198](poker_ocr/live.py#L2198)）加一条闸：
   ```python
   if getattr(advice, "cross_check", None) == "severe":
       return "cross_check_conflict"
   ```
   **注意**：`cross_check_conflict` 不要加进 `DEFER_CLICK_REASONS`（[live.py:371](poker_ocr/live.py#L371)）——
   规则冲突不会因为等下一帧而消失，补点只会重复撞同一堵墙。
4. CLI 加 `--cross-check {off,warn,block}`，默认 `block`（严重冲突不点，只记日志/看板）。
   参数校验走 `live.py` 现有 fail-fast 风格（参考 [live.py:2936](poker_ocr/live.py#L2936)）。

**为什么默认 block 而不是 off**：模型建议已经会进 MySQL 和复盘，点错一次是真金白银；
而严重冲突（规则喊弃、模型喊加注/全下）在本地样本里本来就该是罕见事件，拦住它的成本接近零。

**测试**：

### B4（P2）confidence：把闸打开并做校准

**现状**：`min_advice_confidence` 默认 `0.0`（不生效）；`output.py` 把 confidence 写成「可选」。
于是：模型不给 confidence 时闸门形同不存在；给了也没有任何依据说明 0.7 的含义。

**改法（分两步）**：

1. **提示词**把 confidence 从「可选」改成「建议给出」（不强制，避免截断 JSON）：

   ```text
   需要置信度时（可选，但**建议给**）：
   {"option": "<id>", "reason": "...", "confidence": 0.7}
   confidence 的含义：这次动作在当前事实下你有多确定（0–1）；事实缺口越大、越接近混合策略，就越低。
   ```

2. **工具** `tools/confidence_calibration.py`：读 `logs/live.states.jsonl` + 手牌库，
   输出分桶可靠性表（0–0.4 / 0.4–0.6 / 0.6–0.8 / 0.8–1.0 各自的命中率与样本数），
   用「建议是否与实际摊牌结果一致」当代理标签。有了这张表，才谈得上设 `--min-advice-confidence 0.6`。

   复用现有手牌导出：`tools/export_live_hands.py` 已有解析逻辑，不要重写。

**落地建议**：先跑一次校准，再决定默认值；**不要**在没有数据时直接把默认闸设成 0.6——
那会把大量正常建议拦成 `low_confidence`，用户体感是「不点了」。

## 3. C 组：架构

### C1（P0）`live.main` 抽 `_run_live`

**现状**：`poker_ocr/live.py` 共 3579 行，`main()` 从 [live.py:2800](poker_ocr/live.py#L2800) 起 **737 行**
（体检文档记录 527 行 / CC 130，之后还在长）。它同时做：参数解析、`.env` 加载、
profile 校验、日志/看板/点击器装配、主循环、退出清理。

**改法**（纯搬运，不改行为）：

```python
def _build_parser() -> argparse.ArgumentParser: ...      # 参数定义
def _load_runtime_env(args) -> None: ...                 # .env + STRATEGY_TABLES_PROFILE 校验
def _build_runtime(args): ...                            # reader/tracker/runner/web/clicker 装配
def _run_live(args, runtime) -> int: ...                 # 主循环 + finally 清理
def main(argv: list[str] | None = None) -> int:
    args = _build_parser().parse_args(argv)
    _load_runtime_env(args)
    return _run_live(args, _build_runtime(args))
```

**验收**：`main` ≤ 60 行；`nv -m poker_ocr.live --help` 输出与改前逐字一致（可 `diff` 保存的 help 文本）；
`--test` 跑通一次；`nv tests/run_all.py` 无新增失败。

**风险点**：`finally` 里的 writer flush / web stop / runner.close 顺序不能变，
否则硬杀时可能丢最后一条建议。搬运时保持退出顺序原样。

### C2（P1）`build_state` 拆 4 段

**现状**：15 个入参（[frame_state.py:232](poker_ocr/frame_state.py#L232)），一个函数干 15 件事。

**改法**：按体检文档的方案切「质量闸 / 座位重建 / 名字与名单 / 盲注与弃牌与 All-in」，
主函数只做顺序编排，入参收进一个 `BuildContext`（`@dataclass(frozen=True)`）避免继续加参数。

**硬约束**：`errors` 的判定顺序**不能变**——`errors` 非空即丢帧，顺序变了会改变哪些帧被丢。
重构前先把「丢帧集合」用 golden 快照锁住：对 `images/` 里的固定样本跑一遍，
把每帧的 `errors` / `status` 序列存成 JSON，重构后逐帧比对。

## 6. 风险与回滚

| 改动 | 主要风险 | 回滚方式 |
|---|---|---|
| A1 河牌措辞 | 攻击块在河牌变得更保守，可能少赚价值 | 单条文本回退；版本号回退需重跑 golden |
| A2 频率目标让位 | 模型可能因「历史统计」而弱化下注倾向（又回到紧弱） | 保留目标数字不变，只删让位句即可 |
| A3 打牌面措辞 | 几乎无风险（纯措辞） | 回退一行 |
| B1 规则兜底 | 规则引擎在边缘点给出比「保守」更激进的动作 | 兜底不进自动点击（`allow_fallback=False` 已是默认），只影响日志；若仍不放心，加开关 `--no-rule-fallback` |
| B2 交叉校验 | 规则与 prompt 口径不同步时可能误拦 | `--cross-check warn` 一键降级为只记录 |
| C1/C2 拆分 | 顺序（尤其 `errors` 判定、退出清理）改变会静默改行为 | 先做行为快照（丢帧集合 / help 文本），diff 通过再合 |

**原则**：提示词改动一律「一次 bump、一次 golden、一次 A/B」；代码拆分一律「先锁行为快照、再搬代码」。
