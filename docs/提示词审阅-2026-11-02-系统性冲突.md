## 一、结论摘要

本报告列了 **8 个 P0、11 个 P1、8 个 P2**，共 27 项。最需要先处理的不是措辞，
而是下面 5 个会直接改变动作的结构性冲突：

| # | 冲突 | 一句话后果 |
|---|---|---|
| 1 | 炸弹池同时写“按正常翻后规则打”和“顶对及以上只打一条街、被下注即弃” | 模型可以合理化下注/跟注，也可以在任何下注前弃牌；两种读法都能找到原文 |
| 2 | 河牌同时写“跟注看赔率/线路”和“被加注默认弃” | 面对小加注、有赔率时也会弃；或反过来用赔率给跟注找理由 |
| 3 | 面对 4-bet 仍写“可以 4-bet”；5-bet 选项被标成“4-bet” | 模型会把 5-bet 当 4-bet，套用“4-bet 只用 KK/AA”，或在不该加注时加注 |
| 4 | system 写“无弃牌率别用听牌硬下注”，攻击块写“仅强牌/强听下注（没有该街弃牌率）” | 同一屏两句相反；攻击块更具体，通常会赢，system 规则被架空 |
| 5 | 翻前范围结论一句里同时写“在开池范围内”和“不在收紧后的范围内”，下一行是“平跟 1BB” | 复跑里 13 次在溜入池平跟；报告确认 12/13 还原 system 后仍平跟——问题在事实层/选项，不在 system 某一句 |

另外三个高频误导源：

- **“关键事实缺失→最保守=能过牌就过牌”** 没有定义“关键”，而数据质量经常写
  “无”，模型要么过度保守，要么误以为事实齐全。
- **“对范围权益”** 把“对跟注范围的河牌权益、未计后续下注”当成“程序计算”
  的权威事实；K9s 的 91% 由此而来。K3s 的“赔率够”则是同一类问题的另一面：
  把“全下/单街赔率够”当成“可以跟”，没有区分对手的加注范围。
- **“本手已投入”** 还在渲染，但 system 里已经没有“已投入是沉没成本”的提醒；
  设计文档原先有，后来被删掉了。

三个机制值得单独说：

### 2.1 补丁式加规则，不删旧规则

每一轮亏损都对应一条新规则：K3s → 炸弹池一条街；AK 4-bet 到 100 → 4-bet 只用
KK/AA；K9s 河牌跟注 → 河牌被加注默认弃；54o 听牌全下 → 无弃牌率不推。
这些规则被**追加**到 system，旧规则（“按正常规则”“按赔率决定”“跟注看赔率/
线路”“价值下注看更差的牌会不会跟”）没有删。结果不是“新规则覆盖旧规则”，
而是两套规则同时在场。

### 2.2 单桌/单手过拟合

497 手复盘自己写了依据：

- 炸弹池 41 手里真正交过手的只有 8 手；唯一的大坑是 K3s 一手（-140.5），
  其余 40 手合计 +112.5（`reports/手牌复盘-2026-11-01-全量497手.md:216-228`）。
- “4-bet 只用 KK/AA”来自这张桌子 3-bet 范围 QQ+/AK 的判断
  （同报告 `:324`）。
- “河牌被加注 = 弃掉所有非坚果”来自这张桌子河牌加注 95% 是价值
  （同报告 `:305-306`）。

这些是**本桌剥削**，不是普适规则。写成 system 的“只用/默认/即弃”后，换一张
桌子就会反向吃亏。

### 2.3 1900 字符预算把“条件句”挤成了“绝对句”

`tests/test_advice.py:3246` 断言 `len(system) <= 1900`；当前 system 正好 1898 字。
预算本身不是错，但它让每次修复只能“加一句短的绝对规则”，没有空间写
“如果…则…；除非…”。于是规则越来越硬，冲突越来越多。这是本报告认为最需要
先松开的约束：多 300–400 字（约 300–500 token）远比一次错误的全下便宜。

### 2.4 事实层承担了建议，但没有单一裁决

事实块里现在至少有五段是**建议**，不是事实：

- `## 攻击机会` 的“结论：…”
- `## 剥削判断` 的“结论：跟着过牌…”
- `## 炸弹池打法` 的“顶对及以上…被下注即弃”
- `桌况读法` 的“强牌可以过牌诱导 check-raise”
- `## 决策提示` 的“桌况提示：…”

它们和 `## 实时牌力`、`## 范围`、`## 对手画像` 混在一起，system 的“事实优先级”
又没有给它们排位。模型会把“建议”当“事实”，或者反过来用“事实”压“建议”。

### 2.5 文档/测试与代码漂移

- `docs/中文-lean-提示词-重构方案.md:125` 明确写“**不写‘永远/绝不’**……新 prompt
  只给决策顺序和常见错误”；当前 system 却有“只用 KK/AA”“非坚果不打三条街，
  被加注默认弃”“无弃牌率别用听牌硬下注”。
- `README.md:110-111`、`:137-139` 仍写“炸弹池按正常翻后规则打”；当前 system
  写“只打一条街、被下注即弃”。
- `docs/live-stream.md:244-249` 也仍是旧口径。

这不是文档问题，而是**没有单一事实源**：system、事实块、README、设计文档各自
记一份口径，改一处不会同步另外三处。下次审阅还会拿 README 当事实。

## 三、P0：会直接改变动作的冲突

### P0-1 炸弹池：三套口径同时出现

**原文（system，`advice.py:2314`）**

> 炸弹池（强制前注、低 SPR）：顶对及以上总共只投一条街的钱（下注/跟注），
> 之后过牌/弃牌、被下注即弃；低于顶对默认过牌/弃牌、不主动下注，只有
> 「有位置+画像可读(疯子/高弃牌率)+赔率≥3:1」才跟一注。

**原文（事实块，`advice.py:3657-3672`）**

> 炸弹池结构：SPR 0.9，3 人池；底池大不等于必须打光，**按正常翻后规则**
> （牌力、赔率、位置、对手线路）打。
>
> 炸弹池浅码：后手少、底池大，但顶对/超对仍**按赔率和对范围权益决定**；
> 无加注、干燥面、价格合适时可以继续，但不主动造大底池……
>
> 炸弹池打法：顶对及以上总共只投一条街的钱（下注/跟注），之后过牌/弃牌、
> **被下注即弃**……

**实测渲染（3 人炸弹池、SPR 0.9、Hero 顶对 A 踢）**

```
炸弹池结构：SPR 0.9，3 人池；底池大不等于必须打光，按正常翻后规则……打。
炸弹池浅码：……顶对/超对仍按赔率和对范围权益决定；无加注、干燥面、
            价格合适时可以继续……
炸弹池打法：顶对及以上总共只投一条街的钱（下注/跟注），之后过牌/弃牌、
            被下注即弃……
```

**为什么是冲突，而不只是啰嗦**

1. “按正常规则”允许在干燥面用顶对下注/跟注；“一条街”只允许一次；“被下注
   即弃”又要求面对任何下注都弃。三句话给出三种动作。
2. “总共只投一条街的钱（下注/跟注）”与“被下注即弃”在**同一条街**就冲突：
   Hero 过牌，对手下注——这算“一条街的钱（跟注）”，还是“被下注即弃”？
3. `advice.py:3687-3690` 还有一条更硬的“节奏”规则：只要前一街投过钱，本街
   “只能过牌/弃牌，**不能跟注、不能加注**”。这条规则不看到底池赔率：对手下注
   1BB 进 100BB 也必须弃。
4. 条件本身还写反了：跟注时你想要对手会诈唬/下注宽，而“高弃牌率”是对手
   面对下注弃得多——说明他下注范围偏强/被动，恰恰不该用弱牌跟。这里应写
   “对手会诈唬/范围宽”，不是“高弃牌率”。
5. 它和 P0-2 的河牌规则叠加时，河牌会被弃两次；和 P1-1 的“对范围权益”叠加时，
   模型又会用权益给跟注找理由。

**建议**

炸弹池不要写“正常规则”和“一条街”两套。选一套，并给出条件。推荐：

> 炸弹池（强制前注、低 SPR）：按正常翻后规则打，但默认只打两条街；
> SPR<2 或 4 人以上时，顶对/超对只打一条街（下注或跟注一次），之后过牌。
> 面对下注/加注按赔率与范围决定，不默认弃；只有“本桌回测/画像明确显示
> 转河大注几乎全是价值”时，才把“面对转/河大注默认弃”作为**本桌剥削**。
> 低于顶对默认过牌/弃牌；要跟一注，需要“有位置 + 对手会诈唬/范围宽 +
> 赔率≥所需权益”，不要用固定 3:1 代替 outs。

把“本桌 41 手炸弹池回测”的那条放进可开关的 `SYSTEM_EXPLOIT_ZH`（见 §6.2），
不要写进 core。这样既保留这张桌的 edge，又不会在别的桌把顶对/明三条弃掉。

### P0-2 河牌：“非坚果不打三条街，被加注默认弃”与赔率/线路冲突

**原文（`advice.py:2312`）**

> 河牌：纯听牌等同空气，已成对的牌仍有摊牌价值；跟注看赔率/线路，
> 价值下注看更差的牌会不会跟。**非坚果不打三条街，被加注默认弃。**

**冲突**

- 同一句前半说“跟注看赔率/线路”，后半说“被加注默认弃”。如果赔率合适
  （例如对手 min-raise、Hero 只需再跟 10% 底池），到底看赔率还是默认弃？
- “非坚果”范围太大：第二坚果同花、非坚果葫芦、三条都算“非坚果”。这些牌
  面对一张紧手的河牌加注，很多时候仍是最好牌。
- “已成对的牌仍有摊牌价值”也太宽：四人池、四花面、四顺面上的底对没有
  摊牌价值；这句话会让模型用底对抓诈。
- 它和事实块的范围警告（“河牌面对全下，80% 压过你，几乎没有诈唬；不要拿
  ‘我现在有牌’当跟注理由，按权益和价格判断”，`advice.py:2984-2991`）方向
  一致，但和“跟注看赔率”不一致；模型会优先读更具体的范围警告，于是“默认弃”
  又变成“看范围警告”。

**为什么误导**

这条规则来自这张桌“河牌加注 95% 是价值”的读数，但写成了通用规则。换一张
有诈唬能力的桌子，Hero 会用“非坚果”弃掉本应抓诈的牌；在同一张桌子，Hero
又可能因为“赔率合适”跟注，而忽略“对手加注范围已经收窄”。两种错误都由
同一句话授权。

**建议**

> 河牌：纯听牌等同空气；已成对的牌有摊牌价值，但要看牌面/人数。
> 跟注看赔率与对手线路；价值下注看更差的牌会不会跟。
> 非坚果默认不打三条街；被加注时先按**加注范围**重算权益与赔率，
> 只有赔率不足、对手是价值型、或范围警告显示你只赢诈唬时才弃；
> 不要用“我是非坚果”单独弃牌。

如果这张桌确实“河牌加注几乎全是价值”，把“默认弃”放进
`SYSTEM_EXPLOIT_ZH`，并绑定一个可验证条件（例如 `fold_to_river_raise >= 80%`
且样本 ≥20），而不是写进 core。

### P0-3 4-bet：规则、事实、选项三处都写错级别

这是本报告里最“硬”的 bug，因为它不是风格问题，而是**动作级别写错**。

**实测渲染（UTG 开 5BB，LJ 3-bet 20BB，HJ 冷 4-bet 55BB，Hero AA）**

```
面对加注：4-bet+，HJ 再加注到 55BB；身后还有 5 人没响应加注
对加注的牌力：AA 在 面对 4-bet 的继续范围（QQ+/AK）（3%）内
              → 价值牌，可以 4-bet 或跟注
...
- raise-3x｜4-bet 到 150BB（3 倍）；后手不足，等同全下
- all-in｜全下 150BB
```

**问题**

1. Hero 面对的是 4-bet，下一次加注是 **5-bet**，不是 4-bet。事实块却写
   “可以 4-bet 或跟注”。
2. 选项 `raise-3x` 的标签写“4-bet 到 150BB”，实际是 5-bet；`all-in` 也是
   5-bet。模型看到“4-bet”会套用“4-bet 只用 KK/AA”的规则，可能因此 call，
   而不是 shove。
3. 代码只按 `preflop_shapes` 里的 `"three-bet"` 决定标签前缀
   （`advice.py:332-337`），没有 `four-bet` 状态；`n_raises` 只用来选范围，
   没用来选标签。于是所有“3-bet 池”都写 4-bet，4-bet 池也写 4-bet。
4. `advice.py:3411-3419` 的 `n_raises >= 2` 分支把 3-bet 和 4-bet 合并：
   面对 4-bet 时仍输出“可以跟注，不 4-bet（4-bet 只用 KK/AA）”——这句话在
   面对 4-bet 的节点上没有意义（能做的只有 5-bet/fold/call）。

**与短码规则的冲突**

system 同时写：

- `advice.py:2305`：“4-bet 只用 KK/AA，AK 只跟。”
- `advice.py:2313`：“后手 ≤20BB 的翻前推/弃区全下是标准动作。”

20BB 面对 3-bet，AK/QQ 的 standard play 是 shove（4-bet all-in），但第一条
说 AK 只能跟、4-bet 只能 KK/AA；第二条说全下是标准。两条规则在同一个节点
直接打架。`_all_in_option()` 又确实会在 `stack <= PREFLOP_ALLIN_MAX_STACK_BB`
或面对 3-bet 时给出 all-in（`advice.py:122-160`），所以模型看得到这个选项，
却被规则告知不要用。

**建议**

1. 标签按 `n_raises` 生成：1 次加注=2-bet/开池，2 次=3-bet，3 次=4-bet，
   4 次=5-bet；`raise-3x/4x` 的 id 可以保留，但标签必须写实际级别。
2. 面对 4-bet 的分支单独写：“面对 4-bet：5-bet 只用 KK/AA/AKs；QQ/AK 默认
   跟注或弃牌（按价格/对手）；不要写‘可以 4-bet’。”
3. 把“4-bet 只用 KK/AA”限定为“面对 3-bet”；加一句“后手 ≤20BB 时按推/弃，
   不受此限”。
4. 如果这张桌的 3-bet 范围确实是 QQ+/AK，把“AK 只跟”写成**条件**：
   “对手 3-bet 范围窄（QQ+/AK）或没有读数时，AK 只跟；对手松凶/3-bet 宽时，
   AK 可以 4-bet。”

### P0-4 听牌：system 说“无弃牌率别下注”，攻击块说“强听可以下注”

**原文**

- system（`advice.py:2308`）：“多人池（含 Hero）：4 人以上顶对/超对降级，
  3 人池 SPR<3 可套池。**无弃牌率别用听牌硬下注。**”
- 攻击块（`advice.py:4019`）：“结论：**仅强牌/强听下注**（没有该街弃牌率，
  不能默认开火）。”
- 陷阱分支（`advice.py:3993-3994`）：“结论：跟着过牌，看免费牌；**只有强牌/
  强听可以下注拿价值**，别用空气/中等牌硬开。”

**实测渲染（6 人溜入池，Hero 坚果同花听，本街全部过牌到 Hero，无该街弃牌率）**

```
## 攻击机会（宽范围/死钱）
翻前 3 人溜入、没人加注；本街全部过牌到 Hero（你收尾）→ 对手范围宽，底池是死钱。
...
没有对手过牌-加注数据，不能把这里当无风险开火点。
结论：仅强牌/强听下注（没有该街弃牌率，不能默认开火）
依据：
牌面有花/顺可能：……降低开火频率；……纯空气别硬开。
```

**冲突**

同一屏、同一个 spot：

- system：没有弃牌率，别用听牌下注。
- 攻击块：没有该街弃牌率，强听可以下注。
- 攻击块更具体、更靠近“可选动作”，模型大概率照它做；system 的“别用听牌硬
  下注”就被事实层覆盖。这不是优先级 bug（system 自己说“程序裁决优先”），
  而是两套规则本身矛盾：“攻击”被贴了“程序裁决”的标签，但它其实是桌况建议
  （见 P0-8）。

**另外两个措辞问题**

- “强听可以下注**拿价值**”：听牌还没成牌，拿的是弃牌率/后续权益，不是价值。
  这会训练模型用“价值”给半诈唬找理由。
- “仅强牌/强听下注”在 `fold_verdict == "neutral"` 时也会出现，而 neutral
  表示弃牌率一般（例如 40%），不是“没有弃牌率”（见 P1-4）。

**建议**

先决定这张桌的剥削方向，再统一两处：

- 如果这张桌是跟注站（用户 497 手报告的结论）：
  “没有弃牌率时，听牌默认过牌/跟注；强听也不主动下注，除非有位置 + 对手
  确实会弃。”
- 如果保留半诈唬：
  “没有弃牌率时，纯听牌不主动下注；强听（≥8 outs，含坚果听/组合听）可以
  半诈唬，但多人池/无位置默认过牌。”

无论选哪个，把攻击块的“强听下注”改成同一方向，并把“拿价值”改成“半诈唬/
保护”。不要在 system 和事实块各留一套。

### P0-5 “关键事实缺失→最保守”没有定义，且与价值/诈唬规则冲突

**原文（`advice.py:2296`）**

> 关键事实缺失时选最保守的合法动作并说明缺什么；保守=能过牌就过牌、
> 面对下注缺牌力/赔率/筹码则弃、不主动下注/加注/诈唬。事实齐全时正常决策。

**问题**

1. “关键”没有定义。底牌/公共牌/底池/需跟/后手/人数缺了，和“某座位范围
   未知”“对手筹码未读出”显然不是一个级别，但都叫“事实缺失”。
2. 数据质量段经常写“无”（见 P1-2），模型会认为“事实齐全”，于是正常决策；
   反过来，看到一行“只建模前 4 名对手”也可能触发保守线，连 AA 的河牌价值
   下注都变成过牌。
3. “能过牌就过牌”在**轮到我、没人下注**时几乎总是合法；如果有一条小缺口，
   模型就有理由用坚果过牌。这是“保守”条款最大的副作用。
4. “事实齐全时正常决策”与“关键事实缺失”之间没有可操作的边界；模型只能
   凭感觉。

**实测渲染（无人入池 BTN，行动线为空）**

```
翻前形态：未知
最后翻前加注者（PFR）：未知（翻前动作线缺失）
...
## 数据质量（硬事实缺失会影响可用动作；范围缺口会降低范围权益可信度）
无
```

一边说“未知”，一边说“无缺口”；模型不知道要不要保守。

**建议**

把“关键”写死，并让措辞与数据质量段对齐：

> 只有「数据质量」标为硬缺口（底牌/公共牌/底池/需跟/后手/在局人数）时走
> 保守线：能过牌就过牌；面对下注且赔率/筹码不明则弃，并在 reason 说明缺
> 什么。只有范围/画像/桌况缺口时，**不改变价值下注/弃牌**，只降低诈唬频率。

同时修数据质量：`_gap_zh()` 目前没有映射 `"no preflop action"`
（`field_ranges.py:218`），所以行动线为空时数据质量会写“无”。补一条：
“翻前动作线缺失，翻前形态/PFR 未知（按未知处理）”。

### P0-6 翻前：system 让你看“有效筹码”，筹码段让你看“可玩深度”

**原文**

- `advice.py:2305`：“翻前：看位置、前面行动（未开池/溜入/单加注/3-bet）、
  **有效筹码**和范围……”
- `advice.py:2323`：“**可玩深度** = min(我的后手, 最深未弃牌对手的后手)；
  **翻前开池/单挑范围用它**，不含本街已下注。”

**实测渲染（AKo UTG 被 LJ 3-bet，BTN 只有 59BB）**

```
有效筹码：59BB｜可玩深度：189BB（对最深对手的后手；翻前开池/单挑范围按此，
不含本街已下注；翻后套池看有效筹码）
```

**冲突**

- 决策顺序说翻前看“有效筹码”（59BB），筹码段说翻前看“可玩深度”（189BB）。
- 模型看到 59BB 会把整桌当短码局，可能用 59BB 的逻辑 shove/fold；但它的
  可玩深度是 189BB，开池/单挑范围应按 189BB。
- 这正是 10-30 d3a9 修过的问题（`docs/复盘-2026-10-31-八手与提示词.md:25`：“多人池一个短码把有效筹码压到
  29BB，模型把整桌当短码局”），修了事实层，却没修 system 的决策顺序。

**位置语义也有同样的残留**

- `advice.py:2309` 说“位置=翻后座位顺序……翻前行动顺序另看「翻前行动」”。
- `advice.py:2305` 的翻前第一条却又说“看位置”。
- 事实块翻前只渲染“翻后位置”和“翻前行动”两行（`advice.py:4146-4158`）。
  BB 在翻前是最后行动，但“翻后位置：Hero 无位置”；模型如果按“看位置”读，
  会把 BB 当成无位置而收紧，实际上 BB 翻前有收尾的选项。

**建议**

> 翻前：看**翻前行动顺序**（几号位、前面谁加注/溜入）、可玩深度和范围；
> 翻后：看翻后位置、有效筹码和 SPR。

并把“有效筹码/可玩深度”的分工写成一句：“翻前看可玩深度；翻后/套池看有效
筹码。”不要在决策顺序里混用。

这是 13 次平跟里最直接的一条链。

**实测渲染（BTN QTo，前面 UTG/HJ/CO 三个溜入）**

### P0-8 “程序裁决”把文字建议块抬到了画像/观察之上

**原文（`advice.py:2298-2302`）**

> 1. 硬事实：牌/公共牌/底池/需跟/在局人数/后手/位置/行动线/有效筹码/底池类型。
> 2. 程序计算：SPR、赔率门槛、牌型/坚果/听牌、范围权益、当前落后比例、听牌价格。
> 3. 逐座位对手画像；4. 当前牌桌统计/全场先验/人工观察；5. 通用经验。
> 冲突时高级覆盖低级、规则提示不能压硬事实；**程序裁决（攻击/炸弹/听牌价格）
> 优先于画像/桌况，人工观察是启发式**。

**问题**

1. “高级覆盖低级”没有定义“高级”是序号 1 还是序号 5。中文里“高级”更常指
   更高层/更重要，但读者也可能按编号理解。模型没有确定答案。
2. “规则提示”没有定义。system 自己的“4-bet 只用 KK/AA”“非坚果不打三条街”
   算不算“规则提示”？如果算，它们不能压硬事实；如果不算，它们是什么？
3. “程序裁决”把三个完全不同的东西并列：
   - 攻击块：从桌况统计（第 4 层）推出来的**文字建议**；
   - 炸弹池：从底池结构推出来的**文字建议**；
   - 听牌价格：真正的程序计算。
   结果是一个由第 4 层数据推出来的建议，被抬到第 2 层，压过第 3 层的逐座位
   实测画像。这是优先级反转。
4. “人工观察是启发式”与事实块标题“人工观察（现场记录；统计算不出来的
   东西）”矛盾。一个针对本桌的现场读数，和一个跨桌人群先验，权重显然不同，
   但两者都被放在第 4 层。

**具体例子**

- 座位画像：BB 对 c-bet 弃 65%（实测，n=12）→ 座位 hint 写“干燥面可以开火”
  （第 3 层，实测）。
- 攻击块：全场面对翻牌下注弃 25% → “不开火”（由第 4 层桌况推出）。
- system 说“攻击优先于画像”，模型于是忽略 BB 的 65% 实测，按全场 25% 不打。
  谁更具体？显然是 BB 的画像。

**建议**

把优先级写成可执行的：

```
## 事实优先级（序号小者优先）
1. 硬事实：牌/公共牌/底池/需跟/在局人数/后手/位置/有效筹码/底池类型。
2. 确定性计算：SPR、赔率门槛、牌型/坚果/outs、听牌价格。
3. 模型估计：范围权益、当前落后比例、逐座位画像、桌况统计——都带假设，
   不能当已发生事实。
4. 现场观察：.table_dy 的当前桌记录；与 3 冲突时以观察为准，但不得压 1/2。
5. 通用经验。
同一层内“更具体”优先：逐座位 > 本桌 > 全场先验。文字建议块（攻击/炸弹/
桌况读法）不是硬事实，不能压画像/观察；它们只提供结论，最终按本表仲裁。
```

如果不想大改，至少删掉“程序裁决（攻击/炸弹/听牌价格）”这一句，改成：
“攻击/炸弹/桌况读法只是建议，与逐座位画像冲突时，以更具体的画像为准；
只有赔率门槛/SPR/牌型这些计算才是硬裁决。”

## 四、P1：会系统性带偏的规则

### P1-1 “对范围权益”同时说“假设后面不再下注”和“按后续下注折价”

**原文（`advice.py:2317`）**

> 对范围权益 = 对建模范围（未建模对手按随机牌计入）的河牌胜率，**假设后面
> 不再下注**；**非全下时按后续下注折价再比门槛**。

**问题**

- 前半说“不再下注”，后半说“按后续下注折价”；两句话描述的是两个不同的
  权益口径，但没有折价系数，模型无法执行。
- 事实块只写“按河牌、未计后续下注”（`advice.py:3134`），没有“折价”提示；
  模型会直接拿 88%/91% 和单街门槛比。
- 更关键的是**范围口径**：`hand_ranges` 的范围取决于事件模型有没有把“加注”
  当成收窄事件；在 K9s 这类河牌加注点，它仍是跟注范围/未按加注收窄的范围，
  不是“对手加注范围”。河牌面对加注时，91% 对跟注范围没有意义，对加注范围
  可能只有 30%。497 手报告的 K9s 就是这样：AI 把“对跟注范围 91%”当成
  “对全下范围 91%”，于是跟注。
- 497 手报告 `:360` 决定“不修权益引擎”，可以理解（K9s 是 cooler），但提示词
  仍把这个数字放在“程序计算”层，且没有字段说明“这是对哪个动作范围的权益”。

**建议**

1. 把事实行改名为“对当前范围权益（未计后续下注；不是对加注范围）”。
2. 面对下注/加注时，如果范围模型没有按加注动作收窄，显式写：
   “这是对跟注范围的权益；对手加注后范围更窄，不能直接用它跟注。”
3. 给一个可执行的折价规则，或者干脆删掉“折价”一句：
   “只在全下/套池时用权益门槛；否则用赔率 + 隐含赔率 + 对手线路。”
   不要留一个模型无法计算的“折价”。

### P1-2 数据质量写“无”，但事实块有“未知”

**问题**

`_gap_zh()`（`advice.py:2638-2664`）只映射了部分英文告警；`field_ranges.py:218`
的 `"no preflop action"` 没有被映射，也没有被 append 到 warnings。于是：

```
翻前形态：未知
PFR：未知（翻前动作线缺失）
## 数据质量
无
```

模型会认为“没有缺口”，system 的保守条款不触发；同时它又看到“未知”，
可能自行保守。两个信号相反。类似地，`_summarize_gaps()` 只保留 4 条，
超过 4 条的技术缺口会被截掉；如果模型只读“数据质量”，会低估缺口。

**建议**

- 补 `no preflop action` 映射：“翻前动作线缺失，翻前形态/PFR 未知”。
- 数据质量没有缺口时写“无已知硬缺口”，不要写“无”。
- 如果 `## 当前局面`/`## 翻前信息` 出现“未知”，数据质量至少要有对应一行；
  两者不能一个说未知、一个说无。

### P1-3 桌况 stab 读法不看位置：0 人待行动也能“过牌诱导 check-raise”

**实测渲染（Hero BTN 最后行动，前面两家已过牌，桌况 stab=50%）**

```
位置：Hero 有位置（按座位顺序最后行动）｜跟注/过牌后待行动：0 人｜……
...
桌况读法：前面没人下注时这桌爱开火（50%）。你过牌不是免费看牌——
          强牌可以过牌诱导 check-raise，中等牌别主动下注把他们的空气打走……
...
桌况提示：这桌前面没人下注时爱开火（50%）；你过牌不是免费看牌，
          强牌可过牌诱导，中等牌过牌控池。
```

**问题**

- Hero 是最后行动，过牌就结束本街；没有任何人能下注，哪来的“过牌诱导
  check-raise”？“过牌不是免费看牌”在这个 spot 是假的。
- `_table_stab_read_zh()` 只看桌况，不看 `players_left_to_act`/`in_position`；
  `_table_stab_hint_short()` 又在文末重复了一遍（`advice.py:4066-4079`），
  两段措辞还不完全一样（“别主动下注” vs “过牌控池”）。
- 这是一个“事实说 0 人、建议说有人会开火”的同屏矛盾。

**建议**

- `_table_stab_read_zh(stats, players_left_to_act=..., in_position=...)`：
  - 0 人待行动：只说“你最后行动，过牌免费；下注后被 check-raise 的风险来自
    已经过牌的人”，不要说“过牌不是免费”。
  - 有人待行动：保留原文。
- 有完整 `桌况读法` 时不要再输出 `桌况提示`；二者只留一个。
- 把 `桌况提示` 从“决策提示”段移到桌况段，避免模型先读建议后读事实。

### P1-4 中性弃牌率被写成“没有该街弃牌率”

**实测渲染（桌况：对手面对翻牌下注弃 40%，机会 100 次）**

```
结论：仅强牌/强听下注（没有该街弃牌率，不能默认开火）
依据：
本桌：对手面对翻牌下注弃 40% → 弃牌率一般，不能单独作为开火理由
```

**问题**

`_attack_fold_verdict()` 返回 `"neutral"`（弃牌率在 35%–50% 之间）和
`"unknown"`（没有数据）时，`render_attack_zh()` 共用了一句“没有该街弃牌率”。
40% 不是“没有”；这是事实错误。模型会低估对手的弃牌率，或反过来不信任
依据行。

**建议**

- `neutral` 写：“弃牌率一般（40%），不能单独作为开火理由。”
- `unknown` 才写：“没有该街弃牌率数据。”
- 把 `_attack_fold_verdict` 的返回值直接映射到文案，不要用 else 兜底。

### P1-5 座位/桌级的“可以开火”没有被攻击块裁决

**问题**

- `opponent_profile.py:2651` 的座位 hint 仍会输出“对 c-bet 弃得多 —— 干燥面
  可以开火”；`table_exploit_zh()` 也会输出“对 c-bet 弃得多 —— 翻牌小注有
  弃牌率”。
- `render_attack_zh()` 只在**溜入池**触发；非溜入池的 c-bet 点没有攻击块。
  这时座位 hint 的“可以开火”就是唯一结论，没问题。
- 但在溜入池里，攻击块可能说“不开火”（桌况弃牌率低），座位 hint 仍说
  “可以开火”（某个对手弃 c-bet 65%）。`suppress_cbet` 只压桌级 c-bet hint
  （`advice.py:4261`），不压座位 hint。于是同一屏两套结论：一个来自实测
  画像，一个来自攻击块；system 说“攻击优先于画像”，但攻击块又没看这个
  座位的 c-bet 数据。

**建议**

- 有攻击块时，座位 hint 只输出事实（“对 c-bet 弃 65%”），不要输出“可以
  开火”；把“开火/不开火”统一交给攻击块。
- 或者让攻击块读 `opponent_reads`，把“本街有对手高弃 c-bet”作为支持条件；
  但这是更大的改动。
- 至少不要让两段文字都带“开火”这个动词。

### P1-6 “本手已投入”没有沉没成本提醒

**原文（`advice.py:4203`）**

> 本手已投入：3BB

**问题**

设计文档原先在“常见错误”里写：“不要因为‘已经投入’而跟注；不要因为‘怕被
反超’而弃掉明显领先的牌”（`docs/中文-lean-提示词-重构方案.md:119`）。当前
system 没有这一句。事实块却把“本手已投入”放在“当前局面”里，模型很容易写
“已经投了 3BB，便宜跟”。

497 手报告里的 AK 4-bet 到 100 最明显：已经投了 100BB 后不愿弃；K3s 河牌
连续跟注也可能是“已经投了”的延续。这里不是断言因果，而是说提示词没有
任何一句阻止这种推理。

**建议**

在决策顺序或输出契约加一句：

> 已投入是沉没成本：不要因为“已经投了 XBB”而跟注；只看当前赔率、权益和
> 对手范围。

如果预算紧，至少在本手已投入那一行加“（沉没成本，不构成跟注理由）”。

### P1-7 决策顺序只问“更差的牌会不会跟”，没有诈唬分支

**原文（`advice.py:2305`）**

> 翻后：先问哪些更差的牌会跟、哪些更好的牌会加，再比权益与赔率门槛，
> 决定价值/诈唬/过牌/弃牌。

**问题**

- 第一问只覆盖价值下注；如果更差的牌不跟、更好的牌会加，模型下一步就是
  过牌/弃牌，不会问“更好的牌会不会弃”（诈唬）。
- 但事实层的攻击块又说“别只拿成牌下注”“可高频小注攻击”，table exploit
  也说“没摊牌价值时可以诈唬收池”。system 的决策树里只有“价值”的前置问题，
  没有问“更好的牌会不会弃”，模型只能从事实层学，导致“system 说价值、
  事实层说诈唬”的撕裂。
- “强听可以下注拿价值”（P0-4）也是这个缺口的产物：没有“半诈唬”这个类别，
  模型只能把听牌下注叫“价值”。

**建议**

> 翻后下注/加注前问两个问题：更差的牌会不会跟（价值）？更好的牌会不会弃
> （诈唬）？两者都没有就过牌；两者都有就选尺度。跟注看权益与门槛。

### P1-8 `raise-3x/4x` 的倍数在 3-bet 池里过大；`open-*` 的 id 也不是金额

**问题**

- system 说“3x/4x=上家加注的 3/4 倍”（`advice.py:2290`）。在 3-bet 池里，
  对 20BB 的 3-bet 做 4x = 80BB；标准 4-bet 通常 2.2–2.5x（约 45–50BB）。
  这不是绝对不能打，但作为通用提示，会把模型推向过大的 4-bet/全下。
- `open-3.5` 的 id 是**基础倍数**，标签却是“开池到 6.06BB”；`open-3.75`
  → 6.5BB，`open-4` → 6.93BB（实测渲染）。模型如果按 id 理解金额，会以为
  “open-3.5”是 3.5BB。system 说“id 映射以可选动作为准”，但没有解释这个
  差异。
- 这不是纯 UI 问题：模型要在 reason 里引用尺度，id 和金额不一致会让理由
  和动作对不上。

**建议**

- 选项 id 改成 `open-small/medium/large` 或直接 `open-6.06`，不要让 id
  看起来像金额。
- 4-bet 尺度用 `2.2x/2.5x` 或直接给金额；如果这张桌的规则就是 3x/4x，
  在标签里写“本桌规则：4-bet 3x”。
- 在事实块加一句：“id 只是槽位，金额看标签；不要用 id 里的数字当尺度。”

### P1-9 “≤20BB 推/弃”“SPR>6 一对不做大底池”“强牌=超对/顶对”都是无条件句

这三条单独看都像“经验”，放在一起会互相拆台：

- `advice.py:2313`：“后手 ≤20BB 的翻前推/弃区全下是标准动作。”
  20BB 在现金局不是自动推/弃；16–25BB 通常还是正常加注/3-bet。它和
  “20–40BB 仍是正常加注”（`:2325`）正好在 20BB 处打架。
- `advice.py:2324`：“SPR 高（>6）一对不做大底池。”
  对跟注站、干燥面，AA 可以打三条街；规则没有“除非”。
- `advice.py:2307`：“强牌=两对+/超对/顶对（踢脚 T+）。”
  超对在 A/K 高面不是强牌；顶对在 4 人池按中等牌——下一句自己说了
  “4+ 人顶对按中等牌”。同一段里，模型要自己做第二次映射。

**建议**

- 20BB 改成“≤15BB 按推/弃；16–25BB 正常开池/3-bet，面对 3-bet 可全下”。
- SPR>6 加“默认控池；干燥面/对手跟注站可以两街价值”。
- 强牌改成“相对的”：两对+/set 在干燥面；超对/顶对在无 A/K、少人池；
  4+ 人池降级。不要让“强牌”标签独立于牌面/人数。

### P1-10 “人工观察是启发式”把现场读数放低了

**原文（`advice.py:2302`）**

> ……程序裁决（攻击/炸弹/听牌价格）优先于画像/桌况，**人工观察是启发式**。

**问题**

- 事实块标题写“人工观察（现场记录；统计算不出来的东西）”，暗示它有价值；
  system 又说它是“启发式”，和第 4 层的全场先验同级。
- 一个针对本桌的现场读数（“这桌河牌加注几乎全是价值”）和一个跨桌人群
  先验（VPIP 30%），权重显然不同。模型可能用后者压前者。
- 座位画像标题又写“优先于全场统计/人工观察”（`opponent_profile.py:2472`），
  把人工观察放在画像之下；如果画像是 n=5 的 tentative，这条“优先”就更可疑。

**建议**

- 把“现场观察”单独列一层（在模型估计之上、硬事实之下），并说明：
  “观察只覆盖它明确描述的范围；与逐座位实测画像冲突时，写出两者，不默认
  谁优先。”
- 或者至少把“人工观察是启发式”改成“人工观察是针对本桌的启发式，优先于
  全场先验；与硬事实/计算冲突时以硬事实/计算为准”。

### P1-11 `reason ≤40 字` 与“引用事实/说明缺什么”互相打架

**原文（`advice.py:2285`）**

> {"option": "<id>", "reason": "<中文一句话，≤40 字>"}

**问题**

- system 同时要求 reason 引用“牌力/赔率/位置/画像/SPR/底池类型/牌面”，
  还要在缺失时“说明缺什么”。40 字里放不下，模型只能选一两个，或者写空话。
- `_clip_reason()` 会在 40 字处截断（`advice.py:4851`），用户看到的理由可能
  是半句；复盘时无法判断模型到底看了什么。
- 设计文档原本写 30 字（`docs/中文-lean-提示词-重构方案.md:98`），现在 40，
  仍然不够。

**建议**

- 改成 60–80 字，或拆成 `reason`（≤40，动作理由）+ `detail`（≤80，引用
  事实/缺口）。如果只保留一个字段，至少允许 60 字。
- 如果预算/解析不允许，删掉“引用牌力/赔率/位置/画像/SPR/底池类型/牌面”
  这个长列表，改成“引用一个最关键的事实”。

## 六、根因：为什么这些冲突会反复出现

### 6.1 规则是“补丁”，不是“决策表”

现在的 system 是一条条经验句，不是一张“节点 → 条件 → 动作”的表。经验句
之间没有互斥/优先级；每修一手就加一句，最终同一节点有多句。要根治，必须把
“翻前/翻后/河牌/炸弹池/多人池”做成节点表，每个节点只留一个结论，条件写在
同一行。

### 6.2 本桌剥削没有和通用规则分开

497 手报告里新增的三条硬规则（以及更早的“无弃牌率听牌”规则）都是本桌读数：

- 炸弹池 41 手里 8 手交过手，1 手大坑；
- 这张桌河牌加注 95% 是价值；
- 这张桌 3-bet 范围 QQ+/AK；
- 这张桌跟注站不弃牌。

这些应该进一个**按条件追加**的 `SYSTEM_EXPLOIT_ZH`，就像现在的
`SYSTEM_ANTE_ZH` 一样：

```
## 本桌剥削（仅在统计/现场观察满足条件时追加）
- 炸弹池：本桌回测 41 手，顶对+ 打第二街后继续跟注是主要漏洞 →
  面对转/河大注默认弃；样本不足时不启用。
- 河牌：本桌河牌加注 95% 是价值（n≥20）→ 非坚果面对大加注默认弃。
- 翻前：本桌 3-bet 范围 QQ+/AK → AK 只跟不 4-bet。
- 听牌：本桌跟注站不弃 → 无弃牌率时听牌只过牌/跟注。
```

core 里只留通用规则。这样既保留 edge，又不会在别的桌反向吃亏。

### 6.3 1900 字符预算

`tests/test_advice.py:3246` 的 1900 字断言，把“简洁”变成了“不能写条件”。
建议：

- 把预算放到 2300–2400 字；多出的 300–400 字用来写条件和例外。
- 或者把“本桌剥削”拆出去，core 仍 ≤1900，但 exploitation 块另算。
- 测试改成断言“没有重复结论/没有无条件绝对句”，而不是字符数。

### 6.4 事实层承担建议，且没有“单一裁决”

`## 攻击机会`、`## 剥削判断`、`## 炸弹池打法`、`桌况读法`、`## 决策提示`
都是建议。它们应该：

- 要么移到 `## 程序建议（不是事实）`，明确写“这是建议，不是事实”；
- 要么只保留事实，由 system 的统一决策表给结论；
- 同一主题（开火、炸弹池、stab）只能有一个结论，不能座位/桌级/攻击块
  各说一套。

### 6.5 文档/测试与代码漂移

README、live-stream、设计文档、system、事实块各自记一份口径。建议指定
`advice.py` 的 system 为唯一事实源，文档只引用版本号；每次改 prompt 用
`PROMPT_VERSION` + golden hash + 一个“口径变更”小节同步。

## 七、建议

### 7.1 先做 5 个 P0（最小改动，可回归）

按“改动小、收益大、容易测”排序：

1. **炸弹池只留一套口径**（P0-1）：删“按正常规则”或删“一条街”，推荐
   “正常规则 + 两条街上限；SPR<2/4+ 人只一条街；被加注按赔率，不默认弃”。
2. **河牌去掉“被加注默认弃”**（P0-2）：改成“按加注范围重算；赔率不足/
   价值型/范围警告才弃”。
3. **4-bet/5-bet 标签与分支**（P0-3）：按 `n_raises` 生成标签；面对 4-bet
   单独写；短码推/弃例外（阈值见 P1-9）。
4. **听牌口径统一**（P0-4）：system 与攻击块选同一个方向；把“拿价值”改成
   “半诈唬/保护”。
5. **范围结论 + 平跟选项**（P0-7）：单一裁决；给 `call` 加劝阻 note；
   `no preflop action` 进数据质量。

这五项都不需要重写整个 prompt，但需要同步改测试/golden。

### 7.2 再改 4 个 P1（结构性）

6. **优先级重写**（P0-8/P1-10）：明确 1>2>3>4>5；区分“确定性计算”和
   “模型估计”；“文字建议块”不能压画像/观察；现场观察单独一层。
7. **权益口径**（P1-1）：改名“对当前范围权益（未计后续下注）”；面对加注
   时说明“不是对加注范围”；删掉无法执行的“折价”，或给具体系数。
8. **数据质量**（P1-2/P1-3/P1-4）：补 `no preflop action`；没有缺口写
   “无已知硬缺口”；stab 读法看位置；neutral 不要写“没有弃牌率”。
9. **沉没成本 + 诈唬分支**（P1-6/P1-7）：加回“已投入是沉没成本”；决策顺序
   加“更好的牌会不会弃”。

### 7.3 具体替换句（可直接粘）

| 旧句 | 新句 |
|---|---|
| `4-bet 只用 KK/AA，AK 只跟。` | `面对 3-bet：默认 4-bet 范围 KK/AA + 少量 AKs/QQ；对手 3-bet 范围窄（QQ+/AK）或没读数时，AK 只跟。面对 4-bet 的再加注是 5-bet，只用 KK/AA/AKs；短码推/弃时不受此限。` |
| `无弃牌率别用听牌硬下注。` | `没有弃牌率时，纯听牌不主动下注；强听（≥8 outs，含坚果听/组合听）可以半诈唬，但多人池/无位置默认过牌。` |
| `非坚果不打三条街，被加注默认弃。` | `非坚果默认不打三条街；被加注时先按加注范围重算权益与赔率，只有赔率不足/对手价值型/范围警告显示只赢诈唬时才弃，不要用“我是非坚果”单独弃牌。` |
| `顶对及以上总共只投一条街的钱……被下注即弃……` | `按正常翻后规则打，但默认只打两条街；SPR<2 或 4 人以上时顶对/超对只打一条街；面对下注/加注按赔率与范围决定，不默认弃。` |
| `关键事实缺失时选最保守……` | `只有数据质量标为硬缺口（底牌/公共牌/底池/需跟/后手/在局人数）时才走保守线；范围/画像/桌况缺口不改变价值下注/弃牌，只降低诈唬频率。` |
| `翻前：看位置……有效筹码和范围` | `翻前：看翻前行动顺序、前面行动、可玩深度和范围；翻后看翻后位置、有效筹码和 SPR。` |
| `QTo 在 BTN 的开池范围内（参考……）；……已不在收紧后的范围内` | `QTo：BTN 开池范围内；但有 3 个溜入者，隔离范围（约 LJ 强度）已不包括它 → 默认弃牌；要玩就加注隔离，不要平跟。` |

### 7.4 结构改造（建议下一版做）

1. **事实/建议分节**：
   - `## 事实`：当前局面、行动线、翻前信息、实时牌力、范围、画像、桌况、
     人工观察、数据质量。
   - `## 程序建议（不是事实）`：攻击、炸弹池、stab，每主题一行结论；明确“建议，不是事实”。
   - `## 可选动作`。
2. **单一裁决**：同一主题只留一个结论；座位/桌级/攻击块不能各说一套。
3. **数据质量前置**：把 `## 数据质量` 放在事实与结论之间，模型先知道缺口，
   再读结论。
4. **去重**：`桌况读法` 与 `桌况提示` 二选一；`可争夺底池` 只写一次；
   异常帧的三行合并。
5. **预算**：system 2300–2400 字，或者 core ≤1900 + `SYSTEM_EXPLOIT_ZH`。

## 九、一句话总结

**当前提示词不是“写得不够多”，而是“写得太多、互相打架、没人裁决”。**
先把 2026-11-01 的三条硬规则（以及更早的“无弃牌率听牌”规则）改成“有条件 +
本桌可开关”，再把事实层的建议收敛成“每主题一个结论”，最后把优先级写成
1>2>3>4>5、区分“计算”和“估计”。
在这之前，继续加第五条硬规则只会让模型更会找理由，而不是更会打牌。
