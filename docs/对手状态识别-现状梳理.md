# 对手状态识别：现状梳理（ROI 实时链路）

> 2026-11-02。本文只描述**当前代码的实际判定口径**，不提出改法。所有结论文

## 0. 一页速览

| 状态 | 主要证据 | 次要/兜底证据 | 判定位置 |
|---|---|---|---|
| 本街下注额 `bet` | `bet_slot` 的下注 pill（数字+BB） | 空文本/中文 → 按 0；百分数 → 当胜率，不是下注 | `frame_state.py:339-358` |
| 下注/加注/跟注/过牌 | 名字槽上的**动作徽章**文字（盖住名字） | 徽章漏读时用下注额 vs 本街水位反推 | `frame_state.py:288`、`hand_track.py:940-951` |
| 弃牌 `fold` | 头像底角红色「POKER」手牌图标**消失** + 头像「弃牌」文字，**两条件缺一不可** | 街末「街初在局 − 街末在局」差集补；离桌补 | `frame_state.py:294-313`、`hand_track.py:1233-1286` |
| 全下 `all_in` | 头像黄色 `All in` 徽章 | 筹码=0 且有下注/曾经全下；胜率百分比出现 | `frame_state.py:452-456` |
| show 牌 | `action_slot` 里识别出 1–2 张明牌（不是 OCR 文字） | 头像区变白（牌顶掉头像）只用于排除图标 | `cards.py:711-761`、`state_stream.py:635-648` |
| 在座但没入局 | 头像文案：**正在带入 / 等待审核 / 等待中**（det+rec 读原文） | 筹码 0 + 无下注 + 无动作 + 无手牌图标 | `frame_state.py:418-458`、`parse.py:230-289` |
| 空位/暂离 `away` | 无图标 + 名字/筹码/下注/动作全空 | — | `frame_state.py:428-438` |
| 本手中途离桌 | 整座「还有人」的证据连续 `max_vanish`(3) 帧消失 | 手牌图标重新出现可撤销离桌 | `state_stream.py:574-633` |
| 本手中途入座 | 不在换手第一帧锁定的 `hand_roster` 里 | — | `frame_state.py:507-521` |
| 庄位/位置 | 白底「D」圆片（blob，非 OCR） | 死按钮：庄家离桌按固定座位环排 | `dealer.py`、`positions.py:1-13` |

**两条贯穿全局的约定**（不理解它们会误读上表）：

1. `in_hand` 是**「这一手有没有他的份」**，不是「还在池里」。弃牌后
   `in_hand` 仍为 `True`、`status="folded"`；「还在池里」看
   `_active_seats()`（`hand_track.py:1187-1197`）。
2. `fold` / `is_fold_badge` / `is_all_in_badge` 都是**三态**：
   `True / False / None`。`None` = 这一帧判断不了，**不等于没弃牌**。

## 1. 一帧读什么：每座 3 块 + 头像 + 可选胜率槽

`SEAT_FIELDS = ("name", "chip", "bet")`（`roi_reader.py:61`）——每座只跑这三块
固定 ROI 的 rec，不跑全图 det。

| 块 | 位置 | 拿来判什么 |
|---|---|---|
| `name_slot` | 名字行 | 名字；**动作徽章画在这里**，会盖掉名字 |
| `chip_slot` | 筹码胶囊 | 后手筹码；全下时可能变成胜率 `30%` |
| `bet_slot` | 座位前的下注 pill | 本街已投入 |
| `avatar_slot` | 头像 | 弃牌遮罩文字、`All in` 徽章、「带入」；**图标检测在这里做** |
| `action_slot` | 名字+头像那一片 | **亮牌**（摊牌时两张牌画在这里） |
| `equity`（临时） | 筹码胶囊下方 | 只在检测到 All-in 徽章时才读，全下胜率 |

头像区是 `read_avatars()` 单独读的（`roi_reader.py:589-633`），不走
`read_frame`。疑似弃牌的座位会**额外用 det+rec 复核一次**（rec-only 会把
「弃牌」读成「奔牌/井脚/不」甚至空）。

每块 ROI 都有跨帧去重：分块 dhash 完全一致、或灰度 MAD ≤ 0.2 就复用上一帧读
数，不跑 rec（`roi_dedup.py`）。**复用出来的读数和真读到的在语义上没有区别**，
所以「这一帧没变」不等于「这一帧没看」。

## 2. 状态模型

`PlayerState`（`frame_state.py:40-93`）：

```text
seat_id / name / position / stack / bet / action / fold / in_hand / all_in /
equity / status / left / notes / name_raw / name_score / name_tracked
```

`status` 只有 5 个值（`frame_state.py:461-465`，按优先级从高到低）：

| status | 含义 | 是否会进 `players_in_hand` |
|---|---|---|
| `buying_in` | 头像写「带入」且筹码 0：人坐下了但没被发牌 | 否 |
| `away` | 这位置没人（虚线「+」占位，或筹码 0 且连名字都没有） | 否 |
| `sitting_out` | 有人、有筹码 0，但这一手没他份（含本手才入座的人） | 否 |
| `folded` | 这一手有他，已弃牌（含中途离桌） | 是 |
| `playing` | 这一手在局 | 是 |

`FrameState` 还带全局量：底池、上一街底池、盲注、庄位、`bomb_pot`、
`players_in_hand`、`errors`（质量闸）。

## 3. 逐状态判据

### 3.1 本街下注额 `bet`

来源只有 `bet_slot` 的文字。规则集中在 `frame_state.py:346-359`：

* 文本为空 → `bet = 0.0`（这款 app 不渲染 pill 就是没下注）；
* 文本里**有汉字** → 也是 0，并留一条 note（促销按钮/动作徽章落进这块 ROI）；
* 是百分数 → 当胜率 `equity`，`bet = None`（不是金额）；
* 其它读不成数字的乱码 → `bet = None` → 质量闸报 `bet:<seat>`，整帧丢弃。

> 所以「bet=0」有三种来源：真没下注、pill 没渲染、读到了非金额文本。只有
> `bet=None` 才代表「读坏了」。

### 3.2 下注 / 加注 / 跟注 / 过牌：动作徽章

app 在名字位置直接渲染中文徽章，词表是收齐的 5 个
（`parse.py:170-176`）：`让牌→check`、`跟注→call`、`下注→bet`、
`加注→raise`、`弃牌→fold`。

`parse_action(name_raw)` 是**精确等值匹配**，不是模糊匹配（`parse.py:187-190`）。
徽章会停留好几秒、并且盖住名字，所以：

* `build_state` 先认徽章、再决定这块文本算不算名字（`frame_state.py:287-288`）；
  动作期间 `name_raw` 会被写成 `None`，避免把「加注」当名字。
* 动作的有效性用 `action_signature()` 判（含 `action`/`fold`/`hero_turn`），
  但**记录**用的 `signature()` 刻意不含 `action`/`fold`（徽章淡出会造假记录，
  `frame_state.py:606-637`）。

**徽章漏读时的兜底**（`hand_track.py:940-951`）：拿本帧 `bet` 和这条街的
当前水位 `level` 比——

* `bet` 没超过该座已知基线 → 不记动作；
* `bet > level` → 非翻前且原本无人下注记 `bet`，否则记 `raise`；
* `bet ≤ level` 且涨了 → `call`。

同一座重复帧的去重（`hand_track.py:953-968`）：动作类型相同且下注额没涨 → 丢；
涨了但中间没有别人抬高水位 → 只更新金额，不新增记录。

### 3.3 弃牌 `fold`

**两个条件同时成立才判弃牌**（`frame_state.py:294-308`）：

1. 头像底角红色「POKER」手牌图标**消失**（`card_icon.py`，红色填充率 ≥0.55、
   尺寸/底角位置/白边/白字四道校验，槽高 <56px 直接返回 `None`）；
2. 头像中间读到「弃牌」文字（`is_fold_badge`，容忍「奔牌/奔脚/奔摊/奔雄」，
   `parse.py:184-204`）。

只有图标消失、没读到文字 → `fold = None`（未知），**不判弃**：换手残留、
遮挡、压缩都会让图标消失，4d6d 的大盲就是这样被丢掉的（代码注释原话）。

其它覆盖规则：

* 图标在 → `fold = False`（最终，压过文字）；
* hero 头像从不挂图标，只能靠「弃牌」二字（`frame_state.py:306-308`）；
* 亮牌座位 → 头像被牌顶掉、没有图标，`fold` 沿用**上一份被接受状态**的结论
  （`frame_state.py:309-313`）——亮牌 ≠ 没弃牌；
* `all_in` → 强制 `fold = False`；
* 无人 → `fold = None`。

图标「消失」需要**连续 2 帧**才确认（`state_stream.py:660-671`，
`CARD_ICON_ABSENT_FRAMES = 2`）；「出现」是当帧立即生效。

### 3.4 全下 `all_in` 与胜率

`all_in = in_hand and (徽章 or equity is not None or (stack==0 and (bet>0 or 上帧全下)))`
（`frame_state.py:452-456`）。

* 徽章：头像 `All in`（黄色字），容忍 `Alin/aiin/a1in` 等拼法，
  短文本才做模糊匹配（`parse.py:207-227`）；
* 胜率：三个来源，优先级 `bet 槽 %` > `chip 槽 %` > 专门读的 equity 槽
  （`frame_state.py:319-330`）。equity 槽只在全场有人挂 All-in 徽章时才读 9 块，
  避免普通帧多付 OCR（`state_stream.py:322-341`）；
* 全下后 `stack`/`bet` 允许读不到，质量闸对 `all_in` 放行
  （`frame_state.py:578-583`）。

全下的另两个用途：**换手信号**（徽章连续 2 帧可读地消失 → 判这手结束，
`state_stream.py:286-320`；但还在发 flop/turn 时、或仍轮到 hero 时会否掉这个
信号）和 `prev_all_in` 集合（结算后筹码 0 与离桌的区分依据）。

### 3.5 show 牌

**不是 OCR 文字，是牌面识别**：摊牌/主动秀牌时 WPK 把牌画在该座的
`action_slot`，`recognize_shown_cards()` 逐座裁这块、按「紧贴的牌」模式识别
（`cards.py:711-761`）：

* 2 张 = 正常摊牌；1 张 = 河牌主动只秀一张（另一张是牌背，逐张过滤掉）；
* 牌背 / 遮挡 / 点数 `?` / 低置信度一律丢弃；
* 两张 code 相同 = 误读，整座丢掉；
* hero 跳过（hero 的牌由 `hero_cards` 单独读）。

结果通过 `extra_signature` 第 3 位传进 `StateStream`，`_shown_seats()` 解析成
`{seat_id}`（`state_stream.py:635-648`），只用于两件事：

1. `build_state` 里亮牌座位的 `fold` 沿用上一份状态的判定；
2. `card_icon` 之外解释「为什么这帧没有手牌图标」。

亮牌帧常常因为筹码/底池被牌顶掉而 `state.ok=False`，所以亮牌走**独立入口**
`LiveHandTracker.record_shows()`，不等 `observe()`（`hand_track.py:500-534`）。

### 3.6 人在座位但没入局

两条独立的证据线，任一成立就判「这一手没他份」：

**① 头像文案（2026-11-02 新增，主判据）**

WPK 在头像上直接写三种文案：**正在带入 / 等待审核 / 等待中**。只要读到其中
任意一种，就是人坐在桌边、这一手没被发牌 —— **不看筹码**（实测这位玩家筹码
200BB 照常显示）。

来源是 `waiting_badge()`（`parse.py:252-289`），只有两种返回：`"buying_in"`
（正在带入）和 `"waiting"`（等待审核 / 等待中）。读数有两条差异极大的路径：

| 路径 | 触发条件 | 实测读数 |
|---|---|---|
| det+rec | 该座**没有手牌图标**（`det_seats`） | `等待中` / `等待审核179` / `正在带入11`，分数 1.00 |
| 纯 rec | 每帧都跑 | `#中`(0.68) / `#德中`(0.52) / `练待中`(0.54) |

所以判据按**命中的不同汉字数**算，不要求整词：`等待中` 命中 2 个即算，
`等待审核` / `正在带入` 命中 3 个即算；只数汉字（det 会把旁边的计时数字一起
框进来），汉字数 ≤6 且分数 ≥0.45。

两道防误判：

* **连续 2 帧确认**（`state_stream.py:680`，未确认时当没读到）；
* **在局证据优先**（`frame_state.py`）：已经弃牌 / 全下 / 亮牌 / 还挂着手牌图标
  —— 任意一条成立，这一手显然有牌，头像文案作废。

名单锁还会为它**推迟**（`_wait_pending`）：真没发到牌的人一旦被写进
`hand_roster`，这一手就再也摘不出来（名单里的座位不受文案影响），所以等确认
完再锁。推迟最多 3 帧（`ROSTER_DEFER_MAX`）——文案抖动时宁可锁错一个人，也不能
让整手都没有 roster（位置会随在场人数重排）。

**② 结构化证据（旧口径，仍然保留）**

| 判定 | 条件（`frame_state.py:421-455`） | status |
|---|---|---|
| 正在带入 | 头像读到「带入」**且** `stack == 0`（兜底：文案没读全时） | `buying_in` |
| 坐出/没入局 | `zero_idle`：`stack==0` 且 无下注、无动作、非 hero、没全下、没亮牌、没图标；或 `empty_zero` 且还有名字 | `sitting_out` |
| 空位 | `empty_slot`：没图标 + 名字/筹码/下注/动作**全空**；或 `empty_zero` 且连名字都没有 | `away` |

`zero_idle` 的注释写得很清楚：光靠头像文字不够（rec 时好时坏，人数会在 8/9
之间跳），所以要求「筹码 0、本街没下注、也没有动作」——全下的人 `bet>0`，
跟注/下注过的人 pill 至少在结算前还在。

判完这一手不参与：`in_hand=False`、不算人数、不排位置、不参与行动线；
**名字和筹码照常保留**（他还是桌上的玩家，只是没被发牌），notes 里留一条
`头像 '等待中' → 在座未入局，本手不参与`。

样本：`images/status/waiting_frame.jpg`、`waiting_avatar_x4.jpg`。

### 3.7 本手中途离桌（`left`）

前提：live 传了 `extra_signature`，且这一手的 `hand_roster` 已锁（`§4.3`）。
非 live / 没锁 roster 时走旧行为：只报 `vanished:<seat>` 错误、整帧丢弃。

流程（`state_stream.py:574-633`）：

1. 每帧对 roster 里每位（除 hero、除已 confirmed left）看 `in_hand`；
2. `in_hand` 为真 → `vanish` 计数清零；
3. 否则 `vanish++`：`≤ max_vanish`（默认 3）时**整帧丢弃**（`vanished:<seat>`），
   遮挡和真离桌在前 3 帧不可区分；
4. `vanish > max_vanish` → `_mark_left()`：`left=True`、`fold=True`、
   `status="folded"`、`in_hand=True`、`stack=None`、`bet=0`、`action=None`，
   名字/位置沿用 roster，note 写「本手中途离桌，按弃牌处理」；
5. 下一帧起 `build_state` 的 `left_here` 分支（`frame_state.py:487-501`）直接
   按弃牌重建这一行：不再要求筹码/下注（人都不在了，读不到是正常的），
   质量闸跳过该座（`frame_state.py:576-577`）。

**误判恢复**：`vanish` 期间手牌图标重新出现 → `hand_left` 里移除、计数清零，
这一帧按正常玩家重建（`state_stream.py:239-247`）。牌桌层再撤销之前补的
`left` 弃牌记录（`hand_track.py:1007-1025`，只删 `left=True` 的合成记录）。

**对行动线的影响**（`hand_track.py:988-1005`）：离桌者立刻补一条
`inferred=True, left=True` 的 `fold`，名字/位置沿用离桌前，让 AI 在当前街就
能看到「这家已经弃牌」。全下的人、hero、这手已有 fold 记录的人跳过。

### 3.8 本手中途有人入座

判据是**名单（roster）**，不是画面：换手第一帧锁定的 `hand_roster` 里没有这个
座位 → 本手不参与（`frame_state.py:507-521`）：

* `in_hand=False`、`status="sitting_out"`、`name=None`、`stack/bet/action` 清空；
* note 写「本手开始后入座，下一手再识别」；
* 不占人数（`players_in_hand`）、不输出名字、不参与位置排序；
* 牌桌座位数 `table_seats` 不变（那是物理座位数）。

特殊组合：某个座位这一手开始时有人在、中途走了、**又来了新人**——该座位在
roster 里，`left_here` 分支优先，所以仍按旧人弃牌处理、显示旧名字，直到下一手
重建 roster。若新人在 3 帧内就坐下（vanish 还没确认），则不会被判离桌，而是
沿用旧身份、名字靠 `NameTracker` 逐渐换成新人（`§4.4`）——这是已知的取舍。

### 3.9 庄位与位置（离桌/暂离的连带影响）

* 庄位走独立的全图 blob 扫描（白底圆片 + 深色 `D`），不是 OCR；一手内不重跑，
  每 `DEALER_RECHECK_SECONDS` 兜底复核（`state_stream.py:226-266`）。
* 有人退出/暂离时按钮可能留在空座上——**死按钮**：传完整座位环
  `seat_ring` 按按钮在环上的位置排，空座只跳过，不重排后面的人
  （`frame_state.py:537-548`、`positions.py:1-13`）。
* 座位身份锁打开时，位置按 **roster** 排而不是当前在场人数，否则少一个人会让
  空位后面的人整体前移（hero 的 UTG+2 → LJ），行动顺序/AI 上下文全错。

## 4. 跨帧与会话层

### 4.1 稳定与质量闸

一帧要被**记录**，需要同一个状态指纹连续 `stable_frames`(2) 帧（可选再加
`stable_seconds` 最小稳定时长），且指纹与上次记录的不同（`state_stream.py:412-431`）。
被质量闸丢弃的帧会打断「连续」（`stable_reset_on_discard`）。

质量闸（`frame_state.py:553-585`）任一不满足 → 整帧 `discard`：

* 盲注 / 底池 / 庄位读不到；
* `players_in_hand < 2`；
* 庄位有了却排不出位置、`pot_before_street > pot`；
* 有人的 `stack` / `bet` 是 `None`（`all_in`、`left` 豁免）；
* `bet > pot`。

这是「宁可丢帧也不猜」的口径，代价是动作动画、摊牌、被弹窗遮挡时大量丢帧；
弃牌徽章/亮牌这些本来就会丢的字段因此走独立入口或街末补全。

### 4.2 「这一座还有没有人」的证据

`present`（`frame_state.py:372-380`）——名字文本（动作徽章不算名字、roster 内
座位不算）、动作、`stack is not None`、`bet > 0`、手牌图标在、亮牌、All-in、
有胜率。任一成立即「还有人」。

注意：**`bet = 0` 不算在场证据**（空座也会被读成 0），只有 `bet > 0` 才算；
否则空座会以「有下注字段、没筹码」进质量闸，报 `stack:<空座>`，整场 100% 丢帧。

`in_hand`（`frame_state.py:447-451`）= 有上述任一证据，且不是
`buying_in` / `sitting_out` / `no_player`。

### 4.3 一手牌内的座位身份锁（roster）

只有 live 传 `extra_signature`（手牌/公共牌）时才启用。换手信号的下一帧，
若本帧通过质量闸、hero 在局、在局人数 ≥2，就把当前在局的人锁成
`{seat_id: (名字, 位置)}`（`state_stream.py:446-470`）。锁之后：

* 名字槽不再作为「这一座还有人」的证据（名字可能被 ROI 缓存钉住，人走了还
  返回旧值）——否则空座会让每帧都报 `stack:<seat>`（2026-10-29 实盘）；
* 离桌/新入座按 §3.7 / §3.8 处理；
* 名字事后被纠正只同步名字，不动位置和成员，且只接受
  `NameTracker.confirmed()` 的名字（`state_stream.py:500-530`）；
* 换手时整个 roster 作废，其余慢变量（名字/盲注钉住、庄位结果、全下集合、
  爆炸底池）一起清（`state_stream.py:704-724`）。

### 4.4 名字与「换人」

`NameTracker`（`parse.py:293-460`）按座位投票，`confirm=3` 帧才确认一个名字；
`names_similar()` 区分「同一人 OCR 抖动」和「真换了人」并写进 `name_warnings`。
名字槽被动作徽章盖住时 `name_raw` 不写，避免把徽章当名字。画像侧还有
`NameLexicon`（词表纠正/别名/占用冲突），见 `name_lexicon.py`。

### 4.5 换手（一手牌什么时候算结束）

`LiveHandTracker._is_new_hand`（`hand_track.py:661-720`）四个信号：

* 庄位换了；
* 公共牌从 >0 连续 2 帧掉回 0（4→3、5→4 不算，那是读丢一张）；
* hero 两张牌换成另一组（翻前且底池还在盲注水位才认；翻后要底池同时变小）；
* 在局人数一次变化 ≥2（仅翻前 + 底池初始水位）。

`StateStream` 侧另有 `_hand_changed()`（`state_stream.py:673-702`）和
「All-in 徽章消失」作换手信号。收手后还要等一帧真正属于新手的信号才开新记录，
避免把上一手的牌面写成新手开局（`hand_track.py:405-423`）。

## 5. 手牌层：动作记录与补全

对手状态最终要落成行动线，这里有三个**推断入口**（都带 `inferred=True`）：

| 入口 | 触发 | 位置 |
|---|---|---|
| 徽章/下注额反推 | 每帧 | `hand_track.py:904-986` |
| 街末差集补弃牌 / 补过牌 | 换街、收手 | `hand_track.py:1233-1286` |
| 底池对账补跟注/加注 | 换街时 `pbs(新街) − pot_start(旧街)` 对不上 | `hand_track.py:1029-1183` |

* 街末补弃牌：`街初在局 − 街末在局 − 已有 fold 记录`。这是视频流里弃牌徽章
  整条街抓不到时的主力证据。
* 街末补过牌：只在这一街**没有任何 bet/raise** 时补；有人下注时没记录的人更
  可能是跟注，写成 check 会污染行动线。手末的翻前不补（全弃到 BB 是直接收池）。
* 底池对账：先试「只补跟注」，再试「单次加注 + 全部跟注」，用剩余人数反解
  最终水位；解出 73.33 这种非半格数就不猜。金额精确、**加注者身份是推断**。
* 爆炸底池的翻前只有强制前注，不补 check/fold（会把 VPIP 分母拉大）。

快照里 `OpponentSnapshot.folded = (fold is True or status == "folded")`
（`hand_track.py:1393-1402`），`opponents_in_hand` 统计的是 `not folded`；
`players_dealt` 用的是 `in_hand or status=="folded"`（含已弃牌/离桌，不含空座）。

## 6. 已知缺口与风险（按影响排序）

1. **「在座未入局」依赖 det 复核，且只覆盖没有手牌图标的座位。** 纯 rec 只能
   读到 `#中` / `#德中` 这种碎片（0.52–0.68），真正把它读成原文的是 det+rec，
   而 det 只在「该座没有手牌图标」时才跑。所以：图标判断为 `None`（低分辨率/
   头像被盖住）时读不到这三个词；`detect_fold=False` 的离线路径完全不读头像。
   —— 这是有意的取舍：det 每座 ~85ms，不可能每帧对 9 个座位都跑。
2. **弃牌是 best-effort 三态。** 实测同一帧 5 个弃牌玩家会漏 2 个（rec 直接
   返回空）。`fold=None` 只能等街末差集补，**街内**的 AI 上下文可能看到的是
   「还在池里」。
3. **亮牌座位的弃牌只能继承。** 若接管时已经处于摊牌画面（没有上一份状态），
   `fold=None` → `status="playing"`，会少算一次弃牌。
4. **新入座者本手完全不可见**：不输出名字、不算人数、不算对手——包括他在这手
   结束前就已经坐下、只在看牌的十几秒。这是刻意设计（保证位置和人数稳定），
   但 AI 看到的人数会比画面少。
5. **3 帧窗口内的座位更替不可分辨**：离桌确认要 4 帧（`vanish > 3`），这之前
   整帧丢弃；如果新人在窗口内坐下，旧身份会被沿用、名字靠 `NameTracker` 慢慢
   换过去，不会产生 `left`。
6. **`bet` 的三个 0 语义相同**（真没下注 / pill 没渲染 / 非金额文本），只有
   `None` 才代表「读坏了」。遮挡导致 pill 没渲染时会静默变成 0。
7. **动作徽章与名字共用一块 ROI**：徽章在场时名字读不到，名字靠
   `prev_names` / `NameTracker` 兜底；roster 锁定后名字槽更是完全不能当在场
   证据。
8. **位置重排只在 roster 锁下被抑制**：离线工具（不传 `extra_signature`）没有
   锁，中途少人会让后面的人整体前移。
9. **质量闸很硬**：单帧任一字段读不到就整帧丢。这也意味着 `status`/`fold` 的
   很多判定只在「干净帧」上发生，动画期全靠跨帧补全。
10. **全图路线（`pipeline.py`）只判占用**（`EMPTY/OCCUPIED/UNCERTAIN`，
    `in_hand` 看筹码能否读出），不判动作、弃牌、全下、亮牌。两条路线的状态
    模型不通用。
