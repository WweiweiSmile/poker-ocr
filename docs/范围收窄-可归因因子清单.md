# 范围收窄：可归因因子清单

2026-11-13。只读调查，代码基线为当前工作区；行号均为实际读到的那一行。
配套设计稿：[`docs/对手范围-事件模型-设计.md`](对手范围-事件模型-设计.md)（§12 是落地口径）。
目标是为 `logs/live.range.jsonl` 与看板确定「哪些因子能事后归因、哪些不能」。

> 一句话结论：**单看一个 combo，只要记住每一步的类别与三个归一化分母，
> 权重变化就能写成 log 空间的严格加和**；真正不可精确归因的是四类东西——
> 作用于整手牌集合的分母（Z_k / 剔除后的总质量 / 截断后的保留质量）、
> `min_likelihood` 的截断（不可逆）、离散的类别映射（同一 combo 在不同牌面上换档），
> 以及缓存命中后已经不在内存里的中间量。

## 2. 可精确分解的部分

代码实际执行的递推（`build_range` `:589-636`）逐字写出来是：

```text
w⁰(h)  = w0(h) / Σ_h' w0(h')                                   (:589-590)
f_k(h) = max( L_k(c_k(h)) · M_k(c_k(h), ctx_k) · D_k(c_k(h), |B_k|),  ε ) ^ α   (:600-603)
w^k(h) = w^{k-1}(h) · f_k(h) / Z_k ,   Z_k = Σ_h' w^{k-1}(h') · f_k(h')        (:604-608)
w^K⁺(h) = w^K(h) / (1 - m_dead)                                                (:613-620)
保留集  = { h : w^K⁺(h) ≥ support_floor · max_h' w^K⁺(h') }    （不归一化）      (:622-625)
w_final(h) = w^K⁺(h) / ρ ,   ρ = Σ_{h∈保留集} w^K⁺(h)                          (ranges.py:173-176)
```

取对数相减，对**保留下来的** combo 有严格恒等式：

```text
log w_final(h) − log w_prior(h)
  = Σ_k α · [ log L_k(h) + log M_k(h) + log D_k(h) ]      ← per-combo，可加
  − Σ_k log Z_k                                          ← 每步一个全局常数
  − log(1 − m_dead) − log ρ                              ← 两个全局常数
```

其中（`L` 的内部结构同样可加）：

```text
log L_k(h) = log p_{a_k}(c_k(h)) + log boost_{a_k}(draw_k(h)) − log T_k(c_k(h))
T_k(c)     = Σ_{a ∈ 合法动作集} p_a(c) · boost_a(draw_k(c))
             面对下注：{call, raise, fold}      (:440)
             无人下注：{check, bet}            (:454)
log M_k(h) = log bucket_tier[bucket_k][made_k(h)]
           + [a_k ∈ {bet,raise}] log spr_aggr[spr_k][made_k(h)]
           + [a_k ∈ {bet,raise} ∧ group=bluff] log arch_bluff[arch]
           + [a_k = call] log arch_call[arch]
           + [all_in ∧ spr ∈ {<0.5,0.5-1}] log 1.10
             （a_k = check ⇒ 全部为 0，:420-421）
log D_k(h) = log street_factor[|B_k|]，仅 draw ∈ {combo,flush,oesd,gutshot}
```

所以**归因是严格成立的**，前提是三件事同时成立：

1. 每一步的 `c_k(h)`（成牌档/听牌档/三组）已知 —— 由 `(h, B_k)` 唯一决定，可重放；
2. 每一步的 `Z_k` 已知 —— 它不在返回对象里，必须落盘或整手重算；
3. `m_dead` 与 `ρ` 已知 —— 前者由 dead 集合算出，后者要记录截断前的权重和。

满足这三条时，`log w_final − log w_prior` 可以**逐项拆到 (事件 k × 因子)** 的粒度，
且残差为 0（浮点误差外）。这是给看板画「第几步被哪个因子砍掉多少」的数学基础。

## 3. 不可精确分解的部分

1. **每一步的分母 Z_k 依赖整手牌集合，不是 per-combo 常数。**
   `:608` 每步都做一次 `_normalize`，`Z_k = Σ_h w_{k-1}(h) f_k(h)`。它依赖先验里
   所有 combo 的权重，也依赖**别的类别**当步的 `L·M`；一个 combo 的 log 变化里
   含 `−log Z_k`，这一项与它自己无关。只有把 `Z_k` 写进 trace 才能补上；不写就
   只能整手重算。

2. **`min_likelihood` 截断不可逆。**
   `:602-603` 的 `max(·, ε)` 作用在 `L·M·D` 上（**先截断再取 α 次幂**）。
   可实现值本身仍可加，但一旦被夹，`log f_k` 里 `table 贡献` 与 `floor 贡献` 就混成
   一个数，无法回答「这张表本来给多少」。更麻烦的是内层还有一处截断
   （`:444`、`:446`、`:458`、`:459`）：先把**归一化后的概率**夹到 ε，再乘 `M`。
   两处截断不可交换（`max(p,ε)·M ≠ max(p·M, ε)`），所以「表值 → 概率 → 乘数 → 外层截断」
   这条链上，只要任一环被夹，反推表值就不唯一。

3. **河牌听牌的 0 被外层截断“救”回来。**
   `draw_street_factor` 河牌取 0（表 `:165-167`），`factor = 0`，随后 `max(0, 1e-4) = 1e-4`。
   也就是说「河牌听牌权重为 0」在实现上是 `1e-4^α`，不是 0。log 上是有限值，
   但语义上已被截断污染；看板若直接把 `log f` 画成「听牌在河牌归零」会读错。

4. **支撑集截断是集合级操作，且截断后不再归一化。**
   `:622-625` 只保留 `w ≥ support_floor·peak`，`:620` 之后没有第二次 `_normalize`；
   保留下来的权重和 ρ < 1，最后由 `make_range` 再除一次（`ranges.py:173-176`）。
   ρ 依赖「谁被砍掉」，而被砍掉的那些 combo 又受 dead 剔除、撞牌归零、每步 Z_k 影响。
   对被砍掉的 combo，`log w_final = −∞`，没有连续归因可言；对留下的 combo，
   `−log ρ` 是一个**跨 combo 的耦合项**。

5. **dead cards 是集合删除，不是乘性因子。**
   `:613-616` 用 `del` 从 dict 移除，发生在**全部连乘之后**；它不参与 `Π f_k`，
   却改变后面的 `peak` 与 `ρ`。所以「dead 让权重降了多少」这个问题本身没有 per-combo
   乘数答案——只有「还在/不在了」，以及一个全局的 `1/(1−m_dead)`。

6. **类别映射是离散的，且档位会随牌面跳变。**
   `made` 由**牌面百分位**定（`:255-264`、`:365-367`），百分位的分母
   `total = len(features_for_board(board))` 是「该牌面上不撞牌的 combo 数」。
   同一个 combo 在翻牌是 `medium`、转牌可能变 `weak`，乘数从 1.05 跳到 1.15 这种
   「跳变」无法表达成某个因子的连续贡献；只能记「第 k 步它在哪一档」。

7. **α 由 `len(events)` 决定，而事件可能被静默跳过。**
   `:582` 用 `len(events)` 算 α；循环里 `if not classes: continue`（`:598-599`）会跳过
   没有牌面的事件。于是**一次没有产生任何乘法的动作也会让 α 降温**，这个影响分摊到
   所有事件、所有 combo 上，无法归到某一个 combo 或某一个动作。

8. **口径不匹配时是常量 0.5，且完全跳过 M。**
   `:473-474`（动作词不认识）与 `:479-482`（未面对下注却记成跟注 / 面对下注却记成过牌）
   直接 `return 0.5`。这条路径没有 `L`、没有 `M`、没有表值，事后只能说「当时判成中性」，
   拆不出任何因子。

9. **缓存命中后中间量已不在内存。**
   `build_range` 的缓存 `:584-587` 只存最终 `Range` 对象；`Z_k`、每步 `f_k`、
   被砍掉的 combo 全都没有留。命中时直接返回，**不会重算**。更要注意缓存键
   `(prior.id, prior.version, events, round(alpha,4), archetype, dead_set, round(support_floor,6))`
   **不含表 profile/variant**——运行中切 `STRATEGY_TABLES_PROFILE` 不会失效。
   上层 `hand_vs_ranges._CACHE`（`:479-496`）键里带 `id(rng)`，命中 `:553-555` 时连 MC 都不跑，
   同样拿不到中间量。

10. **最终宽度是计数口径，不是权重口径。**
    `width_pct = 非零 combo 数 / 1326`（`ranges.py:181`），与 `log w` 没有函数关系；
    `weighted_width`（`ranges.py:184`）才是保留质量。两者混用会让「哪一步把范围砍窄了」
    出现自相矛盾的答案（例如某步只砍权重不改支撑集，`width_pct` 完全不动）。

## 4. 对 trace schema 的直接约束

为了让上面第 2 节的恒等式事后能复现，日志里至少要存：

1. **输入身份**：`prior_id` + `prior_version`（`ranges.py:40` `RANGE_VERSION=1`，经 `ranges.py:167` 写进
   `Range.version`）+ 完整的 `events` 序列（`ActionEvent` 的 `street/board/action/facing_bet/
   raises_before/n_callers/players_behind/is_first_to_act/is_donk/all_in/spr` 一个都不能少，
   因为 `bucket_of` `:226-246` 与 `spr_bucket` `:209-223` 全靠它们重放）。
2. **参数快照**：`alpha_in`、`alpha_eff`（`:582` 之后的实际值）、`n_events` 与 `n_applied`、
   `archetype`（逐座位）、`dead` 列表、`support_floor`（含 env 覆盖）、`RANGE_EVENT_MODEL` 开关。
3. **表身份**：`strategy_tables.profile()` / `variant`（v0|v1）+ `poker_ocr/tables/range_flow.json` 的
   内容哈希。理由：`_BUILD_CACHE` 的键（`:584-585`）不含表版本，只靠它无法判断一次结果用的
   是哪套数。
4. **逐事件中间量**：每步的 `bucket`、`spr_bucket`、`Z_k`（`:608` 归一化前的总质量）、
   以及每步的 `mass_before/mass_after`；缺 `Z_k` 就必须整手重算才能归因。
5. **逐 combo（至少 top-N 与 hero 关注的那几个）**：`w_before/after`、`made/draw/group`、
   `L`（含 `l_pre_clamp` 与 `clamped` 布尔）、`M` 的四个分项、`D`、以及三个丢弃原因
   （`zeroed_by_board` / `dropped_by_dead` / `dropped_by_floor`）。
6. **前后宽度**：`width_pct`、`weighted_width`、`effective_width_pct`、`peak`、`ρ`（保留质量）
   与 `combos_before/after`，并按 `path: "event_model" | "board_range"` 标出走了哪条链路
   （`hand_vs_ranges.py:683-691`：事件链不可用时回退 `board_range.build`，那条路没有 α/M）。
7. **命中标记**：`cache_hit: bool` 与 `compute_id`。缓存命中时上述中间量都拿不到，
   日志要么复用首次计算的 `compute_id` 关联，要么显式写 `cache_hit=true` 让看板知道
   「这一步的归因来自另一次计算」。**不能**在缓存命中分支里假装自己算过。

> 现成的落点参考：`poker_ocr/advice.py:853-868` 已经把 `range_id/width/behind/tie` 写进
> `facts["hand_ranges"]`——新 trace 应与它共用 `hand_id` + `seat` + 决策序号的键，
> 只是把每步因子补上，而不是另起一套口径。
