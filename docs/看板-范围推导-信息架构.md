## 0. 一句话

手牌详情弹窗新增「范围推导」tab：顶部 hero equity 条，左栏纵向时间线（step0 先验 →
逐事件 → final），右侧 13×13 热图，热图下方 combo 表；一个 hash 深链复原
`手牌 + 街 + 座位 + 步 + 格子`，三种「没有推导」各有各的说法。

## 1. 宿主与入口

- 宿主是**手牌详情弹窗**（`poker_ocr/web/live/app.js` 既有 modal），tab 顺序：
  `概览 / 行动线 / 数据质量 / 建议 N / 范围推导`。不新增页面、不新增前端构建。
- 入口只有一个：打开手牌 → 点「范围推导」。一手有多个决策点时，tab 内顶部是
  **决策选择器**（街 + 行动数，如 `翻牌 · 7 个动作`），默认选该手最后一个翻后决策。
- 深链可直接打开弹窗并落在 tab 上（见 §5），不要求用户先点手牌。
- 与提示词的关系：不复制提示词正文，只给「去 User 事实块看这一句 ↗」的跳转；
  行级 refs 由 #7 的 `prompt_refs` 提供。

## 2. 数据通路

trace 不进 SSE、不进 `/api/snapshot`（单条 40–180 KB，快照每帧推不起）。

```
GET /api/range?hand=42&street=flop&actions=7
```

- `live_web.py` 新增只读路由；从当日文件起按 mtime 倒序扫 `logs/live.range.jsonl*`，
  按 `decision_key`（hand / street / actions）匹配，同键多行取 `ts` 最新一条（契约 §5）。
- `actions` 省略时返回该手该街的全部记录（数组），前端自行挑；`hand` 必填。
- 响应：`{"status":"ok","record":{…}}` 或 `{"status":"skipped|missing|off|budget_exceeded|write_failed"}`；
  `Cache-Control: no-store`。
- 前端懒加载：点开 tab 或 hash 带 `seat` 时才请求；一条记录含全部 `seats`，切座位与切步
  **不再请求**。请求失败显示错误态 + 「重试」，不静默空屏。

四个验收问题的锚点：

| 问题 | 锚点 | 一屏内怎么被回答 |
|---|---|---|
| A 为什么只剩 12% | 左栏时间线每步 `width_before → width_after` + `Z_k` + `dropped{dead,zero,floor}` | 从 100% 一路读下来，哪一步掉得最多一眼可见；点该步右侧热图与表同步到那一步 |
| B 为什么 equity 38%、建议却是 XX | 顶部 equity 条（behind / tie / ahead + 95% CI）+ 「提示词那句话」跳转 | 38% 是哪个基准、CI 多宽、提示词原句在哪，同屏可核 |
| C 某 combo 为什么归成 air | 右侧热图点格子 → 下方 combo 表 | 每行给 `group / made / draw / L / M / D / Δw / cut`，可按步看 |
| D 翻前先验本身是否就错 | 时间线第一行 step0 | 先验 `source`（RFI / BB_DEF / rules / uniform）、宽度、169 热图都在第一行 |

断点：≥1080 px 两栏；<1080 px 时间线折叠成顶部横向步骤条，热图与 combo 表上下叠。

### 3.1 2026-11-14 原型复验后的修订

原型的两次截图评审（`docs/proto/screens/1-h104-3bet-jam.before.png` / `4-h4-cell-filter.before.png`
→ 同名 `.png`）暴露五处，已并入上面的线框：

1. **建议条独立成行**，不再挤在 header 第二行末尾；label 20–22px、理由 ≤2 行、`model · ms` 只做右端弱化元数据。
2. **各家宽度概览移进左栏、时间线之下**，改横条 + 0–100% 刻度轴（旧口径黄条、各步竖线）；原来它在页底，h4 在 820px 窗口直接被挤出可视区。
3. **筛选反馈贴到热图下方**（pill：格子 / 占本步 pct / 条数 / 清除 ✕），表格标题随之变「格子 KQo 的 12 条组合」；final 步隐藏 `Δw`/处置 两列。
4. **右栏两 panel 等高**：热图定高，表格吃剩余高度、内部滚动并做 16px 底部淡出；表格底边与热图底边对齐。
5. **中间步徽章「待删」、final 才 `dead`**；表头右侧给「共 N 个组合有变化」。热图空位补 1px 网格线，范围窄时仍能读出 13×13 结构。

## 4. 交互清单

首屏必须有（四项，缺一不可）：

| 交互 | 行为 |
|---|---|
| 切座位 | 顶部 chips；切换只换渲染数据，不重新请求；1 家时 chips 隐藏 |
| 点 step | 时间线行可点；选中态高亮该行、热图与 combo 表切到该步 `grid` / `top` |
| 点 13×13 格子 | 按 169 键筛 combo 表（命中该键的 4–12 个 combo），热图下方出筛选 pill（可清除），再点同一格取消 |
| 点 combo | 展开该 combo 本步明细（`l_pre`/截断、`M` 四分量合计、`D`、`cut`），并高亮时间线上的对应步 |

收起 / 后续（不在首屏加载）：

- 换表版本 diff：只留「用当前表重算」入口，转 #9 的原型；本页不请求重算结果。
- 提示词正文：只跳现有提示词 tab，不在本 tab 内二次渲染。
- 键盘：`←/→` 切 step，`↑/↓` 切座位，`Esc` 取消格子筛选。

状态全部进 hash（§5），浏览器前进/后退可用。

## 5. 深链

```
#/range?hand=42&street=flop&seat=3&step=2&cell=AhKh
```

- 恢复顺序：打开手牌弹窗 → 激活「范围推导」tab → 选决策（`street` + `actions`）→
  拉 `/api/range` → 选 `seat` → 选 `step`（缺省 `final`）→ 应用 `cell` 筛选。
- 参数缺失或非法（手牌不存在、座位不在 `seats`、step 越界）：逐项退回默认，**不整页报错**；
  地址栏保留用户原参数，不静默改写。
- 交互产生的状态变化（切座位/切步/点格子）用 `history.replaceState` 写回 hash，不新增历史条目；
  从别的 tab 进「范围推导」才 `pushState`。
- 复制链接即可把「这一步有问题」发给别人；刷新后同一位置复原。

## 6. 空态与错误态

| 情况 | 显示 | 保留 |
|---|---|---|
| (a) 本次会话 `--no-range-trace` | 「未开启（本次会话）」+ 一行如何重开（去掉 `--no-range-trace`） | 不画空热图、不放大字占位；本 tab 内仍显示 facts 旧视图（宽度/equity 摘要） |
| (b) 记录早于 trace / 当次未落盘 | 「无推导（记录早于 trace）」 | facts 旧视图；不显示「0%」，不自动回填 |
| (c) 翻前 | 「翻前不做范围计算」+ step0 先验视图 | 先验来源/宽度/169 热图（回答 D 类问题） |
| (d) `skipped`（board_short / no_hero_cards / no_specs / disabled / error） | 按 `reason` 出中文一句 + 原值 | facts 旧视图 |
| (e) `budget_exceeded` / `write_failed` | 「已停写（超日预算）」/「写盘失败」 | facts 旧视图；写盘失败只提示一次 |
| (f) `missing`（接口不通或文件被清） | 「找不到这条推导记录」+ 重试 | 手牌其余 tab 不受影响 |

所有空态都是一行说明 + 一个可做的动作，不做插画、不做渐变遮罩。

## 7. 座位伸缩

- 1 家：隐藏 chips，时间线标题直接写位置（`BB`）。
- 2–4 家：chips 横排（超出横向滚动），当前家高亮；`omitted > 0` 时 chips 末尾显示 `+N 家未建模`，
  点开只有一句解释，不画热图。
- 永远单家聚焦渲染热图与 combo 表；4 家对比靠底部「各家宽度概览」条（`step0 → final` 两段宽度 +
  折线），不并排 4 张 13×13。

## 8. 验收

- [ ] 从手牌打开 → 「范围推导」tab 在 300 ms 内出首屏（含一次 `/api/range` 往返）。
- [ ] A 类问题：不点任何东西，时间线上能指出掉得最多的那一步。
- [ ] B 类问题：equity 条显示三个基准的区分与 CI，点「提示词那句话」能跳到 User 事实块对应行。
- [ ] C 类问题：两次点击（格子 → combo）能读到该 combo 本步的 L / M / D / cut。
- [ ] D 类问题：step0 行给出来源与宽度，热图可看先验分布。
- [ ] hash 深链刷新后复原到同一座位/步/格子；非法参数逐项回退不报错。
- [ ] 六种空态文案与保留内容符合 §6，且都不出现「0%」。
- [ ] 1 家与 4 家都不出现横向滚动条（chips 区除外）。

## 10. 实现落点与偏差（2026-11-14）

实现见工作树（未提交）：后端 `poker_ocr/live_web.py`（`/api/range` 路由 + 注入式
`range_query`，handler 不认识 trace 模块）、`poker_ocr/live.py`（启动时 configure + 把
`range_trace.lookup` 注入 server）；前端 `poker_ocr/web/live/range_tab.js` /
`range_tab.css` + `app.js`（tab 注册、renderModal 里给弹窗加 `is-wide`、深链
`hashchange`/`restore`）+ `index.html` 两行静态引用。

与本文档的偏差（都是实现期发现后的取舍）：

1. **弹窗放宽**：范围推导 tab 用 `.modal-card.is-wide`（`min(1320px,100%)`、
   `max-height: min(92vh,1150px)`），其它 tab 仍 1100 px。1100 px 减去左栏 300 px 后右栏
   只剩约 750 px，装不下「热图 420 + 表格 ≥400」两列。
2. **右栏断点 1200 而非 1080**：≥1200 px 两列并排（热图定宽 420、表格吃剩余宽度、JS
   `alignRight()` 把表格 panel 高度拉平到热图，内部滚动 + 16 px 底部淡出）；<1200 px 叠成
   单列（表格回到 420 px 内部滚动）。1200 是「1320 弹窗 − 左栏 300 − 间距」还够两列的下限。
3. **点格子只列存活支撑集**：筛选结果只取该 169 键在 `detail`（存活、含 `dead` 行）里的
   combo，与筛选 pill 的「本格 N 个组合」（= `cell_n`）同口径；`top` 榜里的归零 / 待删行
   是「本步怎么变的」，不进筛选结果。不点格子时表格仍按 `|Δw|` 展示变化榜。
4. **final 默认是 169 格聚合**：`final` 只落 `grid[169]`（契约 v1.2），表格按份额降序；
   逐 combo 明细在 `steps[-1]`，点格子时明细从最后一步取，并注明「floor 剪枝没有逐条落盘」。
5. **翻前空态不画先验热图**：trace 翻前零记录（契约 §2 设计决定），没有可画的 grid；
   先验视图落在首个翻后决策的 step0 行。原 §6(c) 的「step0 先验视图」因此只做到文案 + 不画空图。
6. **概览条**用终局 `width_pct`；`board_range` 座位（旧口径）黄条取记录里的 legacy 宽度，
   与事件模型座位区分开、不直接比大小。
7. **空态不再重复渲染 facts 旧视图**：六种空态都是一句文案 +「事实视图（概览 / 行动线 /
   数据质量 / 建议）不受影响」的提示，用户切 tab 即可看到；不在本 tab 内再摆一份宽度 / equity
   摘要（会变成第二个概览页）。
8. **未实现（记录在案）**：键盘 `←/→/↑/↓/Esc`；换表 diff 入口（按 #9 不做）；
   「跳到提示词那一行」目前只跳既有建议 tab——行级 `prompt_refs` 还没落 states.jsonl，
   精确到行要等 #7 的实现。
9. **三类零权重格（2026-11-15，#32 补齐）**：§3 线框里「dead ✕ / floor 斜纹 / 先验无 = 白」
   原先只落了前两类。现在 169 格分三类——有份额（染色）、先验含但本步为 0（`.rt-cell.zero`，
   tooltip 写「已被删 · 第 k 步」）、先验里就没有（`.rt-cell.absent`，透明底，tooltip 写
   「先验未包含」）；判定是纯函数 `poker_ocr/web/live/range_cells.js`（node 直测），
   热图下方三色图例给三类计数，每步删减图例追加一句「另有 M 格先验未包含（不计入 N）」。
   M 是全集口径（169 − 先验覆盖的格），不随步变；`dropped` 仍只报 dead/归零/剪除。

验证：`nv tests/run_all.py` 58 个套件全过；用手搓样本（h104 两个决策点、3 家）起只读
demo server，按 1440×1400 / 1440×1200 / 1100×1000 三种窗口截图核过并排两列、等高、
筛选 pill、空态。
