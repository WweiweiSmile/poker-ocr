# 手牌范围基准：现状与缺口

> 场景：9-max 现场，实际入池 3–5 人。
> 目标：给定**我的具体手牌**、**实际牌面**、**仍在池中的每个对手的范围**，
> 知道当前手牌大致**领先什么牌 / 落后什么牌**，再按对手画像做偏移。
> 不要求：3–5 人 GTO 均衡、翻后 solver 的尺度/单手 EV、184 类全量跑批。
>
> 本文把“手牌范围基准”定义为 **hand vs ranges**：
> 我的手牌 vs 对手范围，而不是“范围 vs 范围”的整体优势。后者在
> 2026-11-05 随 GTO 组件一起移除，当前只有逐对手范围构成（composition）
> 作背景，见 §2.4。

---

## 0. 结论

**hand vs ranges 已落地：主路是「对手范围 + 联合拒绝重抽」，兜底是「随机牌独立近似」且显式标注。剩下的缺口是范围质量，不是引擎。**

- ✅ 开池 RFI（7 个位置）是完整的代码表；BB 防守、冷跟、溜入、3-bet 先验也已进 `poker_ocr/ranges.py`（描述性池子先验，不是均衡频率）。
- ✅ 每个在局对手的角色/先验/动作事件由 `poker_ocr/field_ranges.py` 解析，`poker_ocr/range_flow.py` 按翻后动作顺序收窄范围；缺角色时写 `range unknown`，不拿别的范围冒充。
- ✅ `poker_ocr/hand_vs_ranges.py` 给出逐对手 `behind_i`、联合 `behind_any`、打到河牌的 `equity`、范围构成与「赢你的/你赢的」；主路用整组拒绝重抽。
- ✅ 没有范围时退回 `coach.at_least_one_behind` 的随机牌独立近似，提示词明写「按随机牌下界」，复盘 facts 带 `beatAtLeastBasis`，UI 标「（近似）」。
- ⚠️ 冷跟先验已按入池人数分 2/3/4 人池三档（`poker_ocr/tables/cold_call_buckets.json` + `poker_ocr/cold_call_tiers.py`，票 #78），2 人池数值逐位不变；位置轴仍未分（`_vs_<位置>` 同宽）。范围覆盖率仍受翻前动作读数限制。
- ❌ GTO/solver 表没有回归：`gto/` 于 2026-11-05 整体移除，且它是 HU 的策略表，不回答 3–5 人池的 hand vs ranges。

> 2026-11-19 更新：口径取舍与重开条件见 `docs/adr/0002-multiway-behind-any-caliber.md`。

## 1. 目标拆成四个能力

| 能力 | 你要的回答 | 现状 |
|---|---|---|
| A. 对手范围 | 池里每个人大概是什么范围？ | ✅ 开池 RFI + BB/冷跟（2/3/4 人池三档）/溜入/3-bet 先验；位置轴仍未分 |
| B. 手牌 vs 范围 | 我这手牌领先/落后他们范围里的什么？ | ✅ `hand_vs_ranges`：`behind_i` / `behind_any` / `equity` / composition |
| C. 范围优势背景 | 这个牌面整体对谁有利？ | ⚠️ 无 range-vs-range 权益；只有逐对手 composition + 牌面结构 |
| D. 偏移 | 对手是 station/LAG 时怎么调？ | ✅ 画像 archetype 进 `range_flow` 的上下文乘数；不是独立一套文本规则 |

你现在的“基准 + 偏移”需要的是 **A + B**，再用 **C** 做背景，最后用 **D** 偏移。
A/B/D 已有代码路径；C 只剩逐对手构成与牌面结构，整体范围优势未实现。

## 2. 已经有了什么

### 2.1 开池 RFI（完整）

- 位置：`poker_ocr/preflop_ranges.py` 的 `CHART_ADDITIONS` / `RFI`。
- 7 个非盲位置，按“累计新增”写法；组合加权开池率 UTG 12.1% → BTN 44.8%。
- 配套函数：`expand()`（169 键展开）、`chart_text()`（生成提示词里的 RFI 表）、
  `open_frequency()`、`range_verdict()`（开池归属 + limper 时的隔离归属）。
- 用途：翻前建议的 `Preflop range` 事实行；提示词里的 `<<RFI_CHART>>` 也从这里生成，
  不会和代码漂移。
- 局限：**app 松弱口径，不是 GTO**；只回答“该不该开池”，不回答“跟注方是什么范围”。

### 2.2 范围先验与角色解析（已落地）

- 位置：`poker_ocr/field_ranges.py`（角色/先验/事件）、`poker_ocr/ranges.py`
  （169 键 → 1,326 combo 的加权范围）、`poker_ocr/range_flow.py`（按动作
  顺序更新范围）。
- 先验 ID：`RFI_<pos>`、`BB_DEF_VS_<bucket>`、`COLD_CALL_<IP|OOP>_vs_<bucket>`、
  `LIMP_<EP|MP|LP>`、`3BET_vs_<bucket>`、`3BET_CALL_vs_<bucket>`、`BOMB`、
  `BB_CHECK`；未知角色返回 `None` 并写 warning。
- 翻前角色只用可确认的证据：第一个加注者=opener；最后一个加注者=3-bettor；
  跟注加注的 BB=BB 防守；其他跟注=冷跟；溜入池按位置分桶；炸弹池=任意两张。
  形状与动作线矛盾时不猜。
- 翻后：`range_flow` 按时间顺序把每个动作的似然/上下文乘数连乘；事件模型
  默认开，`RANGE_EVENT_MODEL=0` 回退 `poker_ocr/board_range.py` 的按街单次
  过滤（legacy，不丢翻前先验）。
- 局限：
  - 冷跟先验按入池人数分 2/3/4 人池三档（票 #78，4 人以上归 4 人池），
    2 人池数值逐位不变；位置轴仍未分（`_vs_<位置>` 同宽）。人数读不出时
    退回无后缀现状档，事实里标「未定」，不猜档。
  - 最多建模 4 个对手（`field_ranges.resolve` 的渲染/性能上限），更多座位
    按随机牌补位并计入权益，但不对他们展开范围。
  - 先验是描述性池子基线，不是均衡频率；换池/换数据要重新校准。

> 2026-11-19 更新：原 §2.2 写的 `gto/specs/spots.json` 已随 `gto/` 移除，
> 当前范围路径见上；取舍见 `docs/adr/0002-multiway-behind-any-caliber.md`。

### 2.3 手牌排名引擎（完整，但基准是随机牌）

- 位置：`poker_ocr/coach.py` 的 `_rank_cached` / `rank_hands` / `beat_rate`。
- 精确枚举对手所有两张暗牌（约 990–1,081 个组合，随牌面长度变化），返回：
  - `win_pct` / `tie_pct` / `beat_pct` / `equity_pct`；
  - `beat_at_least_pct`：多人时「至少一家牌力严格大于我」，由
    `coach.at_least_one_behind(p, n)` 计算（`1-(1-p)^n`，函数返回 0..1；
    `situation` / facts 再 ×100 成百分数）；
  - `beaten_by`：按牌型分组的“能打败我的牌”（含组合数/示例）；
  - `best_opponent_category` / `best_opponent_cards` / `hero_is_nuts`。
- 用途：`ground_truth` 的 `Beaten by` / `NUT STATUS`；提示词兜底分支的
  `beat_at_least_pct` 行；`capped_by_board` 的闸门。
- 局限：**基准是“所有随机两手牌”，不是对手范围**；`beat_at_least_pct` 是
  随机牌独立近似，只在 `hand_ranges is None` 时进提示词，且文案已写
  「按随机牌下界」。有范围时走 `hand_vs_ranges` 的联合重抽。

### 2.4 范围 vs 范围的牌面权益（已移除）

- `poker_ocr/board_equity.py` 于 2026-11-05 随 `gto/` 一起移除；当前没有
  range-vs-range 的整体牌面权益。
- 现在能用的背景是逐对手的**范围构成**（`range_flow.composition`）：
  成牌/听牌/空气、两对+/顶对等占比，以及 `hand_vs_ranges` 的逐对手
  `behind_i`；牌面结构由 `poker_ocr/prompt/user/board.py` 从
  `ground_truth.board_info` 渲染。
- 局限：composition 回答「他范围里有什么」，不回答「这个牌面整体对谁
  有利」；不要把单家 behind 或牌面结构当成 range advantage。

## 4. 两条线：范围数据 vs 计算

```text
范围数据线
  RFI（preflop_ranges.py）
    └─ BB_DEF / COLD_CALL / LIMP / 3BET / 3BET_CALL（ranges.py 规则先验）
         └─ 169 键 → 1,326 combo 权重；命名范围 loader（ranges.get）

计算/渲染线
  field_ranges.resolve（角色 + 先验 + 动作事件）
    └─ range_flow.build_range（按动作顺序收窄）
         └─ hand_vs_ranges._monte_carlo（整组拒绝重抽）
              └─ ## Hand vs ranges / Hand-strength read / fold equity
```

- 数据线仍是瓶颈：先验是描述性池子基线；冷跟已按人数分 2/3/4 档（#78），位置轴仍未分。
- 范围链路已不再从 `coach.rank_hands` 的随机牌枚举出发；随机牌只保留在兜底
  分支和 `ground_truth` 的牌型事实里。

## 5. 现在就能用 / 需要改 / 不要做

### 现在就能用

- **开池判断**：`preflop_ranges.range_verdict`（7 位 RFI、limper 隔离）。
- **手牌 vs 范围**：`hand_vs_ranges` 的 `behind_i` / `behind_any` / `equity`
  / composition；主路联合重抽。
- **随机牌下界**：`beat_pct` / `beat_at_least_pct`；提示词只在没有范围时用，
  已写“random 是下界”。
- **范围优势背景**：逐对手 composition + 牌面结构；没有 range-vs-range 权益。
- **偏移**：`Opponent reads` / `Table context` + `range_flow` 的画像乘数。

### 需要改

- 冷跟先验的位置轴（`_vs_<位置>` 仍同宽）与 3–4 人池样本；人数轴 #78 已完成，落地后重跑票 #75。
- 范围覆盖率：翻前动作/位置缺失时的 `range unknown`，以及 6+ 人池的
  随机补位。
- `board_range` legacy 路径只在 `RANGE_EVENT_MODEL=0` 时用；新代码不要接。
- 6–9 人池的样本与阈值；当前只有 11 点，不能外推。

### 不要做

- 不要为“手牌范围基准”跑 184 表；它不解多人，也不输出 hand vs range。
- 不要把 `beat_pct`（随机牌）当成“对他们的范围领先多少”。
- 不要把 3–5 人池的决策建立在 HU solver 的 range mix 上。
- 不要把 `beatAtLeastPct`（百分数、随机牌独立近似）和
  `handStrength.behindAny`（比例、范围联合重抽）相加或互相替换。

## 7. 验收标准

> 2026-11-19：以下标准对 `hand_vs_ranges` 仍有效；当前实现已按此回退
> （没有范围时标 random-hand lower bound，不伪装成范围基准）。

- **人数**：2–4 个对手（3–5 人池）；每个对手有具名范围。
- **牌面**：flop/turn/river 都用实际 board；flop 发 3 张、turn 发 1 张、river 发 0 张。
- **输出**：
  - `equity`（vs field）；
  - `behind at least one`；
  - `behind_i`（每个对手）；
  - `beaten_by` 的牌型分组（范围加权）；
  - `ahead_of` 的类别/比例。
- **正确性**：
  - 2 个对手、小范围的暴力枚举对照；
  - 去重牌（hero/board/对手之间不重复）；
  - 权重为 0 的组合不参与；
  - 范围为空/对手已弃牌时返回 `None`，不猜。
- **性能**：缓存后 <100ms/决策；缓存 key = (board, hero, 范围 id 列表)。
- **回退**：没有范围时，明确标 “random-hand lower bound”，不要伪装成范围基准。

## 8. 风险与口径

- **范围是主要误差**：先验是描述性池子基线；冷跟已按人数分档（#78）但位置轴未分；3-bet 粗；
  （不再截断在 4 家：6+ 人池的全部在局对手都进同一组联合重抽，#115；缺证据的按随机牌补位并标注。）
  计算引擎再准，范围错了答案就错。
- **独立性与去重牌**：主路 `behind_any` 用整组拒绝重抽，已经处理不放回与
  去重牌；`1-prod(1-behind_i)` 这类独立近似不再用于主路，兜底只用
  `at_least_one_behind` 的单一 p 随机牌近似，且必须标注。两者不能混用，
  见 `docs/adr/0002-multiway-behind-any-caliber.md`。
- **“领先”vs“权益”**：听牌现在可能落后，但有权益；成牌现在领先，但可能被反超。
  渲染要分开写：`made-hand rank` 和 `equity`，不要合成一个数。
- **3–5 人池的范围相关性**：caller 的范围受 opener 影响；用独立范围是简化，
  但比 HU solver 或随机牌好得多。
- **抽水**：对范围宽度有影响，对当前街 equity 的直接影响小；先把范围修对。
- **不要用 solver 表**：它是 HU 的翻后策略，既不生产 3–5 人范围，也不回答
  hand vs range；继续跑 184 对这个目标是负 ROI。
