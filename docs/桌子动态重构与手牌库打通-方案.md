## 0. 结论

**问题不是「pool_key 没有真正隔离」，而是「玩家身份、当前牌桌、历史统计」三个概念被塞进了同一个扁平 store。**

- `pool_key` 现在是**写时打标**：同名玩家在另一个池出现时，键会变成 `名字@池`；但读取 `_resolve_key()` 先查裸名字，`pooled()` 又全量合并。所以它既没有隔离读取，也没有隔离桌子动态。
- 按你的目标，**跨桌合并恰恰是对的**：你需要的是「一个玩家的长期行为模式」，不是「每个池一份互不相通的画像」。
- 真正要修的是两件事：
  1. **身份全球化**：玩家键不再带池后缀，跨桌、跨 session 累积同一套行为统计；池只作为手牌/观察的元数据。
  2. **桌子动态按当前桌名单派生**：`TableDynamicsView = f(当前在座/本手在局的人)`，每手结束或换人时重算；手牌进行中冻结，不用未完成的手污染统计。
- 当前手、行动街动作只存在内存；**手结束才 commit** 成手牌记录，再由记录派生观察/画像/手牌库。这个边界要写成协议，而不是靠调用顺序。
- 手牌库要打通，关键不是「再加一个导入按钮」，而是把 **HandRecord v2 + 线上建议上下文快照 + 自动 outbox 入库** 做出来；否则 A/B 重跑和线上建议不是同一个上下文，比了也不可信。

**最快见效的一步**（不需要改库、不需要迁移数据）：把 `live.py` 里的 `profile_store.pooled()` 换成「本手在局对手的 stats 聚合」，并把提示词标题从「全场数据（可能跨桌）」改成「当前牌桌数据」。这一步就能消掉你看到的错误桌况。完整目标架构再按第 7 节分阶段做。

## 1. 现状：代码到底怎么跑的

### 1.1 `pool_key` 是存储后缀，不是读取过滤器

`poker_ocr/opponent_profile.py`：

- `pool_key_from_blinds()`（`:94`）生成 `0.5/1-9max` 这样的池键。
- `ProfileStore.update_hand()`（`:1842`）在「同名玩家已经存在于另一个池」时，把键改成 `名字@池`（`:1857-1875`），避免写在一起。
- `ProfileStore._resolve_key()`（`:1993`）读的时候**先查裸名字**，再查 `名字@当前池`。只要裸名字存在，就会读到一个可能来自别的池的画像。
- `ProfileStore.set_pool_key()`（`:1794`）只在 `_pool_key` 为空时设置；换桌后**永远不会更新**。而 `live.py` 每个决策点都在调用它（`:1337`），看起来像在切池，实际是空操作。
- `ProfileStore.pooled()`（`:2029`）把 `self.players` 全量合并，没有任何「当前桌」参数。
- 单元测试 `tests/test_opponent_profile.py::test_pool_keys_are_separated`（`:623`）只断言「写的时候分了键」，没有断言「读的时候按池过滤」。所以测试是绿的，语义是漏的。

**一句话：这是「写时打标 + 读时串池」，不是隔离。**

还要注意：**不要把 `pool_key` 改成真正的读时隔离**。那会变成「换一张桌就从零开始」，
和你「跨桌统计所有用户行为模式」的目标相反。正确方向是把「身份」和「桌子视图」
拆开：身份全局合并，桌子视图按当前桌名单过滤。

### 1.2 提示词自己承认「可能跨桌」

`poker_ocr/advice.py::render_table_stats_zh()`（`:2599`）：

```python
lines = ["## 全场数据（同盲注/人数画像库，可能跨桌）"]
```

这段数字会直接进模型。也就是说，模型看到的「全场 VPIP 38%」可能是：

- 昨天另一张桌的 6 个玩家；
- 上个月 5/10 的样本；
- 以及当前桌完全没出现过的人。

这不是「标注可能跨桌」，这是**把跨桌数据当成本桌事实注入**。

### 1.3 「当前桌有谁」不是一等公民

- `HandSnapshot.opponents`（`hand_track.py:149`）只包含**本手在局/已弃牌**的人，不包含坐着但没发牌的人。
- `LiveHandTracker._seat_meta`（`:309`）是每帧覆盖的缓存，不是可引用的名单；空名字帧还会把之前读到的名字覆盖成 `None`。
- 手牌记录里的 `seat_meta`（`hand_track.py:1438-1456`）只给「确实在局」的人；旁观、暂离、刚坐下没入池的人不会进记录。
- 没有 `table_roster` / `table_session` 字段，所以「当前桌动态」只能靠下一帧重新猜。

### 1.4 当前手、手牌落库、画像更新耦合在一个函数里

`poker_ocr/live.py::drain_advice()`（`:1424`）的顺序是：

```text
收建议 → take_finished() → _write_hand(finished) → _update_profiles(finished)
```

顺序是对的，但缺少三个协议：

1. **幂等标记**：手牌记录没有 `applied_at` / `profile_version`，画像更新失败后只能靠 `seen_hands` 去重，不知道哪一手没应用。
2. **事务边界**：手牌写成功、画像写失败时，下次启动不会自动补。
3. **partial 语义**：退出时 `_write_hand(current, partial=True)` 会落一条截断手牌，但 `_update_profiles` 不会被调用；重建工具/手牌库如果没有 `partial` 过滤，可能把半手当完整手。

### 1.5 手牌库是手动导入，且 live 建议上下文没带全

- 现在的链路是：`live` 写 `logs/live.states.jsonl` → `tools/export_live_hands.py` 导出 `hands/1023.hands.json` → 在 replay-console 里手动导入（`replay-console/README.md:232`）。
- `normalize_live_hand()`（`replay-console/replay/importer.py:353`）把对手压成 `villains`（按位置聚合），**丢掉 `seat_id` / `seat_meta` / 完整名单**（`_live_villains` `:439-492`）。手牌库想做「按玩家看行为」时没有稳定锚点。
- `advices` 虽然写进 `payload_json`，但只用于详情页展示（`service.py:638-675`）；没有进独立表，也没有和 `replay_decisions` 对齐。
- 线上建议只有 `opponent_reads`（`advice.py::Advice.to_dict` `:3284`），**没有 `table_stats` / `table_dynamics` / roster 快照**。
- replay 重跑只注入 `table_dynamics` 文本（`replay-console/replay/engine.py:128-129`），**不注入 `opponent_reads` / `table_stats`**。所以「线上建议」和「重跑建议」用的不是同一个上下文，A/B 不可比。

### 1.6 A/B 目前只是「多版本跑同一批」

- `replay_jobs` 支持多个 `version_ids`，对比视图按版本展示；这已经是一个可用的雏形。
- 但没有「实验」对象：没有假设、没有 A/B 数据集切分、没有指标口径、没有显著性判断、没有把「线上实际动作 / 结果 / 人工复盘结论」接进来。
- 现在的 A/B 是人工在 `docs/复跑-*.md` 里写结论，无法在手牌库里复现。

## 2. 目标模型

### 2.1 三条不变量

1. **未结束的手不是事实**：当前手、当前街动作只在内存；手结束才写手牌记录，才进入画像和手牌库。
2. **一手牌内桌况冻结**：同一手的翻前/翻牌/转牌/河牌看到同一份桌况快照；换手或换人后才重算。
3. **身份跨桌，桌况只取当前桌**：玩家统计可以跨桌累积；桌子动态只由当前桌名单派生。

### 2.2 分层

```text
┌──────────────────────────────────────────────────────────────┐
│ 事实层 Fact                                                   │
│   HandRecord v2（完整手牌 + roster + result + advice 快照）    │
│   HandObservation（每个玩家每手的机会/行动，可重建）             │
└──────────────────────────────────────────────────────────────┘
                              │ 派生
                              ▼
┌──────────────────────────────────────────────────────────────┐
│ 画像层 Profile                                                │
│   PlayerIdentity（全局 player_key + aliases）                  │
│   PlayerStats（lifetime + recent window，跨桌）                │
│   PopulationPrior（全场先验，用于冷启动/收缩）                   │
└──────────────────────────────────────────────────────────────┘
                              │ 按当前桌名单取
                              ▼
┌──────────────────────────────────────────────────────────────┐
│ 视图层 View                                                   │
│   TableRoster（当前在座：seat → player，逐帧更新）              │
│   TableDynamicsView（当前桌的聚合统计，每手结束/换人重算）        │
│   HandContext（决策点冻结的桌况/画像/桌风快照）                  │
└──────────────────────────────────────────────────────────────┘
                              │ 快照
                              ▼
┌──────────────────────────────────────────────────────────────┐
│ 实验层 Experiment                                             │
│   手牌库 → 决策点 → 线上建议 / 重跑建议 → A/B 实验 → 复盘结论    │
└──────────────────────────────────────────────────────────────┘
```

### 2.3 数据流

```text
视频帧
  │
  ▼
FrameState
  │
  ├──► RosterTracker（每帧：座位、名字、status、in_hand）
  │        └──► TableRoster（当前在座名单）
  │
  ▼
LiveHandTracker（当前手，内存）
  │
  ├──► 决策点
  │        ├── TableDynamicsView（从 TableRoster 派生，冻结）
  │        ├── OpponentReads（按本手在局对手）
  │        └── HandContext ──► AI 建议（带 context 快照）
  │
  └──► 手结束
           ├──► HandRecord v2（原子写）
           ├──► HandObservation（幂等，按 hand_uid）
           ├──► 画像聚合更新 + TableDynamicsView 失效
           └──► Outbox ──► 手牌库（replay-console / MySQL）
```

## 3. 核心重构

### 3.1 身份：去掉池后缀，全局合并

**目标**：`player_key = normalize_name(name)`，跨桌、跨 session 累积。`pool_key` 只留在 hand / observation 上做元数据。

具体改动：

| 位置 | 现在 | 改成 |
|---|---|---|
| `observations_from_hand()` | 每手算 `hand_pool` | 保留 `pool_key` 字段，但不再参与 key |
| `ProfileStore.update_hand()` | 同名跨池 → `key@pool` | 永远用 `name`；`@pool` 只在迁移时合并 |
| `ProfileStore._resolve_key()` | 先裸名，再 `name@pool` | 裸名 + aliases；不再回退到池键 |
| `ProfileStore.set_pool_key()` | 首手后固定 | 废弃/只记录 `last_pool`，不参与读 |
| `ProfileStore.pooled()` | 全量 | 保留为 `population_prior()`，只用于冷启动/收缩 |
| 统计结构 | `pool_key: str` | `pools: list[str]`（见过的池）+ `last_pool` |

迁移：

```python
# load() 时一次性折叠
for key, stats in list(players.items()):
    if "@" in key:
        base = key.split("@", 1)[0]
        merge(players[base], stats)
        del players[key]
```

注意：

- 现有 `data/opponents/profiles.json`（32 人 / 193 手 / `0.5/1-9max`）没有 `@` 键，迁移是 no-op；但要把 `schema_version` 升到 2，并保留 `pools`。
- **同名不同人**的风险要承认：没有平台 UID 时，只能靠 `session|seat_id` 别名 + 人工 merge/split。建议加 `identity_confidence`，并在 `opponents` 工具里提供 `--merge` / `--split`。
- **桌型/级别差异**：6max 和 9max 的位置统计不可直接混（`open_by_bucket` 的 EP/MP/LP 定义不同）。建议：
  - 总体指标（VPIP/PFR/3bet/AF）全局合并；
  - 位置相关指标优先取「同 table_size」子集，样本不足再回退全局，并在 `TableDynamicsView.source` 里标注。
- **池不是完全没用**：保留它作为「同级别先验」的过滤条件，但**不做硬隔离**。这符合你说的「跨桌无所谓」。

### 3.2 当前桌名单：`TableRoster`

新增 `poker_ocr/table_roster.py`（或放在 `hand_track.py` 里，但独立更清晰）：

```python
@dataclass(frozen=True)
class RosterSeat:
    seat_id: str
    player_key: str | None       # normalize_name(name)；None = 名字没读到
    display_name: str | None
    position: str | None
    status: str                  # playing/folded/buying_in/away/left
    in_hand: bool
    stack: float | None
    first_seen: str
    last_seen: str

@dataclass(frozen=True)
class TableRoster:
    seats: tuple[RosterSeat, ...]
    table_size: int
    version: str                 # 名单内容 hash，变化时递增
    updated_at: str

    def seated_keys(self) -> tuple[str, ...]: ...
    def in_hand_keys(self) -> tuple[str, ...]: ...
```

`RosterTracker`：

- 每个 `state.ok` 帧调用 `observe(state, hero_seat_id=...)`。
- **只在读到非空名字时覆盖**，避免空帧把名字擦掉。
- 占座判定：`status in ("playing", "folded")` 或 `in_hand=True`；`away` / `buying_in` / `left` 视为空座。
- 同一座位名字变化 = 换人：旧玩家 `last_seen` 收口，新玩家 `first_seen` 开始；同时打一条 `roster_event` 供复盘。
- `version` 由 `(seat_id, player_key, status)` 排序后 hash，名单一变就变。

两个 scope 要分清：

| scope | 内容 | 用途 |
|---|---|---|
| `table_roster` | 当前在座的所有人（含暂离/旁观） | 手牌库展示、桌子动态面板 |
| `hand_roster` | 本手实际发牌/在局的人 | 提示词里的桌况统计 |

**提示词默认用 `hand_roster`**：暂离的人不会行动，把他算进「这桌很松」会误导当前决策。`table_roster` 用于 UI 和「这张桌长期是什么样」的展示。

### 3.3 桌子动态：`TableDynamicsView`

新增 API：

```python
@dataclass(frozen=True)
class TableStats:
    scope: str                 # current_table / population_prior / mixed
    as_of: str
    window_days: int | None
    table_size: int
    players_seated: int
    players_in_hand: int
    players_known: int
    hands: int                 # **去重后的手数**，不是各玩家 hands 之和
    vpip: float | None
    pfr: float | None
    threebet: float | None
    limp: float | None
    fold_to_cbet: float | None
    fold_to_bet_flop: float | None
    fold_to_bet_turn: float | None
    fold_to_bet_river: float | None
    opportunities: Mapping[str, float]
    source: Mapping[str, str]  # 指标 → current_table / prior / fallback

class ProfileStore:
    def stats_for_keys(self, keys, *, as_of=None, window_days=90) -> list[OpponentStats]: ...
    def table_stats(self, roster, *, as_of=None, window_days=90) -> TableStats: ...
```

聚合规则：

1. **只取当前桌名单**：`roster.in_hand_keys()`，不是 `self.players` 全量。
2. **按机会加权**：沿用现在的 `vpip/preflop_opps` 口径，不按动作数。
3. **手数去重**：`hands = COUNT(DISTINCT hand_uid)`，不能把 6 个玩家各记一次再加总（现在 `pooled()` 用全局 `seen_hands`，会把「这 6 个人都不在」的手也算进来）。**P1 还没有观察表**时用 `max(stats.hands)` 作近似（下界），并标注「近似样本」；精确值等 P5。
4. **最近窗口**：默认近 90 天 / 每人最近 300 手；窗口内样本不足时回退 lifetime，并标 `stale=True`。
5. **冷启动先验**：当前桌没人有画像时，`scope="population_prior"`，用全场先验（可按同池/同人数加权），提示词明确写「全场先验，不是本桌数据」。
6. **未知玩家**：`players_known / players_in_hand` 要显示覆盖率；未知玩家不伪造个人数据，必要时用先验收缩，但标注。
7. **不调模型、不读文件**：纯内存聚合，目标 <1ms。

重算时机：

- 手结束、观察应用之后；
- `TableRoster.version` 变化（换人/离桌）；
- 换手时（新一手的 `hand_roster` 不同）；
- **手内不重算**：同一手的所有街看到同一份 `TableStats`，避免翻前/翻牌桌况不一致。

提示词改动（`render_table_stats_zh`）：

```text
## 当前牌桌数据（本手在局 6 人，4 人有画像，近 90 天）
4 人 / 312 手：VPIP 38%｜PFR 12%｜3-bet 4%｜溜入 21%｜对 c-bet 弃 62%
面对下注弃：翻牌 41%｜转牌 55%｜河牌 63%
整体：松、被动
当前桌可剥削：...
```

冷启动：

```text
## 当前牌桌数据（本手在局 6 人，0 人有画像）
样本不足，以下为全场先验（同级别/同人数，312 人 / 8,421 手）：
VPIP 31%｜PFR 9%｜...
```

明确删掉「可能跨桌」这种自我免责；模型需要知道这是当前桌，还是先验。

### 3.4 提交协议：当前手 → 手牌 → 观察 → 画像

```python
def on_hand_finished(hand, roster, advices, context):
    record = build_hand_record_v2(hand, roster, advices, context)

    # 1) 事实先落盘（原子、幂等）
    store.append_hand(record)                 # uid 唯一

    # 2) 派生观察（幂等；崩溃后可重放）
    store.apply_observations(record)          # 写 hand_observations + 更新 players 缓存

    # 3) 视图失效 + 画像缓存
    table_view.invalidate(record.uid)
    profile_cache.save()                      # 节流，失败不阻塞

    # 4) 手牌库 outbox（异步、可重试）
    outbox.enqueue(record)
```

关键点：

- `append_hand` 和 `apply_observations` 用同一个 SQLite 事务；`applied_at` 为空表示「手牌已写、观察未应用」，启动时补。
- `hand_observations` 的唯一键 `(hand_uid, player_key)`，重复应用不会重复计数。
- `partial` 手牌写 `applied_at=NULL`，永不进入统计；只用于调试/复盘。
- 当前手可选每 N 秒写一个 `current_snapshot` 到日志（不是事实），崩溃后能解释最后发生了什么，但不参与统计。
- outbox 成功 ack 后写 `library_synced_at`；失败保留，指数退避，超过 N 次进 `dead_letter`。

### 3.5 存储：SQLite 事实库 + JSON 缓存

为什么不继续只用 `profiles.json`：

- 需要 **as-of 查询**（A/B 重跑要用「当时」的画像）；

- `seat_meta` 保留，兼容旧导入器；新代码优先读 `table_roster`。

### 4.3 上下文快照：让「线上」和「重跑」可比

`replay_versions` 增加两个字段（`006`）：

```sql
ALTER TABLE replay_versions
  ADD COLUMN context_mode VARCHAR(16) NOT NULL DEFAULT 'none'
    COMMENT 'none/snapshot/recompute',
  ADD COLUMN table_stats_mode VARCHAR(16) NOT NULL DEFAULT 'none'
    COMMENT 'none/snapshot/recompute';
```

- `snapshot`：从 `replay_live_advices.context_json` 取当时的 `table_stats` / `opponent_reads` / `table_dynamics`。默认用于 live 手牌。

`engine.execute_unit()` 改动：

```python
sit = build_situation(
    decision.snap,
    table_dynamics=version.get("table_dynamics") or "",
    opponent_reads=context.opponent_reads,
    table_stats=context.table_stats,
)
```

否则 A/B 比的是「有画像的线上」vs「没画像的重跑」，结论一定失真。

## 5. A/B 与复盘分析

### 5.1 「A/B 集」的两种含义都要支持

| 类型 | 含义 | 做法 |
|---|---|---|
| **A/B 变体** | 同一批决策点，A 版本 vs B 版本 | 一个 job 带两个 `version_id`，成对比较 |
| **A/B 数据集** | A 集调参、B 集留出验证 | 按 `hand_uid` 分层切分，冻结手牌集合 |

两者可以组合：实验 = 数据集切分 + 变体对 + 上下文模式。**不要按决策点切分**，同一手牌的翻前/翻后必须落在同一侧，否则泄漏。

### 5.2 实验模型

创建实验时：

1. 用当前手牌库筛选出候选 `hand_ids`；
2. 按 `hand_uid` 的 hash 分层（street/position/结果）切 `dev/holdout`；
3. 冻结 `hand_ids + fingerprint`；
4. 跑 A/B 时生成一个 `replay_jobs`，带两个版本、`repeat_count>=3`；
5. 结果按 `(decision_id, version_id)` 配对。

### 5.3 指标口径

不要用「实际动作」当 ground truth——它只是人类行为，不是最优解。建议分三层：

**A. 与人类行为的一致性（便宜、可大规模）**

| 指标 | 定义 |
|---|---|
| `agreement` | `same / (same + action + size)`，来自 `replay_results.bucket` |
| `action_agreement` | 动作类型一致（call/check/bet/raise/fold） |
| `size_agreement` | 金额在容差内（如 ±0.5BB 或 ±10%） |
| `deviation_rate` | 动作或尺寸不一致的比例 |
| `violation_rate` | 命中硬规则审计标签的比例 |

**B. 模型自身稳定性**

| 指标 | 定义 |
|---|---|
| `consistency` | 同一决策点 `repeat_count` 次的多数占比 |
| `flip_rate` | 重复之间动作类型翻转的比例 |
| `fallback_rate` | `source != model` 的比例 |

**C. 结果与人工结论（少量、高价值）**

| 指标 | 定义 |
|---|---|
| `hero_net` | 手牌级盈亏（BB），只作为噪声标签 |
| `review_good/bad/unsure` | `replay_decision_marks` |
| `dispute_rate` | `bad / (good + bad)` |
| `context_coverage` | 有完整 context 的决策点比例 |

展示要求：

- 每个指标带 **n 和 95% CI**（paired bootstrap，按手牌重采样，不按决策点，避免同手相关）；
- n < 30 手时只显示描述统计，不写「显著」；
- 按街/位置/spot/对手类型分桶时，同时显示每桶 n；
- 明确写「一致性不是正确率」。

### 5.4 复盘工作流

1. **手牌库列表**新增列：`建议数`、`线上建议版本`、`A/B 重跑`、`hero_net`、`复盘状态`。
2. **手牌详情**：
   - 左：实际行动街（现有）；
   - 中：每个决策点的线上建议 + 重跑 A/B 结果并排；
   - 右：上下文面板（当前桌统计、对手 reads、桌风、roster）；
   - 底：逐决策点标记 `good/bad/unsure` + 标签 + 备注。
3. **自动标签**：
   - `advice_differs_actual`
   - `size_differs`
   - `hard_rule_violation`
   - `result_loss`
   - `unknown_opponent`（画像覆盖不足）
   - `context_missing`（没有 table_stats/reads）
4. **复盘看板**：
   - 筛「只看分歧」「只看亏损」「只看未知对手」「只看河牌大注」；
   - 按版本/实验/街/位置聚合；
   - 导出 CSV/Markdown，直接贴 `docs/复跑-*.md`。
5. **结论回写**：`replay_decision_marks` 是逐决策点的人工结论；`replay_marks` 继续做手牌级收藏/标签。两者不要混。

## 8. 测试与验收

### 8.1 单元测试

- 身份：同名跨池合并、`@pool` 迁移、temp key → 名字合并、同名不同人 split。
- Roster：名字空帧不覆盖、换人检测、`table_roster` vs `hand_roster`。
- TableStats：只含当前名单、手数去重、窗口回退、冷启动先验、覆盖率。
- 冻结：同一手翻前/翻牌拿到的 `TableStats` 相同；换手后变化。
- HandRecord v2：v1 兼容、`action_index` 对齐、partial 不统计。
- 幂等：同一 `hand_uid` 重复 `update_hand` 不重复计数；outbox 重复 POST 不重复入库。
- as-of：`as_of` 在两手之间时，只统计之前的手。
- 提示词 golden：当前桌标题、冷启动标题、无「可能跨桌」。

### 8.2 集成测试

- `live` 模拟一手：决策点 → 手结束 → SQLite → outbox → mock ingest → 手牌库行/建议行。
- replay：导入 v2 手牌 → 建决策点 → 用 `snapshot` 上下文重跑 → 结果 `facts_json` 含 reads/stats。
- A/B：两版本跑同一批 → 指标配对 → 导出。
- 迁移：`001`–`006` 在空库/已有库上都能跑。

### 8.3 验收标准

1. 换桌后，提示词里的「当前牌桌数据」只包含当前桌名单；不再出现「可能跨桌」。
2. 同一手内，翻前/翻牌/转牌/河牌的桌况快照一致。
3. 手结束后 ≤5 秒，手牌库能按 `uid` 查到，且详情页能看到线上建议 + 上下文。
4. 同一手重复写入/重复导入不产生重复行。
5. A/B 实验能回答：「A 版本在 B 集上的 agreement / violation / review 结论是否优于 baseline，n 和 CI 是多少」。
6. 从手牌记录重建画像，和线上画像在允许误差内一致。

## 9. 风险与待确认

### 9.1 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 同名不同人 | 统计串人 | `session|seat` 别名、人工 merge/split、`identity_confidence`；不要假装 100% 准 |
| OCR 名字抖动 | 临时键/重复玩家 | 现有 alias 机制 + roster 只在非空时覆盖 + 人工修正 |
| `hero_net` 读不准 | 复盘结果偏差 | 标记 `source`；结果只做噪声标签，不做唯一判据 |
| 上下文缺失 | A/B 不可比 | `context_coverage` 指标；缺失时显式 `none` 并分桶 |
| 手牌库离线 | 数据滞后 | outbox 重试 + 本地 SQLite 兜底 |
| 统计显著性 | 小样本过度解读 | n/CI 强制展示；n<30 不下结论 |
| 迁移破坏旧数据 | 画像丢失 | 备份 + `schema_version` + 可重建 |
| 窗口选择偏差 | 近期样本少 | 窗口/ lifetime 双显示；回退时标 `stale` |

### 9.2 需要你确认的决策

1. **身份**：全局按名字合并，接受同名风险？还是保留「同名 + 池」作为弱区分，仅当证据不足时合并？
   - 推荐：全局合并；池只做先验，不做身份。
2. **桌况 scope**：提示词用「本手在局的人」还是「当前在座所有人」？
   - 推荐：本手在局；在座名单用于 UI。
3. **窗口**：近 90 天 / 每人 300 手，是否合适？你打牌频率高的话可以改成 30 天。
4. **A/B 方式**：先离线重跑（可控、可复现），还是也要线上分流（实时对比）？
   - 推荐：先离线成对 A/B；线上分流成本高、噪声大，等离线稳定再说。
5. **手牌库同步**：outbox → HTTP ingest 是否可接受？还是希望 live 直接写 MySQL？
   - 推荐：outbox + HTTP；live 不依赖 DB。
6. **位置统计**：6max/9max 的位置指标是否要分开？还是全部合并？
   - 推荐：总体合并；位置指标同 table_size 优先，不足回退全局并标注。

## 10. 最小可行版本（如果只想先做一件事）

**P1：把桌子动态从「全库」改成「本手在局对手」**，不改库、不改记录格式：

```python
# live.py，替换 table_stats = self.profile_store.pooled()
stats = self.profile_store.stats_for_opponents(point.opponents)
table_stats = self.profile_store.pooled_for_stats(stats)
```

```python
# advice.py
lines = [f"## 当前牌桌数据（本手在局 {stats.players} 人，"
         f"{stats.hands} 手）"]
```

同时把 `render_table_stats_zh` 的「可能跨桌」删掉。

这一步的收益：

- 模型不再看到别的桌的数字；
- 不需要迁移 `profiles.json`；
- 现有测试只需改标题/口径；
- 为后续 roster / SQLite / A/B 留出干净的接口。

代价：

- 暂时不包含「坐着但没发牌」的人；
- 手数仍只能用 `max(players[*].hands)` 近似（同一手多人重复、不同玩家在场次数不同），需要 P5 的观察表才能精确去重；
- 窗口/冷启动先验还没有，样本少时仍可能波动。
