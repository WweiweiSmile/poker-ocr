### 为什么 Q25 改判（保留推理，防以后反复）

书给的是**默认动作与尺寸**，实测给的是**这套默认在本池的兑现率**。之前写成"尺寸归实测"，结果是同一节点两套数字互相覆盖，等于又回到 2026-11-01 的"两套规则同场"。改成书优先后，实测只剩一个合法位置：`exploit` 层的偏离系数，且必须写明触发条件（例如 c-bet 用 1/3 仅在对手弃牌率显著低于 55% 时）。

### 为什么不走 CFR（Q29 的理由，写进代码注释防复活）

1. CFR 收敛的是「对手也按频率平衡」的纳什策略；本池 3-bet 6.2%、limp 45.2%、59.4% 是松系（`data/opponents/profiles.json`，171 人 / 7866 手），假设不成立。
2. 验证能力不足：案例集 13 个、`FREQ_MIN_N = 15`（`replay-console/replay/scoring.py:24-28`）→ 覆盖率恒 0，换提示词好坏测不出，更测不出求解器。
3. 抽象质量决定解质量，单 spot GPU 小时级，是维护子系统不是跑算法。
4. `gto/` 2026-11-05 已整体移除（`AGENTS.md:80`）。

## 2. 三层结构

```
事实层（代码算，精确/半精确）
  └─ 谓词快照 facts_snapshot(sit) → {street, hero_position, limpers_before, spr, …}
规则层（poker_ocr/rules/ledger/*.json，必须带 preconditions，按 slot 分工）
  └─ match_rules(facts) → 命中项；intent/size/why 各取一条，拼成两行
兜底层（现有散装经验，只在规则零命中时出现）
  └─ 逐步删减，最后只剩「无事实可用」的场景
```

### 2.1 冲突的三条铁律

- 规则与事实矛盾（如位置事实 vs 规则前提）→ **事实赢**，规则不渲染。
- 规则之间：按 §2.2 槽位判定，同槽位前提有交集即判定失败，强制作者拆前提或声明 `coexist_with`。
- 规则与实测冲突 → 书赢默认值；实测只能进 `exploit` 层并带具名触发条件。

### 2.2 槽位模型（Q33）

| slot | 回答 | 每个命中点最多 |
|---|---|---|
| `intent` | 要不要下注 / 跟 / 弃 / 加注 | 1 |
| `size` | 下多大（只能引用 `rule_params`，禁止字面数字） | 1 |
| `why` | 为什么（≤40 字，拼在动作行后） | 1 |

判定（`tools/export_rules.py --check` 实现）：

1. **同 slot + 前提有交集** → 失败，除非该规则声明 `coexist_with: [<id>]`（必须双向声明）。
2. **不同 slot** → 允许同时命中，各取一条，渲染成动作行 + 尺寸行。
3. **同 slot 多条都合法** → 取前提条数最多者（更具体优先）；打平即失败，要求补谓词。
4. 交集判定不靠人工：对两条规则的**公共谓词**做笛卡尔积枚举（谓词空间有限，<100 条规则，毫秒级），任一组合两边都成立即算交集。

三个例外，写进 loader 注释：

- `po.cbet.hu`（要不要下注）带默认尺寸 `cbet_size_hu`，与 `po.size.texture`（牌面尺寸）在 size 维度相撞 → 双向 `coexist_with`，**牌面规则优先**；牌面未命中才退回默认半池。这正是书 p35「按牌面选尺寸」的本意。
- `ex.*` 三条是 `intent` 槽的修正层，前提里带 `opponent_archetype`，与基础规则天然有交集 → **不进普通匹配**，由 `render_rules_zh` 在命中基础规则后按画像追加一行修正。
- 零命中不渲染、不占空行；命中项为空时整段消失。

## 4. 数据模型

### 4.1 一条规则

```json
{
  "id": "pf.iso.limp",
  "version": 1,
  "slot": "intent",
  "street": "preflop",
  "node": "隔离 1–2 个溜入者",
  "preconditions": [
    {"fact": "limpers_before", "between": [1, 2]},
    {"fact": "raises_before", "eq": 0},
    {"fact": "in_position", "eq": true},
    {"fact": "hand_in_open_range", "eq": true},
    {"fact": "hero_hand_tier", "not_in": ["small_pair"]}
  ],
  "action": "raise",
  "size": {"table": "rule_params", "name": "iso_size_per_limper"},
  "coexist_with": [],
  "why": "有位置惩罚溜入者，翻后可 c-bet 也可过牌",
  "source": {"book": "Little Green Book", "page": 23, "status": "verbatim"},
  "confidence": "book",
  "verified": false
}
```

字段硬约束（loader 校验，违反即启动失败）：

- `preconditions` 非空、至少 2 条、必须含 `street`；谓词键必须在 §5 白名单内。
- `slot ∈ {intent, size, why}`；`intent` 必须给 `action`，`size` 必须给 `size` 引用，`why` 只给 `why`。
- `action` ∈ 现有 `options` 的 action 集合，不允许出现模型选不到的动作。
- `size` 只能引用 `poker_ocr/strategy_tables.py:135 table(kind, name, profile)` 可解析的路径；**禁止字面数字**（书里的数在 `rule_params.json`）。
- `why` ≤40 字，`node` ≤30 字。
- `source` 必须给 `book` 或 `measured`，`status ∈ {verbatim, rebuilt}`；`rebuilt` 要在 `docs/规则台账-首批20条.md` 写明重建依据。
- `verified: false` 照常渲染，但 `confidence ∈ {book, inferred}`，不能冒充实测。
- `coexist_with` 必须双向；同 slot 前提有交集且无白名单 → 失败。

### 4.2 谓词算子

`eq` / `in` / `not_in` / `between` / `gte` / `lte` / `exists`。缺失事实一律 **fail open 到「不命中」**——前提不满足就不渲染，绝不抛异常。

| `hero_hand_tier` / `hand_label` | `ground_truth` | 精确 |

## 6. 渲染与预算

`render_rules_zh(sit)` 输出**最多两行**（intent + size），命中 why 拼在动作行括号里：

```
规则: 单挑翻牌你先行动、对手只跟注 → 高频下注 [书 p29-30]
尺寸: 牌面中等连接 → 2/3 池 [书 p35]
```

- 命中 ≤5 条，渲染 ≤2 行 + 可选的画像修正 1 行；整段 ≤800 字（含标题）。
- 每条用 `refs.fact(text, {"ns": "rules", "path": "R12"})` 登记，看板可跳转。
- 零命中时整段不出现（不是空行）。
- 只命中 intent 不命中 size：尺寸交回现役 `aggression.py` 默认值，不渲染半截建议。

**净减口径**：台账上线的那次改动，必须同时删掉被替代的散装句（`aggression.py:39/45-46/47-48`、`preflop.py:291`、`hand_type.py:15-50` 片段，合计约 1900 字）；`len(system) + len(user)` 相对于 `lean-zh-2026-11-16.3` 的 fixture **不增加**，且 system 教学段字符数下降 ≥1000 字。

## 7. 多街计划（plan as fact）

用户 m00030 的核心诉求：不能计划翻牌 CR 却在转牌继续下注把自己打到强牌上。

- 翻牌决策时产出 `plan`：`{"plan_id": "...", "line": "bet-bet-check", "streets": 3, "created_at": "..."}`。
- 存放：`Advice` 增加 `plan` 字段；同一手内由 `poker_ocr/live.py` 的 `_last_advice` 携带（已有 `hand_id` 相等判断，`poker_ocr/live.py:1936-1944`），并落到 `logs/live.states.jsonl`。
- 后续街：`render_rules_zh` 段头加一行「本手计划：翻牌下注 → 转牌下注 → 河牌过牌」（≤30 字），匹配时把 `previous_line` 作为谓词。
- 偏离：当前动作与计划冲突时，`Advice` 记 `deviation = {"from": "bet-bet-check", "at": "turn", "reason": "..."}`，**先只记日志不阻断**；连续 100 手统计偏离率再决定是否硬拦。
