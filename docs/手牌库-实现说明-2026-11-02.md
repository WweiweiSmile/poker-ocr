## 1. 怎么重启/启用

### 1.1 必须重启进程

这次改了 Python 代码和前端构建产物。**已经在跑的 replay-console（8010）和
live 进程不会自动加载新代码**：

1. 停掉旧的 `replay_api.py` / uvicorn（8010）；
2. 重新 `cd replay-console && ../nv replay_api.py`；
3. 重新启动 live。

前端 `dist/` 已经重新构建；重启后浏览器刷新即可。

### 1.2 live 自动入库

默认就会开启（`.env.example` 已加）：

```bash
HAND_INGEST_MODE=auto
HAND_INGEST_URL=http://127.0.0.1:8010
# HAND_INGEST_TOKEN=...
HAND_INGEST_INTERVAL=2.0
HAND_INGEST_BATCH=20
HAND_INGEST_TIMEOUT=20
HAND_INGEST_MAX_FAILURES=8
HAND_INGEST_BACKOFF=2,5,15,60,300
```

行为：

- 手牌结束 → 先写 `data/hand_outbox/pending/<uid>.json`（不阻塞打牌）；
- live 内嵌线程自动 `POST /api/hands/ingest`；
- 成功 → 移到 `sent/`；失败留在 `pending/`，指数退避；
- 手牌库没开 → 继续留在 pending，下次恢复/重启自动补；
- `HAND_INGEST_MODE=off` 可回到「只写 outbox」；
- `tools/sync_hand_outbox.py` 仍保留，用于回填/人工重试。

启动日志会打印：

```text
[手牌] outbox .../data/hand_outbox
[手牌] 自动入库 http://127.0.0.1:8010（auto，每 2s，批量 20）
```

### 1.3 数据库迁移

replay-console 启动时会自动迁移。新增：

```text
000_migration_version_width.sql   # 迁移版本列 20 → 64（新增文件名较长）
008_live_prompt_and_flags.sql     # prompt/raw/reason_full + timeline/flags
009_hand_sets.sql                 # 手牌集 + 实验新字段
010_pair_reviews.sql              # 成对偏好
011_version_channel.sql           # prod/candidate/archive
```

> 为什么有 000：`replay_schema_migrations.version` 原来是 `VARCHAR(20)`，
> `008_live_prompt_and_flags` 这样的文件名会插入失败。000 先把它放宽到 64，
> 再应用后续迁移。已有库里如果 008 的列已经加上但迁移记录没写入，需要像本次
> 一样补一条 `(version, checksum)` 记录；新库直接按顺序跑即可。

本次已在共享 MySQL 上应用完 000–011。若你换库，启动新 replay-console 会自动迁移。

## 2. 线上 prompt 捕获

### 2.1 代码落点

`poker_ocr/advice.py`：

- `Advice` 新增字段：
  `prompt_system`、`prompt_user`、`prompt_sha256`、`raw_response`、
  `response_sha256`、`reason_full`、`facts`、`model_params`、
  `captured_at`、`prompt_missing`、`prompt_missing_reason`、`attempt`；
- `advise()` 在 `build_messages()` 之后、模型调用之前保存 system/user；
- `complete` 返回后保存原始 JSON；
- 模型失败（AIError）仍保留已经发出去的 prompt；
- 未配置模型 / 0 对手异常帧不构建 prompt，显式 `prompt_missing=True`；
- `reason` 仍保留 40 字短版，新增 `reason_full` 存全文；
- `prompt_sha256 = sha256(system + "\n---\n" + user)`；
- 新增 `advise(..., prompt_override=(system,user))`，给 A/B baseline 重放旧
  prompt 使用；仍复用同一套选项校验/legacy 解析。

### 2.2 落库

`replay_live_advices` 新增列（008）：

```text
prompt_system, prompt_user, prompt_sha256, raw_response, response_sha256,
reason_full, facts_json, model_params_json, prompt_missing,
prompt_missing_reason, captured_at, attempt
```

`poker_ocr/live.py` 的 `_write_hand()` 仍把 `advices` 附在手牌 JSON 里，
`ingest` 时：

- 写 `replay_live_advices`（带 prompt）；
- 同时保留 `payload_json` 里的 advices（当前为了兼容/追溯有重复，见 §7）。

> 旧手牌没有 prompt：`hand_prompt()` 会返回 `promptMissing=true` +
> `legacy_no_prompt`，不会伪造空 prompt。需要旧手牌的 prompt 只能重跑重建，
> 并标 `reconstructed`，不能当作线上原文。

### 2.3 看 prompt

手牌详情底部「导入时的 AI 建议」有「看回放 / Prompt」；或：

```text
/hands/{id}/replay?mode=waterfall
/hands/{id}/replay?mode=table
```

在决策点行点「看 Prompt」→ Drawer：

- System（原文）
- User（原文）
- Raw（模型原始响应）
- Reason（完整理由）
- Facts（事实快照）
- Context（桌况/画像/桌风）

顶部显示 `promptSha256`、字节数、token、耗时、版本、是否缺失。

## 3. 手牌库：深挖与筛选

### 3.1 新增列

手牌列表：

- **深挖分**：0–100，启发式排序，不是 EV；
- 标记数：`AI_DIFF` / `AI_FALLBACK` / `DATA_WARN` / `BIG_POT` /
  `RIVER_BIG` / `AB_FLIP` / `PROMPT_MISSING` / `PARTIAL` 等；
- 原有质量、决策点、最近重跑不变。

### 3.2 筛选

新增：

```text
flags=AI_DIFF,AB_FLIP       # 多个标记同时满足（AND）
minScore=50                 # 最低深挖分
```

手牌库顶部有「值得看」「A/B 翻转」「兜底建议」三个快捷视图（会重置当前筛选）。

后端：

- `flag_mask` 位图（`BIGINT`）用于 SQL 过滤；
- `flags_json` 存每个标记的可读原因；
- `review_score` 物化列，ingest/实验后更新；
- `review_score` 排序字段：`sort=review_score`。

### 3.3 标记口径

| 标记 | 触发 |
|---|---|
| `AI_DIFF` | bucket != 一致，或 option kind 与实际动作不同 |
| `AI_FALLBACK` | 建议 source != model |
| `LOW_CONF` | confidence < 0.5 |
| `DATA_WARN` | 严重警告（异常/不可靠/矛盾/断裂/缺失/0 对手）或 approx/invalid |
| `BIG_POT` | 最大底池 ≥ 50BB 或最小 SPR ≤ 2 |
| `RIVER_BIG` | 河牌底池 ≥ 30BB 且有 bet/raise/allin |
| `UNKNOWN_OPP` | 至少 2 名在局对手无画像 |
| `AB_FLIP` | 最近一次实验 A/B 动作/金额不同（实验完成后回写） |
| `PROMPT_MISSING` | 模型建议没有 prompt 原文 |
| `PARTIAL` | partial=1 |
| `INVALID` | 重建 invalid |
| `SHOWDOWN` | 有摊牌/秀牌 |
| `MULTIWAY` | 本手最多 ≥4 人 |
| `BOMB_POT` | 爆炸底池 |

深挖分权重：`AI_DIFF 30 + FALLBACK 20 + DATA_WARN 15 + BIG_POT 15 +
RIVER_BIG 10 + UNKNOWN_OPP 10 + AB_FLIP 25 + REVIEW_BAD 20 + LOW_CONF 10`，
封顶 100。UI hover 显示原因。

已入库的旧手牌可用（不调模型）：

```bash
nv tools/backfill_hand_enrichment.py --dry-run
nv tools/backfill_hand_enrichment.py --limit 200
```

本次已对共享库的 70 手导入手牌跑了 backfill；旧手牌的 `AI_DIFF` 等标记现在
可用了，但因为旧记录没有 prompt，会带 `PROMPT_MISSING`。

> 注意：`DATA_WARN` 不把「部分对手筹码缺失」这类常见 warning 全算进去，
> 只算严重异常 + approx/invalid，避免每手都 15 分。

## 4. 回放：瀑布流 + 牌桌

### 4.1 统一时间线

`replay/timeline.py`：

- 输入 `row + HandAnalysis + replay_live_advices`；
- 输出 `ReplayTimeline`（`frames[]`）；
- 帧类型：`hand_start` / `street_start` / `action` / `decision` /
  `showdown` / `hand_end`；
- 决策点按 **全局 action_index** 插到对应 action 之前；
- action 的 `amount` 是「本街加到总额」，`delta` 由该座本街已投入反推；
- 底池优先用 `pot_start`，筹码优先用 roster/start_stacks；
- 缺失金额/筹码/对账失败 → `derived=true` + `warnings`，不猜；
- 旧手牌没有 `table_roster` 时用 `villains`（位置聚合）兜底。

> 同时修正了 `replay/decisions.py` 的 `action_index` 口径：之前是「本街第几个
> 动作」，现在与 live 的 `Advice.action_index` 一致，是「整手牌第几个动作」。
> `CURRENT_RECONSTRUCT_VERSION` 从 `recon-3` 升到 `recon-4`；旧决策点会按新
> 版本重建，旧行保留但查询只取当前版本。

### 4.2 API

```text
GET /api/hands/{id}/replay
GET /api/hands/{id}/advices/{adviceId}/prompt
```

`replay` 优先读 ingest 时物化的 `timeline_json`；没有就现场 `build_timeline()`。
`prompt` 懒加载，列表/回放不一次拉全部大字段。

### 4.3 瀑布流

`/hands/:id/replay?mode=waterfall`：

- 左/上：播放控件、速度、决策点暂停；
- 中：事件流，从翻前到河牌；
- 每个决策点就地展开 option/reason，按钮打开 Prompt；
- 自动滚动跟随；点击行跳帧；
- 键盘：空格播放/暂停，←/→ 上/下一帧，P 打开 prompt；
- 旧手牌没有 prompt 时显示「prompt 缺失」而不是空白。

### 4.4 牌桌

`/hands/:id/replay?mode=table`：

- 9 个固定座位锚点（`hero/lowL/.../topR`）；旧记录按位置近似映射；
- 中央公共牌/底池；每个座位名字/位置/后手/本街下注/动作；
- 「下一帧」按语义事件推进（action/decision），不是视频帧；
- 决策帧弹 AI 气泡，可点 Prompt；
- 右上角「推算」标记来自 timeline 的 `derived`；
- 支持上一帧/下一帧/播放/暂停/街跳转/速度/决策点暂停。

> 牌桌是语义回放，不默认保存整段视频；需要视频关键帧是后续 P5。

## 5. 手牌集与 A/B

### 5.1 手牌集

入口：

- 左侧「手牌集」→ 新建；
- 手牌库勾选多手 → 底部「加入手牌集」→ 选集合；
- 手牌集详情可移除、冻结 revision、直接「用这个集合跑 A/B」。

数据：

```text
replay_hand_sets        id/name/description/purpose/revision/frozen_at
replay_hand_set_items   set_id/hand_id/fingerprint/role/priority/expect_json/note
```

角色：`golden/regression/exploration/negative`；`priority=0` 是 P0。
`expect_json` 可放断言，例如：

```json
{"assertions":[
  {"type":"option_kind","value":"call"},
  {"type":"not_option_kind","value":"fold"},
  {"type":"amount_range","min":10,"max":14},
  {"type":"reason_contains","value":"赔率"},
  {"type":"stable_across_repeats","value":true}
]}
```

支持断言：`option_kind`、`not_option_kind`、`option_id`、`amount_range`、
`reason_contains`、`reason_not_contains`、`stable_across_repeats`。
未实现的 `facts_contains` 在 UI/文档中暂不承诺（后续可加）。

### 5.2 从手牌集创建实验

手牌集详情 →「用这个集合跑 A/B」→ 跳到 `/experiments?handSetId=...`，
弹窗已预选集合；选 baseline/variant、重复次数、改动类型后创建。

创建时：

- 读取 set 当前 revision；
- 按 `hand_id + fingerprint` 复制到 `replay_experiment_hands`；
- 之后改集合不影响旧实验；
- A/B 默认只用 `exact` 决策点（approx 会混噪声）。

### 5.3 baseline prompt 模式

`replay_experiments.baseline_prompt_mode` 默认 `stored`：

- baseline 版本：从 `replay_live_advices` 取该决策点的 `prompt_system/user`，
  通过 `advise(prompt_override=...)` **原样重放**；
- variant 版本：用当前代码 `build_messages()` 重渲染；
- 找不到线上 prompt → 自动退回 `rerender`（结果 `facts.promptSource=rerender`），
  不会伪造；
- 这样改 prompt/事实后，比较的是「旧文本 vs 新文本」，不是「新代码+配置 A vs
  新代码+配置 B」。

> 如果改动同时改了选项集合/金额映射，旧 prompt 里的 option id 可能和新解析器
> 不一致；这时应把 experiment 标 `changeScope=mixed` 或改用 `rerender`/旧服务，
> 不要把解析失败当成模型变差。

### 5.4 成对复盘

实验详情 →「成对复盘」：

- 每行一个决策点：实际动作、A、B、自动差异、P0、人工偏好；
- 按钮：A 更好 / B 更好 / 一样 / 不确定；
- A/B 侧显示多数派 option/reason、重复次数、稳定性；
- 每侧「Prompt」打开 A/B 的 system/user/raw 并排对照（第一版不做逐行高亮）；
- 过滤：全部 / 有差异 / 未复盘 / P0；
- 顶部统计：配对数、有差异、A wins、B wins、P0 回归；
- 「实验结论」卡：adopt / reject / iterate / inconclusive + 一句话结论；
  adopt 时把 variant 标 `prod`，旧 prod 标 `archive`。

API：

```text
GET  /api/experiments/{id}/pairs?only=changed|unreviewed|p0
POST /api/experiments/{id}/pairs/{decisionId}/review
POST /api/experiments/{id}/outcome
```

人工偏好存 `replay_pair_reviews`，与 `replay_decision_marks`（good/bad/unsure）
分开：一个回答「这次改动 A/B 谁更好」，一个回答「这个决策本身好不好」。

### 5.5 P0 回归

`experiment_pairs` 会：

- 读 `replay_hand_set_items.expect_json`；
- 对 A、B 分别跑断言；
- **A 全过且 B 有失败** 才算 `p0Regression`；
- 汇总 `p0Regressions`；成对页红色统计。

## 7. 已知边界与未做项

按优先级：

1. **截断手牌（partial）仍不会自动入库**：退出时 `_write_hand(partial=True)`
   只写 JSONL，不进 outbox；最后一手如果没等到换手，手牌库看不到。
   建议后续加 `--hand-outbox-partial` 或 journal 恢复。
2. **新 live 手牌的结果/hero_net 还没有自动算**：`HandRecord` 里没有稳定的
   `hero_end_stack`，目前手牌库结果仍是 `unknown`；旧记录也缺。需要 live 在
   手牌结束时把最后后手传进来。
3. **旧手牌没有 prompt**：只标 `prompt_missing`，不能精确回填；重跑得到的
   prompt 只能标 reconstructed。
4. **牌桌筹码是推算的**：动作帧的 stacksAfter 依赖 roster/start_stacks；缺失时
   `derived=true`，UI 显示推算，不保证每一帧都精确。决策帧优先用 snapshot。
5. **没有实时 prompt 窗口**：打牌时仍只在终端看建议；SSE/本地 inspector 是
   P5。当前看 prompt 是赛后回放。
6. **没有视频关键帧**：牌桌是语义帧，不是视频播放器。
7. **没有多用户鉴权**：仍是 `user_id=0`、127.0.0.1 单用户；表结构预留。
8. **prompt/advices 在 `payload_json` 与 `replay_live_advices` 里有重复**：
   第一版为了兼容保留；后续可在 ingest 时从 payload 剥掉 prompt/raw，只留
   `prompt_sha256`，减少存储。
9. **A/B 不会自动触发**：改代码后仍需手动创建/运行实验；没有 CI gate/自动发布。
10. **`facts_contains` 断言未实现**：当前支持动作/金额/理由/稳定性；事实断言
    需要再补。
11. **手牌集初始 revision**：创建时就带 handIds 时 revision 会从 1 增到 2；
