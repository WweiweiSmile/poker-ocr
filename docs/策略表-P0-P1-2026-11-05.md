`range_flow` 与 `fold_equity` 里原本写死 26 张表、约 150 个数字，决定了「对手范围

的模型**推导出一套 v1，用 profile 切换，默认仍是 v0（行为零变化）。

不是靠肉眼比对，是两道路检查：


第 2 道是有必要的：`--check` 只能证明「模块 = JSON」，证明不了「JSON = 改动前的值」。
JSON 是在改代码**之前**从常量导出的，加上第 2 道检查，整条迁移才闭合。

## 2 P1：v1 不是「另一组手调」，是「一个模型的输出」

填一组看起来更对的数，只是把手调换个作者。所以 v1 由 `tools/derive_strategy_tables.py`
从 defend model 算出来，可复现：

```
p        = size / (pot + 2·size)           # 他的价格，1/2 池 → 0.25
继续 c_t = σ((e_t·R_t − p) / τ)            # 可实现权益高于价格就继续
加注占比 = σ((e_t − 0.65) / 0.10)
call = c·(1−加注占比)，raise = c·加注占比，fold = 1−c
```

`e_t` 是对下注范围的权益（**假设值**），`R_t` 复用已有的 `REALIZATION_BASE ×
REALIZATION_UNKNOWN_POS`（不再新增一组假设），`τ=0.06`。

### v1 覆盖三张表

- `range_flow.facing_probs`（5 档 call/raise/fold）
- `fold_equity.base_fold`（9 档、参考价格下的弃牌率）
- `fold_equity.size_gamma`（由同一模型算出的价格弹性）

其余 23 张表没有 v1，`sourced` profile 下自动回落 v0 并被标记 `fell_back`（有测试守着）。

### v0 → v1 的差异（`--tables`）

弃牌率（价格 0.25 → 1.0）：

| 档位 | v0 @1/2 | v0 @1 | v1 @1/2 | v1 @1 |
|---|---|---|---|---|
| 强成牌 | 3% | 12% | 1% | 3.7% |
| 顶对强踢 | 15% | 60% | 1.1% | 4.1% |
| 顶对弱踢 | 32% | 97% | 7.4% | 27% |
| 中/底对 | 52% | 97% | 36% | 97% |
| 弱听 | 58% | 97% | 59% | 97% |
| 空气 | 72% | 97% | 94% | 97% |

## 3 三个值得记下的发现

**① v0 的线性弹性会「撞顶」，那不是策略，是外推副作用。**
`fold = base × (p/0.25)^1.0`：中/底对在 2/3 池就到 97%，顶对弱踢在 3/4 池到 96%。
也就是说 v0 隐含「半池以上任何尺寸对中等牌都等于必弃」——这让「尺寸选择」这个决策
在 1/2 池以上几乎失去区分度，而 `best_size` 恰恰是模型要选的东西。

**② 价格弹性这个数可能不值得折腾。**
从模型反解出的 γ 是 **0.939**，和手调的 `1.0` 几乎一样。也就是说「线性外推」这个
假设本身是对的，坏的是**端点被钳制**（97%）而不是 γ。这一条把「该花力气的地方」
从「拟合弹性」挪到了「重设钳制/分档上限」。

**③ 表之间是耦合的：把似然变极化，会顺带收窄范围宽度。**
`_SUPPORT_FLOOR` 是「相对峰值」的，v1 把 nut/strong 的权重抬高一个量级后，空气跌到
阈值以下被移出支撑集，raise 线路的宽度从 39.4% → 34.6%、两对+ 从 18.5% → 12.9%。
**改一张表会动另一张表的观感**——所以 v1 必须整包对比，不能一格一格地换。

## 4 实测：两套表在真实决策点上差多少

命令：`nv tools/strategy_table_diff.py --compare`

362 个翻后决策点（`logs/live.states.jsonl`，快照重建与 `replay_live_decisions.py` 同源，
不调模型）：

| 指标 | v0 | v1 | Δ | \|Δ\|中位 |
|---|---|---|---|---|
| 条件弃牌率 | 0.1167 | 0.1138 | −0.003 | 0.023 |
| 范围权益 | 0.1891 | 0.1892 | +0.000 | 0.000 |
| 强成牌占比 | 0.1406 | 0.1404 | −0.000 | 0.000 |
| 最优尺寸 EV | 29.97 | 29.77 | −0.20 | 2.71 |
| 尺寸 EV 跨度 | 5.44 | 8.56 | +3.12 | 2.45 |

- **尺寸排名翻转 2/362（1%）**；弃牌率变化 ≥8pt 的 5/362。
- 弃牌率中位只动 2.3pt：因为 v1 同时抬高了空气（0.72→0.94）和压低了中等牌
  （0.52→0.36），在空气重的范围里互相抵消。

**这份实测的效力必须打折，不要拿它下结论。** 覆盖率：362 个点里只有 **85 个**能算出
条件弃牌率，其中 **61 个**用的是接近均匀的范围（`field_ranges` 在离线重建里拿不到
翻前先验），真正「收窄过的范围」只有 24 个。也就是说：这条重放路径**测不到**
`facing_probs` 真正生效的地方（对手跟注/加注后的范围收窄）。

能下结论的只有表级对比（`--tables`：3 个先验 × 3 个牌面 × 4 条线路），那里 v1 的
收窄效果是明确可见的。

## 5 怎么用

```bash
# 看当前生效的 profile、每张表的来源与是否回落
nv -m poker_ocr.strategy_tables --profile sourced

# 表级对比（不读日志）
nv tools/strategy_table_diff.py --tables

# 真实决策点对比（362 点，约 17 秒）
nv tools/strategy_table_diff.py --compare

# 校验 JSON 与代码一致
nv tools/export_strategy_tables.py --check
```

切换表：**用真环境变量**，不要写进 `.env`。

```bash
STRATEGY_TABLES_PROFILE=sourced nv -m poker_ocr.live ...
```

原因：表在 `import` 时读、常量在模块级定值，而 `.env` 是 `live.py` 跑起来之后才加载的
（`load_env()` 在 import 之后调用）。写进 `.env` 不会报错，只是静默不生效——这是当前
的已知边界。

## 6 下一步（P2：裁判）

现在能回答「两套表差多少」，还不能回答「哪套更好」。要回答后者，按性价比：

1. **对手库按 tier 拆弃牌率**：`opponent_profile` 已有逐街弃牌率，缺的是按手牌档拆分
   （顶对 vs 空气）。有了它，`BASE_FOLD` 就能从「假设」变成「实测」，`verified` 才有
   意义。这是最便宜的一步。
2. **尺寸弹性实测**：同一对手在 1/3、1/2、满池下的弃牌率。它同时验证 ② 和 ①。
3. **求解器锚点**：~~`gto/` 的 Rust CFR~~ —— **已放弃**。GTO 相关的求解器、
   specs、数据以及 `gto_lookup` / `board_equity` 已在 2026-11-05 从仓库整体移除，
   这条路径不再存在。现在只有两个变体：`hand-tuned`（v0）与 `sourced`（v1）。

在 P2 有结果之前，**默认保持 v0**。`sourced` 是实验开关，不是升级。
