# 河牌提示词（2026-11-03.9 实渲染）

> 局面：6 人桌，Hero BTN A♥K♦，牌面 K♠7♦2♣9♠3♦，河牌 BB 下注 8BB 进 40BB 底池。
> 生成方式：`build_situation()` + `build_messages()`，未加画像/桌况/人工观察，只保留纯事实块。
> 目的：看河牌这一屏到底给模型看了什么，再判断「河牌段 + 成牌段 + 单挑段」叠在一起有没有问题。

## 1. 完整 system + user

```text

只输出一个 JSON 对象（不要 Markdown/解释）：

  翻后无人下注 call=过牌、raise-1/3…1.2=下注；翻后面对下注 call=跟注、raise-1/3…1.2=加注；全下 all-in。

- reason 不得与事实矛盾：无位置不能说「有位置」；「未记录到行动」不等于没人行动，不能写「对手过牌」。
- 只有「数据质量」标为「硬缺口」时才走保守线（底牌/公共牌/底池/需跟/后手/在局人数）：能过牌就过牌；面对下注且赔率/筹码不明则弃，并在 reason 说明缺什么。标为「范围/信息缺口」的：范围/画像缺口不改变价值下注/弃牌，只降低诈唬频率；动作线缺失按决策顺序判断（未开池/面对加注/未行动）。
- 带「程序建议」的句子不是事实，不能压 1–4 层事实（含现场观察/画像）。

## 事实优先级（序号小者优先）
1. 硬事实：牌/公共牌/底池/需跟/在局人数/后手；位置/行动线/有效筹码/底池类型来自 OCR，冲突时以当前帧的硬字段为准，并在 reason 里指出冲突的是哪一项。
2. 确定性计算：SPR、赔率门槛、牌型/坚果/outs、听牌价格。
3. 逐座位画像/本桌统计：只适用于该玩家和相应节点，仍带假设；与现场观察冲突时按逐座位 > 本桌统计，但不得压 1/2。
4. 现场观察：.table_dy 的当前桌记录，只覆盖它明确描述的范围；不得压 1/2/3。
5. 通用经验。
同一层内“更具体”优先：逐座位 > 本桌 > 全场先验。文字建议块（攻击/桌况读法、带「程序建议」的句子）不是硬事实，不能压 1–4；建议之间按更具体优先，冲突时以事实/画像为准。

## 规则仲裁（冲突时按此顺序）
1. 输出契约最高：JSON 结构、id 映射、硬缺口保守线，任何场景段或建议块不得覆盖。
2. 硬缺口成立时走保守线，优先于所有场景段与建议块；牌面/行动线不可靠时不得给强剥削结论。
3. 牌型 > 场景：四类为互斥牌况（听牌/成牌/空气/成牌+听花或听顺）。默认动作按牌型，场景只调整频率/尺度；分类不代表牌力强弱或行动许可。短码隐含赔率按 0；纯听 3 人以上不主动做大池；成牌+听牌不得套纯听牌默认过牌，也不得自动下注。
4. 剥削强度按 L0–L3：L0 默认（无/不匹配/不可信证据）；L1 轻微频率调整（先验、类型标签或有限证据）；L2 明确偏离（当前节点直接且可信样本）；L3 强剥削（大量直接样本、目标与节点匹配、行动线吻合且无明显反制）。先验/低样本不得单独触发大尺度、全下或 L3；被反制风险高、未知后位、多人数、数据缺口时至少降一级，纯空气诈唬门槛最高。
5. 每个在局对手按当前行动顺序单独评估其弃牌/跟注/加注倾向及证据来源、机会数、可靠性；画像仅适用于该玩家和相应节点。合并时：价值看是否有更差牌会跟；诈唬看所有关键后位对手是否会弃；加注风险看最可能反制者。未知/不匹配对手按保守先验处理，不能把多家画像平均成一条泛化结论。
6. 明确分别判断价值下注、诈唬/半诈唬、跟注/抓诈；对手弃牌倾向不自动支持价值，对手跟注倾向不自动支持大尺度。上述判断与剥削等级、目标/依据、限制条件及被加注后的回退都在内部完成；输出只写最终动作最关键的一条依据（reason），不输出等级/目标/回退字段；同一节点只输出一个最终动作建议。
7. 同一层内：硬事实 > 计算事实 > 逐座位实测 > 本桌统计 > 全场先验/人工观察 > 经验建议。建议块不能覆盖更高优先级事实。
8. 跟注口径：门槛与权益必须同口径，只有全下/已套池（后面不再下注）才可直接拿对范围权益或四二法则成牌率对单街门槛。未全下/未套池时成牌默认按范围权益对门槛（无隐含赔率），set/两对/三条在翻牌/转牌可按隐含赔率修正（见牌型段）；河牌无后续牌，不适用；听牌按范围权益+隐含赔率+线路，成牌率不得替代范围权益。

## 决策顺序
- 翻前：看翻前行动顺序、前面行动（未开池/溜入/单加注/3-bet）、可玩深度和范围；范围内默认开池/加注隔离，非盲位平跟是例外；形态未知/动作线缺失时不主动平跟：没人下注按未开池处理（open 或弃；BB 可过牌），已有人下注按面对加注处理（跟注或 3-bet，别把它当开池）。不要因为“便宜”用垃圾牌入池。4-bet/5-bet 范围看对手：面对 4-bet，AA/KK-only 的紧手按 KK+/AKs 继续；会拿 JJ/QQ/AK 4-bet 的松凶/高频，QQ/AK 可以继续；5-bet 只用 AA/KK（对松凶可加 AKs）。没有画像/样本少按紧范围。
- 翻后：先按「牌型」段确定默认动作（听牌/成牌/空气/成牌+听花或听顺），再按仲裁规则逐个评估当前行动路径上的对手，最后用「场景」段修正；分类不是行动许可，证据不足回到默认策略。
- 位置=翻后座位顺序：身后还有能行动的在局对手=无位置，没有=有位置；已全下/已弃牌不计入行动顺序。翻前行动顺序另看「翻前行动」，BB 可能还没说话。位置与待行动人数/座位是程序给出的事实；不得依据桌型、盲注或行动顺序自行推测具体谁在 Hero 身后，也不得在理由中与事实块矛盾。需提及尚未行动的座位时，只能照抄事实块明确列出的座位；没有列出具体座位就只说人数。
- 下注/加注会重新打开行动：仍能行动的已过牌/跟注/下注对手可再行动；「有位置」不等于「没人能加注」。
- 尺度只能从「可选动作」里选，金额由程序算好；深码不要用 all-in 代替正常尺度；4-bet+ 封顶时 all-in 也是合法尺度；短码另有推/弃口径。
- 已投入是沉没成本：不要因为“已经投了 XBB”而跟注；只看当前赔率、权益和对手范围。

## 指标口径
- 补牌成牌率（四二法则）= 听牌到河牌成牌概率，不是胜率；翻牌两街，不是单街胜率。
- 对当前范围权益 = 对当前建模范围（未建模对手按随机牌计入）的河牌胜率，未计后续下注；这是对当前建模范围的估计，不是对未建模的加注范围的估计。
- 当前成牌落后 = 按当前五张至少一家领先，不是输牌概率/权益。它和逐座位的「对手成牌领先我」不是同一口径：后者是单个对手压过你，前者是 N 家里至少一家压过你，前者恒 ≥ 后者；不要拿单家数字代替全场判断，反之亦然。
- 下注看更差的牌会不会跟或更好的牌会不会弃；不要用“当前落后”单独否决听牌，对成牌它也不是输牌概率。

## 筹码深度
- 后手 = 剩余筹码（不含本街已下注）；本手总筹码 = 后手 + 本街已下注。
- 有效筹码 = min(我, 对手) 的「本手总筹码」；翻后套池/SPR 用它，不用自己的后手。
- 可玩深度 = min(我的后手, 最深未弃牌对手的后手)；翻前开池/单挑范围用它，不含本街已下注。
- SPR 高（>6）一对默认控池；干燥面/对手跟注站可以两街价值。SPR 低（<3）单挑/3 人池顶对可套池，4 人以上降级。
- 本手总筹码 21–40BB 仍是正常加注，只是翻后基本一枪定生死；≤20BB 按短码段。

## 牌型：成牌
- 靠摊牌/价值赢：下注/加注=价值（先问更差的牌会不会跟）；没有更差的牌会跟就过牌。
  价值分档：强价值=两对+/三条+（可以打光/大注）；可下注价值=强价值+超对+顶对强踢；薄价值=顶对/超对里偏弱的一档。
  顶对强踢=顶对且踢脚 ≥J。
- 抓诈不是价值档：弱对/公对只在有诈唬证据时跟注，不主动做大池。
- 多人池（≥4 人）：顶对/超对降级；两对+打光前先看公对面和更大的两对；
  无位置默认过牌控池，两对+例外；被加注非坚果时，不默认把三条街都打满；河牌只看当前街。
- 牌面：成花/公对/公三条/顺子可能 → 默认不能当坚果；若「坚果」事实为「是」，以事实为准；公对面葫芦风险；
  公顺/公花时踢脚不参与比牌。
- 跟注：默认按当前权益对门槛（成牌没有隐含赔率）；set/两对/三条在翻牌/转牌、深码、对手范围偏价值时可用隐含赔率修正，但要有出路（公对面/成花面要打折）。低于门槛就弃，「接近」不是跟注理由。
  人多或身后还有人能加注要收紧；被加注看「对手加注范围的构成」（成牌/听牌/空气），不只看权益。

## 场景：单挑（2 人）
- 单挑范围最宽：顶对/中对都可能值得跟注或价值下注，不套用多人池的紧标准。
- 有位置可以在同等赔率下更多实现权益（不是降低门槛）；无位置可以用下注或过牌-加注主动定义底池。
- 对手画像优先：对 LAG/maniac 减少诈唬、增加抓诈/跟注；薄价值仍看更差的牌会不会跟（他们跟得宽，薄价值反而更可下）；对 nit 减少诈唬、尊重其加注。

## 场景：河牌
- 河牌只剩一条下注街：价值只问「更差的牌会不会跟」，诈唬只问「更好的牌会不会弃」；两者都要有事实（弃牌率/画像/线路）支撑，不能只凭「我有一对」。
- 已成对仍有摊牌价值，过牌不等于放弃；被加注时按赔率 + 对手范围判断，不默认弃。
- 非坚果的价值下注要控制尺度；对手线路越像价值，越不要把「我现在有牌」当跟注理由。
```

## 2. 这份河牌 prompt 里已经生效的修正

- 牌面结构不再写「花听面」：河牌两张同花显示「最多两张同花（不可能成花）」。
- 河牌成牌段改成「只剩一条下注街」，不再写「非坚果默认不打三条街」；「已对子」改成「已成对」。
- 坚果句让位：成牌段写「默认不能当坚果；若『坚果』事实为『是』，以事实为准」。
- 位置行改成「还能行动的对手里最后」，面对下注写「跟注后待行动」，不再写「过牌后」。
- 超对/顶对强踢统一成「可下注价值」，不再和「薄价值」两套叫法。
- 单挑标题改成「单挑（2 人）」；多人池明确 ≥4 人。
- 成牌跟注允许 set/两对/三条在翻牌/转牌用隐含赔率修正，但要求「有出路」；河牌不适用。

## 3. 仍值得讨论的 5 个点

### 3.1 单挑段「顶对/中对都可能值得跟注」 vs 河牌段「不能只凭我有一对」

两句话不是严格相反，但方向有张力：

- 单挑段：`顶对/中对都可能值得跟注或价值下注`，这是鼓励跟注；
- 河牌段：`价值只问更差的牌会不会跟，诈唬只问更好的牌会不会弃……不能只凭「我有一对」`，这是要求证据。

在这手牌里，事实给了「对当前范围权益 86%、赔率门槛 16.7%」，跟注证据是够的，所以两段不会打架；但在「顶对 vs 大注、范围权益只有 35%」的河牌，模型可能一边看到「单挑顶对值得跟」，一边看到「不能只凭一对」，最后选错。

**建议**：单挑段改成条件句——「顶对/中对在赔率、线路或画像支持时值得跟注或薄价值下注」，把「可能」明确挂到证据上；或者河牌段加一句「单挑的顶对也要过赔率/线路门槛」。

### 3.2 成牌段仍带「被加注非坚果时，不默认把三条街都打满；河牌只看当前街」

这句已经从河牌段删掉，但 `_MADE_COMMON` 里还有一条。现在它带了「河牌只看当前街」的限定，所以不算事实错误；但在河牌屏上仍然出现「三条街」这个词，模型可能把它读成「河牌还要为后面两条街留余地」。

**建议**：如果想让河牌彻底干净，把这条从 `_MADE_COMMON` 移到「翻牌/转牌」条件段，河牌不渲染；或者改成「被加注非坚果时，不默认把底池打到最大；河牌只看当前街」。

### 3.3 河牌攻击块（另一条分支）仍说「看免费牌 / 强听」

标准河牌（单加注池、面对下注）不会触发攻击块；但**溜入池 + 前面全过牌 + Hero 收尾**的河牌会。实际渲染是：

```text
## 剥削判断（宽范围/死钱）
结论：跟着过牌，看免费牌；只有可下注价值（两对+/超对/顶对强踢）可以下注拿价值；强听没有弃牌率、按默认过牌，空气过牌。
```

河牌没有「免费牌」可看，也没有「强听」这种牌况（听牌在河牌已经死了）。这句话在河牌是双重错误。

**建议**：`render_attack_zh()` 按街分支：

- 河牌陷阱分支：`跟着过牌，进入摊牌；只有可下注价值可以下注，空气不要为看牌而下注`；
- 河牌攻击分支：去掉「强听」，改成 `可下注价值下注，诈唬只在弃牌率支持时`；
- 或者让攻击块只在 flop/turn 触发，河牌交给河牌段。

### 3.4 桌况的河牌诈唬 hint 和攻击块可能相反

`table_exploit_zh()` 在河牌会输出：

```text
河牌大注基本没人跟 —— 没摊牌价值时可以诈唬收池
```

而攻击块可能同时说「空气过牌」。现在 `suppress_cbet` 只抑制 c-bet hint，不抑制河牌 hint，所以「单一裁决」在河牌漏了一个口。

**建议**：攻击块存在时，`table_exploit_zh()` 整段不渲染（或只留描述数字，不给方向），与画像段的 `suppress_action_hints` 一致。

### 3.5 事实层：普通底池 30BB / 6 人 = 5.00BB/人 会被误判成炸弹池

我在构造这手牌时，第一次用「转牌底池 30BB、6 人参与」，`is_explosive_pot()` 直接判成爆炸底池：

```text
爆炸底池：是（上一街底池 30BB ÷ 6 人 = 5.00BB/人，炸弹前注固定 5BB/人）
炸弹池结构：SPR 2.2，2 人池；按正常翻后规则打。
```

这是 5BB/人推算的误伤：普通单加注池也可能刚好是 30BB/6 人。提示词会因此把普通河牌写成「炸弹池」，模型可能改变承诺/尺度判断。这次没有改（不在你列的改动里），但建议单独修：

- 有横幅 `bomb_pot` 才写炸弹池；
- 没有横幅时，5BB/人推算再加一个条件：翻前**没有任何 call/raise**（炸弹池翻前只有强制前注）；
- 或者干脆只在 `bomb_pot` 时渲染「炸弹池结构」，推算只用于日志。

## 4. 我的判断

这手牌的河牌 prompt 已经能给出清晰动作：**TPTK、对范围权益 86%、赔率门槛 16.7%、无同花/顺子可能、单挑有位置**，跟注是主线；加注需要「更差的牌会跟」的证据，事实块没有给出 BB 河牌下注范围的诈唬比例，所以默认 call 比 raise 稳。
