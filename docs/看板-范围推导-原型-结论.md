# 看板「范围推导」原型结论（一次性）

> 票：地图「对手范围与牌力推导的可观测化」→ 原型：拿一手真实记录手搓推导时间线
> 原型：`docs/proto/range-timeline-prototype.html`（单文件、内联数据、无外部依赖，双击即开）
> 重新生成：`nv tools/proto_range_timeline.py`（读 `hands/1023.hands.json`，覆盖同一路径）

样本三手：h104（三人 3-bet 池，AK 在 9s8sTs 面 c-bet 被加注到 52）、h4（单挑多街，转牌 2/3 池后的抉择）、h8（五家池，BB 满池 donk 进四家）。

## 一、四个验收问题

**A. 能一屏回答「我为什么在这个范围里」吗——能，但只到「翻后怎么走到这一步」。**
1440 宽下时间线 + 热图 + 本步 top Δ 表同屏。h104 的 `flop:jam-raise` 一步把范围从 3.77% 压到 2.49%，Z=0.08，热图只剩 TT+/AKs/AQo——「对面是坚果线」一眼成立。h8 的 donk 一步把 BB 的有效宽度从 90% 压到 57%，配 top Δ（同花听 +0.35%、空气 −0.06%），能解释「为什么 12% 权益要弃」。
答不了的两块：翻前来源（step0 只有一个 prior 名，答不了「为什么是这个 prior」）、换表前后 diff（无第二版本，归 #9）。

**B. T2 schema 缺哪些字段——见下面缺口 1–5。**

**C. 热图口径在真实数据上可读吗——可读，但必须三条同时成立：**
1. √ 归一 + 单色阶。h8 从 100% 到 52%，线性映射会把其余格子压成黑色；
2. 只给归一值 > 0.12 的格子画 169 标签，否则 13×13 在 420 px 下全是毛刺；
3. 点格子要能筛且要显示该格占比。缺第 3 条的数据（缺口 1）：final 步点 `KQo` 能出 12 条（4.01%），中间步点同一格是空的。

**D. 交互顺序自然吗——自然顺序是 座位 chips → 时间线 → 热图 → 表；默认落点必须是「有 trace 的座位 + 最后一步」。**
证据来自原型第一版：h104 默认停在第一个座位（CO，无翻后动作），首屏是一张「旧口径」空卡。改成默认焦点到有 trace 的座位后，首屏才立得住。

## 二、缺口清单（按严重度）

1. **逐 combo 只有 top 榜。** 中间步点热图格子大多空。要支持「点格子筛 combo」，trace 需按 169 键存 `top_by_key`（每格 top 3），或提供按需重算接口。
2. **同一手牌两种口径并存。** 没有翻后动作的座位走 `board_range`（h8 三家 18.6% / 20.8% / 24.4%，h104 CO 2.3%），有动作的走事件模型。看板必须逐座位标口径来源，否则并排的数字不可比。
3. **中间步含已死组合。** `build_range` 只在全部事件之后删 dead；h104 的 `flop:jam-raise` 一步 top gained 第 1 名是 `AsKs`——As 在板面上，物理不可能。UI 要过滤或标记；T2 应在逐步事件里就标记 dead，或至少让消费端能过滤。
4. **没有 SPR / 筹码量。** hands 归档缺 stack，`spr` 全退化成 99（`spr_bucket` 恒 high），「为什么这一步压得这么狠」少一半解释力。T2 应把每个事件的 `spr`、`spr_bucket` 落盘。
5. **prior 无版本、无 prompt_ref。** 换表 diff 与「跳到提示词那句话」都缺锚点；diff 归 #9。

## 三、三条 UI 修正（相对信息架构文档）

1. **默认焦点**＝有 trace 的座位 + 最后一步；无 trace 的座位单独一张卡写明旧口径宽度，不画空热图、不给组合表。
2. **时间线步卡**写「宽度 3.8% · 有效 3.4%」（两个指标并排），不写「x% → y%」（不是前后步）；final 步显示「留存量 53.6%」，不显示 Z。
3. **equity 条旁必须有「被至少一家压过 x%」。** h8 是 12.3% 权益 / 94% 被压过——单看 12.3% 会误读成「还有戏」，两个数一起才是弃牌的理由。

## 四、对后续票的影响

- 采集 schema / 推导口径相关票应吸收缺口 1–4：`top_by_key`、逐座位口径字段、dead 逐步标记、`spr`+`spr_bucket`。
- 信息架构文档的六种空态在原型里全部走通（URL 带 `empty=off|none|preflop|skipped|budget|writefail|missing`，配 facts 旧视图）。
- 三份资产都是一次性的：`docs/proto/` 与 `tools/proto_range_timeline.*`，不接 live、不进构建；结论吸收后即可删。
