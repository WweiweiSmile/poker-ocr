# 实时牌面范围（board-conditional range）设计

> 回答的问题：给定公共牌，把“和牌面有关联”的组合实时生成出来，
> 再算我的手牌在这个范围里大致是强还是弱。
> 关联文档：[`手牌范围基准-实现方案.md`](./手牌范围基准-实现方案.md)

---

## 0. 结论

**可行，而且是现有 `hand_vs_ranges` 的自然扩展：只换“范围从哪来”，引擎不用重写。**

但有三个前提，否则算出来的“强/弱”会失真：

1. **牌面不会改变他发到什么牌，改变的是他“继续”的范围。**
   翻前他跟注后，他的范围是翻前范围；翻牌他下注/跟注，才把范围收窄到
   “和牌面有关联的牌”。所以这张表是 **动作条件范围**，不是“他的全部范围”。
   - 他下注/加注 → 关联范围（强成牌 + 强听 + 少量空气）；
   - 他过牌 → 不能按牌面硬筛，否则把空气全删了，会高估他；
   - 他跟注 → 关联范围，但门槛更低（中对子/后门也算）；
   - 还没行动 → 翻前范围。

2. **必须按 combo + 花色分类，不能按 169 类粗筛。**
   在 `AsKs4d` 上，`7s8s` 是**同花听牌**（AsKs + 7s8s = 4 张黑桃），
   `7h8h` 只是后门顺；`QhJh` 有卡顺（等 T 成 Broadway），不是空气。
   用“78 一律排除”会误杀花听，用“QJ 是空气”会漏掉卡顺。

3. **最好保留一个翻前先验（哪怕很粗）。**
   纯牌面范围在 `AsKs4d` 上会包含 44.6% 的组合（所有对子、卡顺、花听），
   其中 `25o`、`34o` 这类牌很多翻前根本不会玩；而 `AK/AA/KK` 又和
   `22` 被当成同样“有关联”。用“翻前先验 × 牌面连接度”才是他实际的范围。

原型（`AsKs4d`，加权范围，3000 次权益抽样）：

| 范围口径 | 宽度 | `AhQh`（顶对 Q 踢） | `QhJh`（卡顺） | `5s6s`（花听+后门顺） |
|---|---|---|---|---|
| 纯牌面关联（全部组合） | 44.6% | behind 9.1% / eq 71% | 83.4% / 28% | 96.0% / 40% |
| ∩ BTN RFI | 24.5% | 9.4% / 70% | 86.3% / 25% | 99.5% / 37% |
| ∩ UTG RFI | 9.4% | 17.0% / 67% | 91.2% / 25% | 100% / 36% |

这张表已经能回答“我的手牌在这个范围里是强、弱、还是听牌”：
`AhQh` 强，`QhJh` 弱，`5s6s` 现在大幅落后但有 38% 权益。

“强弱”不要合成一个分数，至少两个维度：

- `behind_now` 低 + `equity` 高 → 强（TPTK）；
- `behind_now` 高 + `equity` 中 → 听牌（花听/卡顺+后门）；
- 两者都差 → 弱（QJ 只有卡顺、没有成牌）。

**宽度和先验不同，数字会变**，所以渲染时必须把范围口径写出来。

`AsKs4d` 的 44.6% 具体由什么构成（阈值 0.3，组合数）：

| 类别 | 占比 | 例子 |
|---|---|---|
| 对子（未成两对/三条） | 31.7% | `AX` 顶对、`KX` 第二对、`4X` 底对、`22` underpair |
| 卡顺（无成牌） | 6.8% | `25`、`QJ`、`JT`、`QT` |
| 花听（无成牌） | 3.4% | `5s6s`、`7s8s`、`QsJs` |
| 两对 | 2.0% | `AK`、`A4`、`K4` |
| set / trips | 0.7% | `AA`、`KK`、`44` |

所以“44.6%”不是“他很宽”，而是“这面牌和很多牌都有某种关系”；
乘上翻前先验后，BTN 只剩 24.5%，UTG 只剩 9.4%。

性能：朴素实现 450–660ms/board；用位掩码 + 同 board 缓存约 **11–12ms/board**，
可以进实时链路。

## 1. 语义：为什么不能“只看牌面”

### 1.1 牌面是条件，不是发牌

翻前跟注后，他可能拿着任意两手牌（在翻前范围内）。翻牌 `AsKs4d` 发下来，
**不会把他手里的 `7h8h` 变成 `7s8s`**；牌面只影响他**愿不愿意继续**。
所以：

```text
P(hand | board, action) ∝ P(action | hand, board) × P(hand | preflop)
```

- `P(hand | preflop)`：翻前先验（位置/动作/范围表）；
- `P(action | hand, board)`：这手牌在这样的牌面上会不会下注/跟注；
  牌面连接度是它的**代理**，不是精确概率；
- 只用牌面连接度 = 假设“他只用有关联的牌继续”，这只在“他下注/跟注”时近似成立。

### 1.2 按动作选范围

| 对手当前街的动作 | 用什么范围 | 原因 |
|---|---|---|
| 过牌 | 翻前范围（不按牌面筛） | 过牌可以是空气；筛掉空气会高估他 |
| 下注 / 加注 | 牌面关联范围，高门槛（强成牌 + 强听 + 少量空气） | 下注范围是收窄的 |
| 跟注 | 牌面关联范围，低门槛（对子/听牌/后门） | 跟注可以很宽，但仍有下限 |
| 还没行动 | 翻前范围 | 没有新信息 |
| 全下 | 关联范围，只留强成牌/强听 | 全下范围最窄 |
| 已弃牌 | 排除 | — |

多人池里每个对手可以有不同的 `mode`；`hand_vs_ranges` 本来就支持
“每个对手一个范围”，不需要改引擎。

## 2. `AsKs4d` 例子：哪些算“有关联”

> 分数是“连接度”，不是胜率；胜率由后面的 equity 算。
> 关联阈值默认 `0.3`；`call` 模式 ≥0.3，`bet` 模式 ≥0.75。

| 手牌 | 成牌 | 听牌 | 分数 | 关联 | 说明 |
|---|---|---|---|---|---|
| `2h5h` | 空气 | 卡顺等 3（A2345） | 0.35 | ✅ call / 可诈唬 | 不是“毫无关联” |
| `3h4h` | 对 4（底对） | 后门顺 | 0.70 | ✅ call | 用户举的例子 |
| `5s6s` | 空气 | 花听 + 后门顺 | 0.90 | ✅ call / bet 半诈唬 | 用户举的例子 |
| `7s8s` | 空气 | **花听** + 后门顺 | 0.90 | ✅ call / bet 半诈唬 | **不是“78 无关”** |
| `7h8h` | 空气 | 仅后门顺 | 0.10 | ❌ | 这才是要排除的 `78` |
| `QhJh` | 空气 | 卡顺等 T（Broadway） | 0.35 | ✅ call | 不是空气 |
| `AhQh` | 顶对 Q 踢 | 后门顺 | 0.90 | ✅ call / bet | 强 |
| `AcKc` | 两对（A+K） | — | 1.25 | ✅ bet | 强 |
| `2c2h` | 小对子（underpair） | 后门顺 | 0.55 | ✅ call / ❌ bet | 有对子，但很弱 |
| `4c4h` | 三条 4（set） | — | 1.40 | ✅ bet | 强 |
| `AcAd` | 三条 A（set） | — | 1.40 | ✅ bet | 强 |
| `7h2c` | 空气 | — | 0.00 | ❌ | 排除 |

几个容易吵的点：

- **“所有的口袋对”**：`22` 确实是“有关联”（有对子），但它是 underpair，
  只能算 call 模式的低权重，不能进 bet 模式；`44/AA` 是 set，才是强牌。
- **`78` 不能整类排除**：`7s8s` 是花听，`7h8h` 才是空气。
  所以分类必须是 **combo 级**，花色要进特征。
- **`QJ` 不是空气**：`AsKs4d` 上等 T 成 Broadway，是卡顺。
  纯手工列“有关联的牌”一定会漏这种。
- **`25` 也不是空气**：等 3 成轮子，卡顺；只是它翻前很少进范围，
  所以现实里要靠翻前先验把它压掉，而不是靠牌面分类。

## 3. 分类与打分

### 3.1 特征

对每个 combo（不含公共牌）：

- **成牌**：`coach.evaluate(hole + board)` → 牌型、踢脚；
  - 对子细分：overpair / top pair / second pair / middle / bottom / underpair；
  - 两对、三条/set、顺子、同花、葫芦、四条。
- **同花听**：`hole + board` 里某花色 4 张，且 hole 有该花色；
- **后门花**：某花色 3 张，且 hole 有该花色（flop 才算；turn/river 不算）；
- **顺子听**：下一张能成顺的点数；≥2 个点数 ≈ 两头/双卡，1 个点数 = 卡顺；
- **后门顺**：需要 turn+river 两张才成顺（flop 才算；turn/river 不算）；
- **高张**：hole 两张都高于牌面最大牌（dry board 才有意义）；
- **打牌面**：最好的五张全靠公共牌（这种牌人人都有，权重应低）。

### 3.2 连接度分数（起始值）

| 特征 | 分数 |
|---|---|
| 空气、无听、无高张 | 0 |
| underpair | 0.45 |
| 底对 / 中对 | 0.60 / 0.70 |
| 第二对 | 0.75 |
| 顶对 | 0.80 |
| overpair | 0.90 |
| 两对 | 1.25 |
| set / trips | 1.40 |
| 顺子 | 1.50 |
| 同花 | 1.60 |
| 葫芦 / 四条 | 1.70 |
| 同花听 | +0.80 |
| 两头/双卡（≥8 outs） | +0.70 |
| 卡顺（4 outs） | +0.35 |
| 后门花 | +0.15 |
| 后门顺 | +0.10 |
| 高张（无对） | +0.10 |

- 分数封顶 1.8；听牌和成牌可以叠加（顶对+花听 ≈1.7）。
- 后门分只在“没有下一张听牌”时加；已经有卡顺/花听时不再叠后门，避免重复计数。
  所以 `25` 是 0.35（卡顺），不是 0.45；`7h8h` 是 0.10（只有后门顺）。
- `turn/river` 不再加后门分；`river` 不再加任何听牌分。
- 顺子 outs 用位掩码算，不要把“补成葫芦”算成顺子补牌
  （现有 `ground_truth._draws` 已经注意这一点，复用它的口径）。

### 3.3 从分数到范围

```python
w(combo) = preflop_weight(combo) * board_score(combo)
if w < min_weight:  # 默认 0.3，只丢纯空气/纯后门
    w = 0
normalize(w)
```

- 用**加权**而不是硬筛：`25`（0.35）、`QJ`（0.35）是弱关联，
  `5s6s`（0.90）、`44`（1.40）是强关联；加权能保留“弱关联但可能有”的牌，
  又不会让纯空气进范围。
- 硬阈值只做“丢空气”；真正的范围宽度由 `preflop_weight` 和动作模式决定。
- 报告两个宽度：
  - `weighted_width`：权重和 / 最大可能权重；
  - `combo_count`：`w > 0` 的组合数 / 1326。
  渲染时至少给一个，避免“范围看起来很大/很小”没有解释。

### 3.4 动作模式

| mode | `min_weight` | 额外规则 | 典型用途 |
|---|---|---|---|
| `check` | — | 不乘 board_score，直接用 preflop 范围 | 对手过牌 |
| `call` | 0.30 | 保留对子/卡顺/后门 | 对手跟注 |
| `bet` | 0.75 | 去掉 underpair/底对/纯后门；保留顶对+/强听 | 对手下注 |
| `raise` | 0.85 | 只留两对+/set/强听；少量空气诈唬另加 | 对手加注 |
| `allin` | 0.90 | 只留强成牌/强听 | 对手全下 |
| `unknown` | 0.35 | 纯牌面范围，标注“board-only” | 动作读不到 |

`bet/raise` 的“少量空气诈唬”是 P2：可以给“有阻断牌 + 后门”的空气
一个小权重（例如 0.1），但不要默认给，否则范围会虚宽。

### 3.5 翻前先验

优先级从高到低：

1. **具名范围**（`RFI_<pos>`、`BB_DEF_vs_<opener>`、`COLD_CALL_*`）——
   最准确，直接乘 `preflop_weight`。
2. **规则先验**（没有表时）：
   - 对子 1.0（小对子 0.75）；
   - 同花 0.9；双高张 0.8；连张/隔张 0.7；A 高 0.65；
   - 非同花 0.5；被统治的非同花 A/K/Q 0.3；
   - 位置/角色乘子：开池 1.0、冷跟 0.85、BB 0.95。
   这不是精确范围，但比“全部 1,326 组合”好得多，而且不需要维护表。
3. **均匀先验**（`weight=1`）——纯牌面范围；只在没有前两条时用，
   且渲染必须写 `board-only (any two cards)`。

## 4. 与现有引擎的集成

### 4.1 新模块

```python
# poker_ocr/board_range.py
@dataclass(frozen=True)
class BoardRange:
    board: str
    mode: str                  # check / call / bet / raise / allin
    range_id: str              # "BOARD:call:RFI_BTN"
    weights: Mapping[str, float]   # combo key -> weight
    combo_count: int
    weighted_width: float
    note: str

def build(board: str,
          mode: str = "call",
          preflop_range: Range | None = None,
          prior: str = "named",   # named / rules / uniform
          min_weight: float = 0.3,
          ) -> BoardRange: ...
```

- `board_range.build` 输出 `Range` 兼容对象；`hand_vs_ranges` 不用改。
- `field_ranges` 给每个对手选 `mode`：
  - 当前街 `bet/raise` → `bet`/`raise`；
  - 当前街 `call` → `call`；
  - 当前街 `check` → `check`（不筛）；
  - 还没动作 → `check`（翻前范围）；
  - 动作读不到 → `unknown` + warning。
- 每个对手可以不同 `mode`，`hand_vs_ranges` 已经支持。

### 4.2 计算流程

```text
board + mode + preflop_range
  → board_range.build()          # 11ms 冷启动，同 board 缓存
  → hand_vs_ranges.compute()     # 精确 behind + MC equity
  → render “vs board range” + “vs preflop range”
```

渲染建议同时给两个口径：

```text
## Hand vs ranges (BTN open; board-connected, call mode)
Board: AsKs4d | Your AhQh | flop
Range: board-connected ∩ RFI_BTN = 29.0% (384 combos; weighted 24%)
Behind now: 9.4% (tie 2.6%) | Equity: 70% ±1%
Ahead of: worse aces, underpairs, missed broadways | Behind: AK/AA/KK/44, A4s
Read: top pair Q kicker is strong even against the connected part of his range.
Preflop-only comparison: behind 3.7%, equity 81% — the board filter makes his range stronger (equity drops to 70%), as it should.
```

`QhJh` 同一牌面：

```text
Behind now: 86.3% | Equity: 25% | Ahead of: air/underpairs | Behind: any pair, AK/AA/KK/44
Read: gutshot only — weak now, insufficient equity to continue without a price.
```

`5s6s`：

```text
Behind now: 99.5% | Equity: 37% | Draw: flush draw + backdoor straight
Read: behind now but 38% equity — a draw, not a made hand; judge by price, not by behind-now.
```

### 4.3 为什么还要“vs preflop range”

- 牌面范围回答“在有关联的牌里我算强还是弱”；
- 翻前范围回答“他实际可能有什么”；
- 两个都给，模型才能区分“我这手在关联范围里强，但他范围里还有很多空气”
  和“我这手在关联范围里都弱，那大概率真的弱”。

如果只给一个，建议按动作：
- 对手下注/加注 → 牌面关联范围（更接近他的下注范围）；
- 对手过牌 → 翻前范围（保留空气）。

## 5. 性能与实现细节

### 5.1 为什么朴素实现慢

逐 combo 调 `coach._count_outs`（45 张补牌 × 1,326 组合）≈ 450–660ms/board。
实时链路不能接受；回放批量更不行。

### 5.2 优化

1. **位掩码算顺子**：预计算 8,192 个 rank mask 的 `straight_high`；
   每个 combo 只查表，不再逐张 `evaluate`。
2. **combo 级特征缓存**：`(board, mode)` 缓存；同一街多帧只算一次。
3. **169 类预计算**（可选）：成牌/顺子特征按 169 类算一次，
   花色特征按 combo 补；可再降一半。
4. **抽样**：`hand_vs_ranges` 的 equity 用 1,500–2,000 次；
   范围构建本身不抽样。
5. **回放/批量**：默认关或降到 500 次；实时链路保留完整精度。

原型（位掩码版）：`AsKs4d` 11ms、`Ks7d2c` 12ms（不含 equity MC）。

### 5.3 正确性检查

- 快慢分类器对照：位掩码版 vs `_count_outs` 版，在同一批 combo 上
  的 `fd / outs / bd` 必须一致（允许 outs 张数与点数口径差异，需统一）。
- 花色：`7s8s` 必须 `fd=True`，`7h8h` 必须 `fd=False`。
- 街道：flop 有后门；turn/river 后门必须为 0。
- 牌面重复/不足 3 张 → `None`。
- 范围为空 → `None`，不要返回空范围让 equity 变 0。

## 6. 验收

### 6.1 分类单测（`AsKs4d`）

- `2h5h`：卡顺，分数 0.35，`call` 包含、`bet` 不包含；
- `3h4h`：对 4 + 后门顺，`call` 包含；
- `5s6s`：花听 + 后门顺，`call`/`bet` 包含；
- `7s8s`：花听，必须包含（不能被“78 无关”误杀）；
- `7h8h`：仅后门顺，默认排除；
- `QhJh`：卡顺，`call` 包含、`bet` 不包含（除非诈唬）；
- `2c2h`：underpair，`call` 低权重、`bet` 排除；
- `4c4h` / `AcAd`：set，`bet` 包含；
- `7h2o`：空气，排除。

### 6.2 范围与权益

- 纯牌面范围宽度在 40–70%（湿牌面）合理；干牌面 25–45%；
- ∩ BTN RFI 约 20–35%；∩ UTG RFI 约 8–20%；
- `AhQh`、`QhJh`、`5s6s` 的 behind/equity 方向符合直觉；
- 与暴力枚举（小范围、river）对照 ±2%；
- 同 board 同 mode 输出确定；缓存后 <1ms。

### 6.3 回放

20–30 手，覆盖：
- 对手下注/跟注/过牌三种 mode；
- flop/turn/river；
- 湿/干/ paired 牌面；
- 对比“只用翻前范围”和“牌面关联范围”的差异，记录哪些手结论反转。
  反转不一定是错，但要有解释（例如“过牌时不该筛掉空气”）。

## 7. 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 纯牌面范围当成“他的全部范围” | 把空气删光，高估对手 | 按动作选 mode；过牌用翻前范围 |
| 包含翻前不会玩的牌 | `25o/34o` 拉宽/拉弱范围 | 乘翻前先验；没有表用规则先验 |
| 按 169 类粗筛 | 误杀 `7s8s` 花听、漏 `QJ` 卡顺 | combo 级 + 花色特征 |
| 后门权重过高 | 范围虚宽、权益虚高 | 后门 ≤0.15；turn/river 归零 |
| 范围宽度随牌面剧烈变化 | 同一手在不同牌面答案不可比 | 渲染宽度/combo 数；报告 mode |
| 听牌重复计数 | outs/equity 虚高 | 用并集口径；权益用 MC，不用 outs 估算 |
| 模型过度信任 | 范围错时更自信 | 标注 `board-only` / `call mode`；给翻前对照 |
| 性能 | 实时/回放变慢 | 位掩码 + 缓存；批量降采样 |

## 8. 排期

| 阶段 | 工作 | 天数 |
|---|---|---|
| B0 | `board_range.py` 分类器 + 位掩码 + 单测 | 1 |
| B1 | 加权范围 + 动作 mode + 接 `field_ranges` / `hand_vs_ranges` | 1 |
| B2 | 性能/缓存 + 快慢对照 | 0.5 |
| B3 | 20–30 手回放校准 + 渲染口径 | 1 |

**合计 3–3.5 天**，可以和主方案的 P1 并行；如果先做 B0+B1，
两天内就能看到“`AhQh` 强 / `QhJh` 弱 / `5s6s` 听牌”的实时输出。

## 9. 一句话

**牌面关联范围能回答“我的手牌在有关联的牌里算强还是弱”，
但不能单独回答“他实际有什么”；把它做成按动作切换的条件范围，
并保留一个翻前先验，才是可用的实时范围。**
