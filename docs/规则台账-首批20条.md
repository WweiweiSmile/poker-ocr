### 0.2 新表 `poker_ocr/tables/rule_params.json`

书里的数字**不许写进 JSON 规则**（AGENTS 铁律）。全部落表，`verified: false`、`source` 写页码：

```json
{"kind": "rule_params", "name": "open_size_bb",
 "rows": {"early": 2.75, "middle": 3.25, "late": 3.75, "sb": 3.0},
 "source": "book:p19", "verified": false}
```

需要的条目：`open_size_bb`（按位置）、`threebet_multiplier`（3.0，盲注位 4.0，p26）、`fourbet_min_tier`（premium，p25）、`cbet_freq_hu`（0.65，p30）、`cbet_size_hu`（0.5，p30）、`cbet_size_paired`（0.4，p28）、`size_ladder`（强 1/3、中 2/3、弱 1.0，p35）、`block_bet`（0.25，p33）、`river_value_band`（[0.66, 1.0]，p52）、`iso_size_per_limper`（1.0，p23）。

> 规则 6/8 追加的两条（不在上面清单里）：`bb_complete_raise_bb`（BB 对 SB 补齐加注到 3BB，p22）与 `fourbet_multiplier`（4-bet 到对手加注的 2.2–2.5 倍，p25）。规则里不许写数字，所以规则 6/8 的尺寸必须落表。

### 0.3 槽位模型（决定“同时命中”算不算冲突）

每条规则只回答一个维度的问题，写进 `slot` 字段：

| slot | 回答 | 每个命中点最多命中 |
|---|---|---|
| `intent` | 要不要下注 / 跟 / 弃 / 加注 | 1 |
| `size` | 下多大（只能引用 `rule_params`，禁止字面数字） | 1 |
| `why` | 为什么（≤40 字，拼在动作行后） | 1 |

判定（写在 `tools/export_rules.py --check`）：

1. **同 slot + 前提有交集** → 判失败，除非该规则声明 `coexist_with: [<id>]`（白名单，且必须双向声明）。
2. **不同 slot** → 允许同时命中，各取一条，渲染时拼成动作行 + 尺寸行。
3. **同 slot 多条都合法** → 取前提条数最多者（更具体优先）；打平则判失败，要求作者补谓词。
4. 交集不用人工看：对两条规则的**公共谓词**做笛卡尔积枚举（谓词空间是有限枚举，全表 <100 条规则，毫秒级），任一组合两边都成立即算交集。

两个特例：

- `po.cbet.hu`（要不要下注）与 `po.size.texture`（下多大）是不同 slot，正常共存；但 `po.cbet.hu` 自己带默认尺寸 `cbet_size_hu`，所以它与 `po.size.texture` 在 size 维度会撞——声明 `coexist_with: ["po.size.texture"]`，并让**牌面规则优先**（更具体的尺寸覆盖默认半池）。牌面规则未命中时才退回半池，这正是 p35“按牌面选尺寸”的本意。
- `ex.station` / `ex.loose` / `ex.tight_passive` 是 `intent` 槽的修正层，与基础规则同 slot 但前提里带 `opponent_archetype`，与基础规则（不带画像谓词）天然有交集——因此它们**不进普通匹配**，由 `render_rules_zh` 在命中基础规则后按画像追加一行“修正”。这是 slot 模型唯一的显式例外，写进 loader 的注释。
