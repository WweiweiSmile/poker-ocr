# 对手行动线改为「证据驱动 + 街末最小补全」

现状 692 条动作里 380 条是 inferred，其中 290 条弃牌全部由街末按 `seat_id` 排序补出，顺序与发生时刻脱节；名称区徽章只做精确匹配，头像弃牌状态从不落成行动。屏幕能给出的事实只有五类：名称区行动类型、头像弃牌、注额金额、底池约束、观测时刻顺序；盲注是强制投入，没有徽章。因此行动线改为由带时间戳的证据事件归约而成，证据优先级为 **名称区动作 > 头像弃牌 > 本街注额差 > 底池账本**：徽章只决定类型，金额永远取「本街加到总额」；弃牌是一等动作，连续 2 帧确认、按首次观测时刻入序，街末不再补；盲注只做基线，「没看到徽章」只当负证据；街末只补不变量唯一决定的类型与金额，标 `source=ledger`，顺序不确定则标 `order_unknown` 并放街末，不伪造顺序。

徽章解析允许前后缀剥离与子串命中（名字槽只认四类动作：让/跟/下/加）；单字一律不单独成动作，交给注额反推并标 `source=bet_delta`；弃牌只从头像读；含徽章词的帧不更新玩家名字。引入轻量「待行动集合」（位置顺序 + 已行动标记 + 本街水位 + fold/all-in）来判断街何时结束、谁还欠动作；同帧动作仍按下注额排序，同额歧义标 `order_unknown`；不读 UI 回合指示器，不做最小加注。英雄位纳入同一套顺序，金额仍走底池反解。

## Considered Options

- **保持每帧每座位独立判定 + 街末批量补**：弃牌顺序和完整性都无法保证，且无法区分「徽章漏读」与「确实没轮到」。
- **完整回合状态机**：需要识别 UI 回合指示器，并实现最小加注 / 短 All-in 合法性，成本与误判面都过大。
- **以底池账本为最高优先级**：金额最可靠，但类型和顺序不可得，正是当前失真的来源。

## Consequences

- 弃牌 inferred 归零，总 inferred 验收线 ≤25%（现状 55%）；行动线顺序可解释。
- 新增 `source` / `order_unknown` 字段；prompt 模板不改，但 `CURRENT_ADVICE_VERSION` 必须 bump，否则新旧行动线在复盘里混在一起无法比较。DB 只加 JSON 字段，不改表。
- 徽章单帧即认，误读会直接成为事实；靠质量闸门（注额不可信、超过本街总注）与 `source` 兜底。
- 同额跟注之间仍可能 `order_unknown`；不做历史数据回填，只对新产生的行动线生效。
- 模块落点、开关与回滚方式放在 spec，不在本 ADR。
