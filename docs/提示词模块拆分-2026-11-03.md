# 提示词按功能/场景拆分（2026-11-03）

> 对象：live 实时建议的中文 lean 提示词。
> 版本：`PROMPT_VERSION = lean-zh-2026-11-03.1`，
> `CURRENT_ADVICE_VERSION = advice-2026-11-03.1`。
> 结论：提示词代码从单文件 `poker_ocr/advice.py` 拆成
> `poker_ocr/prompt/` 包（system / user / shared / offline）+ `poker_ocr/pot_math.py`；
> 拆分本身不改变任何事实块文本，system 按局面新增五个**条件场景段**。

---

## 1. 为什么拆

拆分前 `advice.py` 有 5200+ 行，提示词和「算牌桌」的代码混在一起：

- system、user 事实块、逐座位画像、桌况统计、攻击/剥削结论、旧英文提示词、
  Value directive、Math gate、复盘审计标签全在一个文件；
- 改「听牌口径」要在 2000 行里找，容易顺手改到另一段；
- 新人看不出「哪段是事实、哪段是建议、哪段是历史遗留」；
- system 只有一个大字符串 + 前注局特例，想加「短码/多人池」只能继续往
  恒定段里塞绝对规则——`docs/提示词审阅-2026-11-02-系统性冲突.md` 已经
  证明这条路会制造互相矛盾的规则。

拆分的判据只有一条：**一段文字只服务一个决策问题**。同一件事（比如人数）
在事实层只写一次，在 system 场景段只写「拿到这个数字之后怎么权衡」。

## 2. 现在的结构

```text
poker_ocr/
├── pot_math.py               牌桌几何/赔率/位置纯计算（不渲染文字）
└── prompt/
    ├── __init__.py           对外入口：build_messages / build_system / PROMPT_VERSION
    ├── version.py            PROMPT_VERSION / PROMPT_LANGUAGE
    ├── shared/
    │   ├── format.py         BB 数字格式（唯一口径）
    │   └── labels.py         街/底池类型/翻前形态/花色/牌型/质地词表
    ├── system/
    │   ├── __init__.py       组装：恒定段 + 前注局 + 场景段
    │   ├── intro.py          角色与节奏
    │   ├── output.py         输出契约（只回一个 option id + reason）
    │   ├── priority.py       五级事实优先级
    │   ├── decision.py       决策顺序（翻前/翻后/听牌/多人池/位置/河牌/尺度）
    │   ├── metrics.py        指标口径（四二法则、对当前范围权益、落后）
    │   ├── stack.py          筹码深度（有效筹码/可玩深度/SPR）
    │   ├── ante.py           场景：前注局
    │   └── scenario.py       场景：短码 / 多人池 / 单挑 / 听牌 / 河牌
    ├── user/
    │   ├── __init__.py       组装：顺序 + 空行（不写事实）
    │   ├── situation.py      当前局面：桌况/在局/Hero/街道
    │   ├── geometry.py       有效筹码/可玩深度/SPR/底池类型/短码/已投入
    │   ├── position.py       翻后位置/身后待行动 + 谁还没跟到最高注
    │   ├── price.py          赔率门槛/可争夺底池
    │   ├── explosive.py      爆炸底池结构与权益（无特殊打法规则）
    │   ├── action_line.py    行动线（每个街的动作顺序，含「推断」标记）
    │   ├── preflop.py        翻前形态/PFR/范围结论/面对加注的继续范围
    │   ├── strength.py       实时牌力（牌型/坚果/听牌/对范围权益/价格）
    │   ├── ranges.py         对手范围：线路/宽度/分区/谁赢我/封顶
    │   ├── profiles.py       逐座位对手画像
    │   ├── table_stats.py    桌况统计 + 可执行读法（stab/剥削口径）
    │   ├── notes.py          人工观察（.table_dy）的过滤与条件化
    │   ├── attack.py         攻击/剥削的单一裁决
    │   ├── quality.py        数据质量（硬缺口/范围缺口）
    │   └── options.py        可选动作（id + 中文标签 + 实际金额）
    └── offline/
        ├── strategy.py       旧策略层：Value directive / Math gate / 价值取向
        ├── hand_facts.py     旧英文事实块 render_hand_facts
        └── audit.py          复盘审计 audit_advice_tags
```

`advice.py` 现在只做三件事：**算事实**（`build_situation`）、**给选项**
（`build_options`）、**调模型/兜底**（`advise` / `AdviceRunner`）。它仍
re-export 所有旧名字（`render_facts_zh`、`render_hand_facts`、`value_directive`、
`audit_advice_tags`、`call_amount`……），旧调用方与测试的 import 路径不变。

## 3. 数据流

```text
HandSnapshot + 对手画像/桌况/人工观察
        │  advice.build_situation()
        ▼
    Situation（结构化事实）
        │  prompt.user.render_facts_zh()      prompt.system.build_system()
        ▼                                    ▼
    user 事实块（## 当前局面 … ## 可选动作）  system（契约 + 场景规则）
        └────────────── build_messages() ────┘
                          │
                          ▼
                 /chat/completions → {"option": "...", "reason": "..."}
```

事实块里的每个数都由程序算好（`pot_math` / `ground_truth` / `hand_vs_ranges` /
`opponent_profile`），模型只做选择；`offline/` 的旧规则层不再进入 live prompt。

## 4. 分段顺序

### system

| 顺序 | 段 | 文件 | 何时出现 |
|---|---|---|---|
| 1 | 角色 | `system/intro.py` | 恒定 |
| 2 | 输出契约 | `system/output.py` | 恒定 |
| 3 | 事实优先级 | `system/priority.py` | 恒定 |
| 4 | 决策顺序 | `system/decision.py` | 恒定 |
| 5 | 指标口径 | `system/metrics.py` | 恒定 |
| 6 | 筹码深度 | `system/stack.py` | 恒定 |
| 7 | 前注局 | `system/ante.py` | `blinds.ante` 有值 |
| 8 | 短码 | `system/scenario.py` | Hero 总筹码 ≤ 20BB |
| 9 | 多人池 | `system/scenario.py` | 在局对手 ≥ 2（3 人以上） |
| 10 | 单挑 | `system/scenario.py` | 在局对手 = 1 |
| 11 | 听牌 | `system/scenario.py` | 强听/弱听，或成牌+≥8 outs |
| 12 | 河牌 | `system/scenario.py` | `street == river` |

### user

`## 当前局面`（桌况/在局/Hero/街道 → 几何 → 位置 → 价格 → 短码 → 爆炸底池）
→ `## 行动线` → `## 翻前信息`（仅翻前）→ `## 实时牌力`（仅翻后）→
`## 对手画像` → 桌况统计 → `## 人工观察`（有 `.table_dy` 时）→ 攻击/剥削
（仅溜入池收尾）→ `## 数据质量` → `## 可选动作`。

空列表 = 该段不出现；空行由 `user/__init__.py` 统一插，单段模块不自己加。

## 5. 场景段的设计约束

来自 2026-11-02 的系统性审阅：**问题不是事实不够，而是规则太多、口径不一、
没有仲裁**。所以场景段必须满足：

1. **条件句优先**：写「如果…则…；除非…」，不写「只用/绝不/永远」。
2. **不重复事实**：人数、SPR、outs、赔率都在 user 块；场景段只讲权衡。
3. **不覆盖优先级**：事实优先级仍然最高，场景段是「在同一层事实内怎么读」。
4. **一段一场景**：多人池段不写河牌的事，河牌段不写听牌的价格口径。
5. **长度不设产品上限**：多 300–500 字换一次错误全下的减少是划算的；但
   `tests/test_advice.py` 保留 `< 6000` 的回归闸，防止无意重复。

新增场景：在 `system/scenario.py` 加 `_xxx_section(sit) -> str | None`，注册到
`SCENARIO_SECTIONS`；不要往 `SYSTEM_SECTIONS`（恒定段）里加局面规则。

## 6. 版本与回归

改提示词文本（system 任一段、user 任一段）时：

1. bump `prompt/version.py` 的 `PROMPT_VERSION`；
2. bump `replay-console/replay/versioning.py` 的 `CURRENT_ADVICE_VERSION`；
3. 更新 `replay-console/tests/test_prompt_golden.py` 的
   `EXPECTED_ADVICE_VERSION` 与 `EXPECTED_PROMPT_HASH`；
4. 同步 README 与本文的版本号。

只挪代码、不改文本时不需要 bump（golden hash 不变），但 `PROMPT_VERSION` 是
「模型看到的语义版本」，不是代码位置版本。

验证：

```bash
.venv/bin/python -m pytest tests/test_advice.py -q
.venv/bin/python -m pytest replay-console/tests -q
.venv/bin/python tests/run_all.py
```

## 7. 迁移对照（旧位置 → 新位置）

| 旧 `advice.py` | 新位置 |
|---|---|
| `SYSTEM_CORE_ZH` / `SYSTEM_ANTE_ZH` / `build_system` | `prompt/system/*` |
| `render_facts_zh` + 各 `render_*_zh` | `prompt/user/*` |
| `_fmt_num` / 中文词表 | `prompt/shared/` |
| `render_hand_facts` / `render_opponent_reads` | `prompt/offline/hand_facts.py` |
| `value_directive` / `math_gate` / 价值取向 helpers | `prompt/offline/strategy.py` |
| `audit_advice_tags` | `prompt/offline/audit.py` |
| `call_amount` / `spr` / `behind_opponents` / `previous_street_pot` / 有效筹码 | `pot_math.py` |

拆分时用 10 个代表性局面（3-bet 池、多人池、转牌听牌、河牌全下、炸弹池、
前注局、0 对手异常、短码、溜入池、golden）对拆分前后做了逐字节 diff：
**事实块与 system 恒定段完全一致**，只有新增场景段与版本号不同。
