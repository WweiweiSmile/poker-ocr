# 对手打法标签与剥削建议 — 设计文档

> 状态：设计（未实现）。基线：2026-11-09，本库 892 手 / 121 个进统计的对手。
> 体检数据由 `tools/label_feasibility_audit.py` 生成，可随样本增长复跑。
> 关联文档：[对手类型识别-设计.md](对手类型识别-设计.md)、
> [对手画像-推断口径-2026-11-01.md](对手画像-推断口径-2026-11-01.md)、
> [摊牌反核-2026-11-05.md](摊牌反核-2026-11-05.md)、
> [对手范围-事件模型-设计.md](对手范围-事件模型-设计.md)。

## 0. 结论摘要

1. **能做**，但必须先承认一件事：**决定标签能不能做的不是难度，是样本量**。
   本库实测：`3-bet` 有 69 个玩家达标（18 手/人），`面对溜入隔离加注`有 56 人
   达标（24 手/人）；而 `c-bet` 只有 15 人（167 手/人）、`check-raise` 只有
   9 人（223 手/人）、`barrel` 是 **0 人**（452 手/人）、`被 3-bet 弃牌` 也是
   **0 人**（489 手/人）。
2. **现有 `exploit_hint_zh` 的主要分支在真实数据上基本不触发**：129 个玩家只有
   53 个能出结论，且集中在 `stab` / `面对下注弃(转/河)` / `溜入` 三支；它最依赖
   的 `fold_to_cbet` / `check_raise` / `barrel` / `fold_to_3bet` 全部落在「没有
   实测值」区。
3. **"在 BTN 偷盲"这个具体案例，本池做不出来**：`BTN 开池` 有 0 个玩家达标，
   每人需要约 616 手。松桌里"全员弃到 BTN"几乎不发生。**替代口径是
   `面对溜入的隔离加注`（32.8 次/百手，是 BTN 开池机会的 25 倍）**——同一个
   "抢底池"行为，在松桌里长成了另一个形状。
4. **落地方案是三层**：事实（已有 17 个带门槛的方向性指标）→ 标签（新，带证据与
   门槛）→ 打法（局面 → 动作，按决策点检索而不是全量渲染）。
5. **必须先修 4 个口径 bug**，否则标签是错的：BB 走牌被算成"开池机会却没开"、
   `iso-raise` 完全没采、单张亮牌被整体丢弃、`bet_sizes` 没有街维度。

## 1. 背景与问题

### 1.1 现有画像到哪一步

| 层 | 产物 | 位置 |
|---|---|---|
| 观察 | `HandObservation`，每手每个对手一条 | `opponent_profile.py:309` |
| 聚合 | `OpponentStats`，β 收缩 + 机会数门槛 | `opponent_profile.py:1053` |
| 类型 | 5 类 softmax：station/lag/maniac/nit/tag | `classify()` `:1810` |
| 提示 | `render_tendencies_zh` 数字行 + `exploit_hint_zh` 最多 2 条方向 | `:2633` / `:2719` |
| 注入 | `prompt/user/profiles.py`、`prompt/user/attack.py` | — |
| 范围 | `range_flow` 按 archetype 的 bluff/call 乘数 | `range_flow.py:417` |

### 1.2 三个缺口

1. **标签是性格词，不是局面**。"松凶"不能告诉模型这一刻该下注还是过牌。
2. **类型是单标签**。同一个人可以同时"爱溜入 + 从不 3-bet + 面对下注弃得多"，
   softmax 只能选一个。
3. **没有证据分级**。模型分不清"实测 12/18"和"3 次机会收缩出来的估计"，
   更分不清"动作频率实测"和"牌力强弱未验证"。

## 2. 目标与非目标

### 2.1 目标

- G1 每个标签是**可反驳的局面断言**，带机会数、命中数、证据类型。
- G2 标签能翻译成**"这个局面 → 这个动作"**，而不只是描述。
- G3 标签**按数据可得性分档**，样本不足的标签不出、或明确标为估计。
- G4 提示词里**按当前决策点检索**，不把 15 个标签 × 9 个座位全灌进去。

### 2.2 非目标（明确不做）

- ❌ 位置级开池率（BTN/CO/SB/BB 单独）：每人需 450–650 手，当前 0 人达标。
- ❌ 每分钟级/实时重算标签：标签是慢变量，离线预计算。
- ❌ per-player 完整范围表：摊牌样本 22 人达标，只够校准**一个**乘数。
- ❌ 用标签改写牌力判断：`ground_truth` 永远是权威（见 §6.3）。
- ❌ LLM 生成标签措辞：规则表优先，可审计、可回归。

## 3. 名词与口径

| 名词                   | 口径                                                                           |
| -------------------- | ---------------------------------------------------------------------------- |
| **局面键** `spot`       | `<street>.<situation>[.<street>][.<position-class>]`，如 `preflop.facing_limp` |
| **机会** `opp`         | 这个局面出现的次数。**必须有机会数才能算比率**                                                    |
| **命中** `hit`         | 在这个局面里做了目标动作的次数                                                              |
| **门槛** `min_opps`    | 机会数下限。低于它只能给收缩估计，不给指令                                                        |
| **实测** `measured`    | `opp >= min_opps`，比率即实测值                                                     |
| **收缩** `shrunk`      | `opp < min_opps`，向人群先验收缩，渲染加 `≈`                                             |
| **未验证** `unverified` | 频率是实测的，但**牌力强弱没有摊牌证据**                                                       |

**关键区分**：`≈` 说的是"样本不够"，`unverified` 说的是"证据类型不够"。
两者风险不同，不能共用一个标记（现在只有 `≈`）。

### 3.1 错误率约定

标签是统计推断，必须给出可接受的误判边界：

- `measured` 标签的目标准确率 ≥ 85%（对人工标注集）；
- `shrunk` 标签只允许出现在"描述"里，**不允许**产生动作建议；
- `unverified` 标签允许产生动作建议，但措辞必须带"未验证"。

### 4.3 三条结论

**① 按数据可得性排序，而不是按理论重要性排序。**

统计上最重要的三个剥削点（c-bet 弃牌率、过牌-加注、转牌续打）恰好是最稀薄
的三个。而"3-bet 频率""溜入""隔离加注""没人下注时开火"这四个几乎人人有
数据。**标签清单必须倒过来排。**

**② 现有剥削提示有大量死分支。**

对 129 个玩家跑 `classify` + `exploit_hint_zh`：

- 有类型 77 人，能出剥削结论 **53 人**，为空 76 人（52 个 unknown + 24 个有
  类型但无实测指标）；
- 能出结论的高度集中：`stab`、`面对下注弃(转)`、`面对下注弃(河)`、`溜入`；
- `对 c-bet 弃`、`过牌-加注`、`第二枪`、`被 3-bet 弃` 这些分支几乎从不触发。

原因不是代码写错，是 `_confident()` 会丢弃被先验收缩的值，而这些指标的
机会数从来没到过 8。

**③ 用户案例要换口径，不是换代码。**

"BTN 无人开池时偷盲"在本池 0 人达标。同一个行为意图在松桌里的高发形态是
**面对溜入隔离加注**（32.8 次/百手）。所以首批标签里，`BTN 偷盲` 被
`facing_limp.iso` 替代，并在措辞上写清"面对溜入"，不假装知道位置。

## 5. 标签体系设计

### 5.1 标签四元组

```
Label = (spot, direction, evidence, counter)
```

- `spot`：局面键，决定"在什么情况下成立"；
- `direction`：方向断言，二值（高/低），**不是程度副词**；
- `evidence`：`hit/opp` + `gate` + `basis`；
- `counter`：反制动作，只有 `measured` 才允许生成。

标签**不写数字在正文里**，数字由渲染器从 evidence 拼，避免文案和统计不同步。

### 5.2 局面键语法

```
<street>.<situation>.<street?>.<position-class?>
```

首批只用两级（street + situation），position-class 只保留 `blinds`：

| spot | 含义 |
|---|---|
| `preflop.unopened` | 轮到我时前面无人主动入池 |
| `preflop.facing_limp` | 前面有人跟注且无人加注 |
| `preflop.facing_raise` | 前面有人加注 → 3-bet 机会 |
| `postflop.unopened.<street>` | 前面全过牌轮到我 |
| `postflop.facing_bet.<street>` | 这条街前面有人下注 |
| `postflop.cbet` | 我是翻前最后加注者，翻牌第一个行动 |
| `showdown.aggressive` | 摊牌时曾主动下注/加注 |

**不做** `*.btn`、`*.co` 这类位置修饰（§2.2）。

### 5.3 证据三级

| gate | 条件 | 渲染 | 能否出动作 |
|---|---|---|---|
| `measured` | `opp >= min_opps` | `58%（17 次）` | ✅ |
| `shrunk` | `0 < opp < min_opps` | `≈58%（6 次，样本不足）` | ❌ |
| `insufficient` | `opp == 0` | 不渲染该标签 | ❌ |

`basis` 独立标记：`action`（动作频率）或 `showdown`（牌力校准）。
`basis=action` 的标签在无摊牌玩家上照常成立；`basis=showdown` 的标签必须
有摊牌样本，否则整个标签不出现。

### 5.4 首批标签清单

门槛默认 `min_opps = 8`，与 `TENDENCY_MIN_OPPS` 对齐。阈值放在
`poker_ocr/tables/`（可导出、可 diff），不写死在 `.py` 里。

分档按**每百手出现率**（决定攒样本的成本），不按"人数多少"——人数是结果，
不是原因。

- Tier A：每百手 ≥ 15 次 → 每人 50 手内可攒够 8 次机会；
- Tier B：每百手 4–15 次 → 需 50–200 手；
- Tier C：每百手 < 4 次 → 需 200 手以上，**暂不做**。

#### Tier A — 现在就能做（每百手 ≥ 15；≥8 达标 43–69 人）

| 标签 key | spot | 判据 | 反制动作 |
|---|---|---|---|
| `preflop.3bet_high` | facing_raise | 3-bet ≥ 12% | 他 3-bet 宽 → 收紧开池，准备 4-bet 陷阱 |
| `preflop.3bet_none` | facing_raise | 3-bet ≤ 3% | 他从不 3-bet → 平跟范围弱，可宽 iso |
| `preflop.limp_high` | unopened | 溜入 ≥ 30% | 有位置直接隔离加注 |
| `preflop.iso_high` | facing_limp | 隔离 ≥ 50% | 少 limp，用 limp-reraise |
| `preflop.iso_none` | facing_limp | 隔离 ≤ 15% | 可以多 limp 便宜看翻牌 |
| `preflop.open_wide` | unopened | 开池 ≥ 35% | 宽 3-bet 挤压 |
| `postflop.stab_high` | unopened | stab ≥ 50% | 过牌给他准备 check-raise |
| `postflop.stab_low` | unopened | stab ≤ 25% | 他过牌≈放弃，下一街接管 |
| `postflop.fold_flop_high` | facing_bet.flop | 弃 ≥ 60% | 高频小注 |
| `postflop.fold_flop_low` | facing_bet.flop | 弃 ≤ 35% | 别用空气开火，价值牌打大 |

#### Tier B — 需要 2–4 倍样本（每百手 4–15；≥8 达标 9–31 人）

| 标签 key | spot | 判据 | 备注 |
|---|---|---|---|
| `postflop.cbet_high/low` | cbet | ≥ 75% / ≤ 40% | 15 人达标，先只做描述 |
| `postflop.fold_turn_low` | facing_bet.turn | ≤ 40% | 25 人 |
| `postflop.fold_river_low` | facing_bet.river | ≤ 35% | 23 人（含推断补推，需标 inferred） |
| `preflop.open_wide_ep` | unopened.EP | ≥ 25% | 31 人 |
| `showdown.bluffy` | showdown | 弱牌激进 ≥ 50% | 9 人，`basis=showdown` |

#### Tier C — 现在不做（每百手 < 4；≥8 达标 0–9 人）

`check_raise`、`fold_to_cbet`、`call_to_cbet`、`barrel`、`fold_to_3bet`、
位置级开池（BTN/CO/SB/BB）、单张亮牌、牌面类型 × c-bet。

**但保留数据采集**：这些计数器继续累加，等样本到量后由体检脚本自动升档。
`CLASSIFIER_VERSION` 变化时重跑体检即可。

### 5.5 冲突消解

沿用 `exploit_hint_zh` 的 block/support 思路，规则升级为：

1. 同一 `spot` 只出一个方向（high 与 low 互斥，取证据更强的）；
2. 跨 spot 冲突时，**反向证据优先**（"别开火"压过"可以开火"）；
3. 每座位最多 2 条 `counter`，超出按优先级截断；
4. `shrunk` 标签永不进 `counter` 列表。

## 6. 打法层设计

### 6.1 标签 → 动作

映射表是一张**静态字典**：`label_key → counter_text`，放在
`poker_ocr/tables/labels.json`。动作文本只描述"方向 + 尺度倾向"，不写具体
牌型，避免和 `ground_truth` 抢权威。

```
preflop.iso_none  →  面对他的溜入少加注，多用 limp 便宜进池
postflop.stab_high →  过牌给他要准备 check-raise；弱牌别过牌白跟
```

### 6.2 按决策点检索

渲染前先按当前局面过滤，**不是把全部标签灌进提示词**：

```
候选 = [L for L in 该座位标签 if 匹配(当前 street, 当前 facing, 当前 spot)]
候选 = [L for L in 候选 if L.gate == "measured" or 允许估计]
候选 = 按优先级取前 2 条
```

匹配规则：翻前只取 `preflop.*`；面对下注只取 `facing_bet.<当前街>`；
无人下注只取 `stab` / `unopened`。这样每座位最多 2 条，9 个座位 ≤ 18 行。

### 6.3 与 `ground_truth` 的优先级（硬约束）

| 内容 | 权威性 |
|---|---|
| `ground_truth`（牌力/胜率/听牌） | **最高，不可被标签覆盖** |
| `options`（可选 id 与金额） | 模型只能从中选 |
| 标签 / 打法 | **只影响频率与尺度倾向** |

标签**不允许**出现"因为他爱诈唬所以你该跟注"这种跨层推理；只允许
"这个局面他的弃牌率低 → 价值下注优先"。这条要写进提示词的系统段。

## 7. 数据契约

### 7.1 `HandObservation` 新增字段

```python
# 新增（全部默认 False/0，旧记录不受影响）
walk: bool = False            # 全员弃牌到 BB，本手不是开池机会
iso_opp: bool = False         # 面对 >=1 个 limp 且无人加注
iso_raised: bool = False      # 在该局面里加注
flop_players: int = 0         # 进翻牌人数（1/2/3/4+）
board_texture: str = ""       # dry / wet / paired / monotone
showdown_cards: int = 0       # 亮牌张数（0/1/2）
showdown_weak: bool = False   # 牌型 <= 一对（需 2 张）
bet_sizes_by_street: dict = field(default_factory=dict)  # street -> tuple[float]
```

### 7.2 `OpponentStats` 新增字段

与上面一一对应的加权计数（`add()` 里乘 `weight`）：

```python
walk_hands: float
iso_opp: float; iso_raised: float
flop_players_2: float; flop_players_3: float; flop_players_4p: float
board_dry_opp: float; board_wet_opp: float
showdown_1card: float; showdown_2card: float
weak_showdowns: float       # 摊牌牌型 <= 一对（任意，不要求曾主动下注）
```

`to_dict` / `from_dict` 必须同步，且 `from_dict` 对缺失字段保持 0（旧文件可读）。

### 7.3 标签存储

`data/opponents/profiles.json` → v2，每个玩家多一个 `labels` 数组：

```json
{
  "labels": [
    {
      "key": "preflop.iso_high",
      "spot": "preflop.facing_limp",
      "hit": 14, "opp": 21, "pct": 67,
      "gate": "measured", "basis": "action",
      "min_opps": 8, "window": 200
    }
  ],
  "label_version": "labels-2026-11-09a"
}
```

- 标签**离线预计算**，实时只读；
- `window`：统计窗口（手数），`0` = 全历史。首批统一 `200`；
- 文件顶层加 `label_version`，与 `classifier_version` 独立递增。

### 7.4 版本与重建

| 版本号 | 何时 bump |
|---|---|
| `CLASSIFIER_VERSION` | 5 类 archetype 的规则/阈值变动 |
| `LABEL_VERSION` | 标签清单、阈值、`min_opps` 变动 |
| `PROMPT_VERSION` | 提示词文案/结构变动 |

改动后跑：

```bash
nv tools/rebuild_opponent_profiles.py --hands ... --reset
nv tools/label_feasibility_audit.py     # 确认标签没饿死
```

`rebuild` 是唯一事实来源路径：手牌记录 → 观察 → 统计 → 标签，全程可复现。

## 8. 前置修复（先做，否则标签是错的）

### 8.1 BB 走牌不算开池机会

现状：`open_opp = 前面无人主动入池`。全员弃到 BB 时 BB 没有动作，
`open_opp=True` 且 `opened=False`，**系统性拉低 BB 开池率**。
本库 11 手。（`audit` 的 `preflop.unopened.walk` 已能看见。）

修法：`walk=True` 时不计入 `open_opp`，单独计 `walk_hands`。

### 8.2 `iso-raise` 未采集

BB/SB 面对 limper 的加注是松桌最高发的"抢池"形态，现在完全不在
`HandObservation` 里（只作为普通 `pfr` 被稀释）。本库 32.8 次/百手。

### 8.3 单张亮牌被整体丢弃

`_showdown()` 要求 `len(cards) == 2`，而河里主动秀一张时记录只有一张
（本库 36 人出现过）。至少能排除"他有 A"这类信息，现在为零。

### 8.4 `bet_sizes` 没有街维度

现在是扁平列表，无法回答"他河牌是不是爱超池"。需要按街存。

### 8.5 赢家字段缺失（本设计不依赖，但要记录）

手牌记录只有 `shows`，没有 winner/pot award。所以"打到摊牌、没亮牌、
且输了"这条负信息通道是断的。修它需要 OCR 侧识别收池动画，成本高，
**不进首批**。

## 9. 提示词接入

### 9.1 渲染位置

在 `prompt/user/profiles.py` 的逐座位块里追加两行：

```
BTN 陈7程 n=211 紧凶 conf=0.66
  动作线：开池 24%（21 次）｜3-bet 5%（19 次）｜溜入 32%（18 次）｜没人下注时开火 58%（17 次）
  标签：爱溜入（32%，18 次，实测）｜没人下注就开火（58%，17 次，实测）
  打法：有位置时放宽隔离；你过牌给他要准备 check-raise
```

- 最多 2 条标签 + 2 条打法；
- 没有 `measured` 标签时不输出"标签/打法"行（不占预算）；
- `shrunk` 标签单独一行，前缀 `≈`，且永不产生打法。

### 9.2 长度预算

9 个座位 × 2 行 ≈ 18 行；估算 < 600 token。超出时按优先级截断：
先删 `shrunk` 标签，再删打法，最后删动作线。

### 9.3 版本流程

按 AGENTS.md 三步走：改文案 → bump `PROMPT_VERSION` +
`CURRENT_ADVICE_VERSION` → 更新 `test_prompt_golden.py` 的
`EXPECTED_ADVICE_VERSION` / `EXPECTED_PROMPT_HASH`。

#### C2. 人工标注集（50–100 手）

标签对不对**没法自动验证**，必须人看。需要你按下面格式标 50–100 手，
优先挑"你印象里风格很鲜明"的对手：

```jsonl
{"hand_uid": "20261101-695bb6e571", "seat_name": "陈7程",
 "line": "BTN 无人入池 → 开池 3BB → 翻牌 c-bet 1/3 → 转牌过牌 → 河牌弃",
 "my_label": "爱开池/翻后一枪就停", "my_counter": "跟一枪，转牌他过牌就接管",
 "confidence": "high", "note": "看过他很多次，转牌基本不续"}
```

字段说明：

| 字段 | 必填 | 说明 |
|---|---|---|
| `hand_uid` | ✅ | 手牌 id，用来回查原始记录 |
| `seat_name` | ✅ | 对手名字（与画像键一致） |
| `line` | ✅ | 这一手他的行动线，用你自己的话写 |
| `my_label` | ✅ | 你认为他这手的风格/意图 |
| `my_counter` | ✅ | 你实际会怎么打他 |
| `confidence` | ✅ | high / medium / low |
| `note` | ⬜ | 依据 |

用途：
1. 算标签准确率（`measured` 标签目标 ≥ 85%）；
2. 定阈值（现在阈值是经验值 + 现有 `exploit_hint_zh` 的旧门槛）；
3. 找出"统计说 A、人说是 B"的冲突，那通常是口径 bug。

#### C3. 口径确认（4 个问题，需要你拍板）

1. **BB 走牌**算不算开池机会？建议**不算**（会拉低 BB 开池率）。
2. **多人池**要不要单独统计？建议按 2 / 3 / 4+ 三档（本池 81% 是 3 人以上）。
3. **时间窗**：全历史还是最近 200 手？建议 200 手（玩家会调整）。
4. **同名换人**：现在靠 roster + alias 合并，改名就分裂。要不要接受？

#### C4. 目标桌型确认

本池 **81% 的翻牌是 3 人以上，HU 只 18.7%**，牌面 48% 双色 / 48% 彩虹 / 18%
成对。如果你的主要场景是 6-max 或单挑，数据分布完全不同——**标签阈值要重定**，
需要另外采一批该桌型的样本。

#### C5. 可选增强（不进首批）

- **赢家识别**：录收池，打通"摊牌没亮牌但输了"的负信息通道（§8.5）；
- **亮牌快照**：把亮出的牌存进画像（而不是只存牌型档），支持"他 3-bet 亮过
  什么"这类问题；
- **同桌基线**：用同桌其他人的亮牌做相对校准（§4.3 提到的人群先验已有，缺的是
  同桌粒度）。

## 11. 验收与 A/B

1. **单元层**：每个标签一个正例 + 一个反例 + 一个样本不足例；
   `tests/test_opponent_profile.py` 已有骨架，按同样风格加。
2. **回归层**：`rebuild_opponent_profiles.py --reset` 后，`label_feasibility_audit`
   的 ≥8 人数不下降（防止改口径把样本改没）。
3. **人工层**：C2 标注集上 `measured` 标签准确率 ≥ 85%。
4. **端到端 A/B**：用 `tools/ab_diff.py` 对比"有标签 vs 无标签"两版建议，
   看三件事：建议是否更具体（动作+尺度）、是否与 `ground_truth` 冲突
   （必须为 0）、是否有过度剥削（把 `measured` 标签当绝对真理）。
5. **线上观测**：`advice.context` 里记录本次用到的标签（key + hit/opp），
   复盘时能回答"模型当时看到了什么"。

## 12. 风险

| 风险 | 表现 | 缓解 |
|---|---|---|
| 样本不足 | 标签晃来晃去 | 门槛 + 收缩 + 体检脚本升档 |
| 过拟合 | 3 次机会算出 100% | `shrunk` 永不产生动作 |
| OCR 误识别 | 动作是推断补的 | `inferred_ratio` 进门槛；`basis` 标 `inferred` |
| 身份漂移 | 改名即分裂 | roster + alias；标签只对稳定名字出 |
| 自我实现 | AI 按标签打，对手调整 | 时间窗 200 手；标签不写进"事实" |
| 提示词膨胀 | 9 座位 × 15 标签 | 按局面检索，每座位 ≤ 2 条 |
| 跨层推理 | 用标签否定牌力 | §6.3 硬约束 + A/B 冲突计数 |
