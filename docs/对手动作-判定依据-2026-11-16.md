## 0. 三句话

1. 代码里只有 **5 种动作类型**：`check / call / bet / raise / fold`（`poker_ocr/hand_track.py:74`）。
   **「全下」不是动作类型**，是挂在任意一条动作上的 `all_in` 标记（`ActionRecord.all_in`，`poker_ocr/hand_track.py:253`）。
2. 动作事实有 **4 个来源**（`ACTION_SOURCES`，`poker_ocr/hand_track.py:80`）：
   名字槽徽章 `badge`、头像弃牌 `avatar_fold`、注额差反推 `bet_delta`、街末底池对账 `ledger`。
   前两个是**观测**，后两个是**推断**（`INFERRED_SOURCES`，落库标「推断」）。
3. 逐帧判定在 `frame_state._build_players`，逐手判定/去重/补全在 `hand_track`：
   实时去重 `_record_actions`（`:1349`）、头像弃牌 2 帧确认 `_record_avatar_folds`（`:1616`）、
   换街对账 `_reconcile_street`（`:1971`）、街末补全 `_finalize_street`（`:2333`）、手末补跟注 `_complete_calls`（`:2437`）。
4. 实时出建议前还有两道闸：本街账单对不上（`street_account_mismatch`），或**有对手的下注读数不可信**
   （`opponent_bet_unknown`）——这时这一帧不出建议，也不占 `advised` 名额（§4.1）。

```
画面帧
  ├─ 名字槽文本 ──parse.parse_action────────► check / call / bet / raise
  ├─ 头像文本 ───is_fold_badge / is_all_in_badge─► fold 判定 / all_in 标记
  ├─ bet pill ──parse_amount + 质量闸────────► 本街加到总额（BB）
  └─ 底池(两横幅) ──pot − pot_before_street──► 本街总额（校验/对账用）
        │
        ▼
  hand_track._record_actions  （逐帧追加 ActionRecord + 去重 + 否决）
        │
        ├─ 换街：_reconcile_street  用下一街 pbs 补上一街漏抓的 call/raise（首注另走 _infer_first_bet）
        ├─ 街末：_finalize_street   补漏抓的 fold、无下注街的 check
        └─ 手末：_complete_calls    账单唯一解时补 call
```

## 1. 证据通道与可信度

| 通道 | 读什么 | 判据 | source | 性质 |
|---|---|---|---|---|
| 名字槽徽章 | 座位名字 ROI 的文本 | `parse.parse_action`（`:232`） | `badge` | 观测；只能产出 4 种（无 fold） |
| 头像徽章 | 头像 ROI 的文本 | `is_fold_badge`（`:268`）/ `is_all_in_badge`（`:287`） | `avatar_fold` | 观测；弃牌唯一正证据 |
| 下注额变化 | `bet` pill（BB） | `bet > 基线`，并与本街水位比较 | `bet_delta` | 推断；分不清时宁缺 |
| 底池账单 | `pot` 与 `pot_before_street` | 差额 ≠ 各座投入之和 | `ledger` | 推断；金额准、身份可能猜 |

每条记录还带两个口径标记：

- `inferred`：由 `source` 派生（`bet_delta` / `ledger` 为真），落库和提示词都写「推断」。
- `order_unknown`：同帧同额、街末补全等**顺序没有观测证据**的情况置真；复盘不能把顺序当真。
- `stack_after`：只有 `badge` 来源才写观测到的后手；推断记录一律 `None`（`poker_ocr/hand_track.py:1565-1566`）。

## 2. 逐动作条件

### 2.1 弃牌 `fold`

弃牌**只有一条正证据**：头像。名字槽读到「弃牌」不算动作（`parse.py:232` 只认 `_NAME_ACTION_WORDS` 的四个词，`:210`）。

**A. 头像弃牌（`avatar_fold`）**

`frame_state.py:459-471` 先把三态判出来：

| 头像手牌图标 | 头像文本 | 结果 |
|---|---|---|
| 有（`icon is True`） | 任意 | `fold=False` |
| 无（`icon is False`） | `is_fold_badge=True` | `fold=True` |
| 无 / hero（hero 从不挂图标） | `fold_badge=True` | `fold=True`（hero 特例） |
| 其余 | — | `fold=None`（判断不了，不当作没弃） |

- `is_fold_badge`：文本非空、rec 分数 ≥ `0.4`，且整段匹配 `^(?:已)?[弃奔](?:[牌脚摊雄权])?[#＃!！。.·]?$`。分数不够返回 `None`（不是 `False`）。
- 落成动作还要 **连续 2 帧**（`AVATAR_FOLD_CONFIRM_FRAMES=2`，`poker_ocr/hand_track.py:124`；`_record_avatar_folds`，`:1616`）：
  - 中间任何一帧不是弃牌 → 候选作废；同一 `frame_id` 重复喂入不算新证据；
  - 已推过全下的座位不提交（全下的人不可能弃牌）；已有 fold 记录的座位不重复；
  - 提交时用**第一次看到它那一帧**的 `hand.actions` 长度作为插入位置，名字/位置也用那一帧，弃牌就落在它前后两条动作之间，而不是街末（`_commit_fold`，`:1649`）。
- 「推过全下」的判据统一走 `_all_in_seats`（`:1604`）：`hand.all_ins`（2 帧确认）**并上**动作记录上 `all_in=True` 的座位（单帧即写）。只查 `hand.all_ins` 会漏掉「这一帧刚推、还没满 2 帧」的人，结算帧上就会出现同一个人既全下又弃牌。
- 弃牌与全下的优先级（`frame_state.py:653-657`）：弃牌证据**强**（手牌图标消失 + 头像「弃牌」同时成立）时弃牌赢，`all_in` 随之作废；只有弃牌证据弱（仅文本、或亮牌帧沿用历史判定）时才轮到 `all_in` 压掉 `fold`。两条记录不能同时为真。

**B. 中途离桌：动作由本街水位决定（`left`，`left=True`）**

`_append_left_action`（`:1762`）在**街末**才补，不是在观测到离桌的那一帧：离桌是观测事实，但他在这一街做了什么由街末不变量唯一决定——水位高于他已投入 → 补 `fold`，否则 → 补 `check`（本街已有动作的人不再补）。补出的记录 `source="left"`、`order_unknown=True`、`left=True`，追加顺序按位置序、不按座位号伪造；hero、已全下、投入未知的座位不补（证据不足）。这是可撤销记录：手牌图标恢复时 `_revoke_left_folds`（`:1796`）只删 `left=True` 的合成记录，真实弃牌不受影响。

**B2. 本手暂离 ≠ 弃牌**（#124）：`p.left_uncertain` 只是「连续若干帧全无读数，看不见他」，不写任何动作记录——`_record_avatar_folds` 与 `_settle_pending_folds` 跳过该座，`_active_seats` 也不含它。离桌后的动作要按注额分流（有注弃牌 / 无注过牌，见 #125），不能在这里提前补 fold。

**C. 街末「人没了」（`ledger`）**

`_finalize_street` ①（`:2333` 起）：**街初在局、街末不在局、本街又没有 fold 记录** → 补 `fold`，并附证据快照 `FoldEvidence`（状态、图标、文本、分数、名字/筹码是否读到、是否亮牌）。`order_unknown=True`——只看到「人没了」，弃牌发生在哪次下注前后没有证据。

**否决/不补的条件**：座位不在本帧、亮牌帧沿用上一帧判定（`frame_state.py:468-471`）、已推过全下（`_all_in_seats`）、已有 fold、街末「未配平」时只进诊断不补。

### 2.2 全下 `all_in`

全下不是一个 `action` 值，而是 `PlayerState.all_in` / `ActionRecord.all_in` 布尔位。判定在 `frame_state.py:644-650`：

```
all_in = in_hand and ( all_in_badge is True
                       or equity is not None            # 界面只在全下后显示胜率
                       or (stack == 0.0 and (bet > 0 or was_all_in)) )
```

- `is_all_in_badge`（`parse.py:287`）：分数 ≥ `0.4`；`^(全下|全押|all[\s_-]*in)` 前缀；或去掉空白/连字符后以 `allin/alin/aiin/ailn/a1in/a11in` 开头；或 `len ≤ 6` 且与 `allin` 的相似度 ≥ `0.72`（实测 rec 会读成 `Alin`）。
- 胜率百分比同帧只能来自全下：`parse_percent` 只认整段 `30%` / `胜率 69%`；裸数字只有头像已确认 All-in 才接受（`frame_state.py:480-492`）。
- 结构化兜底 `stack == 0 且 (bet>0 或 上一帧就是全下)`：结算后全下玩家的筹码位变成 0 且 pill 被收走，看起来像离桌，靠 `prev_all_in` 区分。
- `record_all_ins`（`:822`）另有一条 **2 帧确认**（`ALL_IN_CONFIRM_FRAMES=2`）：单帧亮牌/牌背误判不写进这手的 `all_ins` 明细。动作记录上的 `all_in` 位走单帧判定，两者口径不同，凡是「他是不是推过」的判断一律用 `_all_in_seats` 取并集。

**与其它动作的关系**

- 全下与弃牌互斥，优先级见 §2.1 A 最后一条：弃牌强证据赢，弱证据时 `all_in` 压 `fold`（`frame_state.py:653-657`）。
- `preflop_aggressive`（`:84`）：`bet/raise` 一定算加注；`call + all_in` **只有金额超过当前水位**才算「短码再加注」，否则仍是跟注（不重开行动、不把池型改判成 3-bet）。金额读不到的 all-in call 按跟注处理。
- 提示词里「全下」是作为标签附加在动作文本后的：`（全下）`、`（推断）`（`poker_ocr/prompt/user/action_line.py:30-40`）。

### 2.3 过牌 `check`

**A. 徽章**：名字槽读到「让牌」（`parse.py:210`）即 `check`，走 `_record_actions` 常规路径。若同一帧同额（过牌金额 0）出现多条，全部标 `order_unknown`。

**B. 街末补全**（`_finalize_street` ④，`:2425-2433`）。

先排除一种自相矛盾的局面：**翻后有人弃牌，但整街没有任何 `bet/raise` → 不补过牌**（`:2417-2422`）。弃牌只发生在面对下注时，这个组合说明下注整条都没抓到；这时补 check 会凭空造出一个「全场没人下注」的回合，范围模型会当真。只记一条 `data_warnings`（「有弃牌但整街无人下注，疑似漏抓下注，不补过牌」）。翻前不适用——面对盲注就弃牌是正常线路（UTG 弃、其余人跟）。

其余情况，四个条件**同时**成立才补：

1. 这一街**没有任何 `bet/raise`**（含推断出来的）；
2. 没有「未配平」的座位——还欠钱或投入不可信的座位一律不补，只记 `data_warnings`；
3. 该座仍在局、没有全下、这一街还没行动过、投入可信（不是 `baseline_unknown` / `level_unknown`）；
4. 不是「手末的翻前」（所有人弃牌到 BB 时 BB 直接收池，不是过牌）。

`order_unknown`：位置读不到 **或** 这一街出现过弃牌（弃牌与过牌的先后无法从「人没了」唯一确定）。

**为什么这么保守**：一旦有人下注，没记录到动作的人更可能是跟注，写成 check 会污染行动线（代码注释原文）。

**不补的场景**：炸弹池/大前注的翻前且没有真实 call/raise（`:2351-2359`，避免凭空造出「翻前机会」拉大 VPIP 分母）。

### 2.4 跟注 `call`

**A. 徽章**：名字槽「跟注」→ `call`。

**B. 注额差反推（`bet_delta`）**：没有徽章时，`bet > 基线 + 1e-9` 且 `bet ≤ 本街水位 level` → `call`（`:1440-1465`）。

前置约束：
- `bet ≤ 强制投入上限` → 不记（盲注/炸弹前注到账不是行动，`_forced_preflop_level`，`:1315`）；该座同时是全下时额外记一条诊断，仍不记动作（§2.5 否决）；
- `baseline_unknown` 的座位第一次可靠读数只当基线，**不当行动**；
- `level_unknown`（本街水位不可信）时不反推，等全场读数恢复。

**C. 换街底池对账（`ledger`）**——`_reconcile_street`（`:1971`）：

```
上一街实际投入 = pot_before_street(下一街) − pot_start(上一街)
各座已记录投入 = 盲注基线 + 每条动作的「本街加到总额」+ hero 反解
missing = 实际 − 已记录
```

- 先认 hero 那笔（`_note_hero_bet`，hero 客户端不画下注 pill）；
- ① 本街没有任何激进动作（水位还是 0）→ 走首注反解，见 §2.5 C；
- ② 只补跟注：所有剩余座位补齐到当前水位，欠额之和 = `missing`（容差 `RECONCILE_TOLERANCE=0.02`）→ 逐个补 `call level`；已有动作但金额空的，只补金额不新增（`_fill_amount_instead`，`:2174`）；
- ③ 差额对不上 → 走 §2.6 C 的单次加注反解；
- 只允许往后推进（`STREET_SEQ`），公共牌 5→3 的单帧误读不能倒着补。

**D. 手末唯一解（`ledger`）**——`_complete_calls`（`:2437`）：最后一街没有「下一街 pbs」，只有在底池账单与各座欠额**精确相等**（≤0.02）时才补 `call`，对不上宁可留缺口。

**E. 跟注全下**：`all_in=True` 的 call；是否算「再次加注」见 `preflop_aggressive`。

### 2.5 下注 `bet`

**A. 徽章**：名字槽「下注」→ `bet`。

**B. 注额差反推**：`bet > level` 且**翻后**、本街水位还是 0（`level ≤ 1e-9`）→ `bet`（`:1461`）。翻前同样情形记 `raise`——盲注不算「下注」，翻前第一个激进动作按加注口径记。

**C. 底池对账反解首注（`ledger`）**——`_infer_first_bet`（`:2126`）。

`_infer_single_raise` 需要本街先有一条激进动作当锚点；首注不需要——新街水位从 0 起算，第一个激进动作按定义就是 `bet`，类型无歧义。

```
final = (实际投入 − 非剩余座位已记录投入) / 剩余人数
```

必须同时满足：**翻后**（翻前水位为 0 只说明盲注也没抓到，平摊出来的是前注）；本街没有任何激进动作；剩余座位已记录投入相同（不一致说明弃牌者的钱没记到）；`final > 已有投入 + 0.02`；是 0.5BB 整倍；`n × final + 其它已知 ≈ 实际`。

下注者取「最早能行动的人」，其余按行动顺序补 `call`，全部标 `order_unknown`：金额是精确值，先后是推断。

**否决/降级**：
- 该座这一帧的下注不可信（`bet_unknown`）→ 只认徽章，金额留 `None`；
- 已弃牌且没有徽章 → 跳过（残留 pill 不能推成新动作，2026-11-06 实盘 SB 20.5 事故）；
- 强制投入线（翻前 `bet ≤ 强制投入`）→ 只更新基线；若该座同时是全下，额外记一条诊断（「全下 XBB 未超过强制投入 YBB，按前注/盲注处理，不记动作」），**不**补一条 raise。能落进这道闸的全下，金额必然全在强制投入以内（前注 5BB 桌上后手 3BB 的人，推出去的 3BB 就是他的前注），补 raise 等于凭空造一次自愿行动、带偏 VPIP/PFR。

### 2.6 加注 `raise`

**A. 徽章**：名字槽「加注」→ `raise`。

**B. 注额差反推**：`bet > level + 1e-9`（翻后或翻前都算）→ `raise`，金额 = 该座本街加到总额（`:1461`）。

**C. 底池对账反解单次加注（`ledger`）**——`_infer_single_raise`（`:2049`）。触发条件：①只补跟注对不上账，且本街已有激进动作。

```
final = (实际投入 − 非剩余座位已记录投入) / 剩余人数
```

必须同时满足：`final > level + 0.02`；是 0.5BB 的整数倍（OCR/弃牌投入误差不能造出 73.33 这种数）；`n × final + 其它已知 ≈ 实际`；没有剩余座位已经投入超过 `final`。

加注者身份**推断**：锚点 = 最后一个达到当前水位的激进动作；加注者 = 锚点之后、还差钱的人按行动顺序最早能行动的那个（`_after_rank`）。金额是精确值，身份是猜的，落库标 `inferred`。

推不出来直接放弃：锚点之后已有投入高于旧水位的记录（插不进正确位置）、位置读不到、绕不成一圈。

## 3. 所有动作共用的守卫

### 3.1 帧级（`frame_state` 质量闸）

- `errors` 非空 ⇒ **整帧丢弃**：盲注/底池/庄位读不到、在局人数 < 2、位置推算失败、`pbs > pot`、`pbs >= pot` 但场上还有下注、筹码/下注字段缺失（全下、亮牌、离桌除外）。
- 单座下注读坏**不丢整帧**：`bet > pot` 或 `bet > 本街总额` → `bet=None` + `bet_unknown=True` + 记警告（`:874-899`，2026-11-13 用户裁定「降级，并给出错误日志」）。
- 底池自己不可信（0 / 比前注总额还小）时，`bet > pot` 退回整帧丢弃——分不清谁读坏。
- 底池没变且非 hero 回合时，读不出的 bet 沿用上一帧（`:807-821`）；**hero 回合不兜底**。
- 空 bet 文本（`bet is None`，非全下/亮牌）⇒ **整帧丢弃**（`:900-901`）。与上一条的不对称是有意的：空 bet 多半是 pill 还没渲染，下一帧就恢复；整帧丢的代价是换手识别迟滞（2026-11-08 实盘连续丢 52/95 帧，下手牌 8.8s/22s 才开始）。
- 空 bet 文本或带中文的文本按本街 0 处理（促销按钮/徽章落进 bet 槽），带汉字只可能是别的 UI。

### 3.2 记录级（`_record_actions`，`:1349`）

| 守卫 | 条件 | 结果 |
|---|---|---|
| 不在手 | `not p.in_hand and action != "fold"` | 跳过 |
| 非动作类型 | `action not in ACTION_TYPES` | 跳过 |
| 已弃牌 | `p.fold is True and p.action is None` | 跳过 |
| 强制投入 | 翻前 `call/bet/raise` 且金额 ≤ 强制投入 | 只更新基线（全下另记诊断） |
| 跨街残影 | 同一徽章、下注额没变（`_stale_badges`） | 跳过 |
| 重复帧 | 同座同街同动作，且 `bet ≤ 上次金额` | 跳过 |
| 金额后到 | 同动作、`bet` 变大，但中间没人加注 | 只在原记录 `source=="badge"` 时补金额 |
| 同帧同额 | 多条同动作同金额 | 全部 `order_unknown` |

「下注不得超过本街总额」只在帧级质量闸里判（`bet > street_total + 1e-6` → 降级成 `bet_unknown`，整帧保留）。记录级原来还有一道 `+0.75` 的重复闸，因为 `bet_unknown` 的座位在更早就被跳过，永远不可达，2026-11-16 删掉。

处理顺序（决定同一帧里的先后）：按本帧 `bet` 升序，金额相同则激进动作优先（`:1378`）。这只保证稳定展示，不保证真实顺序。

水位 `level` 只在记录到 `bet/raise` 且金额更大时抬升；hero 没有 pill，用 `hero_street_bet`（反解值）抬。

## 4. 这些事实到下游怎么用

### 4.1 需跟注额 `to_call`

`_snapshot`（`:2655`）：

```
hero_bet = max(hero pill, hero 本街反解投入)
max_bet  = 在局座位里最大的 bet
to_call  = max(max_bet − hero_bet, 0)
```

**对手下注读不出 → 这一帧不出建议**：`bet_unknown` 的座位不进 `max_bet`，`to_call` 会偏小甚至为 0——模型可能把「面对 20BB」看成「没人下注」。`_snapshot` 因此把这类座位记进 `HandSnapshot.bets_unknown`（`:355`）并挂 warning，`_maybe_decision` 见到它就置 `skip_reason="opponent_bet_unknown"` 直接返回，不占 `advised` 名额（`:2593-2601`）。本街账单那道闸（`street_account_mismatch`）多数时候会先拦下（钱已经进池），这是第二道网。

决策点去重是**两层**（都在 `_maybe_decision`，`:2515`）：

1. 粗判 key = `(hand_id, 街, 全手已记录动作条数, hero 底牌)`，进过 `advised` 就不再问（`:2635`）；
2. 细判 spot = `(hand_id, 街, hero 本街动作数, to_call)`，与上次相同（`to_call` 容差 `0.25BB`，`DECISION_TO_CALL_TOLERANCE`，`:115`）也不再问（`:2628-2630`）。

第二层是补第一层的坑：对手的徽章晚到一帧会让「全手动作条数」+1，人还没动却被当成新局面（2026-11-09 实盘连问两次）。另外 `to_call ≤ 0` 时会排除「hero 自己金额 ≤ 盲注」的记录，防止盲注 pill 晚渲染被反推成一次 call/raise 而吞掉 BB 的选项（`:2607-2616`）。

### 4.2 可选动作的合法性（`options.build_options`，`:470`）

| 局面 | 给出什么 | 代码 |
|---|---|---|
| `to_call ≤ 0` | 「过牌」（id 仍是 `call`，kind `check`）+ 各档下注 `bet` | `:499-501` |
| `to_call > 0` | 跟注 `call` + 弃牌 `fold` + 各档加注 `raise` | `:502-514` |
| `to_call ≥ hero_stack` | 只有「跟全下」+ 弃牌，不给加注/全下（与客户端一致） | `:505-511` |
| 底池或后手缺失 | 只给过牌/跟注/弃牌（`_unsized_options`，`:409`） | `options_mode == "unsized"` |
| 翻后 0 对手异常帧 | 同上，note 写「状态帧异常」（`_abnormal_options`，`:432`） | `anomaly=True` |

**全下选项 `all-in` 的门槛**（`_all_in_option`，`:77`）：

- 后手读不到或 ≤ 0 → 不给；`to_call ≥ stack` → 走「跟全下/弃牌」分支，不重复给。
- 翻前：只有「总后手 ≤ 20BB 短码」或「面对 3-bet」才挂（`PREFLOP_ALLIN_MAX_STACK_BB=20`，`:74`）。
- 翻后：全下额 ≤ 现有最大档位 → 不给；
  金额 > 跟注后底池的 2.5 倍（`ALL_IN_MAX_POT_MULTIPLE`，`:73`）、且 SPR > 3、且不是被大注逼着套池（`to_call < 0.5 × stack`）→ 不给。
- 金额封顶到有效筹码（对手跟不动的部分注明「退回」）。

档位金额全部由代码算：低于最小加注额的抬到合法值，超过后手的封顶（`_cap`，`:170`）。

### 4.3 对手范围事件（`field_ranges.build_events` → `range_flow`）

- 只有翻后产生事件（翻前由先验覆盖，避免算两次）。
- `fold` **不产生范围事件**，只从「身后还有几人 / 谁弃了」的集合里移除。
- `check / bet / call / raise` 各带行动前上下文：是否面对下注、本街第几次加注、跟注数、身后人数、是否首个/最后行动、是否封口、是否 donk、SPR，落成 10 个桶之一（`BUCKETS`，`poker_ocr/range_flow.py:55`）。
- 似然按「成牌档 × 动作」查表（数值在 `poker_ocr/tables/range_flow.json`，默认 v0）：

| 成牌档 | 面对下注 call / raise / fold | 无人下注 check / bet |
|---|---|---|
| nut | 0.22 / 0.70 / 0.08 | 0.22 / 0.78 |
| strong | 0.36 / 0.42 / 0.22 | 0.40 / 0.60 |
| medium | 0.45 / 0.06 / 0.49 | 0.72 / 0.28 |
| weak | 0.26 / 0.015 / 0.725 | 0.88 / 0.12 |
| air | 0.06 / 0.003 / 0.937 | 0.96 / 0.04 |

- 听牌另有乘性调整（`_DRAW_PROBS`，`:159`）；听牌权重再按街衰减（翻牌 ×1.0 / 转牌 ×0.5 / 河牌 ×0，`event_factor` `:493-495`，后门听只在翻牌成立、不缩放）。
- 桶/SPR/画像乘数只作用在**非过牌**动作上：`_context_multiplier` 里 `action == "check"` 直接返回 1.0（`:418-423`）。
- 面对下注却记成「下注」的，按一次加注（raise）处理（`:447-448`）；口径不匹配（面对下注却过牌）给中性 0.5，不放大也不清零（`:482-484`）。
- 对账补出来的 `inferred` 动作**照用全价**，只在 `warnings` 里记一句（`field_ranges.py:420-421`、`:447-448`）。画像侧不是这样，见 §4.4。

### 4.4 对手画像（`opponent_profile.py`）

- **按机会计数**，不是按观察手数：VPIP 的分母是「这一手在翻前有真行动机会」的次数，爆炸底池里只有前注、没有非推断的 `call/bet/raise` 时整手跳过 VPIP，不猜（`:753-772`）。
- `vpip` = 有翻前机会且真的主动入池；`pfr` = 有翻前机会且出现过激进动作，**`call + all_in` 也计一次加注**（`:855-858`、`:1134-1137`）。
- **推断动作在这一侧降权**：一手里 `inferred` 占比 > `INFERRED_DOWNWEIGHT=0.3` 时，整手对画像的权重降到 `INFERRED_WEIGHT=0.5`（`:72-73`、`:942-943`）；个别统计更严格，直接排除带 `inferred` 的那条动作（iso-raise 看 `first_pre`，`:1002`）。范围侧没有这层降权（§4.3）。
- 低频样本**不做原始比例展示**，向全场均值 β 收缩：`shrunk = (hit + k·p0) / (opps + k)`，`k` 按事件稀有度取 4–10（常见事件 8–10、稀有 4–6），`p0` 是全场均值，没有人群数据时退回 `DEFAULT_PRIORS`（`:151-200`）。
- 桌级剥削提示另有更低的机会数门槛：`TABLE_MIN_OPPS = {river: 12, fcbet: 20, limp: 20, threebet: 20}`（`:1763-1768`）。
- 分母为 0 的比率返回 `None`（3bet、AF）或 0（VPIP/PFR），下游必须容忍缺值（`:1275-1298`）。

## 5. 已知边界（fail open 的地方）

1. **弃牌会漏**：头像「弃牌」实测同一帧 5 个人会漏 2 个，rec 直接返回空；所以下游必须允许 `fold=None`。
2. **徽章会串**：动作徽章在名字槽停留几秒，期间别人可能已行动；去重只能按「这个座自己上一条动作」判断，跨座顺序不可靠。
3. **谁加注不可证**：底池只给金额，`_infer_single_raise` 取「最早能行动的人」当加注者，`_infer_first_bet` 取「最早能行动的人」当下注者，落库标推断。
4. **两种坏读数待遇不同**：读到荒谬值（`bet > pot` / `> 本街总额`）降级成 `bet_unknown`、整帧保留；读不到（`bet is None`）整帧丢弃。理由是恢复速度和代价不同（§3.1）。
5. **未配平不猜**：街末只补 fold 与「整街无人下注」的 check；欠钱或投入未知的座位只记 `data_warnings`；翻后有人弃牌而整街无人下注时也不补 check（§2.3）。
6. **全下两套口径**：动作记录的 `all_in` 单帧即写，`hand.all_ins` 明细要 2 帧确认——所以「他推过没有」要用 `_all_in_seats` 取并集，别只看任意一边。
7. **强制投入闸不给全下开口子**：金额没超过前注/盲注时，那笔钱就是强制投入本身，补 raise 会凭空造一次自愿行动、带偏 VPIP/PFR。全下事实由 `hand.all_ins` 与动作上的 `all_in` 位记着，闸门只额外记一条诊断。
8. `parse.ACTION_WORDS`（`parse.py:201`，含「弃牌」）是旧词表，名字槽实际只用 `_NAME_ACTION_WORDS` 四词；改词表改后者。
