## 1. 背景

### 1.1 已经发生的事

h8（`Jh Qd`，BB，牌面 `Ad As Qc Kc 8d`）暴露了一个问题：模型把整桌当成“松弱跟注站”，在转牌用 `A A Q Q` 两对主动下注 1/3 池。实际桌上 BTN 是松浪/松凶（芒果与西米），SB 才是偏松弱（好运常在ok）。对松浪做薄价值下注，等于主动撞进一个会加注的范围。

当前已经落地的临时修复（commit `f188b46`）：

- `table_dynamics.is_aggressive_table()`：识别桌风里的“松浪/松凶”；
- `Situation.aggressive_table`：桌级布尔；
- `value_directive` 的 aggressive 分支：中等成牌无人下注 → check，面对单注 → 抓诈；
- lean/skills 提示词按对手分类；
- `.table_dy` 改成松浪/松弱/混合三组。

### 1.2 还缺什么

`aggressive_table` 是**桌级**的：混合桌里只要有一个松浪，整桌中等牌都会走保守分支。正确做法是**按本手在局的对手**判断，而不是按整桌平均。

同时，当前实时动作线**经常不记录弃牌**，所以真正的 VPIP/PFR 算不出来。现在报告里的“PFR%”是“在观察到的入池手牌里至少加注一次”的比例，不是真 PFR。用这种数据做类型识别会把“弃牌多的人”误判成“入池多的人”。

### 1.3 目标

1. 每手结束自动更新每个对手的统计画像；
2. 决策时按**本手在局对手**的类型调整建议，而不是整桌一个标签；
3. 分类可解释、有置信度、样本不足时不乱下结论；
4. 支持人工修正，且人工修正优先于自动；
5. 画像可持久化、可重建、可离线复盘；
6. 不显著增加实时建议延迟（目标 < 5ms，且不调用模型）。

### 1.4 非目标

- 不做精确 HUD（不追求和商业软件逐项对齐）；
- 不训练深度模型（几十手样本训不出稳定模型）；
- 不做实时对手手牌预测；
- 不把画像上传云端（隐私）；
- 不替代 `.table_dy` 的人工整桌笔记；两者是互补关系。

## 2. 设计原则

1. **事件源 → 派生画像。** 手牌记录是唯一事实来源；画像是派生缓存，丢了能从手牌重建。
2. **按机会计数，不按动作计数。** VPIP 的分母是“有翻前行动机会的手数”，不是“观察到的动作数”。
3. **按对手，不按整桌。** 本手在局的人里，谁是松浪比“整桌平均是什么”重要。
4. **置信度门控。** 样本不足或类型概率不够高时，只展示、不改变硬指令。
5. **确定性优先。** 分类用规则/贝叶斯，不调用 LLM；LLM 只用于离线总结。
6. **人工优先。** 用户 pin 的类型覆盖自动结果；自动结果覆盖 `.table_dy` 的宽泛描述。
7. **本地优先。** 实时链路不依赖远程 DB；持久化用本地文件/SQLite。
8. **可回放。** 任何一次建议都能回答“当时用了哪个对手的什么类型、置信度多少”。


## 4. 数据层

### 4.1 每手每对手的观察记录

新增一个轻量结构 `HandObservation`（不必先落库，先由 `ProfileStore.update_hand()` 从 hand dict 解析）：

| 字段 | 类型 | 含义 |
|---|---|---|
| `opponent_key` | str | 对手稳定键（见 4.3） |
| `hand_uid` | str | 手牌唯一键（`session` + `hand_id`，或导出时的 `uid`） |
| `session_id` | str | 会话标识 |
| `pool_key` | str | 牌桌池，例如 `0.5/1-9max` |
| `preflop_opp` | bool | 有翻前行动机会（被发牌、未离桌） |
| `vpip` | bool | 翻前主动投钱（call/raise/allin；盲注不算） |
| `pfr` | bool | 翻前加注/全下 |
| `threebet_opp` | bool | 首次行动前已经有人加注 |
| `threebet` | bool | 面对加注再次加注 |
| `saw_flop` | bool | 翻前没弃牌且翻牌发出 |
| `postflop_opp` | bool | 翻后有行动机会 |
| `bet_raise` | int | 翻后 bet/raise/allin 次数 |
| `call` | int | 翻后跟注次数 |
| `fold` | int | 翻后弃牌次数 |
| `check` | int | 翻后过牌次数 |
| `facing_bet` | int | 翻后面对下注的次数 |
| `open_size` | float \| None | 翻前首个加注的 BB 数 |
| `bet_sizes` | list[float] | 每次翻后下注/加注额 ÷ 下注前底池（0–10，过滤异常） |
| `showdown_category` | int \| None | 摊牌牌型（0–8，`coach.evaluate`） |
| `aggressive_showdown` | bool | 摊牌前是否主动下注/加注 |
| `inferred_ratio` | float | 该手动作里 inferred 的比例（数据质量权重） |

### 4.2 弃牌/过牌补全（P0，必须先做）

现状：`ActionRecord` 有 `fold` 类型，但实时链路经常漏掉弃牌徽章，导致 `hands/*.json` 里大量玩家 `fold=0`。

在 `LiveHandTracker` 里补：

1. **街开始快照**：每街开始时记录 `street_start_active: set[seat_id]`（当时 `in_hand` 且未弃牌/未离桌）。
2. **街末补弃牌**：街切换时，对 `start_active - current_active` 且没有 `fold` 记录的玩家，追加：
   ```python
   ActionRecord(street=prev_street, ..., action="fold", inferred=True)
   ```
3. **街末补过牌**：对看到该街、没有动作、没有弃牌、没有 all-in 的玩家，如果行动已经轮过（可用位置/动作顺序近似），追加 `check`（`inferred=True`）。
4. **手牌结束补弃牌**：`finish_current()` 前再跑一次同样的补全，覆盖河牌。
5. **机会标记**：在 `_hand_dict` 里按 seat 输出 `preflop_opp/vpip/pfr/...` 汇总，或输出 `start_stacks` + 每街 active 列表，让 `ProfileStore` 自己算。

验收：拿 `hands/1023.hands.json` 重放，原本 `fold=0` 的玩家应出现合理的弃牌数；VPIP ≤ 100%，且大多数玩家 < 60%。

没有 `start_stacks` 的旧手牌：用 `players_dealt + opponents` 近似；如果连“谁被发牌”都无法确定，**跳过该手的 VPIP 统计**，不要猜。

### 4.3 身份键

- 有名字：`opponent_key = normalize(name)`（NFKC、去首尾空格、连续空格合并）。
- 名字 OCR 失败：临时 `temp:<session>:<seat_id>`；之后读到名字时合并到名字键，并写 `aliases`。
- 跨 session：名字相同默认视为同一人；`pool_key` 不同则分开（避免 1/2 和 5/10 混在一起）。
- 人工别名：UI/配置里维护 `alias -> opponent_key`，覆盖自动匹配。
- 不要用 `seat_id` 做长期键；座位会换人。

`pool_key` 建议：

```python
f"{sb:g}/{bb:g}-{table_size}max"  # 0.5/1-9max
```

有前注时可加 `-ante{ante:g}`，但同一桌通常固定，MVP 可先不加。

**MVP（推荐先做）**

## 5. 特征层

### 5.1 公式

| 特征 | 公式 | 最小样本 |
|---|---|---|
| VPIP | `vpip / preflop_opps` | 10 |
| PFR | `pfr / preflop_opps` | 10 |
| 3bet% | `threebet / threebet_opps` | 5 次机会 |
| 翻后激进% | `bets_raises / postflop_opps` | 8 |
| AF | `(bets_raises + check_raises) / max(calls, 1)` | 8 |
| c-bet% | 翻前加注者翻牌下注 / 翻牌 c-bet 机会 | 5 |
| barrel% | 转牌继续下注 / 翻牌下注后转牌机会 | 5 |
| 超池% | `bet_sizes > 1.2` 的占比 | 10 次下注 |
| 摊牌弱激进% | `weak_aggressive_showdowns / aggressive_showdowns` | 5 次摊牌 |
| open 中位数 | `median(open_sizes)` | 5 |
| 下注中位数 | `median(bet_sizes)` | 8 |

`weak_aggressive_showdown`：摊牌牌型 ≤ 一对（含高牌），但该手有翻后 bet/raise。

### 5.2 窗口与衰减

- 默认用当前 session 的全部手牌；
- 可选指数衰减：`w = 0.5 ** (age_hands / 30)`，半衰期 30 手；
- 换桌/换 session 不重置 lifetime，但“当前 read”用近期窗口；
- 画像文件同时保留 lifetime 聚合和 `recent`（可选）。

### 5.3 数据质量权重

- `inferred_ratio > 0.3` 的手牌降权（乘 `0.5`）；
- 只有 1 张亮牌的手牌不计入摊牌统计；
- 许文文啊这类“多次只读到 Js”的坏帧，按 `cards_warnings` 或重复牌过滤。

## 6. 分类层

### 6.1 类型

| 类型 | 中文 | 典型特征 |
|---|---|---|
| `unknown` | 未知 | 样本不足 |
| `station` | 松弱/跟注站 | VPIP 高、PFR 低、AF 低、open 小 |
| `lag` | 松凶 | VPIP 高、PFR 中高、AF 高、open 5–8BB |
| `maniac` | 松浪 | PFR 很高 / open ≥9BB / 3bet 高 / 超池多 / 弱牌激进摊牌 |
| `nit` | 紧弱 | VPIP 低、PFR 低、AF 低 |
| `tag` | 紧凶 | VPIP 中、PFR 中高、AF 高、摊牌范围强 |

### 6.2 规则评分（MVP）

不做深度学习。用可解释的加权评分 + softmax：

```python
def classify(stats) -> OpponentRead:
    if stats.preflop_opps < 8:
        return unknown(stats)

    vpip = stats.vpip_pct
    pfr = stats.pfr_pct
    af = stats.af
    open_med = stats.open_median
    overbet = stats.overbet_pct
    weak_aggr = stats.weak_aggressive_pct

    scores = {
        "station": gauss(vpip, 45, 12) * gauss(pfr, 8, 6) * gauss(af, 0.7, 0.5),
        "lag":     gauss(vpip, 35, 10) * gauss(pfr, 26, 8) * gauss(af, 2.2, 0.9),
        "maniac":  gauss(pfr, 45, 12) * gauss(open_med, 10, 3) * gauss(overbet, 0.2, 0.12),
        "nit":     gauss(vpip, 14, 6) * gauss(pfr, 9, 5) * gauss(af, 0.8, 0.5),
        "tag":     gauss(vpip, 24, 6) * gauss(pfr, 20, 6) * gauss(af, 2.4, 0.8),
    }
    # 弱牌激进摊牌高 → maniac 加权；摊牌范围强 → tag 加权
    ...
    probs = softmax(scores)
    return OpponentRead(...)
```

`gauss(x, mu, sigma) = exp(-0.5 * ((x - mu) / sigma) ** 2)`。

缺失特征（没有 open、没有摊牌、翻后样本不足）用中性值或跳过该项，**不要用 0 当观测**；每个特征有自己的最小样本，不满足时降置信度。`n` 用 `preflop_opps` 做总样本，但翻后/摊牌特征要单独看自己的分母。

阈值只作为起点，P1 后用真实数据调。**不要**把阈值写死在 prompt 里；分类在代码里做，prompt 只读结果。

### 6.3 置信度

```python
sample_factor = min(1.0, preflop_opps / 30)
confidence = max(probs) * sample_factor
```

更稳的做法：对 VPIP/PFR 用 Beta 后验，取 95% 区间；区间跨类型的，降置信度。MVP 先用 `sample_factor`，P1 再升级。

门控：

| 样本 | 行为 |
|---|---|
| `n < 8` | `unknown`，只显示“样本不足” |
| `8 ≤ n < 15` | `tentative`，只在 prompt 里软提示，不改进硬指令 |
| `n ≥ 15` 且 `confidence ≥ 0.65` | `read`，可改 `value_directive` |
| `n ≥ 30` 且 `confidence ≥ 0.75` | `stable`，可用于硬规则/UI 主标签 |

### 6.4 冷启动

- `.table_dy` 里按名字列出的类型作为先验（伪计数，例如 +5 手）；
- 没有先验 → `unknown`，使用基线策略（不要默认松弱）；
- 人工 pin 直接给 `stable`，自动统计仍更新但不覆盖。

### 6.5 人工 pin

- `manual_pin` 存 `station/lag/maniac/nit/tag` 或 `null`；
- UI 点击循环切换；再次点击清除；
- `source = "pin"`，`confidence = 1.0`，`n` 仍显示自动样本数；
- 优先级：pin > 高置信 auto > `.table_dy` > unknown。

## 7. 画像存储接口

### 7.1 模块

新增 `poker_ocr/opponent_profile.py`：

```python
@dataclass(frozen=True)
class OpponentRead:
    seat_id: str | None      # 当前这手牌的座位；用于把 read 对回具体对手
    key: str                 # 稳定画像键（名字/DB id）
    display_name: str | None
    archetype: str          # unknown/station/lag/maniac/nit/tag
    confidence: float
    n: int
    vpip: float
    pfr: float
    af: float
    source: str             # auto/pin/prior/unknown
    note: str

class ProfileStore:
    def __init__(self, path: Path, pool_key: str, *, enabled: bool = True): ...
    def load(self) -> None: ...
    def update_hand(self, hand: dict) -> None: ...
    def read_for(self, opponents) -> dict[str, OpponentRead]: ...
    def pin(self, key: str, archetype: str | None) -> None: ...
    def save(self, force: bool = False) -> None: ...
```

`read_for(opponents)` 输入 `OpponentSnapshot` 列表，按 `seat_id -> OpponentRead` 返回（内部用 name 匹配，`OpponentRead.seat_id` 一并填好）。匹配不到名字时返回 `unknown`。**不要只用 name 做本手匹配**：同名/OCR 错名时 seat_id 才是本手的唯一锚点。

### 7.2 原子写

```python
tmp = path.with_suffix(".tmp")
tmp.write_text(json.dumps(data, ensure_ascii=False, indent=1), encoding="utf-8")
os.replace(tmp, path)
```

单进程写；读进程不需要锁。每手结束可以只更新内存，每 5 秒或每 10 手落盘一次；退出时强制落盘。

### 8.2 `value_directive`

用本手在局对手，而不是桌级 `aggressive_table`：

```python
reads_by_seat = {r.seat_id: r for r in sit.opponent_reads if r.seat_id}
reads = [r for r in reads_by_seat.values() if r.archetype != "unknown"]
aggressive_reads = [r for r in reads
                    if r.archetype in ("lag", "maniac")
                    and (r.source == "pin" or r.confidence >= 0.65)]
station_reads = [r for r in reads if r.archetype in ("station", "nit")]

# 下注决策：看最可能跟注的人；跟注决策：看当前下注的人。
# last_aggressor_seat() 从本街 action line 取最后一个 bet/raise 的 seat_id，
# 需要时实现为 advice 内部的小工具（snap.actions_of(street) 已能拿到）。
bettor = reads_by_seat.get(last_aggressor_seat(sit.snap))

aggressive = bool(aggressive_reads) or sit.aggressive_table  # 后者作为 fallback
```

- 有 LAG/MANIAC → 现有 aggressive 分支（中等牌 check / 抓诈）；
- 全是 STATION/NIT → 现有价值分支；
- 混合 → 下注决策看“最可能跟注的人”，跟注决策看“下注的人”。

**注意**：`aggressive_table` 保留为 fallback（无画像时），不要让画像缺失导致行为退化。

### 8.3 `render_hand_facts`

在 `Computed facts` 里加：

```text
Opponent reads:
- BTN 芒果与西米: LAG (n=50, VPIP 64%, PFR 29%, AF 3.2, conf 0.82)
- SB 好运常在ok: STATION (n=12, VPIP 75%, PFR 11%, AF 0.5, conf 0.55 tentative)
```

未达到 `read` 门槛的标 `tentative`；`unknown` 不输出，避免噪声。

### 8.4 `live.py`

- 新增 CLI：`--opponent-db PATH`、`--no-opponent-profile`；
- 初始化：

```python
profile_store = ProfileStore(path=args.opponent_db,
                             pool_key=pool_key_from_blinds(args),
                             enabled=args.ai_advice and not args.no_opponent_profile)
profile_store.load()
```

- 手牌结束：

```python
finished = self.hand_tracker.take_finished()
if finished is not None:
    self._write_hand(finished, partial=False)
    if self.profile_store:
        self.profile_store.update_hand(finished)
```

- 决策点：

```python
reads = {}
if self.profile_store:
    reads = self.profile_store.read_for(point.opponents)
situation = build_situation(point, table_dynamics=dynamics,
                            opponent_reads=reads.values())
```

- 退出：`profile_store.save(force=True)`。

### 8.5 优先级

```text
manual_pin
  > auto read（n >= 15 且 conf >= 0.65）
  > .table_dy 按名字
  > .table_dy 整桌（aggressive_table 等）
  > unknown 基线
```

`ProfileStore.read_for()` 返回 merge 后的结果，并在 `source` 字段标明来源。

## 13. 风险与开放问题

| 风险 | 影响 | 缓解 |
|---|---|---|
| 弃牌/过牌缺失 | VPIP/PFR 失真 | P0 补全；`inferred_ratio` 降权 |
| 名字 OCR 错/None | 画像串人 | 别名表、临时键、人工 pin |
| 样本小 | 类型乱跳 | 置信度门控、tentative、先验 |
| 摊牌选择偏差 | 低估/高估激进 | 以行动频率为主，摊牌只做辅助 |
| 非平稳（tilt/换桌） | 旧数据误导 | 衰减、session 重置、pin |
| 自动覆盖人工 | 用户不信任 | pin 最高优先级 |
| 隐私 | 玩家数据泄露 | 本地存储、gitignore、清空命令 |
| 画像污染 | 错误建议 | 可重建、版本化、审计日志 |

**开放问题**：

1. `opponent_key` 是否要跨 pool 合并？建议先按 `pool_key` 分开。
2. 摊牌牌型是否值得进入硬规则？建议只做辅助置信度，不做硬规则。
3. 是否要在建议里显示“置信度低，按基线打”？建议显示，避免用户误信。
4. 是否要支持多人同名？先靠人工 alias，不做自动消歧。
