# 实时 Web 看板与日志排查（2026-11-05）

> 解决的问题：实时链路原来只有终端。牌桌状态、AI 建议和提示词都在滚动日志里，
> 看不清「刚才那一帧到底读到了什么」「模型看到的提示词是哪一份」「这手牌为什么
> 识别错了」。本次加三样东西：
>
> 1. **本地 Web 看板**（`--web`，默认 `http://127.0.0.1:8020`）：每一帧同步牌桌，
>    AI 建议/原因重点展示，提示词可点开逐字查看；
> 2. **结构化事件日志**（`logs/live.events.jsonl`）：帧级索引，记录每一帧的
>    `kind / errors / cards warnings / hand_id` 和决策/建议生命周期；
> 3. **手牌识别倒查工具**（`tools/hand_recognition_audit.py`）：把 states 与
>    events 对齐到手牌粒度，按可疑程度排序，`--explain` 展开逐帧证据。

## 1. 启动

```bash
.venv/bin/python -m poker_ocr.live \
    --profile config/table_wpk_live.json \
    --initial-blinds 1/2 \
    --out logs/live.states.jsonl
```

默认会额外启动：

| 产物 | 默认路径 | 关闭方式 |
|---|---|---|
| Web 看板 | `http://127.0.0.1:8020` | `--no-web` |
| 结构化事件日志 | `logs/live.events.jsonl` | `--no-events` |
| 控制台文本落盘 | `logs/live.log` | `--no-log-file` |

常用参数：

```bash
--web-port 8021          # 端口被占用时换一个
--web-open               # 启动后自动打开浏览器
--web-host 0.0.0.0       # 仅确认局域网可信时使用（提示词/玩家名会暴露）
--events-out /tmp/a.jsonl
--log-file /tmp/live.log
```

端口被占用时只告警，识别主链路继续跑；`session_start` 里会写
`web_url` / `events_out` / `log_file`，事后能对应回这次会话。

## 2. 看板怎么看

```
┌ 顶栏：连接状态 · session_id · profile · prompt_version · 帧/接受/丢弃/耗时/建议数
├ 左：牌桌（座位环 / hero / 公共牌 / 底池 / 盲注 / 庄位） + 本手行动线 + 最近手牌
└ 右：AI 建议（当前/生成中） · 识别健康 · 建议历史 · 识别帧流
```

- **牌桌**：用 profile 的 `name_slot` 中心定位每个座位，hero 单独放底部，
  环上不会重复渲染 hero；座位显示名字/位置/后手/本街下注/动作，弃牌、离桌、
  空位分别淡化。本街下注同时汇总在底池下方（`谁 多少 BB`），主动下注/加注的
  座位用绿色边框，跟注/过牌蓝色，弃牌红色。牌桌只在 `state` 记录时更新；
  丢弃帧只更新帧流和健康面板，不会拿半帧数据覆盖上一张好牌桌。
- **AI 建议**：动作/金额大字号；原因是正文；计划、置信度、耗时、模型、
  prompt 版本、token、对手画像单独列。`source=model` 是绿色「模型」，
  超时/非法选项/未配置凭据是黄色「兜底」并显示 `error`。
- **提示词**：点「查看提示词」或按 `P`。标签页：
  `System 提示词` / `User 事实块` / `事实快照` / `模型原始返回` / `采样参数`。
  内容直接来自 `Advice.to_dict()` 的 `prompt_system` / `prompt_user` /
  `raw_response` / `facts`，**不是前端重新拼的**；因此看到的就是模型实际
  收到的那一份（哈希 `prompt_sha256` 也在弹窗标题里）。
- **生成中**：决策点提交后显示「AI 正在思考…」和计时；提示词要等结果回来
  才有，页面会明确写「与本次实际调用一致」。
- 右栏底部把「识别健康 / 建议历史 / 识别帧流」收进同一个 **tab 区**，
  不再四块面板上下堆叠；建议区占剩余高度并自己滚动，tab 区固定高度、
  内部滚动。切到识别帧流时会自动滚到最新一帧。
- **识别帧流**：每一帧一行，`record` / `no_change` / `discard` / `stale` 用颜色
  区分；丢弃帧带字段错误（如 `pot:遮挡 stack:a`）。可勾「暂停滚动」。
- **识别健康**：接受率、当前牌面是否可靠、建议模型率，以及本帧错误 / 牌面
  警告 / 名字告警 / 上一手推断动作的摘要；tab 上的小圆点显示好/告警/需排查。

看板是**只读**的：没有点击、没有改配置、没有调模型的入口，避免看板成为
第二个控制端。默认只绑定 `127.0.0.1`。

## 3. 事件日志

`logs/live.events.jsonl` 一行一个事件，追加写、立即 flush。与
`logs/live.states.jsonl` 的分工：

| 文件 | 用途 | 是否契约 |
|---|---|---|
| `live.states.jsonl` | state / advice / hand / session：下游手牌库/复盘/导出按它读 | **是**，字段不要随意改 |
| `live.events.jsonl` | 帧级诊断索引：为什么丢、读牌警告、决策/建议生命周期 | 排查用，schema `live.event.v1` |
| `live.log` | 终端文本原样落盘（去 ANSI、加墙钟时间） | 人肉 `grep`/`less` |

事件形状：

```json
{"schema":"live.event.v1","type":"event","event":"frame",
 "event_seq":128,"session_id":"20261105-231500-a1b2c3",
 "logged_at":"2026-11-05T23:15:01.123+08:00","t":12.34,
 "data":{"seq":412,"kind":"discard","errors":["pot:遮挡","stack:a"],
         "cards":{"reliable":false,"warnings":["board 回退"]},
         "hand_id":"20261105-abcdef1234","street":"flop",
         "state_index":17,"proc_ms":281.4,"queue_ms":8.2}}
```

| `event` | 时机 | 关键字段 |
|---|---|---|
| `session_start` | 启动 | `session_id / profile / prompt_version / out / events_out` |
| `status` | 每 10s | 采样/接受/记录/平均耗时/重连/丢弃原因 |
| `frame` | **每个处理过的帧** | `kind / errors / cards / hand_id / state_index` |
| `decision` | 投递建议前 | `hand_id / street / pot / to_call / options / decision_key` |
| `advice_skip` | 牌面不可靠跳过 | `hand_id / street / reason / warnings` |
| `advice` | 建议返回 | `option / source / error / duration_ms / prompt_sha256 / prompt_chars / prompt_missing` |
| `hand` | 换手/退出 | 完整 `streets / shows / data_quality`（去掉 `advices` 全文） |
| `incident` | 疑惑帧落盘 | `reason / folder / hand_id / frames` |
| `session_end` | 退出 | `summary` |

刻意不重复大字段：

- `frame.data` 不带完整 `state`，用 `state_index` 和 states 记录对齐；
- `advice.data` 不带 `prompt_system/user/raw/facts`，用 `prompt_sha256` /
  `prompt_chars` 定位，要看原文去 states 的 `advice` 记录或看板；
- `hand.data` 不带 `advices`，只留 `advice_count`。

这样事件日志可以长期保留（每帧几百字节），而 prompt 全文只在 states 里存一次。

## 4. 倒查：哪些手牌识别有问题

```bash
# 默认读 logs/live.states.jsonl + 同目录 live.events.jsonl
.venv/bin/python tools/hand_recognition_audit.py

# 前 10 名 + 可点击 HTML + JSON/CSV
.venv/bin/python tools/hand_recognition_audit.py \
    --top 10 --html logs/audit.html --json logs/audit.json --csv logs/audit.csv

# 展开某一手：逐帧 kind/errors/cards warnings/建议兜底/疑惑帧目录
.venv/bin/python tools/hand_recognition_audit.py --explain 20261105-abcdef1234

# 只看某个会话 / 某天之后
.venv/bin/python tools/hand_recognition_audit.py --session 2
.venv/bin/python tools/hand_recognition_audit.py --since 2026-11-05
```

输出示例：

```
识别质量排查 · 2 个会话 / 34 手 / 11 手可疑
  #     分数  等级    手牌 ID                       时间            hero    公共牌         主要问题
  1   42.0  高     s02-20261105-abcdef1234      11-05 23:14   Ah      Ks 7d 2c    牌面近似；牌面警告 3 条；…
```

### 评分口径

分数只用于**排序/分流**，不是「识别准确率」。权重：

| 信号 | 分值 |
|---|---|
| 手牌截断（`partial`） | 10 |
| `cards_unreliable` / `approx` | 6–8 |
| `cards_warnings` 每条（去重，封顶） | 2 |
| 推断动作每条（封顶） | 1.5 |
| hero 手牌张数不是 2 | 8–10 |
| hero + board 重复牌 | 12 |
| 公共牌张数不合法 | 6 |
| 事件日志丢弃帧占比（≥20/40/70%） | 4/8/12 |
| 疑惑帧目录每份（封顶） | 5 |
| 建议兜底每条（封顶） | 3 |
| 建议未调用模型每条（封顶） | 2 |
| 牌面不可靠跳过建议每次（封顶） | 2 |
| 名字告警每条（封顶） | 1 |
| 有手牌但完全没有行动线 | 3 |

`--explain` 才是证据：它会把这一手关联的每一帧列出来，包括
`record/no_change/discard/stale`、字段错误、牌面警告、proc_ms，以及
`logs/incidents/<时间>_<原因>/` 的截图目录。典型排查顺序：

1. 先看分数高的手，`--explain` 找连续 `discard` 的原因（`pot/stack/dealer`）；
2. 看 `cards_warnings` 是否集中在翻牌/转牌（多半是动画帧或牌背遮挡）；
3. 看 `inferred_actions` 是否很多（视频漏抓动作，街末靠底池对账补）；
4. 看 `fallback` / `prompt_missing`（模型超时/选项非法/未配置，不是识别问题）；
5. 需要看画面时打开疑惑帧目录，或对同一段重新抓帧跑
   `tools/validate_roi.py`。

## 5. 实现位置

| 文件 | 职责 |
|---|---|
| `poker_ocr/live_web.py` | 标准库 HTTP + SSE 服务；内存快照；profile → 座位布局 |
| `poker_ocr/web/live/` | 看板前端（`index.html` / `app.js` / `style.css`，无构建） |
| `poker_ocr/live_log.py` | 事件 JSONL、控制台文本落盘、路径派生 |
| `poker_ocr/live.py` | `LiveProcessor.events` 出口；main 里接线/启动/关闭 |
| `tools/hand_recognition_audit.py` | states/events 对齐、评分、explain、JSON/CSV/HTML |

事件出口使用统一的 `publish(kind, payload)`：先写事件 JSONL，再推看板。
两边的异常都在 `publish` 里吞掉并打一行警告，**日志/看板故障不允许中断识别**。

## 7. 注意

- 看板默认只绑 `127.0.0.1`；`--web-host 0.0.0.0` 会把提示词、玩家名、
  手牌暴露给同局域网，除非你确认网络可信，否则不要开。
- 看板不落盘；进程退出后页面断开。要看历史，用 `live.events.jsonl` +
  `tools/hand_recognition_audit.py`。
- 提示词里可能包含玩家昵称和画像；`live.log` / `live.events.jsonl` 同样是
  本地敏感数据，不要提交到仓库（`logs/` 已在 `.gitignore`）。
- 事件日志不替代 states：手牌库/复盘控制台仍只读 `live.states.jsonl` 和
  outbox；本次只在 `session_start` 里**追加**了 `session_id` /
  `events_out` / `web_url` / `log_file`，不影响旧消费者。
