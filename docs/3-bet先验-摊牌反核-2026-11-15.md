## 一条重要的否定结论

issue 里候选修法①提议补 `76s / 87s / 97s / T7s`。**本次全量摊牌里没有任何一张同花连张在 3-bet 池亮出来**
（`3BET_CALL_vs_EP` 的 `54s` 是唯一连张，且它是同花连张的邻类但不属于票面那 5 个 key）。
也就是说：票面那 5 个 key 是「A5s 能进、76s 凭什么不能进」的推理类比，**不是本仓数据**。
真要补，依据应该是别的（外部图表 / v1 策略表），而本仓目前的先验契约明确写的是
「他实际会拿什么」的描述性模型（`poker_ocr/ranges.py:243-258`），不是 solver 频率表。

## 结构性缺陷（不需要外部图表也能判定）

两张 3-bet 表的阶梯自相矛盾，说明它们是「逐手写单牌 + 手工阶梯」，不是按类别构造：

- `THREE_BET_CALL`：同花阶梯到 `AQs+`，非同花只有 `AKo` → **有 AKo 却没有 AQo**。
- `THREE_BET`：`A5s+` 展开成 A5s–AKs（含 ATs/AJs/AQs），却把 A4s–A2s 排除；
  有 `KQs`/`KJs`，却没有 `QJs`/`KTs`。

这正是 2026-11-05 那篇反对的做法（按单手加，不按类别加）。当时对 `COLD_CALL_*` / `LIMP_*`
按类别加宽后，命中率 66%→73%、`prior_absent` 55→44。

## 加宽的宽度代价（要拍板的数字）

加宽前 `3BET_vs_MP` = 74 combos / 5.58%，`3BET_CALL_vs_LP` = 50 / 3.77%。
`tests/test_ranges.py:76-77` 钉死窗口 `3BET_vs_EP ∈ (5.0, 7.0)`、`3BET_CALL_vs_LP ∈ (3.0, 5.0)`，
设计目标写在 `poker_ocr/ranges.py:245-250`（3-bet ~5.6%、面对 3-bet 继续 ~3.8%）。实算：

| 改动 | combos | 宽度 | 是否越界 |
|---|---|---|---|
| `3BET` + 77、88、99 | 92 | 6.94% | 窗口内 |
| `3BET` + 66–99 | 98 | 7.39% | 越界 |
| `3BET` + 66、77 + QTs、QTo | 102 | 7.69% | 越界 |
| `3BET` + 66–99 + QTs、QTo | 114 | 8.60% | 越界 |
| `3BET` + 77、76s、87s、97s、T7s（issue 提案） | 96 | 7.24% | 越界 |
| `3BET_CALL` + 22–99 | 98 | 7.39% | 越界 |
| `3BET_CALL` + 22–99 + AQo、KQo | 122 | 9.20% | 越界 |
| `3BET_CALL` + 22–99 + AJo、AQo、KQo | 134 | 10.11% | 越界 |

**结论：任何一次真加宽都会突破现有测试窗口，所以「目标宽度」本身就是要维护者拍板的东西**，
不能只改表 —— 必须同步改 `poker_ocr/ranges.py:245-250` 的注释与 `tests/test_ranges.py:76-77`。

## 口径提醒

只有走到摊牌的牌可见，且天然偏强、样本不独立。因此本笔记只能给**方向**（该补哪些类别），
不能给**精确边界**（补到 77 还是 66、连张补几个）。同 2026-11-05 的自我限定。

## 本笔记不能回答的

- 3-bet 先验的「正确宽度」是多少（那是模型决策，不是数据决策）。
- 同花连张该不该进 3-bet 池（本地无证据）。
- 提示词里 `poker_ocr/prompt/system/scenario.py:60` 的 `_THREE_BET`「按强范围（QQ+/AK）评估」
  要不要同批改 —— 属于提示词口径，须走三步走流程。

## 落地结果（#40，2026-11-15）

维护者拍板按类别加宽，宽度自己定（不追求回到旧窗口）：

| 表 | 加宽前 | 加宽后 | 加了什么 |
|---|---|---|---|
| `THREE_BET` | 74 combos / 5.58% | 102 / 7.69% | 66、77、QTs、QTo |
| `THREE_BET_CALL` | 50 / 3.77% | 122 / 9.20% | 22–99 全类（`22+` 覆盖原 `TT+`）+ AQo、KQo |

不进池：`76s / 87s / 97s / T7s`（本文无证据，见上节否定结论）。

同一份样本（并入 `data/hand_outbox/sent/` 去重后 315 条）复跑
`tools/showdown_range_check.py` + `tools/preflop_prior_gap.py` 口径：

| 口径 | 加宽前 | 加宽后 |
|---|---|---|
| 3-bet 样本 prior_absent | 15 / 22（68.2%） | **5 / 22（22.7%）** |
| 全局 prior_absent | 90 / 315（28.6%） | 80 / 315（25.4%） |

仍缺的 3-bet key：`A9o / AJo / 54s / TT / JTo`——`TT` 属于 3-bettor 那张表
（本次只补到 66/77，`QQ+` 仍是价值核心），其余是同花连张邻类与非同花高张的
残余，留给下一次按类别判断。

提示词同批改了写死的旧枚举：`poker_ocr/prompt/system/scenario.py:60` 改成
「强范围，但含小对子与同花高张构成的诈唬」，`poker_ocr/prompt/user/preflop.py`
的继续范围 label 改成「全对子 + AQs+ / AK / AQo / KQo」；`PROMPT_VERSION`
bump 到 `lean-zh-2026-11-15.1`。
