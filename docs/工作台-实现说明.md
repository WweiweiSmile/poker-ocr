# 工作台（Workbench）实现说明

> 2026-11-12 · 对应 [`工作台-需求与设计-2026-11-12.md`](工作台-需求与设计-2026-11-12.md)
> 代码：`poker_ocr/workbench/`（后端 + 静态页），`poker_ocr/live_web.py`（live 最小接口），
> `poker_ocr/live.py`（`--preview` / `--control-token` / `--run-id`）。

一句话：**把「一次启动所需的一切」收进一个可命名、可体检、可一键启动、运行中可观察/可标定的工作区**，
工作台自己只读/控制 live，不改识别口径。

---

## 1. 启动

```bash
cd /Users/weiweigod/codes/poker-ocr

# 工作台（默认 :8030）
./nv -m poker_ocr.workbench
./nv -m poker_ocr.workbench --port 8030 --open

# 工作区目录默认 workspaces/，运行产物默认 runs/；都可显式指定
./nv -m poker_ocr.workbench --workspaces workspaces --runs runs
```

- 工作台**只绑回环地址**（`127.0.0.1` / `localhost` / `::1`），不做远程访问。
- **改了 Python 代码必须重启工作台进程**。页面静态资源（`app.js` / `style.css`）
  每次请求都从磁盘读，会立即生效；Python 后端不会热重载，容易出现「页面是新
  的、体检/启动还是旧逻辑」的错觉。新版 `/api/health` 会返回 `stale`，页面顶部
  出现「后端代码已更新，请重启」的提示。
- live 仍由工作台 spawn 成子进程，默认从 `:8020` 起找空闲端口（占用则 `:8021+`）。
- 页面上的写操作需要 token；token 由服务注入 HTML（`window.__WB_TOKEN__`），
  不出现在命令行、日志或 manifest。
- 工作台退出（Ctrl-C / SIGTERM）会先停 live、停浮层、写 manifest；
  live 用独立进程组（`start_new_session=True` + `killpg`），不会留下孤儿自动点击。

### 首次使用

1. 打开 `http://127.0.0.1:8030` →「+ 从 profile 新建」。
2. 选 `config/table_wpk_mac.json`，源类型 `window`，点「枚举窗口」选 WePoker 窗口，
   或直接填 `title:WePoker-H5` / `index:N` / `x,y,w,h`。
3. 打开游戏窗口 →「概览」→「固定窗口」记录当前 rect（Retina 下逻辑点 ≠ profile 像素）。
4. 「体检」→ 处理 fail / 确认 warn →「启动 live」。
5. 运行页看帧 + ROI；需要调框时点「标定」。

**与设计文档的刻意差异**（都是更保守的选择）：

1. **force 只接受 warn，fail 永远阻断**。设计 §9 写「fail 阻断启动」，实现里
   `force=true` 也不能绕过 fail；仅用于确认警告。
2. **单张图片不能做 live 源**。`file` 源必须是视频文件；图片只在标定冻结帧里用
   （live 的 `_open_capture` 走 `cv2.VideoCapture`，图片会打开成功但读不到后续帧，
   等于无限重连）。体检会把图片源标成 fail 并说明。
3. **工作台不长期持有摄像头**。抓帧一律「开 → 读 → 立即 release」，启动 live 前
   不再需要额外交接；因此没有「释放预览并重试」按钮（失败日志会直接给权限提示）。
4. **`expected_size` 不猜**。新建工作区不把 `reference_size`（像素）当窗口尺寸
   （逻辑点），未固定时体检给 warn，由「固定窗口」记录真实 rect。
   「窗口 → 一键配置窗口分辨率」会**显式**把游戏窗口调整到期望尺寸（未填时按
   profile 参考比例 + 当前窗口宽度推算），并移动到 `window.position`（默认 0,0）；
   这是用户点击的主动作，仍然不做自动固定。需要「辅助功能」权限，系统拒绝时
   返回系统设置路径。界面上改了但还没保存的游戏窗口/位置也会随这次点击一起
   生效/落库。
5. **体检端口项在 8020 被占但还有空闲端口时给 warn**（不是 fail）：工作台会自动
   换 `:8021+`，报告里写清楚将用哪个端口；全部端口被占才 fail。
6. **`click.confirm=true` 的 y/n 仍在启动工作台的终端里按**（live 的既有语义）。
   页面不会弹确认框；不想依赖终端就设 `confirm=false`（并保留 dry-run /
   暂停点击）或在 dry-run 验证后再开真实点击。

## 3. 代码结构

```
poker_ocr/workbench/
├── __main__.py      # CLI：--host/--port/--workspaces/--runs/--open
├── app.py           # FastAPI 路由 + 静态页 + token/Origin 校验
├── service.py       # 编排层（可脱离 HTTP 单测）
├── store.py         # 工作区 schema / CRUD / profile 发现
├── geometry.py      # 槽位 key、分组、像素换算、几何诊断、错误映射
├── sources.py       # 窗口/摄像头/RTSP/文件 枚举与单帧探测；权限检查
├── preflight.py     # 17 项体检
├── supervisor.py    # live 子进程、运行目录、manifest、历史
├── live_client.py   # live HTTP 客户端（health/meta/preview/control/snapshot）
├── calibration.py   # 草稿、试读 OCR、diff、备份、原子写、回滚
├── overlay_ctl.py   # 屏幕浮层（渲染 + 跟随窗口）
└── static/          # index.html / app.js / style.css（无构建）
```

live 侧新增（只增不改口径）：

| 接口 / 参数 | 说明 |
|---|---|
| `GET /api/meta` | profile 哈希、源规格、帧尺寸、content rect、窗口 rect、点击状态、统计 |
| `GET /api/preview.jpg?w=&full=1` | 最新已处理帧；`X-Frame-Seq` 帧序号 |
| `POST /api/control/click` | `{"enabled": false}` 暂停点击；需要 `X-Workbench-Token` |
| `GET /api/control/state` | 点击开关 / dry-run / 暂停原因 |
| `--preview` | 开启预览（默认关，行为与旧版一致） |
| `--control-token` | 控制面 token（<8 字符拒绝）；同时校验 Origin 同源 |
| `--run-id` | 工作台运行 id，写进 meta/日志便于对账 |

### 3.1 工作台 HTTP API（`:8030`）

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/workspaces` | 工作区列表（含 profile 摘要 / 上次运行） |
| POST | `/api/workspaces` | 从 profile 新建 / 导入 JSON |
| GET/PUT/DELETE | `/api/workspaces/{id}` | 详情 / 改配置 / 删除 |
| POST | `/api/workspaces/{id}/duplicate` | 复制 |
| GET | `/api/profiles` | 发现 `config/table_*.json` 并打兼容标签 |
| GET | `/api/sources/windows` · `/cameras` | 窗口/摄像头枚举 |
| POST | `/api/sources/probe` | 单帧探测（不启动 live） |
| GET | `/api/workspaces/{id}/preflight` | 17 项体检（`?probe=0` 跳过源探测） |
| POST | `.../start` · `/stop` · `/restart` | 启停；`start` 的 `force` 只接受 warn |
| GET | `.../status` | 状态 + live meta + 快照 + 日志尾 + 浮层/草稿 |
| POST | `.../click` | 暂停/恢复点击（转给 live 的控制接口） |
| POST | `.../pin-window` | 记录当前窗口 rect + 期望尺寸 |
| POST | `.../configure-window` | 一键把游戏窗口调整为期望尺寸+位置（可传 `target:[w,h]` / `position:[x,y]`；`spec` 传界面上尚未保存的窗口） |
| GET | `.../preview.jpg` · `.../frame.jpg` | 运行预览（代理 live）/ 冻结帧 |
| GET | `.../slots` | 全量槽位 + 分组 + 像素矩形 + 几何诊断（`?probe=1` 用真实帧尺寸） |
| GET | `.../runs` · `/api/runs/{run_id}/manifest` | 运行历史 / manifest |
| GET | `.../calibration` | 草稿 + diff + 备份列表 + 布局 |
| POST | `.../calibration/edit` · `/undo` · `/redo` · `/reset` | 草稿编辑 |
| POST | `.../calibration/trial` | 单槽试读（裁剪图 + OCR + 解析） |
| POST | `.../calibration/apply` | 保存并重启（失败回滚） |
| POST | `.../calibration/restore` | 从备份恢复（停 live → 写回 → 重启） |
| POST | `.../overlay` · `/overlay/update` | 开关浮层 / 更新组与选中框 |

写操作统一要 `X-Workbench-Token`，带 `Origin` 时校验同源。

**暂停点击语义**：清空 `_pending_decision_key` / `_deferred_click` / `_click_retry`；
恢复后不补点旧决策，只对恢复后的新决策点生效；同时推一条 `control` 事件。
`--no-auto-click` 启动时 `available=false`，暂停/恢复是 no-op，页面显示「未启用点击」。

**预览**：主循环只存最新帧引用；缩放/JPEG 编码在 HTTP 线程、锁外完成，
不阻塞 OCR。工作台 ROI 坐标始终用「归一化 + meta」，不按预览图像素反推。

**标定帧与 live 同口径**：live 停止时抓到的源原图会再走一遍 `rotate → plan_crop →
AspectFit`（复用 `poker_ocr.live` 的同一组函数），保证「标定看到的框 = live 识别
用的框」；live 运行中直接用 `/api/preview.jpg?full=1`，不重复处理。

## 4. 工作区与配置

- 工作区文件：`workspaces/<id>.json`（schema 1，建议提交；不含密钥）。
  仓库自带一个示例 `workspaces/wpk-mac-live.json`（对应设计文档里的
  WePoker Mac 实盘：`table_wpk_mac` + `window:title:WePoker-H5`）。
- **引用不复制**：`profile` 指向 `config/table_*.json`，标定直接改那个文件。
- 标定写回：只改目标槽位；`_note`、未知键、键顺序全部保留；写前跑
  `Profile.check()`，失败不写、不重启；成功后备份 `<file>.bak-YYYYmmdd-HHMMSS`
  （保留最近 20 份）。
- 保存并重启：先停 live → 写文件 → 用新配置启动；启动失败自动恢复备份、
  重启旧配置，草稿保留；成功才清草稿。
- 高级运行参数是白名单（`stable_frames` / `roi_threads` / `rotate` / `crop` /
  `cross_check` 等），UI 不能拼任意 CLI 参数。
- `window.spec`（实现补充，设计 §5.2 未列）：滑杆点击/浮层要落到的**屏幕游戏窗口**。
  窗口源留空 = 跟随源；摄像头/RTSP/文件源不会自动带窗口，必须显式指定（或改
  用窗口源）。从窗口源切到其他源并保存时，工作台会把原 source spec 自动写进
  `window.spec`，避免切换后丢失点击目标。`bet_slider_mac.json` 的 `window` 仅作
  老配置兼容兜底，工作台不再要求它必须非空。写法支持 `id:N`（推荐：标签页
  标题变化不影响，窗口关闭/浏览器重启后失效）、`index:N`、`title:...`、`owner:...`。
- `window.position`（实现补充）：一键配置窗口时同时把窗口左上角移动到 `[x,y]`，
  默认 `[0,0]`，多显示器可为负；只影响窗口位置，不参与识别坐标换算。

## 7. 安全

1. 工作台只绑回环；页面写操作 `X-Workbench-Token` + Origin 同源校验。
2. live 控制接口同样要 token；没配 `--control-token` 时控制面关闭（403）。
3. 参数白名单：命令行只由工作区字段拼出，`shell=False`，不拼任意片段。
4. `.env`/API key 只检查存在性，不回显；manifest 不存 token。
5. 标定写入：校验 → 备份 → 临时文件 + `os.replace`；失败回滚。
6. 退出：进程组 SIGINT → 10s → SIGKILL；浮层随心跳自退。

## 10. 剩余（M3 及以后）

- 座位身份工具：hero / 环序 / 行动方向的可视化重排（当前只读 + 显式改 profile）。
- 逐 ROI 与 live 实际读数对比（需要 live 暴露逐 ROI 诊断）。
- 配置 diff/回滚 UI（后端已有 `restore_backup`，页面只展示最近备份）。
- 热重载（v1 明确不做，保存即重启）。
- 硬杀工作台后的 live 看门狗（v1 只保证正常退出/信号路径）。
- 多路并发、远程访问、多用户（v1 明确不做）。
