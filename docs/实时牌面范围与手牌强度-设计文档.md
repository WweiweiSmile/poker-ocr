# 方案一：实时牌面范围 + 手牌强度 —— 设计文档

> 本文是**方案一的正式设计文档**：给定公共牌，实时生成“和牌面有关联”的对手范围，
> 再用程序算出手牌在该范围里的强度事实（`behind_now` / `equity` / `beaten_by`），
> 作为事实块注入 AI 提示词，让 AI 在事实之上做决策。
>
> 前置背景（过程稿，保留备查）：
> [`实时牌面范围-设计.md`](./实时牌面范围-设计.md)、
> [`手牌范围基准-实现方案.md`](./手牌范围基准-实现方案.md)。

---

## 0. 结论与决策

**采用方案一，不跑完整 GTO。**

理由（已与现状核对）：

1. 现有 GTO 求解器只支持 **HU SRP**（`gto_lookup`：`opponents_in_hand != 1 → None`），
   只跑 BTN/CO 两个 spot、184 牌面类，转牌/河牌未抽取，生产库目前没有 `gto.sqlite`；
   而本场景是 **9-max 现场、3–5 人池**。多人翻后均衡求解在计算上不可行。
2. 现场是松弱池，正确打法是**剥削**而非平衡；GTO 频率对“从不弃牌的跟注站”是错的。
3. LLM 不擅长把频率翻译成动作，擅长把“强/弱/权益”这些**已算好的事实**翻译成动作。

方案一能在当前设备（M2 / 16GB）上落地：

| 指标 | 数值 |
|---|---|
| 实时牌面范围构建 | ~11–12ms/board（位掩码 + 缓存） |
| 手牌强度（behind + equity MC） | ~80ms/决策（3-way 2000 次），缓存后 <1ms |
| 工程量 | 3–4 个工程日 |

## 1. 目标与非目标

### 目标

- 给定 `hero` 两张牌、`board`（3–5 张）、每个在局对手的范围，回答：
  - **`behind_now`**：现在有多少比例的范围比我大；
  - **`equity`**：打到河牌的权益；
  - **`beaten_by`**：比我大的牌是哪些类别/组合；
  - **`ahead_of`**：我领先的类别/比例。
- 把这些作为**事实**注入提示词，AI 只负责选动作（价值下注 / 过牌 / 跟注 / 弃牌 / 尺度）。

### 非目标

- 不追求 3–5 人 GTO 均衡；不输出频率表；
- 不要求翻后 solver 的单手 EV / 尺度；
- 不追求“范围 vs 范围”的整体权益（那由 `board_equity` 负责，作为背景）；
- 不做翻前 solver（标准先验够用）。

## 2. 术语

| 术语 | 含义 |
|---|---|
| combo | 具体两张牌，`((rank, suit), (rank, suit))`，与 `coach` 口径一致 |
| 169 键 | `AA` / `AKs` / `AQo` 这类手牌类别，对子 6 combo、同花 4、非同花 12 |
| 翻前先验 | 对手翻前可能拿什么（具名范围 / 规则先验 / 均匀） |
| 连接度分数 | 某 combo 与当前牌面“关系强度”，0–1.8，不是概率 |
| 动作条件范围 | 按对手当前街动作（下注/跟注/过牌）截断后的范围 |
| `behind_now` | 范围里当前成手牌严格大于 hero 的加权比例 |

## 5. 数据模型

```python
# poker_ocr/ranges.py
Card = tuple[int, str]            # (0..12, 's'|'h'|'d'|'c')，与 coach 一致
Combo = tuple[Card, Card]         # 规范排序

@dataclass(frozen=True)
class Range:
    id: str
    version: int
    combo_weights: Mapping[Combo, float]   # 已归一化（和 = 1）
    width_pct: float                        # w>0 的组合数 / 1326
    source: str                             # "named:RFI_BTN" | "board:call:RFI_BTN" | "board-only"
    note: str = ""

    def combos(self) -> tuple[Combo, ...]: ...
```

要点：

- 统一用 **combo 级权重**。翻前先验是 169 键权重，展开到 combo（对子 6、同花 4、非同花 12）；
  实时牌面范围本来就按 combo 算（花色要进特征）。
- 权重的含义：**范围内抽到该 combo 的概率**。`width_pct` 是“范围宽度”的直观口径，
  权重本身用于 `behind_i` / equity 的加权。
- 空范围 / 权重全 0 → 返回 `None`，不猜。

## 6. 实时牌面范围（board_range）

### 6.1 语义：动作条件范围

**牌面不会改变对手发到什么牌，改变的是他“继续”的范围。**

```text
P(hand | board, action) ∝ P(action | hand, board) × P(hand | preflop)
```

- `P(hand | preflop)`：翻前先验；
- `P(action | hand, board)`：这手牌在这样的牌面上会不会下注/跟注；**连接度分数是它的代理**。

所以必须按动作选范围：

| 对手当前街动作 | 用什么范围 | 为什么 |
|---|---|---|
| 过牌 | 翻前先验（不按牌面筛） | 过牌可以是空气，筛掉空气会高估他 |
| 下注 / 加注 | 牌面范围，高门槛 | 下注范围是收窄的 |
| 跟注 | 牌面范围，低门槛 | 跟注可以很宽，但仍有下限 |
| 还没行动 | 翻前先验 | 没有新信息 |
| 全下 | 牌面范围，最高门槛 | 全下最窄 |
| 已弃牌 | 排除 | — |

多人池里每个对手可以不同 mode；`hand_vs_ranges` 逐对手处理。

### 6.2 特征提取

对每个 combo（不含公共牌），算：

```python
# poker_ocr/board_range.py
@dataclass(frozen=True)
class Features:
    category: int            # evaluate(hole+board) 的牌型下标
    pair_kind: str           # top/second/middle/bottom/under/over/board/None
    flush_draw: bool
    backdoor_flush: bool
    straight_outs: int       # 下一张能成顺的“点数个数”（1=卡顺，>=2=两头/双卡）
    backdoor_straight: bool  # 需要 turn+river 两张才成顺
    overcards: bool          # 两张都高于牌面最大牌（无对）
    plays_board: bool        # 最好五张全靠公共牌
```

实现细节：

1. **成牌**：`cat, key = evaluate(list(combo) + board)`。
   - 对子再细分：overpair / top / second / middle / bottom / underpair；
   - 公对牌面（board 自身有对子）且 hole 没碰到 → `board`，权重低（人人都有）。
2. **同花**：
   - `suit_count == 4` 且 hole 有该花色 → `flush_draw`；
   - `suit_count == 3` 且 hole 有该花色，且 `len(board) == 3` → `backdoor_flush`。
3. **顺子**（位掩码，预计算 8,192 个 mask 的 `straight_high`）：
   - `mask = 公共牌 ranks | hole ranks`；
   - 数 `r ∉ mask` 且 `STRAIGHT_HIGH[mask | 1<<r] >= 0` 的点数 → `straight_outs`；
   - `straight_outs == 0` 且 `cat < STRAIGHT` 且 `len(board) == 3` 时，
     检查是否存在 `r1,r2 ∉ mask` 使 `STRAIGHT_HIGH[mask|1<<r1|1<<r2] >= 0` → `backdoor_straight`。
4. **高张**：`len(board) == 3`、无对、`hole 两 rank > max(board ranks)`。
5. **打牌面**：`evaluate(board)` 与 `evaluate(hole+board)` 牌型相同且 hole 无贡献。

> turn/river 不再给后门分；river 不再给任何听牌分。

### 6.3 连接度分数

分数是“关系强度”，不是概率。起始权重（可调）：

| 特征 | 分数 |
|---|---|
| 空气、无听、无高张 | 0 |
| underpair | 0.45 |
| 底对 / 中对 | 0.60 / 0.70 |
| 第二对 | 0.75 |
| 顶对 | 0.80 |
| overpair | 0.90 |
| 两对 | 1.25 |
| set / trips | 1.40 |
| 顺子 | 1.50 |
| 同花 | 1.60 |
| 葫芦 / 四条 | 1.70 |
| 同花听 | +0.80 |
| 两头/双卡（≥8 outs） | +0.70 |
| 卡顺（4 outs） | +0.35 |
| 后门花 / 后门顺 | +0.15 / +0.10 |
| 高张（无对） | +0.10 |

规则：

- 封顶 1.8；
- **后门分只在“没有下一张听牌”时加**，避免重复计数：
  `25` 是 0.35（卡顺），`7h8h` 是 0.10（只有后门顺）；
- 听牌 outs 取**并集**，不把花听和顺听直接相加。

### 6.4 阈值与动作模式

| mode | `min_weight` | 说明 |
|---|---|---|
| `check` | — | 不乘 board_score，直接用翻前先验 |
| `call` | 0.30 | 对子/卡顺/后门都算 |
| `bet` | 0.75 | 顶对+/强听；去掉 underpair/底对/纯后门 |
| `raise` | 0.85 | 两对+/set/强听 |
| `allin` | 0.90 | 只留强成牌/强听 |
| `unknown` | 0.35 | 纯牌面范围，标注 `board-only` |

默认 `min_weight = 0.30`（只丢纯空气/纯后门）。

### 6.5 翻前先验

三种来源，按优先级：

1. **具名范围**：`RFI_<pos>`、`BB_DEF_vs_<opener>`、`COLD_CALL_*`、`LIMP_*`；
2. **规则先验**（不维护表时）：对子 1.0（小对子 0.75）、同花 0.9、双高张 0.8、
   连张/隔张 0.7、A 高 0.65、非同花 0.5、被统治非同花 A/K/Q 0.3；位置/角色乘子；
3. **均匀先验**：全部 1,326 combo；纯牌面范围，必须标注 `board-only`。

`AsKs4d` 的宽度随先验收紧：

| 先验 | 宽度 |
|---|---|
| 纯牌面（均匀） | 44.6% |
| ∩ BTN RFI | 24.5% |
| ∩ UTG RFI | 9.4% |

### 6.6 构建流程

```python
def build(board: str,
          mode: str = "call",
          prior: Range | None = None,
          min_weight: float = MODE_MIN_WEIGHT[mode],
          ) -> Range | None:
    board_cards = parse_cards(board)
    if len(board_cards) < 3 or 去重失败:
        return None
    weights = {}
    for combo in all_combos():
        if combo 含 board 牌:
            continue
        feat = classify(combo, board_cards)
        score = SCORE(feat)
        if score < min_weight:
            continue
        w = score * (prior.combo_weights.get(combo, 0.0) if prior else 1.0)
        if w > 0:
            weights[combo] = w
    if not weights:
        return None
    归一化(weights)
    return Range(id=f"board:{mode}:{prior.id if prior else 'uniform'}",
                 combo_weights=weights, width_pct=len(weights)/1326, ...)
```

性能：

- 朴素逐 combo 调 `_count_outs` ≈ 450–660ms/board；
- 位掩码 + `STRAIGHT_HIGH` 预计算表 ≈ **11–12ms/board**；
- 缓存 key = `(board, mode, prior_id, min_weight)`；同一街多帧只算一次。

## 7. 角色解析（field_ranges）

```python
# poker_ocr/field_ranges.py
@dataclass(frozen=True)
class OpponentRangeSpec:
    seat_id: str
    position: str | None
    prior_id: str | None      # 翻前先验（None = 没把握）
    mode: str                 # check/call/bet/raise/allin/unknown
    note: str = ""

@dataclass(frozen=True)
class Field:
    specs: tuple[OpponentRangeSpec, ...]
    warnings: tuple[str, ...]

def resolve(snap: HandSnapshot) -> Field: ...
```

步骤：

1. 取翻前 `ActionRecord`，判定 `single-raise / three-bet / limped`，找 opener/aggressor。
2. 对每个未弃牌对手（排除 hero）定先验：
   - 翻前最后加注者 → `RFI_<pos>`（单加注）/ `3BET_vs_<bucket>`（3-bet）；
   - 跟注加注者 → `BB_DEF_vs_<opener>`（BB）或 `COLD_CALL_<IP/OOP>_vs_<bucket>`；
   - 溜入者 → `LIMP_<bucket>`；bomb pot → `BOMB`。
3. 当前街动作 → mode：
   - `bet`/`raise` → `bet`/`raise`；`call` → `call`；`check` → `check`；
   - 还没行动 → `check`；读不到 → `unknown` + warning。
4. 与 `preflop_shapes` 交叉校验，矛盾 → `prior_id=None` + warning，不猜。
5. 位置缺失 / 动作缺失 → 降级，不用 BB 代理。

## 8. 手牌强度计算（hand_vs_ranges）

### 8.1 精确逐对手统计（不采样）

对每个对手范围，去掉与 `hero+board` 撞牌的组合，然后**加权**累加：

```python
me = evaluate(hero + board)
for combo, w in range.combos():
    if combo 与 hero/board 撞牌: continue
    s = evaluate(combo + board)
    if s > me: behind += w
    elif s == me: tie += w
    else: ahead += w
    # 按 (category, 主牌力) 分组，记录组合数 + 2 个示例
```

输出每对手：`behind_i / tie_i / ahead_i`、`beaten_by` 分组（如“sets 1.6%: KK×1, 77×3, 22×3”）。

### 8.2 MC 联合与权益

- **`behind_any` / `tie_any`**：每次独立抽每家一手牌，**整组**检查互撞，
  撞了整组重抽（避免顺序条件抽样的系统偏差）；
  - 有任一家的当前成手牌 > hero → `behind_any += 1`；
  - 没人 > 但有人 == → `tie_any += 1`。
- **`equity`**：同一组手牌，发完剩余公共牌（flop 发 2、turn 发 1、river 发 0），
  与 hero 比大小，平局按 `1/赢家数` 分池。
- 样本数：3-way 2000 / 4-way 1500；标准误 ≈ ±1%。

### 8.3 draw_share（P1，可选）

- 范围里“强听（8+ outs）”的加权占比，解释“为什么 `behind_now` 高但 equity 不低”；
- 复用 `coach._count_outs` 口径；flop/turn 才计算；每范围先抽 200 个 combo 控耗时。

### 8.4 缓存与确定性

- 缓存 key = `(street, board, hero, tuple(range_id + version), samples, seed_version)`；
  `lru_cache(maxsize=256)`。
- seed 由 key 的稳定 hash 派生（`hashlib`/`zlib.crc32`，**不用** Python 内置 `hash()`）；
  同一决策点输出确定，避免帧间抖动。

```python
@dataclass(frozen=True)
class OpponentEdge:
    seat_id: str; range_id: str
    width_pct: float
    behind: float; tie: float; ahead: float
    beaten_by: tuple[RangeGroup, ...]

@dataclass(frozen=True)
class HandVsRanges:
    hero: str; board: str; street: str
    opponents: tuple[OpponentEdge, ...]
    behind_any: float; tie_any: float
    equity: float; equity_ci: float
    samples: int
    warnings: tuple[str, ...]
    def render(self) -> str: ...
```

失败返回 `None` 的条件：无范围 / 范围空 / 过滤后无组合 / 牌面不足 3 张 / 重复牌 /
对手位置动作无法确认。

## 9. 渲染与提示词集成

### 9.1 事实块（示例，数字为原型口径）

```text
## Hand vs ranges (BTN open; board-connected, call mode)
Board: AsKs4d | Your AhQh | flop
Range: board-connected ∩ RFI_BTN = 24.5% (325 combos)
Behind now: 9.4% (tie 2.6%) | Equity: 70% ±1%
Behind: sets 1.4% (AA, KK, 44), two pair 2.0% (AK, A4, K4)
Ahead of: worse aces, underpairs, missed broadways
Read: top pair Q kicker is strong; behind only sets/two pair.
Preflop-only: behind 3.7%, equity 81% — the board filter made his range stronger.
```

`QhJh` 同一牌面：

```text
Behind now: 86.3% | Equity: 25% | Draw: gutshot to T
Read: no made hand; weak unless price is very good.
```

`5s6s`：

```text
Behind now: 99.5% | Equity: 37% | Draw: flush draw + backdoor straight
Read: behind now but 37% equity — a draw, not a made hand; judge by price.
```

### 9.2 接入点

1. `Situation` 加 `hand_ranges: "HandVsRanges | None"`；
   `build_situation` 在 ground_truth 之后 try/except 调用
   `field_ranges.resolve → board_range.build → hand_vs_ranges.compute`。
2. 事实块位置：`ground_truth` 之后、`board_eq` 之前（主答案在前，背景在后）。
3. 旧的随机牌排名行改标题为 `Made-hand rank vs RANDOM hands (lower bound)`，保留作下界。
4. `_LEAN_SYSTEM` 优先级与口径规则：

```text
1. Hard math / computed facts (pot, price, equity, behind-now, SPR)
2. «Hand vs ranges» — use it for “what he has”, not the random-hand rank
3. «Board structure» / «GTO baseline» — background only
4. Generic heuristics
5. Opponent/table profile — an explicit OVERRIDE on the range baseline
```

补充规则（简短）：

- `equity` 是跟赔率比的那个数；`behind now` 说的是**当前成手牌**，两者不要混。
- 花听/卡顺可以现在落后但有权益，不能因为 `behind now` 高就弃牌。
- 有范围块时，随机牌排名只是下界，不要当“他的范围”。
- 某座位没有范围 → 说 `range unknown`，回退随机下界，不要编范围。

| `BOARD_RANGE_MIN_WEIGHT` | 0.30 | 全局覆盖各 mode 阈值 |

- 与 `GTO_ENABLED` 解耦；`BOARD_EQUITY_ENABLED` 单独拆（P1）。
- 所有新代码 try/except 包裹，异常只记 warning，不影响现有建议链路。

### 11.1 分类单测（`AsKs4d`）

- `2h5h`：卡顺 0.35，`call` 包含、`bet` 不包含；

- `4c4h` / `AcAd`：set 1.40，`bet` 包含；
- `7h2c`：空气 0，排除。

### 11.2 范围与强度

- `AsKs4d` 纯牌面 44.6%；∩ BTN 24.5%；∩ UTG 9.4%；
- `AhQh`/`QhJh`/`5s6s` 的 behind/equity 方向符合直觉；
- 2 个对手小范围暴力枚举对照（river 无发牌）：`behind_i`/`behind_any`/`equity` 一致 ±2%；
- 去重牌：hero 持 `As` 时对手 AA 组合减半；
- 权重 0 不参与；空范围/重复牌 → `None`；
- flop 发 2 / turn 发 1 / river 发 0 正确；
- 同 key 两次输出一致；缓存后 <1ms。

### 11.3 性能

- `board_range.build` 冷启动 <50ms，缓存 <1ms；
- `hand_vs_ranges` 3-way 2000 / 4-way 1500 <100ms。

### 11.4 回放

- 20–30 手，覆盖 3/4/5 人、flop/turn/river、湿/干/公对牌面、下注/跟注/过牌；
- 对比“只用翻前范围”与“牌面关联范围”的差异；反转要有解释（尤其过牌不能用牌面筛）。

## 13. 风险与取舍

| 风险 | 影响 | 缓解 |
|---|---|---|
| 纯牌面范围当“全部范围” | 删掉空气，高估对手 | 按动作选 mode；过牌用翻前先验 |
| 包含翻前不会玩的牌 | `25o/34o` 拉宽范围 | 乘先验；无表用规则先验 |
| 按 169 类粗筛 | 误杀 `7s8s`、漏 `QJ` | combo 级 + 花色特征 |
| 后门权重过高 | 范围虚宽、权益虚高 | 后门 ≤0.15；turn/river 归零 |
| 范围宽度随牌面剧烈变化 | 跨牌面不可比 | 渲染宽度/mode |
| 听牌重复计数 | outs/equity 虚高 | 并集口径；equity 用 MC |
| 模型过度信任 | 范围错时更自信 | 标注 `board-only`/`call mode`；给翻前对照 |
| 性能 | 实时/回放慢 | 位掩码 + 缓存；批量降采样 |

**不做**：继续跑 184 solver；3–5 人 GTO 均衡；翻前 solver；把随机牌排名当范围基准。
