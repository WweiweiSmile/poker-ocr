## P0：会直接改变动作

### P0-1 翻前位置 / 待行动：仍存在，且比原描述更严重

原描述是「BTN 有位置 + BB 还没行动」并列。HEAD 已经把 `hero_in_position()`
改成只看翻后座位顺序（`advice.py:727-738`），system 也补了
「位置只看座位」（`advice.py:2230-2231`），但实际输出仍有两层问题：

**(a) 标签仍未区分翻前/翻后。** 翻前 BTN 首个入池时渲染为：

```
位置：Hero 有位置（身后没有在局对手）｜跟注/过牌后待行动：0 人｜...
```

「身后没有在局对手」按翻后座位顺序成立，但翻前 BB 明明还在局、还没行动。
`位置` 两个字没有限定「翻后」，模型很容易直接拿它做翻前范围/偷盲决策。
反过来，BB 面对 BTN 加注时会写「Hero 无位置（翻后先行动）」，但 BB 在翻前
其实是最后一个行动。即使把下面的 (b) 修好，这里也只会变成「待行动 1 人
（BB 还没行动）」，标签仍然没说「这是翻后位置」。

**(b) 更严重：BB 的选项被算成 0 人。** `behind_opponents()` 在有下注时只数
「还没跟到最高注」的人（`advice.py:674-707`）。翻前 BB 已投 1BB，Hero 跟注
1BB 后 `max_bet` 正好等于 BB 的已投注，BB 被过滤掉，于是：

```
跟注/过牌后待行动：0 人
```

但 BB 在 Hero 跟注后仍有 check/raise 的选项，Hero 并没有收尾。同一逻辑也会
漏掉「Hero 平跟、BB 还没行动」的溜入池。测试只覆盖了翻后
（`tests/test_advice.py:2169-2172`），没有翻前 BB option 用例。

影响：模型会以为翻前已经收尾，过度平跟/偷盲，忽略 BB 的再加注。

建议：

- `behind_opponents()` 翻前增加 BB option 特例：BB 未弃牌、还能行动、且本街
  还没有主动动作（只有盲注）时，即使已跟到最高注也算「待行动」；
- 事实块拆两行：
  - `翻前行动：BTN 之后还有 BB 未行动（你跟注后 BB 仍有选项）`
  - `翻后位置：Hero 有位置（按座位顺序最后行动）`
- system 2230 的「身后」改成「翻后座位顺序上的身后」，避免和翻前行动顺序混用。

### P0-2 没行动的范围被写成「过牌范围」：仍存在

`field_ranges._mode()` 在本街没有任何动作记录时返回 `"check"`
（`poker_ocr/field_ranges.py:214-239`），`_RANGE_MODE_ZH` 把它翻成「过牌范围」
（`advice.py:2623-2628`）。实际渲染无行动翻牌：

```
范围：BB 过牌范围 44.8%
- BB 过牌范围：当前成牌领先我 55.2%
对范围权益：89%（按河牌、未计后续下注，2 人池）
```

但 system 自己规定「没人行动过就不能写『对手过牌』」（`advice.py:2215`）。
这不只是措辞：范围权益是按「BB 已经过牌」的范围算的，会系统性高估 Hero 的
权益和弃牌率。数据质量段也没有「本街行动线缺失」提示。

建议：

- 新增 `mode="unacted"`，中文渲染为「当前范围（本街尚未行动，沿用翻前范围）」；
- 行动线为空时，范围权益追加「按对手未行动假设，非已发生事实」，或直接隐藏；
- `_summarize_gaps` 补一条「本街行动线缺失，范围按未行动处理」。

### P0-3 攻击块 / 桌级剥削互相打架：部分修复，仍存在

HEAD 已经去掉了「没有 xr 数据也默认高频开火」（`advice.py:3487-3494`），但只要
**有 xr 数据**，仍然无条件走高频分支（`advice.py:3496-3501`），完全不看弃牌率。
实测（xr=10%，翻牌弃牌率 25%）：

```
这是高频小注攻击的位置：用 1/3–1/2 池下注，别只拿成牌下注；
当前权益低不是过牌的理由 —— 诈唬看的是对手弃牌率……
全场先验：对手面对翻牌下注弃 25% → 弃牌率不足，不支持开火
```

同一个 `## 攻击机会` 块里，上一句让开火，下一句说别开火。`_xr_data_known()`
只判断「有没有 xr 数据」（`advice.py:3356-3363`），不判断 xr 高不高，也不和
`_ATTACK_FOLD_SUPPORT_PCT = 50`（`advice.py:3316-3317`）联动。

桌级版本仍然冲突（翻牌、无 xr 数据、桌面对 c-bet 弃 75%）：

```
全场可剥削：对 c-bet 弃得多 —— 翻牌可以高频开火，别只拿强牌下注；……
## 攻击机会（宽范围/死钱）
没有对手过牌-加注数据……默认只用强牌/强听下注，中等牌/空气优先过牌
全场先验：对手面对翻牌下注弃 25% → 弃牌率不足，不支持开火
```

建议：攻击块改成「先结论、后依据」：

```
攻击结论：不开火 / 仅强牌下注 / 可高频小注
依据：翻牌弃牌率 25%（不足）；xr 数据缺失/10%（不高）；牌面有花顺可能
```

只有 `fold_to_bet >= 50%` 且没有高 xr / 高跟注证据时才允许「高频小注」；
不满足时不要输出「当前权益低不是过牌的理由」这种无条件鼓励。桌级剥削与攻击块
共用同一套阈值，最终只留一个结论。

### P0-4 炸弹池「顶对可以打光」：仍存在，且三套口径不一致

代码（`advice.py:3231-3243`）：

```
顶对强踢/超对在干燥面且价格合适时可以打光
```

system（`advice.py:2234`）：

```
遇到加注/过牌-加注/多街连开或对手明显过度激进时，只用超强范围……顶对/超对降级
```

README（`README.md:127-129`）还写着「SPR ≤2 时顶对就是套池价值牌（翻牌下注、

明确说这是旧口径。

建议：删掉「可以打光」，改成：

> 无加注、干燥面、价格合适时可以继续，但不主动造大底池；遇到加注/
> 过牌-加注/多街连开按两对以上继续。

同步 README。

### P0-5 combo draw 写成「默认下注」：仍存在

`advice.py:2758-2762`：

```
有牌又有听：成牌 + 强听（combo draw，不是纯听牌）；
权益高于公平份额时默认下注 1/3–2/3 池，不要只因为这手“落后至少一家”就过牌
```

实测 4 人池、TPTK + 坚果同花听、权益 35% / 公平份额 25%，仍输出「默认下注」。
system 说「多人池：顶对/超对降级；没有弃牌率时不要用听牌硬下注」
（`advice.py:2229`）。而且 `hand_ranges` 缺失时事实块里没有公平份额/权益，
模型无法验证「权益高于公平份额」这个前提。

建议：

> 有牌又有听：可作为保护/半诈唬下注，不是默认；多人池或没有弃牌率时优先过牌。

只有 `hand_ranges` 存在且权益确实高于公平份额时才给倍数判断。测试
`tests/test_advice.py:1925` 锁定了旧文案，需要一起改。

### P0-6 听牌价格在 SPR≤2 时直接判「够」：仍存在

`advice.py:2835-2848`：

```
听牌价格：跟注 4BB / 可争夺底池 14BB = 29% 门槛；四二法则 36% → 够；
SPR 1.2 时对手通常已套池，弃牌率低，只有对手全下/后面不再下注时，
四二权益才可直接比门槛
```

后半句自己承认不能直接比，前半句已经给了「够」这个硬结论。system 2237 明确说
「翻牌时是两街，不能直接和单街赔率门槛比，只有全下/后面不再下注时才可直接比」
（`advice.py:2237`）。SPR≤2 不等于「已经全下/后面不再下注」。

建议：

- 只有 `to_call >= hero_stack`、已套池或明确「后面不再下注」时才输出 verdict；
- 否则只显示「参考值，不可直接与单街门槛比较」，不写「够/不够」。

### P0-7 单挑也标成「多人池」：仍存在

`advice.py:2820-2825` 无条件用「多人池」：

## P1：会系统性带偏

### P1-1 Hero 后手未知时写「短码/side pot：无」

`advice.py:3641-3659`：`hero_total` 为 `None` 时 `short` 为空，若对手筹码都已知，
落到 else 输出「无」。实测：

```
Hero：BTN｜底牌 Ah Kd｜后手 未知
短码/side pot：无
```

数据质量段同时说「底池/后手未读全」，自相矛盾。

建议：`短码/side pot：未知（Hero 后手未读出）`。

### P1-2 `Hero 是否翻前加注者：否` 语义不清

`hero_is_pfr` 实际是「最后一个翻前加注者」（`poker_ocr/hand_track.py:1404-1410`）。
Hero 开池后被 3-bet 时它也是 `False`，但事实块写成
「Hero 是否翻前加注者：否」（`advice.py:3079`），读起来像「Hero 没加注」。
行动线缺失时同样输出「否」，而不是「未知」。

建议：改成「最后翻前加注者（PFR）：是/否/未知」；Hero 开池后被 3-bet 时补一句
「Hero 开池后被 3-bet」。

### P1-3 座位画像的「可剥削」自相矛盾

`opponent_profile.py:2526-2601` 独立生成最多两条 hint。实测同一行：

```
可剥削：过牌-加注频繁 —— 别对他的过牌随手开火；
c-bet 频率低 —— 翻牌他过牌基本是没中，可以在转牌接管控池
```

前一句说别开火，后一句说可以接管；而且「c-bet 低 = 基本没中」是过度推断
（也可能是设陷阱）。`fold_to_cbet >= 60` 还会单独输出「干燥面可以高频开火」，
和 xr 高的结论直接对撞。

建议：每个座位只输出一个合并后的结论，优先级 xr / call-to-cbet > fold-to-cbet；
删掉「基本是没中」这类不可验证的推断。

### P1-4 事实优先级缺项，且把程序计算归成启发式

`advice.py:2219` 的硬事实只列了：牌、公共牌、底池、需跟、在局人数、后手。
位置、行动线、有效筹码、底池类型都没有归类。`advice.py:2223` 又把「听牌价格」
列进启发式，但它其实是程序算出来的赔率比较（四二权益本身是经验公式）。

建议：把「位置 / 行动线 / 有效筹码 / 底池类型」补进硬事实；「听牌价格」移到
程序计算，并注明四二权益是估算值。

### P1-5 「多人池」没有定义：部分修复

`advice.py:2245` 已经切成「单挑/3 人池顶对可套池，4 人以上降级」，但
`advice.py:2229` 仍写「多人池：顶对/超对降级」，没有说 3 人算不算；事实块又用
「多人池：实际 2 人」。同一份 prompt 里三种口径。

建议：统一成「单挑 / 3 人 / 4 人以上」，并在 system 里给「降级 = 降低尺度、
减少诈唬，不等于弃牌」的定义。

### P1-6 输出契约示例不是合法 JSON

`advice.py:2208`：

```
{"option": "...", "reason": "...", "confidence": <可选 0-1>}
```

`<可选 0-1>` 不是 JSON 值，和「只输出一个 JSON 对象」冲突。

建议给两个合法示例：一个带 `confidence`，一个省略。

### P1-7 `raise-3x` / `raise-4x` 的 id 在 3-bet 池里容易读错

id 仍是 `raise-3x/raise-4x`（`advice.py:320-328`），3-bet 池里标签却是
「4-bet 到 X（3 倍）」。system 2211 只说「面对加注用 raise-3x/raise-4x」，
没有解释 id 是「上家加注额的 3/4 倍」。

建议在 id 映射里补一句：`3x/4x = 上家加注额的 3/4 倍；3-bet 池里标签写 4-bet，
id 不变。`

### P1-8 桌级剥削建议没有按街过滤

`table_exploit_zh(stats)` 没有 `street` 参数（`opponent_profile.py:1577-1615`），
`render_table_stats_zh` 每条街都调用（`advice.py:3200-3205`）。实测翻牌 prompt：

```
全场可剥削：……后位多隔离加注
```

这是翻前建议。河牌 prompt 同样会出现「翻牌可以高频开火」。

建议：`table_exploit_zh(stats, street=...)`，按当前街过滤；与攻击块共用裁决。

### P1-9 A 高面文案过于绝对：部分修复

HEAD 已增加「人工观察说本池见 A 弱」分支（`advice.py:3402-3409`），但没有观察时
仍无条件断言：

```
A 高面：A 是牌面最大张，对手的过牌/溜入范围很难承受 A 高面的压力 → 小注攻击比平时更有效。
```

（`advice.py:3411-3415`）面对跟注站或真有 A 的对手会反向。

建议：改成条件句「有现场观察/弃牌率支持时才成立」，否则只给「A 是最大张」这个事实。

### P1-10 README / 复盘文档与代码不一致（新增）

### P1-11 `_xr_data_known` 只判断「有没有」，不判断「高不高」（新增）
