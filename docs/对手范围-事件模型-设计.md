# 对手范围：事件模型设计

2026-11-01。设计稿；同日已实现（落地口径见 §12，与设计稿的差异都写在那一节）。

> 触发用例：`20261101-d32f55ecc1`（Hero `Ks3c`，炸弹池，牌面 `6h Kd 9d 4h Kh`）。
> 当时事实层给的是「对范围权益 69%」：HJ 未行动范围 100%、UTG+1 全下范围 40.7%，
> 其中约 3/4 是「任意 9x/6x/4x 两对」。模型据此 call 了 63，又 call 了 47。
> 真实情况是：能跟转牌 30、河牌再推出来的范围，几乎就是赢你的那 8.8%。

---

## 0. 结论

把「一条街一个 mode、一次过滤」换成「按手牌时间顺序，每个动作更新一次范围」：

```
P(h | a1..an) ∝ P0(h) × Π_k L(a_k | class(h, B_k), ctx_k)
```

- `P0`：翻前先验（RFI / BB 防守 / 冷跟 / LIMP / BOMB）；
- `a_k`：该对手的每一个动作，按时间顺序，**含街内**（check→call、bet→raise 都算）；
- `B_k`：动作发生时的牌面；
- `ctx_k`：行动前的上下文——身后还有几人、面对什么、是否 donk、SPR、画像；
- `class(h, B)`：这手牌在该牌面上的（成牌档，听牌档）。

范围在整手牌里是一个**持续更新的状态**，不是每街重新从翻前先验算一次。成牌和
听牌分开给似然：成牌随动作强度单调收窄；听牌不被成牌强度门槛砍掉，权益由
剩余牌发完（runout）保证一致。

本设计只改「对手范围怎么来」，不改 `hand_vs_ranges` 的权益算法（精确 behind +
MC runout 仍然可用）。

## 1. 已定口径

| 项 | 口径 | 说明 |
|---|---|---|
| donk | **A（严格）** | 本街按座位顺序**第一个行动**，且他下注/加注进**上一街 aggressor**；aggressor 还在、本街未行动 |
| IP/OOP | **B（相对全场）** | 用 `players_behind` / `is_last_to_act` / `closes_action`；相对 Hero 只用于 Hero 自己的决策事实 |
| pressure | **命名桶，不用标量** | 10 个桶；桶作用在「价值 / 半诈唬 / 诈唬」三组上，不是单一强度轴 |
| jam | **不单独算动作** | 本质是 bet/raise 的 `all_in=True`；用 `spr_bucket` 调整倾向 |
| `n_callers` | **只算本街下注之后的跟注** | 翻前 limper / 冷跟不重复计，已在翻前先验里 |

补充约定：

- `players_behind` 只数**还能行动**的对手：已弃牌、已全下的不算。
- `n_callers` 只数该玩家行动**之前**、本街这个下注/加注之后的跟注，不看未来信息。
- 上下文取「行动前」的状态；动作本身（bet/raise/call/check）是预测目标，不进上下文。
- 动作顺序以 `snap.streets` 的记录为准；OCR 漏抓时按底池对账补出来的动作标
  `inferred`，上下文按补出来的顺序算，并在数据质量段标注。

## 2. 模型

### 2.1 公式

对对手 `i`，按时间顺序的动作 `a_1..a_n`：

```
P(h | a_1..a_n) ∝ P0(h) × Π_k L(a_k | class(h, B_k), ctx_k)^α
```

- `L` 是似然（按 `(class, ctx)` 归一化到 1，便于解释），不是真实频率；
- `α` 是温度（默认 0.7）。连乘 4–5 个动作会过度自信，`α<1` 把每次更新的力度压回来；
- 最后对全部 combo 归一化，得到 `Range.combo_weights`。

为什么不用「每街从翻前先验重算」：那等于假设每街的动作相互独立，且会丢掉
上一街已经收窄的信息。这手牌的 HJ 就是例子——转牌跟注 30 的信息，在河牌
「本街未行动」时被整个丢回 100%。

### 2.2 手牌分类

复用 `board_range.Features`（combo + 花色级），不再写第二套分类器：

| 维度 | 取值 | 来源 |
|---|---|---|
| `made` | nut / strong / medium / weak / air | `evaluate` 的牌型 + `Features.pair_kind` |
| `draw` | combo / flush / oesd / gutshot / backdoor / none | `Features.flush_draw` / `straight_outs` / `backdoor_*` |
| `group` | value / semi_bluff / bluff | 由上两维映射，见 2.3 |

`made` 的建议映射（可按现有 `fold_equity` 的九档对齐）：

| made | 包含 |
|---|---|
| nut | 四条、同花顺、坚果同花/坚果葫芦（按牌面判断） |
| strong | 葫芦、同花、顺子、三条（好踢脚） |
| medium | 两对、超对、顶对顶踢 |
| weak | 顶对弱踢、中对、底对、公对 |
| air | 高牌、打牌面、错过的听牌 |

`draw` 只在翻牌/转牌有意义；河牌一律 `none`，错过的听牌归 `air`。

### 2.3 三组

| group | 包含 | 为什么要单独一组 |
|---|---|---|
| value | 两对以上 | 随动作强度**升**，且向坚果集中 |
| semi_bluff | 花听、OESD、双抽、对子+强听 | 全下/加注的合法来源，**不能被成牌强度门槛杀掉** |
| bluff | 空气、错过的听牌、弱后门 | 随多人/面对下注**降**，但保留一个非零频率 |

这就是为什么不能用单一 `pressure` 标量：多人池里 value 和 bluff 的方向相反。
桶只调这三组的相对权重，不逐格手填。

## 3. 成牌 / 听牌分区与权益一致性

### 3.1 分区

每个 combo 在每个牌面上都有 `(made, draw)`。分区有两个用途：

1. **似然设计**：成牌按 `made` 档查表，听牌按 `draw` 档查表，互不覆盖；
2. **渲染**：告诉模型「他的范围里成牌多少、听牌多少、空气多少」。

分区**不**用于分别算权益。权益永远在当前加权范围上、按剩余牌 runout 算一次。

### 3.2 权益一致性

要求的不变量：对一手不行动的纯听牌范围，

```
eq(flop) == Σ_turn P(card) × eq(turn | card)
```

- 花听翻牌 ≈ 35%，转牌空白 ≈ 19.6%，转牌成花 = 100%；
- 加权回翻牌正好 ≈ 35%。

这条不变量现在会破，原因不是权益算法，而是**换街时把听牌从范围里筛掉了**。
新模型里听牌只被「听牌类动作倾向」加权，不被成牌强度门槛砍，所以不会跳变。

### 3.3 成牌「只缩」的精确化

- 权重：在动作越来越强的序列下单调不增（似然单调）；
- 集合：可以变——公对/反超会让两对降级，牌面变化会改 `class`；
- **慢打**：怪物 call 的概率不能设 0（建议 0.3–0.45），否则 set 慢打会被排除。
  现有 `feature_weight` 对 call 把两对以上折到 0.25，方向对但过头了。

### 3.4 听牌「不变」的精确化

- 不被成牌强度筛掉；
- 但会升级（后门→花听→成花）、降级（转牌没发到）、被大注打弃；
- 所以准确说法是：**听牌的权重只由听牌类动作倾向决定，权益由同一批 combo 的
  runout 决定**。
- **街因子**：听牌权重按四二法则缩放——翻牌 ×1.0（还剩 4 张发牌）、转牌 ×0.5
  （2 张）、河牌 ×0（`draw` 已归 `none`）。4/2 的绝对倍数会在每个动作的合法
  动作集归一化里约掉，所以表里存相对翻牌的 1.0 / 0.5 / 0；它只缩放类别权重，
  权益仍在当前加权范围上按剩余牌 runout 精算。

## 4. 上下文与桶

### 4.1 十个桶

按「行动前」的状态切：

| 桶 | 触发条件 | 典型线路 |
|---|---|---|
| `lead_hu` | 无人下注、他首个行动、身后 1 人 | SB vs BB 的 lead |
| `lead_multiway` | 无人下注、他首个行动、身后 ≥2 | 三人池 UTG lead |
| `donk_hu` | 无人下注、他首个行动、身后 1 人 + 上一街 aggressor 还在且未行动 | 单挑 donk |
| `donk_multiway` | 无人下注、他首个行动、身后 ≥2 + 上一街 aggressor 还在且未行动 | **本手 UTG+1** |
| `stab` | 无人下注、不是首个行动（前面都过牌） | 按钮位 stab |
| `closing_check` | 最后行动、前面都过牌 | 大盲 check |
| `facing_bet_closing` | 面对 1 个下注、身后 0（跟注即封口） | 单挑 call/fold |
| `facing_bet_open` | 面对 1 个下注、身后 ≥1 | 中间位面对下注 |
| `facing_bet_and_call` | 面对下注 + ≥1 个跟注 | **本手 HJ** |
| `facing_raise` | 面对加注（3-bet 场景） | 兜底粗桶 |

规则：

- `donk` 按口径 A 判定，优先于 `lead_*`；
- 稀有桶（`donk_hu`、`facing_raise`）回退到父桶 + 乘数，不单独手填；
- 桶是**联合**的，不是「behind × facing × callers」的加权标量——那会把
  「2 人身后、无人下注」和「0 人身后、面对下注+1 跟注」压成同一个数。

### 4.2 桶乘数（示意，待标定）

| 桶 | value | semi_bluff | bluff |
|---|---:|---:|---:|
| `donk_multiway` | ×1.3 | ×1.0 | ×0.3 |
| `donk_hu` | ×1.2 | ×1.0 | ×0.6 |
| `lead_multiway` | ×1.1 | ×1.0 | ×0.7 |
| `lead_hu` | ×1.0 | ×1.0 | ×1.0 |
| `stab` | ×0.9 | ×1.1 | ×1.3 |
| `closing_check` | ×1.0 | ×1.0 | ×1.0 |
| `facing_bet_closing` | ×0.9 | ×1.1 | ×1.2 |
| `facing_bet_open` | ×1.1 | ×1.0 | ×0.8 |
| `facing_bet_and_call` | ×1.2 | ×0.9 | ×0.4 |
| `facing_raise` | ×1.3 | ×0.9 | ×0.3 |

方向才是重点：多人 + 面对下注 → 价值升、诈唬降；封口跟注 → 反过来。

### 4.3 SPR 与画像

- SPR 分桶：`<0.5 / 0.5–1 / 1–2 / 2–4 / 4+`。SPR 越低，bet/raise（含 jam）的
  倾向越高，中等成牌也能套池。
- 画像只调两个旋钮：**诈唬系数**（station 0.5 / 常规 1.0 / maniac 1.8）和
  **跟注宽度**。不给每个档位单独拟合，样本不够。
- SPR/画像是**乘性修正**，与桶相乘。这是可分离近似，先接受，后续用 outbox
  A/B 看是否需要联合表。

### 4.4 表的大小

- 基础表：3 组 × 4 动作 = **12 格**；需要细分时用 9 个牌型档 × 4 动作 = **36 格**
  （可选覆盖，不强制全填）；
- 桶乘数：10 桶 × 3 组 = **30 个数**；
- SPR/画像：约 **10 个数**。

合计 52–76 个数，可手写、可解释、可单测。对比「5×6×10×4×5×4 = 24000 格」不可维护。

## 5. 数据结构

```python
@dataclass(frozen=True)
class ActionEvent:
    street: str                  # flop / turn / river
    board: str                   # 动作发生时的牌面（3/4/5 张）
    seat_id: str
    action: str                  # check / call / bet / raise
    all_in: bool                 # jam 不单独成动作，只是 True
    amount: float
    facing_bet: bool             # 行动前本街是否已有 bet/raise
    n_callers: int               # 行动前、本街这个下注之后的跟注数（不含 limper/冷跟）
    players_behind: int          # 行动前还能行动的对手数
    is_first_to_act: bool        # 本街第一个行动
    is_last_to_act: bool         # players_behind == 0
    closes_action: bool          # 这次跟注是否封口（身后无人能再加注）
    prev_street_aggressor: str | None   # 上一街最后一个 bet/raise 的人

```

### 5.1 伪代码

```
w = dict(prior.normalized())
for e in events:                       # 只含这个对手自己的动作，按时间顺序
    bucket = bucket_of(e)              # 见 §4.1
    for combo, weight in w.items():
        cls = classify(combo, e.board) # 按 (board, combo) 缓存
        w[combo] *= likelihood(e.action, cls, bucket, spr_bucket(e), archetype) ** alpha
    w = normalize(w)
```

`classify` 按 `(board, combo)` 缓存，1326 个 combo × 4 个事件 × 4 家 ≈ 2 万次查表，
远小于 MC 权益的开销。

## 6. 渲染（给模型的事实）

范围块除了「宽度 + 领先比例」，还要给**分区和线路**：

```
范围（示意）：UTG+1 前置位 donk 进 2 人 ≈6%｜HJ 最后位置面对下注+跟注加注 ≈5%
- UTG+1：成牌 96%（同花 45、葫芦 18、三条 24）、空气 4%（按画像约 3/4 会推）
- HJ：成牌 98%（同花/葫芦）、空气 2%
- 你领先的：空气（诈唬）；赢你的是：同花、葫芦、三条
- 范围警告：这个范围里你只赢诈唬；跟注站 OOP 多人 donk 的诈唬频率到不了 24%
```

要点：

- **线路写出来**（前置位 donk 进 2 人 / 最后位置加注），这是模型判断范围强弱最需要的；
- **分区写出来**（成牌/听牌/空气），而不是只给一个权益；
- 「你领先的 / 赢你的」按牌型列，避免把「领先 76%」误读成「76% 会推」；
- 河牌面对全下时给「只赢诈唬」的警告；翻牌/转牌面对全下时给「听牌占比」。

## 9. 测试与验收

### 9.1 口径单测

- **donk A**：本手 UTG+1 → `donk_multiway`；改成「UTG+1 过牌、Hero 过牌、HJ 下注」→ HJ 走 `stab`；
  「UTG+1 过牌、Hero 下注、UTG+1 加注」→ `check_raise`（不是 donk）；
  aggressor 已弃牌 → 不是 donk。
- **IP/OOP B**：Hero 在中间的三方池，CO 下注、BTN 未行动 → CO `players_behind=1`，
  范围比 BTN 在同样牌面下注更紧；Hero 的「待行动人数」仍按相对 Hero 算。
- **jam**：`all_in=True` 的 bet/raise 不产生新动作档，只走 `spr_bucket`。
- **n_callers**：翻前 limper/冷跟不计入；本街 bet 之后的跟注才计。

### 9.2 单调性（不依赖标定值）

- `behind` 0→1→2+，bluff 乘数单调不增；
- `donk_multiway` 的空气权重 < `lead_hu`；
- `facing_bet_and_call` 的诈唬 < `facing_bet_open`；
- `facing_bet_closing` 的跟注宽度 ≥ `facing_bet_open`。

### 9.3 权益一致性

- 纯花听翻牌权益 ≈ 35%；转牌空白 ≈ 19.6%；转牌成花 = 100%；
  按转牌发牌概率加权回翻牌 ≈ 35%（±1%）。

### 9.4 回归

- 本手：河牌两次决策都 fold；事实层 `对范围权益` ≈ 2–4%（第一次）、≈ 0–1%（第二次）。
- 花顺双抽在翻牌全下：范围里 `semi_bluff` 占比 > 0，不能被强度门槛杀掉。
- 短码（SPR<1）顶对全下：`medium` 档的 jam 似然显著高于深码。

## 10. 风险与未决

1. **标定**：没有 solver 数据，表是先验。先保证方向单调，再用 outbox A/B 微调；
   不要逐格拟合。
2. **连乘过度自信**：用温度 α；同一街重复动作再打折。
3. **多人独立性**：`hand_vs_ranges` 仍然按独立抽样处理对手，未建模范围相关性。
4. **side pot 未建模**：本手第二次 call 的 47 只和 HJ 争边池，现在按一个大池算。
   这是独立问题，建议单开。
5. **动作顺序**：OCR 漏抓/推断的顺序会影响 `players_behind` / `n_callers`，
   数据质量段要标注。
6. **prompt 长度**：分区和线路会增加事实块长度，渲染要控制在一屏内。

|---|---|---|---|---|
| 转牌 | `6h Kd 9d 4h` | HJ | call 30 | 面对 Hero 下注；身后 5 人；n_callers=0 |
| 转牌 | `6h Kd 9d 4h` | UTG+1 | call 30 | 面对 Hero 下注；身后 4 人；n_callers=1（HJ 已跟） |
| 河牌 | `6h Kd 9d 4h Kh` | UTG+1 | bet 63（all-in） | 首个行动；身后 2 人；无人下注；上一街 aggressor=Hero 且未行动 → **donk_multiway** |
| 河牌 | `6h Kd 9d 4h Kh` | HJ | raise 110（all-in） | 面对下注 + 1 跟注；身后 0 → **facing_bet_and_call** |

### 11.2 范围演化

- 翻前：BOMB = 任意两张；
- 转牌跟注后：听牌（红桃）+ 对子/暗三/两对 + 部分 Kx；空气被压低；
- 河牌 `Kh`：红桃听 → 同花；暗三/两对 → 葫芦；Kx → 三条；错过的听牌 → 空气；
- UTG+1 donk-jam：value ×1.3、bluff ×0.3 → 同花/葫芦/好三条为主，空气 ~3–4%；
- HJ 加注：value ×1.2、bluff ×0.4 → 同花/葫芦，空气 ~2%。

### 11.3 结果

| 决策 | 需要权益 | 旧事实层 | 新模型预期 |
|---|---:|---:|---:|
| 河牌 call 63 | 24.1% | 69% | 2–4% |
| 河牌 call 47 | 11.2% | 60% | 0–1% |

结论：两次都 fold。和旧结论的差别在于理由——不是「明三条不够强」，而是
「转牌跟注范围里的听牌在河牌变成了同花，你只赢那部分没中的空气；跟注站
OOP 多人 donk 的诈唬频率到不了 24%」。

## 12. 实现备注（落地口径与设计稿的差异）

代码：`poker_ocr/range_flow.py`（新）、`field_ranges.build_events`、
`hand_vs_ranges._lookup`、`advice.render_ranges_zh`。开关 `RANGE_EVENT_MODEL`
默认开（`=0` 回退旧口径），温度 `RANGE_EVENT_ALPHA`，支撑集
`RANGE_EVENT_SUPPORT_FLOOR`。测试：`tests/test_range_flow.py`。

### 12.1 似然按「合法动作集 + 弃牌项」归一化，不是四动作

设计 §2.1 写的是「按 (class, ctx) 归一化到 1」。落地时改成频率表：

- 面对下注：`call / raise / fold` 三列归一化；
- 无人下注：`check / bet` 两列归一化；
- 听牌在四列上另有乘性调整（花听 call×10、fold×0.08）。

原因：四动作归一化在**绝对频率**上没有意义。一次更新里「空气跟注」和
「花听跟注」最多只差几倍，连乘三个动作也压不掉 700 个空气 combo——实测
本手第一次河牌停在 27.5%，仍高于 24.1% 的跟注门槛。带弃牌项的频率表是
同一公式 `L(a|class,ctx)` 的更严格实现：一个纯花听面对 2/3 池下注几乎
不弃（fold 0.08），纯空气弃 0.937，范围收窄的量级才对得上。

### 12.2 成牌档按**牌面百分位**分，不是按牌型名

设计 §2.2 的映射是绝对牌型（两对、一对……）。落地改成「这手牌在该牌面上
比多少 combo 大」：

| 百分位（比它大的比例） | 档 |
|---:|---|
| ≤2% | nut |
| ≤10% | strong |
| ≤32% | medium |
| ≤68% | weak |
| >68% | air |

原因：KK66 在 `K9642` 上是次坚果，在 `6K94KK`（成花 + 公对）上只是抓诈唬；
绝对牌型会把它们放进同一档，多人池的 donk-jam 里两对就被当成价值牌留下。
牌型名（同花/葫芦/两对）仍然只用于渲染。实现上 `board_range.Features`
多存一个 `tiebreak`，`range_flow._class_map` 按 `(牌型, 踢脚)` 排序算百分位。

### 12.3 桶乘数从 3 组细化为 5 档

设计 §4.2 的桶 × 3 组（value / semi_bluff / bluff）不能表达「价值组内部
还要向坚果集中」：`donk_multiway` 的 value×1.3 会同时抬高三条和两对。
落地改成 10 桶 × 5 个成牌档（50 个数，仍在 §4.4 的 52–76 预算内）：

```
donk_multiway:  nut 1.60  strong 1.35  medium 0.06  weak 0.10  air 0.20
```

方向不变（多人 + 面对下注 → 强牌升、弱牌与诈唬降），但**档位可以反向**：
强牌升、medium 降。`group_multiplier()` 仍按设计稿的 3 组口径提供
（value 取 strong 档做代表），供文档/测试对照。桶乘数仍然只作用在
非过牌动作上（理由见 §2.1 与模块 docstring）。

### 12.4 温度 α 与动作数挂钩

设计稿默认 α=0.7。实测 3 个动作下 α=0.7 太保守：本手第一次河牌 27.5%，
结论仍是 call，P1 验收（<10%）不通过。落地：

```
α_eff = α                         n ≤ 3
α_eff = max(0.5, α·0.97^(n-3))    n ≥ 4
```

`α=1.0`（精确更新）用于短线路，4 个以上动作才降温，避免连乘把范围压成
两三个 combo。`RANGE_EVENT_ALPHA` 可覆盖。

### 12.5 支撑集与「有效宽度」

连乘后每个 combo 都非零，支撑集宽度（`Range.width_pct`）会接近 100%。
落地保留全部权重做权益，但：

- `RANGE_EVENT_SUPPORT_FLOOR`（默认 1e-3，相对最大权重）以下不进范围，
  让真正被压死的空气退出支撑集；
- 提示词里报**有效宽度**：按权重从高到低累加到 90% 质量所需的 combo 占比
  （`Range.effective_width_pct()`）。本手 UTG+1 的支撑集 64%、有效宽度
  5.9%，后者才是「他的范围有多窄」这个事实。

### 12.6 实测（`tools/replay_hand_outbox.py --all --facts`，304 个决策点）

| 项 | 旧口径 | 事件模型 |
|---|---|---|
| 本手河牌第一次 `对范围权益` | 69% | 5% |
| 本手河牌第二次 `对范围权益` | 60% | 1% |
| 两次决策结论 | call / call | fold / fold |
| 109 个有范围的决策点 | — | 均值 −1.2pt、中位数 0pt、仅 3 个移动 >20pt |
| 304 个决策点总耗时 | 13.8s | 15.3s（约 +5ms/决策） |

§9.4 的「≈2–4% / ≈0–1%」第一次落在 5%，比设计稿预期高 1–3 个点：范围里
仍保留约 5% 的两对（Hero 能赢的那部分）。结论（fold）不受影响。
