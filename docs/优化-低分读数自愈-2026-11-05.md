# 低分读数的自愈（ROI 去重）· 2026-11-05

## 问题

`RoiDedupCache` 的判据是**像素**：这块 ROI 和上一帧比没变，就复用上一帧的读数。
而 OCR 是确定性的 —— 同一块像素重读一万次还是那个错字。于是：

> 前几帧把 `TOBD` 读成 `TOBD`（本来是 `10BB`）→ 像素没变 → 每帧复用同一个错值
> → 下游看到它和「识别器读对了」一模一样。

去重本身有两道闸：严格 dhash（逐 bit 全同）和 MAD 兜底（eps 0.2）。**MAD 是宽松的那道**，
它的安全余量只有 1.3 倍（见 `roi_dedup` 模块 docstring）。一块本来就「读得不太确定」的
ROI 再叠一层宽松判据，等于让一个可能是错的值一直挂在缓存里。

## 改动

`poker_ocr/roi_dedup.py`：

| 位置 | 行为 |
|---|---|
| `store()` | 分数落在 `[STRICT_MIN_SCORE, min_cache_score)` 的**非空**读数，标成 `strict` |
| `check()` | `strict` 的 key **不吃 MAD 兜底**，只认 dhash 逐 bit 全同；被拦下的次数记 `blocked_by_strict` |
| `pin()` | `strict` 的 key **不许钉住**（钉住 = 这一手不再重读，错读就没机会纠正） |
| `RoiStream._signature_of()` | 把 `min_cache_score` 并进缓存签名：改这个参数会整份作废缓存 |
| `to_debug()` | 多出 `min_cache_score` / `strict_floor` / `strict_keys` / `blocked_by_strict` |

两头都排除，理由都是实测的：

- **空读数**（这块没字）不标 strict —— 一帧 32 块里有 15 块是空的下注位/横幅，
  重读一次还是读不出，纯浪费 15 次 rec。
- **分数 < 0.35 的碎片**不标 strict —— 头像是照片，rec 会吐 `舞` `展` `A` `G`，
  实测 9 个座位全在 0.10–0.32。这种读重读还是碎片，而头像 det+rec 是最贵的一块。
- 真正「可能是字、但读岔了」的落在 **0.45–0.66**（`TOBD` / `ZCERR` / `1485PB` / `2710`），
  这些才是值得在像素动了之后重读一次的。

标定依据（一张真实样张，32 块）：

```
分数 <0.35 且无文本 : 15 块   → 空读数，不动
分数 0.10–0.32 有文本:  5 块   → 头像碎片，不动
分数 0.45–0.66 有文本:  6 块   → 标 strict
```

## 代价（实测）

| 场景 | 改前 | 改后 |
|---|---|---|
| 静态帧（像素逐 bit 相同）p50 | 19.6ms | 20.0ms |
| 静态帧 `blocked_by_strict` | — | **0**（dhash 照样命中，一次 rec 都没多跑） |
| 一帧 32 块里的 strict 数 | 0 | 9 |

也就是说：**画面真没变的时候一分钱不花**；只有「像素动了但 MAD 想放过」的模糊区间，
才会把复用换成一次重读 —— 那正是我们希望它重读的时刻。

## 没做什么（以及为什么）

原本计划「解析结果也进缓存」，实测后放弃：

```
frame_state.build_state  20 次调用共 0.006s → 0.3ms/帧，占整帧 21ms 的 1.5%
```

解析在这条链路里根本不贵，做缓存只换来 1-2ms，却要引入「解析结果与文本/上下文不同步」
的新故障面。收益不值这个风险。

## 测试

`tests/test_roi_dedup.py` 新增 4 例：

- `test_low_score_read_ignores_mad_fallback` —— 低分 key 被 MAD 拦住会重读；高分 key 照旧命中（对照组）
- `test_empty_read_stays_cheap` —— 空读数继续复用，不进 strict
- `test_photo_noise_is_not_treated_as_uncertain_text` —— 头像碎片继续复用
- `test_low_score_read_cannot_be_pinned` —— 低分不许钉；读到可信值后可以钉

全量 `tests/run_all.py`：**42 个套件全部通过**。

## 还没解决的

- 像素**逐 bit 完全相同**时，错读仍然纠不回来（重读也是同一个结果）。这只能靠下游
  自洽性（pot 对账 / 质量闸）或换模型解决，缓存层无能为力。
- 整帧快速通道（省掉每帧约 13ms 的分块 hash + 图标连通域）还没做：它要改 `ingest` 的
  帧计数语义，得单独设计。
