## 1. 这次改了什么

新增 `poker_ocr/ground_truth.py`，把原来散落在 `render_hand_facts` 里的牌力事实收成一个固定块：

- **精确坚果校验**：枚举对手所有两张暗牌，给出 `beaten_by`（按牌型分组）、`hero_is_nuts`、`best_opponent_*`；
- **牌面结构精确化**：把「已成花可能（≥3 同花）」和「只是花听（=2 同花）」分开；
- **最好五张 / 用了哪两张底牌 / 听牌 outs**；
- **`ABSOLUTE NUTS → RAISE`**：`value_directive` 在 `hero_is_nuts` 且面对下注时，直接禁止「可能有更大的牌」这个理由；
- 两套 system prompt 都注入 `_GROUND_TRUTH_RULES`，要求「只能引用、不能重算」。

对应上次报告里的 990010 转牌退化，这次的目标很明确：**坚果就是坚果，不能因为「被动玩家下注 = 价值」就只跟。**

测试：`tests/test_ground_truth.py`、`test_beat_rate.py`、`test_advice.py`、`test_coach.py` 共 153 条全部通过。

### 3.2 GT 相对上一版，只改了 2 个点

逐行比对 101 个决策点，**99 个完全一样**，只有 h104 两个点不同（动作分布：上一版 fold 53 / passive 33 / bet 6 / raise 9；GT fold 53 / passive 34 / bet 5 / raise 9，差的就是 h104 那一个 bet）：

| 手/街 | 上一版 lean | 本版 GT | 判定 |
|---|---|---|---|
| h104 preflop | `open-4` | `open-4.5` | 尺度噪声，不重要 |
| **h104 flop（单挑，坚果花听）** | **`bet 1/3`** | **`check`（4/5 次）** | **GT 软退化** |

h104 的具体事实：

```
BB AsKd，翻牌 Ts 8s 9s（monotone，三家同花面）
单挑，底池 46，Hero 坚果花听 + 两张高牌，9 outs，36% 权益
```

- 复盘文档的既定结论：**单挑强听没有下注在前 → BET 1/3**；线上实际也是 bet 11.5。
- 上一版 lean：`raise-1/3`。
- 本版 GT：`check`（4/5 重复采样；1/5 会 `raise-2/3`）。
- GT 的理由：「Monotone board with flush/straight already possible; A-high draw has no fold equity vs a station, so check.」

**为什么 GT 会变保守？** 事实块对「未成牌的听牌」仍然写：

```
NUT STATUS: NOT THE NUTS — better hands exist: One pair, Two pair, Trips,
Straight, Flush, Straight flush. Best possible opponent hand: Straight flush.
Warnings: A flush is ALREADY possible... This is a DRAW, not a made hand...
```

这些对「当前未成牌」是正确的，但模型把 `NOT THE NUTS` 当成了「不能下注」，压过了 `SEMI-BLUFF DEFAULT`（8+ outs 单挑应下注）。**这是 GT 本次在线上唯一的实质变化，也是唯一变差的地方。**

### 3.3 线上结论

- 硬规则：GT 和上一版**打平**，都是 14 → 0。
- 线上没有出现 `hero_is_nuts=True` 的点，所以 `ABSOLUTE NUTS` 分支在线上**一次都没触发**；GT 的收益在线上为 0。
- GT 唯一改变的是 h104，而这一手按既定口径应该下注 1/3。**线上这一组，上一版略好。**

### 4.3 关键手细节

#### 990010 转牌：上一版错的，GT 修对了

```
BTN AsTh
翻前：三家 limp，Hero 加注 7.5，三家跟
翻牌 Jc8dKd：三家 check，Hero check
转牌 Qc：三家 check，UTG+2 下注 36（底池 72）
```

- Hero 是 **A-K-Q-J-T 坚果顺**；牌面只有 **两张方块**，没有成花。
- GT 事实块：
  - `Board structure: FLUSH: no made flush possible (at most 2 of any suit — flush DRAW only)`
  - `Made-hand rank: beaten by 0.0%; NUT STATUS: NUTS — no opponent holding can beat you; you can only chop (0.9%)`
  - `Value directive: VALUE DEFAULT — ABSOLUTE NUTS ... RAISE ... Do NOT call`
- 上一版：`call 36`（理由「flush board / made flushes beat me」）。
- 本版：`raise 108`（`raise-2/3`），3/3 稳定；实际线上是 raise 90。
- **这是 GT 最大的价值：把「坚果被幻觉成非坚果」这类错误直接压掉。**

#### 990050 面对 25 all-in：GT 方向对，但不稳定

```
BTN QdQc，翻前 4bet 到 64
翻牌 KsKd3d：Hero bet 89，LJ all-in 114，Hero 需跟 25，底池 362.5
```

- 实际：call（正确；25 / 362.5 = 6.9%，两对即便落后也有足够权益）。
- 上一版：fold（太紧）。
- 本版主跑：call 25；但 3 次重复 **2 fold / 1 call**。
- GT fold 的理由：「my two pair is beaten by 9.3% and the price is not good」——**价格明显是好的**，模型把「被动玩家 all-in = 价值」的启发式压过了赔率。
- 根因：`VALUE CAUTION` 写的是「fold only to a large bet (pot-sized or more) or to a raise/all-in」；这里虽然是 check-raise all-in，但只占底池 6.5%，指令没有「小额 all-in 例外」。**模型有时照字面 fold。**

#### 990034 顶对面对小注：GT 更合理

```
UTG Js3s，翻牌 Jd4d5s
Hero check，UTG+2 bet 7（底池 25），CO call，Hero 需跟 7
```

- 实际：fold（偏紧，用户自己也问「我 fold 过于弱了吗」）。
- 上一版：fold。
- 本版：**call 7，3/3 稳定**；`SHOWDOWN DEFAULT` 明确说顶对面对小注通常该 call。
- **这个点 GT 明显更合理。**

#### 990030 顶对弱踢 5 家池：GT 尺度偏大

```
BB As6s，翻牌 AcJc2d（两家同花面）
5 家，Hero 顶对弱踢（A6），无人下注
```

- 实际：check；上一版：bet 5.5（1/2）；本版：**bet 7.33（2/3），3/3 稳定**。
- GT 理由：「Top pair with 92.7% equity vs five loose-passive callers」——`92.7%` 是**单对手**权益，不是 5 家同时胜率；5 家至少一家领先约 30%。
- 顶对弱踢 5 家池，2/3 偏大；上一版 1/2 更稳。**这是 GT 的软退化，根因是事实块没有渲染 `beat_at_least_pct`，模型把 `equity` 当成了多人胜率。**

## 5. 哪个更好：按维度打分

| 维度 | 上一版 lean | 本版 GT | 胜者 |
|---|---|---|---|
| 硬规则违规（线上 + dev 库） | 0 | 0 | 平 |
| 坚果被误判（990010 转牌） | ❌ call | ✅ raise 108（3/3） | **GT** |
| 小注 all-in 赔率（990050） | ❌ fold | ⚠️ call 主跑，2/3 重复 fold | GT 略好，但不稳定 |
| 顶对 vs 小注（990034） | ❌ fold | ✅ call（3/3） | **GT** |
| 单挑强听（h104） | ✅ bet 1/3 | ❌ check（4/5） | **上一版** |
| 多人池薄价值尺度（990030） | ✅ 1/2 | ⚠️ 2/3（3/3） | 上一版 |
| 价值尺度（990044 转牌） | 1/3 | ✅ 1/2（贴实际 56） | **GT** |
| 稳定性 | 990010 稳定错 | 990010 稳定对；990050 不稳 | GT 略好 |

**结论：整体 GT 更好。** 理由：

1. GT 修掉的是**严重错误**（坚果当非坚果、顶对对小注弃牌、价值尺度偏小），这些对长期 EV 的影响大于「1/3 还是 2/3」的尺度差。
2. GT 在线上没有引入新的硬违规，唯一变化 h104 是**软退化**，且可以通过一条听牌规则修掉。
3. GT 的 990050 虽然不稳定，但方向比上一版的稳定 fold 更对；补一条「to_call / pot < 10% 不 fold」的硬闸即可。

**但不能说 GT 完胜：**

- 如果只看线上这一组，上一版略好（h104）。
- 如果只看「强听单挑该不该下注」，上一版更符合既定口径。
- GT 的多人池 `equity` 口径和听牌 `NUT STATUS` 是两个新引入的误导点，需要补丁。

## 6. 两个新暴露的事实层问题（建议修）

### 6.1 `_rank_text` 漏了 `beat_at_least_pct`

`poker_ocr/ground_truth.py:263` 的 `_rank_text` 只写：

```
beaten by X% of hands; ties Y%; equity Z%.
```

但 `RankInfo` 里明明有 `beat_at_least_pct`（多人时至少一家领先），`rank_hands()` 也已经算好。模型看到「5 opponents ... equity 92.7%」时，会把 **单对手权益**误读成「5 家同时我领先 92.7%」，于是：

- 990030 顶对弱踢 5 家池 → 2/3 下注；
- 990034 主跑偶尔 → 2/3 下注（重复采样又回到 check）。

**建议**：`_rank_text` 增加一行：

```
Multiway: with N opponents, X% chance at least one is ahead
(this is the number to use for thin value; equity above is per opponent)
```

### 6.2 听牌的 `NUT STATUS` 压过了 `SEMI-BLUFF DEFAULT`

h104 的 GT 块：

```
Made hand: HIGH CARD (A-high)
NUT STATUS: NOT THE NUTS — better hands exist: One pair, ... Straight flush
Warnings: This is a DRAW, not a made hand...
```

这些对「当前未成牌」是对的，但模型把 `NOT THE NUTS` 当成「不能下注」，忽略了：

```
Draws: nut flush draw in s (9 outs); total 9 outs (rule of 4/2 equity 36%)
Value directive: SEMI-BLUFF DEFAULT — 8+ out draw with no bet in front — betting is preferred
```

**建议**：对 `hand_tier in (STRONG_DRAW, WEAK_DRAW)`，事实块不要用成手牌的 `NUT STATUS` 作为主状态；改成：

```
DRAW STATUS: nut flush draw, 9 outs, 36% equity; made-hand rank NOT applicable.
Semi-bluff is preferred heads-up; ignore the made-hand NUT STATUS below.
```

或者至少在 `_GROUND_TRUTH_RULES` 里加一条：**「如果是 DRAW，`NUT STATUS` 只描述当前未成牌，不得用它否决 `SEMI-BLUFF DEFAULT` / `DRAW ODDS`。」**

### 6.3 附带：`ABSOLUTE NUTS` 没看 `tie_pct=100`

`value_directive` 的 `ABSOLUTE NUTS` 分支只看 `hero_is_nuts`，没看 `tie_pct`。如果公共牌自己就是皇家同花顺/坚果（所有人都分池），`hero_is_nuts=True`、`tie_pct=100%`，指令仍会说 `RAISE/BET`。建议加 `tie_pct < 1.0` 条件；100% 分池时 check/call。

### 6.4 `VALUE CAUTION` 对「小额 all-in」没有例外

990050 的指令：

```
Do NOT raise. Call a normal-sized bet ... fold only to a large bet
(pot-sized or more) or to a raise/all-in.
```

这里 check-raise all-in 只占底池 6.5%，照字面就该 fold，但数学上必须 call。建议：

```
If to_call <= 10% of pot, call with two pair or better / strong draw,
even if the bet is technically a raise/all-in.
```

## 7. 最终回答

**哪个更好？**

- **整体：GT 更好。** 它在最严重的「坚果被幻觉成非坚果」上稳定修对（990010 3/3 raise），并把 990034 顶对弃牌改成跟注（3/3）；同时保持线上/ dev 库硬违规 0。
- **线上这一组：上一版略好**，因为 GT 把 h104 单挑坚果花听从 1/3 下注改成了过牌（4/5 稳定），这和既定复盘口径相反。
- **dev 库这一组：GT 明显更好**，尤其是 990010 和 990034；代价是 990030 的 2/3 尺度偏大、990050 仍不稳定。

**如果只选一个版本上线：选 GT，但先补 6.1（`beat_at_least_pct`）和 6.2（听牌不要被 `NUT STATUS` 压住）两个补丁。** 补完之后，GT 在 h104 和 990030 这两类软退化上应该能回到上一版的水平，同时保留 990010 的坚果修复。
