# 导入手牌格式说明

手牌库支持两种导入来源：

1. **复盘手牌**：从 `call-back` 的 `review_hands` 导出的 JSON 数组 / JSONL；
2. **实时日志手牌记录**：`tools/export_live_hands.py` 产出的 `hands.json`，或实时识别原始日志 `logs/live.states.jsonl`。

两种格式最终都会归一成与 `review_hands` 同样的内部字段，再交给 `replay.decisions.analyze_hand()` 重建 hero 决策点。因此导入后的手牌可以像原生手牌一样收藏、筛选、逐街对比和重跑。

---

## 1. 入口

页面：**手牌库 → 导入手牌**。

流程：

1. 拖入 `.json` / `.jsonl` / `.txt`，或直接粘贴文本；
2. 选择格式（默认自动识别）；
3. 点 **解析预览**，检查「新增 / 更新 / 重复 / 不可重跑 / 错误」；
4. 点 **确认导入**，回到手牌库即可看到。

API：

```bash
# 预览（不写库）
curl -s http://127.0.0.1:8010/api/hands/import \
  -H 'Content-Type: application/json' \
  -d @- <<'JSON'
{
  "format": "auto",
  "dryRun": true,
  "dedupe": true,
  "allowInvalid": false,
  "content": "<文件原文>"
}
JSON

# 确认导入
curl -s http://127.0.0.1:8010/api/hands/import \
  -H 'Content-Type: application/json' \
  -d '{"format":"auto","dryRun":false,"content":"<文件原文>"}'
```

参数：

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `format` | `auto` | `auto` / `review` / `live` |
| `dryRun` | `false` | true 只预览，不写库 |
| `dedupe` | `true` | 跳过库中已有相同内容的手牌 |
| `allowInvalid` | `false` | 是否导入不可重跑的手牌 |
| `includePartial` | `false` | 仅 live：保留 `partial: true` 的截断手牌 |
| `includeMidHand` | `false` | 仅 live：保留从翻后开始的中途接管手牌 |
| `filename` | 空 | 仅用于批次记录与页面展示 |

## 2. 复盘手牌

### 2.1 来源

`review_hands` 导出的 JSON 数组或 JSONL。控制台**只读** `review_hands`，导入的数据写入 `replay_imported_hands`，不会回写业务库。

推荐导出方式（与 `tools/replay_dev_hands.py` 一致）：

```sql
SELECT JSON_OBJECT(
  'id', id,
  'heroPosition', hero_position,
  'heroCards', hero_cards,
  'heroStackBb', hero_stack_bb,
  'sb', small_blind_bb,
  'bb', big_blind_bb,
  'ante', ante_bb,
  'bombPot', bomb_pot_bb,
  'board', IFNULL(board, ''),
  'villainCount', villain_count,
  'villains', villains,
  'streets', streets,
  'result', result,
  'resultAmount', result_amount,
  'createdAt', created_at
)
FROM review_hands
WHERE deleted_at IS NULL;
```

输出可以是：

- 每行一个 JSON（JSONL）；
- 或把这些行组成一个 JSON 数组。

### 2.2 字段映射

| 导入字段（兼容写法） | 内部字段 | 说明 |
| --- | --- | --- |
| `heroCards` / `hero_cards` | `hero_cards` | 字符串 `AhKd`，也接受 `["Ah","Kd"]`、`Ah Kd` |
| `board` | `board` | 字符串 `Ks7d2c` 或数组 |
| `heroPosition` / `hero_position` | `hero_position` | `UTG` / `BTN` / `BB` … |
| `tableSize` / `table_size` / `villainCount` | `table_size` / `villain_count` | 人数缺失时用 `villainCount + 1` |
| `heroStackBb` / `hero_stack_bb` | `hero_stack_bb` | BB 单位 |
| `smallBlindBb` / `small_blind_bb` / `sb` | `small_blind_bb` | |
| `bigBlindBb` / `big_blind_bb` / `bb` | `big_blind_bb` | `bb<=0` 会被判 invalid |
| `anteBb` / `ante_bb` / `ante` | `ante_bb` | |
| `bombPotBb` / `bomb_pot_bb` / `bombPot` | `bomb_pot_bb` | 真值会标爆炸底池 |
| `villains` | `villains` | `[{position, name, stackBb}]` |
| `streets` | `streets` | 数组，或 JSON 字符串 |
| `streets[].street` | | `preflop` / `flop` / `turn` / `river` |
| `streets[].potStartBb` / `pot_start` | | 该街起始底池；没有则从盲注+行动重建 |
| `streets[].actions[].actor` | | `hero` 或位置名；旧数据 `villain/other` 会标 approx |
| `streets[].actions[].action` | | `fold/check/call/bet/raise/allin` |
| `streets[].actions[].amountBb` / `amount` | | BB 单位 |
| `result` / `resultAmount` | | 仅展示，不参与指纹 |
| `created_at` / `createdAt` | | 手牌时间；缺省用导入时间 |

## 3. 实时日志手牌记录

### 3.1 两种输入

**A. `hands.json`**：由 `tools/export_live_hands.py` 从 `live.states.jsonl` 筛出完整手牌：

```bash
.venv/bin/python tools/export_live_hands.py logs/live.states.jsonl -o hands.json
```

记录形如：

```json
{
  "type": "hand",
  "ts": "2026-10-23T03:08:07+08:00",
  "hand_id": "h4",
  "uid": "s01-h4",
  "hero_cards": ["Ah", "Js"],
  "hero_position": "UTG+1",
  "table_size": 9,
  "blinds": {"sb": 0.5, "bb": 1, "ante": 0.5, "raw": "1/2（1）"},
  "hero_stack_bb": 100,
  "start_stacks": [
    {"seat_id": "topR", "name": "陈7程7", "position": "BTN", "stack": 80}
  ],
  "board": ["7c", "7h", "10d", "8c", "6h"],
  "pot": 66.5,
  "streets": [
    {
      "street": "preflop",
      "pot_start": 4,
      "actions": [
        {"seat_id": "hero", "position": "UTG+1", "action": "raise",
         "amount": 7.5, "all_in": false, "is_hero": true},
        {"seat_id": "topR", "name": "陈7程7", "position": "BTN",
         "action": "call", "amount": 7.5, "all_in": false, "is_hero": false}
      ]
    }
  ]
}
```

**B. 原始 `live.states.jsonl`**：直接拖入日志文件。导入器会：

- 跳过 `type=state`、`session_start` 等非手牌记录；
- 按 `session_start` 计会话；
- 默认跳过 `partial: true`（退出时截断的手）；
- 默认跳过第一条街不是 `preflop` 的中途接管手牌；
- 用 `uid`；没有时用 `s{session:02d}-{hand_id}` 生成。

原始日志没有 `hand_id`/`uid` 也可以；用会话序号 + 行内 `hand_id` 作为追溯 id。

### 3.2 字段映射

| 实时字段 | 内部字段 | 说明 |
| --- | --- | --- |
| `hero_cards` | `hero_cards` | 数组 → 拼接字符串 |
| `board` | `board` | 数组 → 拼接字符串 |
| `hero_position` | `hero_position` | |
| `table_size` | `table_size` | |
| `blinds.sb/bb/ante` | `small_blind_bb` / `big_blind_bb` / `ante_bb` | |
| `hero_stack_bb`（别名 `hero_stack` / `stack_bb`） | `hero_stack_bb` | hero **起始筹码**（前注/盲注之前）；缺了整手只能按 unknown 重建 |
| `start_stacks[]` | `villains[].stackBb` | 各座起始筹码 `[{seat_id, name, position, stack}]`；只补行动线/亮牌/全下里已经出现的位置，hero 自己跳过 |
| `bomb_pot` | `bomb_pot_bb` | `true` → `1.0` |
| `streets[].pot_start` | `streets[].potStartBb` | |
| `actions[].seat_id` | `streets[].actions[].actor` | `is_hero=true` 或 `seat_id=hero` 归成 `hero` |
| `actions[].action` | | `all-in` / `all_in` 归成 `allin` |
| `actions[].amount` | `amountBb` | |
| `shows` / `all_ins` / 行动线 | `villains` | 用位置去重，补充名字 |
| `hero_net` | `result` / `result_amount` | 有就用；没有则 unknown |
| `ts` | `created_at` | 手牌时间 |

## 4. 去重、id 与更新

- 唯一键：`(source, hand_fingerprint)`。`source` 是 `review` 或 `live`。
- 指纹只包含会影响建议的字段：底牌、公共牌、人数、位置、筹码、盲注、对手、行动线；**不包含**标题、输赢金额、时间、原始 id。
- 同一来源 + 相同内容重复导入 → **更新**原记录，`id` 不变，已有收藏/决策点/结果继续有效。
- `dedupe=true` 时，如果 `review_hands` 或另一来源已有相同内容 → 计为「重复」并跳过。
- 导入手牌 id 从 `1e12` 起，避免和 `review_hands` 自增 id 冲突。
- 导入批次记录在 `replay_import_batches`，可通过 `GET /api/imports` 查看。

## 5. 删除与恢复

| 来源 | 删除行为 | 恢复方式 |
| --- | --- | --- |
| 导入手牌 | `replay_imported_hands.deleted_at` 软删除；收藏/决策点/历史结果保留 | 重新导入同一份内容，`upsert` 会清空 `deleted_at` 并恢复 |
| `review_hands` 手牌 | 写入 `replay_hand_deletions`，控制台列表/详情过滤掉；**不修改** `review_hands` | 删除隐藏记录（手工 SQL） |

接口：

```bash
# 单删
curl -X DELETE http://127.0.0.1:8010/api/hands/1000000000002

# 批量删（最多 1000）
curl -s http://127.0.0.1:8010/api/hands/delete \
  -H 'Content-Type: application/json' \
  -d '{"handIds":[1000000000002,990052]}'
```

返回：

```json
{"requested":2,"deleted":2,"imported":1,"reviewHidden":1,"missing":[]}
```

删除后：

- 不再出现在手牌库、收藏、筛选和重跑范围；
- `replay_marks` / `replay_decisions` / `replay_results` 不清理，历史任务仍可追溯；
- 同一导入手牌重新导入会恢复原 `id`，已有收藏继续有效。

## 6. 已知限制

- **旧版实时手牌记录没有起始筹码**：那时导出的 `hands.json` 缺 `hero_stack_bb` / `start_stacks`，只能按 unknown 重建，页面显示黄色「重建可疑」。新版 worker 会在翻前逐帧补齐（见 `docs/live-stream.md` 的 `hand` 字段）；重新导出/导入即可。
- 实时手牌记录里的对手起始筹码只覆盖**行动线/亮牌/全下出现过**的座位；没留下任何动作或徽章的座位不会凭空补进来（避免把已弃牌的人算进有效筹码）。
- 导入**不保存线上当时的 AI 建议**（`hands.json` 里的 `advices` 仍在原始 JSON 中，但暂不作为对比基线）。
- 删除是软删除/隐藏，不做物理清理；需要彻底清理时手工删 `replay_imported_hands` 或 `replay_hand_deletions` 对应行。
- 单次导入上限：内容 32MB、手牌 10000 手。

## 7. 排查

```bash
# 最近批次
curl -s http://127.0.0.1:8010/api/imports | jq

# 手牌库按来源筛选
curl -s 'http://127.0.0.1:8010/api/hands?source=live&pageSize=20' | jq '.total, .items[0]'
```

导入失败时优先看：

1. `issues[].line` / `issues[].index` 指向的记录；
2. 是否选了错误格式（`format=review` 导入了实时日志）；
3. 实时日志是否被 `partial` / 中途接管过滤掉（勾选对应选项再试）；
4. 手牌是否因为缺底牌/行动线/bb 被判 invalid（可勾选「也导入不可重跑的手牌」查看）。
